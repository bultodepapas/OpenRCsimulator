# OpenRC project website

WEB-01 owns `site/` and the isolated `gh-pages` deployment. No simulator runtime files are changed.

## Design

Visual thesis: an RC club's aircraft catalogue, combining oversized workshop typography, original dark studio renders, ivory paper and field green.

Content: aircraft-led poster → interactive five-aircraft hangar → day/night field → transparent flight-model engineering → platform downloads and contribution paths. Spanish is the initial language; English is selectable. Downloads describe v0.1.1; source features are explicitly separate.

Interaction thesis: a short hero entrance, restrained section reveals and tactile aircraft/lighting switches. Reduced-motion preference disables animation; core content and downloads work without JavaScript.

Research, 2026-10-15: [NASA Quesst](https://www.nasa.gov/quesst-the-aircraft/) informed aircraft annotations and experimental status; [X-Plane](https://www.x-plane.com/) informed image-led feature rhythm; [RealFlight](https://www.horizonhobby.com/realflight/) informed the model/field/get-started navigation. These are composition references, not asset sources or endorsements.

## Assets and scope

Aircraft renders are from [presentation media](../docs/media/README.md); field captures are from [LU-21](../docs/research/landscape-upgrade/LU-21/README.md). Web derivatives are generated by `prepare_assets.py`, without changing aircraft or scenery. Original media and its provenance remain authoritative. Fonts are freely licensed; bundled license files live alongside them. No remote font, analytics, runtime framework or paid asset dependency.

## Preview and maintain

From the repository root: `python -m http.server 4173 --bind 127.0.0.1 --directory site`. Open `http://127.0.0.1:4173/`. The page uses relative asset URLs and works at GitHub's project subpath.

Regenerate images with Pillow 12.3.0 and `python site/prepare_assets.py`. Edit copy in `index.html` and its matching English translation in `main.js`. Update platform downloads, version and sizes together after a release. Keep source-state claims separate from release contents and preserve experimental labels.

Publication uses a separate `gh-pages` branch with only the static website. GitHub Pages serves `/` from that branch; `.nojekyll` disables processing. The main working tree and its unrelated pending changes are never included in that publication. The website is a project showcase, not a browser build of the simulator.

Publish with `python site/publish.py` after browser verification. It requires Git identity and an authenticated `gh` with repository admin access; it refuses to replace a different existing Pages source. Only HTML, CSS, JS, favicon, `.nojekyll` and licensed assets are copied into a temporary checkout. No force push or changes to the working branch/index.
