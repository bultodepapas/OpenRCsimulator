# OpenRC project website

WEB-01/02 own `site/` and the isolated `gh-pages` deployment. No simulator runtime files are changed.

## Design

Visual thesis: an RC club's aircraft catalogue, combining oversized workshop typography, original dark studio renders, ivory paper and field green.

Content: aircraft-led poster → OpenAI principal sponsor acknowledgment and Savox introduction → six-aircraft 360° hangar → platform downloads → day/night field → technical system index → asset/vehicle showcase → Savox partner details → development status and contribution paths. Spanish is the initial language; English and a page-wide night theme are selectable and saved locally. Downloads describe v0.1.1; source features are explicitly separate.

Interaction thesis: a short hero entrance, restrained section reveals and real aircraft turntables with drag, angle slider and play/pause controls. Reduced-motion preference disables autoplay and offers deliberate single-frame steps; core content, technical disclosures and downloads work without JavaScript. The viewer loads only near the hangar, pauses offscreen/when hidden, and retains at most two decoded sheets.

Research, 2026-10-15: [NASA Quesst](https://www.nasa.gov/quesst-the-aircraft/) informed aircraft annotations and experimental status; [X-Plane](https://www.x-plane.com/) informed image-led feature rhythm; [RealFlight](https://www.horizonhobby.com/realflight/) informed the model/field/get-started navigation. These are composition references, not asset sources or endorsements.

WEB-02 extends the research with the [Boeing 777X](https://www.boeing.com/commercial/777x) product/gallery/specification sequence and [Airbus A350](https://www.aircraft.airbus.com/en/aircraft/a350) capability-led technical sections. The visual system keeps OpenRC's original typography and colors; no manufacturer design or aircraft assets are copied.

## Assets and scope

Aircraft renders are from [presentation media](../docs/media/README.md); field captures are from [LU-21](../docs/research/landscape-upgrade/LU-21/README.md). Web derivatives are generated by `prepare_assets.py`, without changing aircraft or scenery. Original media and its provenance remain authoritative. Fonts are freely licensed; bundled license files live alongside them. No remote font, analytics, runtime framework or paid asset dependency.

The six native model orbits have their own [capture pipeline and source-hashed manifest](TURNTABLES.md). The current Ventage Jet orbit reflects today's purple/orange builder, unlike the earlier blue/white/red still. The Bisonte image is the supplied studio render from `RC CARS/MT8_Bisonte_entrega1_1/MT8_Bisonte/out/renders/01_tres_cuartos_delantero.png`; its [intake and permission](../research/rc-monster-truck/README.md#rcv-14a-mt8-visual-inspection) remain authoritative. [Brand sources and scope](BRANDS.md) document unchanged official marks. OpenAI support is a ChatGPT Pro subscription for open-source development; Codex is credited as an AI contributor. Savox's role is product-representation permission; catalogue integration remains planned.

## Preview and maintain

From the repository root: `python -m http.server 4173 --bind 127.0.0.1 --directory site`. Open `http://127.0.0.1:4173/`. The page uses relative asset URLs and works at GitHub's project subpath.

Regenerate images with Pillow 12.3.0 and `python site/prepare_assets.py`. Edit copy in `index.html` and its matching English translation in `main.js`. Update platform downloads, version and sizes together after a release. Keep source-state claims separate from release contents and preserve experimental labels.

Additional WEB-02 copy and theme behavior live in `details.js`, presentation in `details.css`, and the orbit renderer in `viewer.js`. `main.js` owns catalogue/language/field selection. Keep all translations in sync with `data-i18n`, including dynamic viewer labels.

Publication uses a separate `gh-pages` branch with only the static website. GitHub Pages serves `/` from that branch; `.nojekyll` disables processing. The main working tree and its unrelated pending changes are never included in that publication. The website is a project showcase, not a browser build of the simulator.

Publish with `python site/publish.py --message "WEB-step: change; proof: completed checks"` after browser verification, replacing the message with the actual change and checks. It requires Git identity and an authenticated `gh` with repository admin access; it refuses to replace a different existing Pages source. Only HTML, CSS, JS, favicon, `.nojekyll` and licensed assets are copied into a temporary checkout. No force push or changes to the working branch/index.
