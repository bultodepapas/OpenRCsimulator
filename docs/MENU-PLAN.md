## Architecture and saved state

Home Fly owns a persistent loading surface through resource preparation, staged construction, cancellation and the first complete flight draw. Private cold-trim work and bounded reuse reduce preparation costs; indivisible main-thread calls can still block. Performance acceptance remains open. [UI-34c / DT-11a implementation, evidence and remaining work](MENU-REDESIGN-PLAN.md#12-home-to-flight-loading-ui-34c-and-dt-11a).

Airplane Fly resumes the accepted session directly when its controls are ready, including a live mapped gamepad. It samples readiness without advancing incremental throttle and retains the configured launch power. Unready controls open Pause for recovery; a user pause or a newer route takes precedence over the deferred launch. Helicopters keep their existing startup flow. [UI-01-R1 checks](research/menu-investigations/README.md#ui-01-r1--fly-directly-into-flight-2026-10-19).

`app_root.gd` owns the route, accepted preferences, Home backdrop and current flight. Home uses a bounded 304–340 logical-pixel rail at normal text size, a 1920×1080 reference canvas and compact reflow below 1500×850 logical pixels. At native 4K the canvas factor is 2 while 3D stays native. Default Home/Pause and Settings fit without scrolling in the EN/ES 1080p–4K matrix; catalogs, expanded detail and enlarged-text bodies can scroll. Practice actions wrap within the rail in all nine languages, with 1080p layout and focus checks. At the 720p fallback, Practice scrolls within the compact rail while keyboard and selected-gamepad focus reveal every action. At constrained normal-text heights, Practice omits its redundant title/introduction and preserves all pilot, failure and trim summaries. [Practice regression evidence](research/release-readiness/PT1-v0.1.9/README.md). Home keeps the current activity’s primary action and utilities pinned. Settings uses an 800-pixel workspace with pinned header/actions; its 15-second display Keep/Revert transaction is unchanged. `ScreenStack` owns screen membership, top-screen activation, layered input isolation, named holds and focus restoration. `Screen` supplies shared modal/sidebar behavior; `Widgets` creates common controls. Existing CanvasLayer wrappers and public test views remain stable. [UI-21 implementation and parity](research/menu-investigations/UI-21/README.md).

`user://settings.cfg` is a validated ConfigFile. Schema 4 is the highest supported settings version; saves use the lowest compatible schema for the selected weather/lighting profile, while also retaining the diagnostic-marker preference. Legacy schemas remain readable. Unreadable files are retained as `.bad`; if preservation fails, the original remains protected from later saves. Newer schemas are read where valid and never overwritten. Language, aircraft, landscape, launch, weather and lighting persist through the interactive route. The landscape ID is an additive `[flight]` setting; missing or stale IDs recover to Club field. Radio calibration has its own file. A refused launch returns to Home with its reason; it does not save a successful launch choice.

Runway selection belongs to `FlightSession`, so R, Pause Restart and crash reset reconstruct the same equilibrium. At Club field, all catalog airplanes default to runway on Home and Quick Flight; airborne is the next selector choice, and explicit saved choices remain valid. Green offers airborne starts. Fresh preferences use Club field and runway; a saved Green selection uses airborne. Trace metadata distinguishes selected launch from the recording-start snapshot; restoring a physics-only checkpoint clears inherited launch claims. Direct technical traces retain their reference start unless explicitly overridden. [Fleet regression evidence](research/menu-investigations/UI-06b/README.md#2026-10-16--fleet-runway-default-ui-06d-r3).

Airplane R, mapped controller, Pause and accident-report restarts share the shell recovery flow. Successful restarts resume immediately when the controls are ready. A live gamepad is sampled without advancing incremental throttle; an already armed radio keeps readiness under unchanged device/profile ownership. Runway rate throttle starts at zero; airborne rate throttle uses the selected launch power, and absolute throttle follows the current control. Unready or lost controllers keep the recovery menu open; a rejected restart retains the menu hold and displays its reason. Helicopter recovery still requires Continue. [UI-02-R2 regression evidence](research/menu-investigations/README.md#ui-02-r2--restart-directly-into-flight-2026-10-19).

The build-info plugin writes `build_info.json` into exports without changing the source tree. The full identity uses Git description/commit/dirty state; platform version fields use numeric `config/version`. The plugin itself is excluded from packs. [Build/export contract](TOOLS.md#release-sequence).

The update notice (UI-16) reads that identity. On the interactive route of an exported build, `app_state/update_checker.gd` asks GitHub's list-releases endpoint at most once a day (cache `user://update_check.cfg`, ETag reused), `app_state/update_check.gd` orders the tags by SemVer and never offers a prerelease to a release build, and Home shows `ui/update_notice.gd` at its top right without moving the column or the focus. Download opens the release page in the browser; updating stays manual. Development runs check only when `OPENRC_UPDATE_URL` names a source; `[updates] check=false` in the settings turns the check off. [UI-16 evidence](research/menu-investigations/UI-16/README.md).
