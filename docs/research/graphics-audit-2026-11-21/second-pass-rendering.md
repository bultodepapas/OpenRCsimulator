## S06 — Smoke event buffers are cleared and submitted without active births

**Source-confirmed redundant API work; performance impact unmeasured.** [app/main.gd:1215–1246, 1646–1648, 4190–4239](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L1215-L1246) constructs a profile only when an eligible stock or Workshop selection has smoke entries and global `--smoke` is not `off`, then advances it for each advancing presentation-clock interval. [app/render/smoke/profile_smoke.gd:207–238, 429–499](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/profile_smoke.gd#L207-L238) runs `_update_emitter` for each configured emitter. Regardless of `can_birth` or whether any event has nonzero effective output, it fills six packed arrays of 32 entries and calls six `set_shader_parameter` APIs plus the count setter; when `can_birth` is false it also writes a zero count. With four configured emitters this is at most 24 fills covering 768 packed elements and 24 array setter calls per advancing presentation interval. These are source-operation bounds, not upload sizes, actual driver transfers, GPU commands, or FPS estimates.

The concern is reachable during an off pump or after the last residual puff: the scheduler emits a start-of-interval event even at level zero ([app/render/smoke/profile_smoke_schedule.gd:128–159](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/profile_smoke_schedule.gd#L128-L159)), and its normal array submissions continue. The process shader reads event arrays only in `start()` for indices below `birth_event_count` ([app/render/smoke/profile_process.gdshader:84–103](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/profile_process.gdshader#L84-L103)). The Avanti stock profile is one concrete show-only choice; stock combustion exhaust and eligible Workshop profiles have different emission activity ([app/render/smoke/stock_profile.gd:13–42, 51–72](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/stock_profile.gd#L13-L42)).

**Counterevidence.** Arrays are already allocated and reused at setup ([profile_smoke.gd:405–410](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/profile_smoke.gd#L405)); neither a new allocation per setter nor a GPU upload per call is established. GPU particle processing itself is requested for new births and thereafter only through the bounded lifetime/interval residual window (`:491–498`), so it is false to claim it processes particles forever. `--smoke=off` avoids this profile's creation in the ordinary flight route. The scheduler, transform priming, accepted source/request tapes, clock, bounds, and existing-puff wind/time updates have real continuity obligations.

**Smallest candidate.** First distinguish `can_birth=false` from an admitted interval whose event levels are all zero. For the former, the arrays are zeroed and count is zero: a material-local initialized/dirty state could avoid repeated unchanged zero-array work after the first required clear. For the latter, the current scheduler can submit an initial zero-level event with count at least one. Skipping that submission or forcing count to zero changes observable uniform state, even if no visible birth occurs; it requires an explicit contract decision and ordering/overflow proof, not a claim of byte-identical event buffers. Retain any updates needed for surviving puffs. Preserve overflow/fault behavior and the existing accepted event order. A separate small invariant-hoisting opportunity exists in `_update_bounds` (`:540–565`): lifetime, per-profile width/shape, static growth/flow and jet/drag extrema are recalculated every interval although the normalized profile changes only on configure (`:49–80`); dynamic bore, wind, carrier, history and bounds still change. Do not skip dynamic bounds while old puffs exist.

**Discriminating validation.** First use `docs/tools/README.md`, `docs/tools/graphics.md`, the existing [app/tests/test_smoke_profiles.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/test_smoke_profiles.gd), `test_smoke_system.gd`, `test_workshop_smoke.gd`, and `research/aircraft-editor/capture_smoke_profiles.gd`; extend an existing harness only for missing attribution. Compare per-call CPU/event-buffer work, allocations and complete paired frame timings for a valid stock Avanti and a four-outlet Workshop profile, pump off/on, with and without residual puffs. Existing [app/tests/test_smoke_profiles.gd:210-220](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/test_smoke_profiles.gd#L210-L220) and [app/tests/test_smoke_system.gd:190-199](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/test_smoke_system.gd#L190-L199) inspect arrays/counts. Check their required contents or explicitly reviewed observational equivalence, off-to-on changes inside an interval, smooth color transitions, future events, freeze/resume, reset, seek, LOD and failure. Use native GPU captures for pixel/lifecycle evidence on Compatibility and Forward+; headless is only a logic check.

## S07 — Independent Workshop smoke derives wash its emitter does not consume

**Source-confirmed conditional consumer mismatch; cost hypothesis.** [app/main.gd:4159–4184](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L4159-L4184) calls `_profile_smoke_wash` for each accepted observer sample, including a profile whose enabled show slots do not consume a source. When profile version is at least 2, the source runs and propulsion has `slipstream`, `:4288–4303` computes air/wind and density, calls `Propulsion.thrust_torque` and `Slipstream.wake`, and transforms the result. Yet [app/render/smoke/profile_smoke_schedule.gd:17–42, 176–184](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/profile_smoke_schedule.gd#L17-L42) selects the user request, not the source observation, for an `independent_request` show outlet; the source wash is selected for a source endpoint or `source_and_request` endpoint. The ordinary main-route request tape contains tick and level rather than wash ([main.gd:4172–4175, 4203–4229](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L4172)).

A concrete route is a Workshop-configured GP Extra smoke profile selecting its independent tail or wingtip outlets ([app/data/aircraft_customization.json:458, 642–706](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/data/aircraft_customization.json#L458-L642)); its propulsion declares slipstream ([app/data/aircraft/gp_extra_300s_60.json:1843](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/data/aircraft/gp_extra_300s_60.json#L1843)). The stock GP Extra profile is not the example: [stock_profile.gd:16–20](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/smoke/stock_profile.gd#L16) requires two exhaust slots that this registry does not provide. The default `PresentationCadence` samples consecutive accepted ticks at most once per eligible process callback under the default cadence; `--presentation-cadence=0`, discontinuities and its 0.1 s limit can produce more frequent observations ([app/render/presentation_cadence.gd:1–16, 56–74](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/presentation_cadence.gd#L1-L16); [main.gd:1434–1450](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L1434)). Do not describe this as an unconditional 240 Hz computation.

**Counterevidence and candidate.** This is a conditional presentation-contract design opportunity, not a ready same-semantics shortcut. Even for independent slots, `_sample_profile_smoke_at` stores changing wash in the source tape and can append extra events; the >256-event reset and `_profile_presented_wash` can therefore change if wash is omitted ([app/main.gd:4177-4187,4213-4239](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L4177-L4187)). If exact source-tape parity is required, replacing wash with zero is ruled out unless deferred computation still reproduces each accepted observation. Any source outlet or source-gated show outlet can use the source/wash, and source running/level is retained in presentation evidence even for some show profiles ([main.gd:4141–4151, 4177–4184](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L4141)). Gate just the expensive wash derivation when all *enabled, resolved* slots are provably independent and no diagnostic or future profile-switch consumer requires it; do not stop accepted observations, change the propulsion/physics calculations, or suppress a requested source-coupled plume. Re-evaluate the predicate on reset/reconfigure rather than assume a model family is sufficient.

**Discriminating validation.** Trace caller counts and full-frame CPU for the concrete GP Extra Workshop route versus a matched source-coupled F4U/P-51 route. Check explicitly approved source-tape semantics, unchanged request tapes, overflow/reset timing, emission scheduling, wash values for source-coupled outlets, residual puffs, mixed profiles, disabled entries, reset/restore, paused edits and new profile attachment. [app/tests/test_smoke_system.gd:149–226](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/test_smoke_system.gd#L149-L226) explicitly checks wash and future accepted-tape ordering and must remain valid; run the smoke suites and native smoke lifecycle capture named above. No speedup follows from eliminating a call until the complete workload is measured.

## S08 — Authored lighting resolves and serializes unchanged or hidden patterns

**Source-confirmed script work; cost hypothesis, Workshop-only flight route.** A Workshop trial with a non-`inherit` lighting selection constructs an RGB rig ([app/main.gd:3547–3559](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L3547-L3559)) and advances it with a displayed-pose clock each frame (`:1569–1584`). For enabled strip bindings [app/render/lighting/aircraft_lighting_rig_3d.gd:239–258](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/aircraft_lighting_rig_3d.gd#L239-L258) calls `LightingPolicy.resolve`, serializes `active_pattern` with `JSON.stringify`, and compares the string with the previous signature. [lighting_patterns.gd:14–64](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/lighting_patterns.gd#L14) deep-duplicates even a non-sequence pattern on every resolve; sequence mode also slices and scans up to 32 cues. The five supported strips cap the number of strip bindings ([aircraft_lighting_rig_3d.gd:14–26](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/aircraft_lighting_rig_3d.gd#L14)). The resolved phase remains time-dependent even when the underlying pattern signature does not.

`_reapply_profile_visibility` hides orientation strips when the user's mode is `nav` or `off` (`:779–802`), but the strip loop checks authored `enabled` rather than current visibility. Thus those modes can continue resolving/serializing enabled hidden strip patterns. [lighting_skins.gd:250–285](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/lighting_skins.gd#L250) has a separate show gate, although visible skins also resolve/serialize a pattern per bound surface. These are conditional paths, not the default inherited stock rig: [main.gd:3548–3549](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L3548) avoids constructing it for `inherit`, and a valid `disabled` profile has no zones ([lighting_profile.gd:120–125](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/lighting_profile.gd#L120)).

A distinct conditional observation in the same rig: if any authored zone names `airspeed` as its reactive source, [main.gd:3550–3551](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L3550) sets a fixed `_lighting_reacts_to_airspeed` flag without checking the zone's `enabled` value. Each frame `:1572–1574` then calls `_observer_air`, including its wind/density work (`:370–372`). With the reduced-flashes preference active, `LightingPolicy.reaction` returns a constant multiplier without consulting the telemetry ([lighting_policy.gd:28–43](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/lighting_policy.gd#L28)); the rig, skins and VFX route their reactive lookups through that policy. This can leave an optional airspeed calculation without a reactive consumer. Check other observational consumers separately rather than suppressing their air data, and refresh the requirement when the preference or resolved bindings change.

**Counterevidence and candidate.** `_set_param` already compares cached values and honors a per-frame write limit ([aircraft_lighting_rig_3d.gd:651–674](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/lighting/aircraft_lighting_rig_3d.gd#L651)); do not claim an equal number of GPU writes. Materials and cue states can need immediate reconciliation when shown again. Cache a validated immutable pattern identity/signature or pre-resolved cue metadata per binding/configuration and retain time-varying phase evaluation; optionally skip presentation-only hidden-strip work while marking it dirty for first visible update. Preserve cue transitions, reduced-flashes preference changes, sequence targets, reactive telemetry, mode/gate changes, reset, skin passes and write-budget retry. Do not pause effect or burst lifecycles merely because a strip is hidden.

**Discriminating validation.** Use the existing [app/tests/test_lighting_flight.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/test_lighting_flight.gd), `test_lighting_policy.gd`, scene integration and pixel suites described in `docs/tools/graphics.md`; the existing trailer real-time lighting harness and frame diagnosis compare complete OFF/Classic/Festival workloads. Add attribution for `resolve`/`JSON.stringify` only if missing. Compare unchanged versus sequence-heavy patterns, mode ALL/NAV/OFF, reduced flashes live toggle, varying exposure and reactive inputs, hidden-to-visible resume, and custom skin bindings. Verify displayed colors and phases and pending write-budget behavior on native renderers. There is no basis yet for saying the bounded string work materially affects a frame.

## S09 — Multirotor entry attempts four live rotor-profile constructions

**Source-confirmed cold/build work; impact and reusability unmeasured.** Flight's [app/vehicles/multirotor/multirotor_scene.gd:232–237](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/vehicles/multirotor/multirotor_scene.gd#L232-L237) calls `Visual.build` with rotor blur enabled by default ([multirotor_visual.gd:42–45](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/vehicles/multirotor/multirotor_visual.gd#L42)), and `:70–76` invokes `PropellerBlur.attach` for each of four rotors. Each attach measures its own live meshes ([app/render/propeller_blur.gd:63–77](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/propeller_blur.gd#L63-L77)): `profile` scans surface vertices, rasterizes blade triangles into a 36 by 240 grid, computes ring coverage and builds descriptors (`:104–183, 198–205`); `_build` subsequently creates split triangle arrays and disc surfaces/materials (`:320–357, 388–421`). Thus four attach attempts occur, with a build only when the pivot and measured profile are valid; source inspection alone does not prove four rotors have identical mesh contents or quantify latency. `Mesh.surface_get_arrays()` is an API call returning surface arrays; it is not, by itself, evidence of a GPU readback or synchronization stall.

**Counterevidence and candidate.** Home's parked preview already passes `with_rotor_blur=false` and correctly avoids this work ([multirotor_visual.gd:44–45](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/vehicles/multirotor/multirotor_visual.gd#L44)); do not report that old omission. The HX-700 already implements a source-hash/algorithm-verified precomputed rotor-profile sidecar with a measured-geometry fallback ([app/render/rotor/heli_rotor_blur.gd:52–61, 64–125, 130–150](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/rotor/heli_rotor_blur.gd#L52-L61)). Consider the same built-in/offline metadata approach only for eligible, proven-identical geometry, transforms, algorithm and profile inputs. Rebind live surface nodes and materials, retain distinct left/right rotor identities and fallback for unknown or edited meshes, and bound retained memory. A general fixed-wing cache also has to include the surrounding model geometry/transform involved in `_cut_radius` ([propeller_blur.gd:286–317](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/propeller_blur.gd#L286)), not just a propeller or aircraft name. Preserve per-rotor speed, blade colors, split geometry, damage/wobble, visibility and scale.

**Discriminating validation.** [app/tests/bench_mr_visual.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/bench_mr_visual.gd) is an existing alternating warm-resource construction screen, not a frame/GPU benchmark; compare the *same animated build* before and after, with per-stage attribution, plus five cold and five warm actual entry samples. Run `test_mr_visual.gd`, the propeller-blur contract/capture in `docs/tools/graphics.md`, and relevant crash/rotor tests against imported and fixture models, asymmetric rotors, changing size/handedness/materials, broken propellers and unknown content. Pair native visual captures at stopped, transition and full blur, and compare deterministic geometry coverage and rebind results.

## S10 — Zero-flash storm shaders retain a dynamic flash expression

**Source-confirmed shader expression; actual executed instructions and GPU impact unmeasured.** Optional Distant Storm and Electrical Storm presets create a bank of up to 30 transparent cloud cards and three rain sheets ([app/data/sky/weather_presets.json:154–179, 183–203](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/data/sky/weather_presets.json#L154-L179); [app/render/weather/storm_bank.gd:60–95](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/weather/storm_bank.gd#L60-L95)). Both card and rain fragment shaders calculate a spatial flash delta and exponential falloff before multiplying by `flash_radiance` ([storm_bank.gdshader:23–35](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/weather/storm_bank.gdshader#L23); [rain_curtain.gdshader:14–25](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/weather/rain_curtain.gdshader#L14)). The radiance starts at zero and is driven by `StormBank.apply_flash` ([storm_bank.gd:177–203](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/weather/storm_bank.gd#L177)). [main.gd:2819–2821](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L2819) and [app/environment/storm_events.gd:26–28](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/environment/storm_events.gd#L26-L28) enable events only for Electrical Storm; Distant Storm normally has no flash. Electrical Storm's `off` mode and quiet intervals clear flash ([lightning.gd:119–130, 341–346, 545–551](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/weather/lightning.gd#L119)); reduced mode can still have a nonzero flash. The default `classic` preset has no storm bank, so this is an optional scene.

**Counterevidence and candidate.** Invisible/discarded fragments do not necessarily perform the later calculations; visible covered pixels, GPU occupancy, driver optimizations and compiler instructions are unknown. [storm_bank.gd:141–161, 192–203](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/weather/storm_bank.gd#L141) already avoids repeated identical lighting and flash uniform submissions. A uniform zero-radiance guard around only the flash calculation is a small A/B candidate; do not remove flash response, rain sheets, cloud parallax or change atmospheric appearance. Godot's [4.7 shader-preprocessor guidance](https://docs.godotengine.org/en/4.7/tutorials/shaders/shader_reference/shader_preprocessor.html) discusses register and runtime-branch tradeoffs, and its [GPU optimization guide](https://docs.godotengine.org/en/4.7/tutorials/performance/gpu_optimization.html) stresses hardware-specific measurement. Those are related-version guidance, not a verification of the pinned 4.8 beta's emitted code.

**Discriminating validation.** Hold camera, weather, exposure, output/internal pixels, bank, and accepted clock fixed. Compare zero-flash Distant Storm, Electrical Storm between events, full/reduced active lightning, and off-to-on transitions with `tools/atmosphere` captures and the graphics ladder/frame diagnosis already indexed in `docs/tools/graphics.md`; inspect actual native GPU timings, frames and images. Use 1080p, or native Retina panel pixels on Apple Silicon, on representative native Compatibility and Forward+ devices. Do not infer savings from 30 cards or a source-level `exp`.

## Leads rejected or deferred after lifecycle inspection

- **Eliminate Compatibility crash shader warmup.** [app/render/crash/shader_warmup.gd:7–18, 78–84](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/crash/shader_warmup.gd#L7-L18) does issue two `force_draw(false)` calls during eligible flight setup, not steady flight. However, retained `docs/research/crash-damage-investigations/CR-22c-R1/README.md` documents why disposable real draws were introduced and the first-impact benefit in that historical experiment; its setup `usec` includes work that might otherwise occur in the first frame. Removing or deferring it without a whole entry/first-impact paired study would move a known risk, not establish a performance improvement. Headless and non-Compatibility renderers skip it.
- **Disable all profile-smoke work once the pump is off.** Existing particles must age/drift, accepted intervals and burst scheduling must remain continuous, and the profile explicitly supports future in-interval state changes. GPU process requests already stop after the bounded residual lifetime. Only the more targeted candidate in finding 1 is supported.
- **Claim inactive aircraft magnifier still renders a scene.** [app/render/camera/magnifier.gd:61–70, 125–147, 211–215](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/camera/magnifier.gd#L61-L70) disables its SubViewport updates when hidden and only enables them when shown. Visible magnifier cost remains a separate measured secondary-view issue covered elsewhere.
- **Use zero rain opacity as a shipped disabled-work example.** The validator permits zero ([sky_appearance_config.gd:355–363](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/environment/sky_appearance_config.gd#L355)), but both supplied storm-bank presets specify positive values and the ordinary configuration selects a catalog preset ([sky_appearance_config.gd:72–126](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/environment/sky_appearance_config.gd#L72)). The validator alone does not prove a normal user-reachable zero-opacity scene.

No source or engine changes were made. The exact pinned engine shader-generation path and native hardware behavior remain unverified; do not present the candidates as shipped fixes or cross-platform measured gains.
