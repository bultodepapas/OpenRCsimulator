# Rendering and landscape audit

Source inspected: OpenRC `57abea025f62b20233ca281d58d2acbee4ab8b8e`; Godot pin `4.8.beta2.official.cafc17a19` ([app/get-godot.sh:4–5](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/get-godot.sh#L4-L5)). File/line references below are to that snapshot. This is source inspection and a review of retained evidence, not a hardware experiment. No game or GPU capture was launched for this rendering review. The separate policy checks are recorded in [review and validation](review-and-validation.md). The lead reports this host lacks a display and GPU; no new FPS, stutter duration, VRAM usage or platform qualification is established. Rendering must consume detached simulation state, use the accepted clock, and leave the 240 Hz simulation and collision inventory unchanged. Each finding distinguishes an observed control path from unmeasured timing; priority reflects decision value, not demonstrated impact.

Review method and routing limits are recorded in [review and validation](review-and-validation.md).

## Findings

### R1. An already-built meadow remains allocated when switched Off

**Source-confirmed lifetime; memory cost unmeasured.** [app/app_root.gd:2089–2126](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/app_root.gd#L2089-L2126) applies presentation changes by changing the meadow preference and calling `set_visible(false)` on the existing `runway_meadow` group. [app/scenery/runway_meadow.gd:148–204](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/scenery/runway_meadow.gd#L148-L204) shows that group owns MultiMesh instances and their meshes/materials. Consequently an On-built field continues to retain those objects after the user turns the meadow Off. Imported vegetation also has static caches (`app/scenery/imported_vegetation.gd:78–85, 115–124`), so freeing the node need not release every shared asset. This is a resource-lifetime gap against the project's disabled-feature memory goal; it is not evidence of an unbounded leak or a claim that hidden plants continue to render. The opposite path already works: [app/render/field.gd:321–333](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/field.gd#L321-L333) skips building the meadow when Off was in effect at field construction.

**Counterweight and fix.** Live hiding supports responsive settings preview/revert; the tooltip promises Off takes effect immediately and building On may wait for the next flight ([app/ui/settings_screen.gd:392–407](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/ui/settings_screen.gd#L392-L407)). Measure node-owned and shared allocations after On → preview Off → revert, and after Off is committed. If retained memory is material, free or compact only committed-disabled meadow ownership and reacquire at the documented next-build boundary; keep preview rollback reliable and never destroy assets needed by other fields or retained Workshop worlds.

**Validation.** Test Off at startup, On → Off → cancel/keep, Off → On with and without a retained node, Home/Fly/Workshop transitions, and leak/soak behavior. Compare resource counts, RSS and backend-reported residency on Windows, Linux and Apple Silicon; shared CPU/GPU memory must not be double-counted. Confirm disabled nodes produce no draw work with the existing debug render/layers tools.

### R2. Low meadow density still constructs and ranks the full candidate set

**Source-confirmed redundant-for-the-low-output work; saving is unmeasured.** When meadow is enabled, [app/render/field.gd:321–333](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/field.gd#L321-L333) calls `RunwayMeadow.build()`. Its `layout()` ([app/scenery/runway_meadow.gd:94–115](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/scenery/runway_meadow.gd#L94-L115)) runs both `_colonies` and `_scatter`, including spatial tests and construction of candidate dictionaries (`:227–329`), then scans the full set and sorts the entries belonging to capped species (`:364–377`), and only afterward filters by low/balanced/high fraction 0.3/0.6/1.0 (`:24–25, 106–115`). Thus Low avoids creating most final scene plants but still generates and scans the high-quality candidate universe and sorts the capped-species subset. Field executes the complete near-grass/meadow phase as one main-thread construction unit (`field.gd:321–339`).

**Counterweight and fix.** Global species caps intentionally operate on the complete High set to keep surviving plants' species and stable nested membership identical across quality levels. Filtering before the cap changes results and is not an acceptable shortcut. First attribute cold/warm Home and Fly time to candidate generation, ranking and MultiMesh publication. If significant, test a compact two-pass representation that determines full-set rank/caps and exact tie order but materializes expensive final records only for selected plants; cache only stable immutable inputs with explicit invalidation. Retain the existing grid/exclusions and no-build Off route. A bounded C++ buffer producer is a later option only if a bulk operation remains material; publish Godot resources on the allowed thread.

**Validation.** Compare exact ordered layout/species/positions/tint across all quality levels, default and translated fields, edge masks and tie cases against the existing implementation (`app/tests/test_runway_meadow.gd`), then cold/warm launch measurements and moving 1080p/Mac Retina images. The square-root group/member filters implement nested density selection; the nominal 0.3/0.6 factors are not guarantees of exact 30%/60% output counts. Candidate counts and configured density fractions do not predict the time saved.

### R3. Field staging yields between units, but lake and other units can block construction

**Source-confirmed responsiveness risk; no observed stall here.** `app/render/field.gd:115–139, 200–201` yields at a checkpoint before executing one indivisible `_advance_build()` on the main thread. Its 16,000 µs check (`:32–34, 263–278`) bounds batching only *between* scenery units; it does not interrupt an oversized unit or cover the other phases. `:289–293` performs lake attachment in one such unit: `app/render/lake/lake_world.gd:47–83, 93–117` builds ground surfaces, scans candidate ground meshes, cuts the bank from them, builds lake geometry/resources and plants, then commits the replacements. `field.gd:345–355` likewise builds countryside and projected shadows in separate unyielding units. `app/main.gd:3525–3529, 3600–3619` selects staged building only when its startup checkpoint is valid; synchronous routes also exist in [app/ui/home_scene.gd:120–121](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/ui/home_scene.gd#L120-L121) and other vehicle-world builders.

**Counterweight and fix.** This is an explicitly documented compromise, not proof that a 16 ms limit was promised or actually missed. `app/render/lake/lake_terrain.gd:16–21, 55–62, 133–142` already has baked geometry and a bounded one-entry CPU-array reuse cache; scenery has staging. [docs/plans/optimization-priorities.md:86–88](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/docs/plans/optimization-priorities.md#L86-L88) prioritizes attribution of a *measured* remaining large unit. Instrument existing load-stage and frame capture tools before change. If the lake or another unit proves dominant, advance pure geometry preparation in bounded deterministic chunks, preserve the detached prepare/atomic-commit/cancellation contract, and confine scene/resource publication to Godot's allowed boundary. Reuse existing staging rather than introduce a broad new worker framework.

**Validation.** At least five process-cold and five warm measurements with loading-frame gaps and stage times, source/import/cache identity, including initial Home, direct Fly, relevant vehicle routes, custom lake, and cancellation. Exercise unchanged shore/contact geometry, failure refusal, safe Quit, and first controlled frame. Hardware target is 1080p first, except native panel pixels on Apple Silicon Retina.

### R4. Projected field shadows are prepared before an Off/Native policy hides them

**Source-confirmed avoided-construction opportunity; prior known F35.** Field construction calls `FieldProjectedShadows.attach` before `ShadowFieldPolicy.attach` ([app/render/field.gd:352–355](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/field.gd#L352-L355)). The former collects cue and scenery caster shapes, allocates projectors, viewports and proxy geometry, up to 16 maps and an 8,388,608-pixel target budget (`app/render/field_projected_shadows.gd:9–13, 22–79, 88–116`). Only afterward does the policy hide fallback planes and disable projectors when projected shadows are not effective (`app/render/shadow_field_policy.gd:52–72, 396–405`). Therefore Off or Native can still pay preparation and retain proxies despite no projected field-shadow output.

**Counterweight and fix.** This is a live-toggle preparation tradeoff, not a full-size target leak: projectors use the small released size and disabled update mode while hidden (`app/render/projected_shadow.gd:426–438, 510–530`); the native directional atlas is parked when native shadows are disabled ([app/render/shadow_settings.gd:141–153](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/shadow_settings.gd#L141-L153)). Existing SA-12 also avoids collecting cells once no slot can be admitted. Measure preparation per mode; if significant, prepare lazily when Projected is first committed, cache immutable shape data only if bounded and beneficial, and preserve immediate toggles and fallback/legacy-shadow correctness.

**Validation.** Compare cold and warm Off/Native/Projected field build time and memory; test Off↔Projected↔Native, day/night, visibility, fallback, changing lights, retained-world reentry, fence/windsock deformation and frame gaps using `tools/shadows/README.md` and native visual captures. Preserve every physical collider and shadow-cue continuity.

### R5. Cloud-tile publication performs a GPU readback and CPU conversion on a completion frame

**Source-confirmed readback path; synchronization duration and improvement are unmeasured.** The default classic selection is seed 1253 ([app/environment/sky_appearance_config.gd:33–38](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/environment/sky_appearance_config.gd#L33-L38)), with visible coverage ([app/spec.gd:52](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/spec.gd#L52)). Unless explicitly disabled, the cache is requested in non-headless execution ([app/render/cloud_shadow_map.gd:33–45](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/cloud_shadow_map.gd#L33-L45)): `Atmosphere.environment()` creates its sky, `update_sky_material()` binds eligible seeds (`app/render/atmosphere.gd:693–736, 739–753, 999–1003`). `_ensure_tile` admits a missing seed, `_create` makes a 2048² HDR SubViewport, then `_bake` waits three process frames and synchronously calls `get_image()`; `_complete_bake` validates samples, converts to RGH and constructs an `ImageTexture` (`cloud_shadow_map.gd:344–356, 401–461, 482–498, 517–531`). Godot's [Texture2D documentation](https://docs.godotengine.org/en/4.4/classes/class_texture2d.html) says `get_image()` copies texture data from the GPU and can be expensive. The prior [pinned-engine source trace](../../../external%20Audits/apple-silicon-stik-audio-cloud-ghost-optimization-probes-181d7ca.md) identifies a flush/stall path for the applicable RenderingDevice readback; independently verify effective backend and trace on the hardware being measured.

This is a cold-admission, retry or changed-seed event, **not a periodic per-second readback**. `World.update` advances accepted-clock cloud offsets ([app/render/world/world.gd:1034–1059](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/world/world.gd#L1034-L1059); `atmosphere.gd:874–884`); it does not itself admit a new seed every second. Paused sky edits can request new seeds via `app/main.gd:2771–2781, 2801–2811`. Ready same-seed tiles are reused; attempts are capped at two and the cache at four. Four final 2048² two-channel half-float tiles contain 64 MiB of logical base-level texels. An ordinary RGBA16F 2048² source would be 32 MiB per image, before staging/temporaries; actual driver allocation and peak memory are not measured.

**Counterweight and fix.** Validation, token/cancellation, bounded capacity, failure and analytic fallback are purposeful; Cloud Shadows Off clears ground consumers and avoids their shader samples while sky relief may legitimately retain the shared tile (`atmosphere.gd:937–948`). Do not remove the cache based on a presumed steady cost or move GPU access to an arbitrary worker. A prior Mac experiment found direct `ViewportTexture` publishing black; copied `ImageTexture` fixed that tested path. Profile bake/readback/convert/upload independently. If the readback dominates, compare a carefully synchronized pinned-engine asynchronous readback retaining validated stable publication and fallback, or offline data for eligible seed identities; test RenderingDevice/Compatibility differences before choosing.

**Validation.** Existing cache tests plus wrong-seed/bad readback, full capacity, cancellation, late callbacks, rapid paused preset edits, seed reuse, scene/Workshop reentry and both Off controls. Correlate native frame gaps with named phases and GPU traces on Windows/Linux Compatibility and Forward+, and Apple Silicon Mobile/Metal; record peak shared/driver memory and actual formats. Do not count the earlier F28 cache reorder issue as outstanding (see rejected leads).

### R6. The full-resolution sky computes layered density and relief per contributing background pixel

**Source-confirmed work; GPU priority is a hypothesis.** `app/render/sky.gdshader:199–282, 284–295` evaluates up to eight ordered layers; each applicable layer can compute analytic density and 2.5D relief, which evaluates three more density samples ([app/render/cloud_relief.gdshaderinc:5–15](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/cloud_relief.gdshaderinc#L5-L15)). Work scales with visible sky pixels and contributing layers; the shader does not enable a half-resolution subpass (`sky.gdshader:11–14`). Cache readiness/seed availability changes the density cost, and some types, zero alpha and radiance passes skip relief. Godot's [sky shader documentation](https://docs.godotengine.org/en/latest/tutorials/shaders/shader_reference/sky_shader.html) offers `use_half_res_pass`, `AT_HALF_RES_PASS` and `HALF_RES_COLOR` as a built-in experiment; the official [Godot 4.0 sky article](https://godotengine.org/article/custom-sky-shaders-godot-4-0/) also describes these longstanding subpasses. Verify the precise behavior and feature availability in pinned beta2 before implementation.

**Counterweight and fix.** Half width and height means one quarter of full-frame pixels in the low-resolution pass, not a fourfold total-render speedup: full-resolution composition remains, and a subpass can process pixels later covered by geometry. Keeping cloud edges/occlusion and sun/moon detail while maintaining the radiance pass, tint, deterministic clock, capture color spaces and reflection/IBL is nontrivial. Treat the repo's [docs/plans/advanced-graphics.md:243](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/docs/plans/advanced-graphics.md#L243) subpass as an existing experiment, not a new finished optimization. Test it only if GPU attribution identifies sky cost; compare a matched non-occluded full-resolution baseline.

**Validation.** Existing sky/atmosphere render suites plus day, night, low sun, clouds crossing sun/moon and aircraft silhouettes, layering/seed/cache combinations, camera motion, horizons and reflection environments. Compare sky-heavy and ground-heavy views with GPU timestamps on Windows/Linux and native Metal at the specified output/internal pixels.

### R7. Water always asks for screen and depth textures when its material is rendered

**Source-confirmed dependencies; copy/resolve cost is platform-dependent.** The default-field lake is resolved unless scenery/lake is disabled ([app/render/lake/lake_world.gd:10–32](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/lake/lake_world.gd#L10-L32)) and its water always uses `app/render/lake/water.gdshader:34–35, 169–201`. It samples depth at both unrefracted and refracted UVs and reads the screen for transmission; planar reflection is a separate optional branch (`:202–209`). Godot's [screen-reading documentation](https://docs.godotengine.org/en/4.6/tutorials/shaders/screen-reading_shaders.html) describes a copy after opaque geometry and before transparent geometry, so transparent objects are not in that capture. This is a known renderer constraint and may incur a copy, resolve or render-pass/bandwidth burden on affected backends; it does not prove a visible artifact or that water is the only consumer of those buffers.

**Counterweight and fix.** Refraction/depth and lake appearance are intentional. Sun glare and lens effects have other screen/depth dependencies, so removing just water's hint does not guarantee all copies disappear. If water dominates measured GPU cost, test a separately compiled/reflection-aware inexpensive water material without the unnecessary screen/depth hint rather than setting a uniform to zero on a shader that still declares the dependency. Include a clear player control and preserve shoreline, depth ordering, water physics and calibrated normal/fog. GPU render-pass graphs should establish whether the variant actually removes a copy/resolve in the target scene.

**Validation.** Compare lake visible/hidden, refraction full/cheap, other depth consumers on/off, still/moving camera, water at screen edge and opaque/transparent intersections, Compatibility versus Forward+/Metal. Record actual GPU timing, draw boundaries and color/depth resolution; inspect matched 1080p and Retina-motion images. Existing 2026-11-19 F32 already tracks this candidate.

### R8. Procedural fallback grass collapses triangles only after batch submission

**Source-confirmed batch geometry; GPU importance unmeasured.** When no eligible default scenery node exists, [app/render/field.gd:321–335](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/field.gd#L321-L335) calls `NearGrass.build` instead of the imported route. `app/render/near_grass.gd:10–17, 175–185, 229–274` validates up to 6,000 rows, clips them into four quadrant MultiMeshes, and each accepted clump is seven triangles. [app/render/near_grass.gdshader:39–51](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/near_grass.gdshader#L39-L51) computes distance, wind and phase per vertex, then collapses the triangle at the 30 m fade end. When a batch AABB is visible, collapse can avoid later rasterization but does not provide per-instance frustum rejection. [Godot's official MultiMesh guidance](https://docs.godotengine.org/en/4.7/tutorials/performance/using_multimesh.html) describes the whole-batch visibility tradeoff. Four batches is already spatial partitioning; the separate imported meadow already has density controls and 40 m chunks ([app/scenery/runway_meadow.gd:148–165](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/scenery/runway_meadow.gd#L148-L165)).

**Improvement and validation.** If profiling identifies vertex waste, compare finer spatial batches or carefully ordered visible-instance prefixes against the increased draw and CPU cost, using the native MultiMesh API first. Avoid changing wind, visible density, field masks, conservative cull bounds or simulation time. Measure pilot, chase, zoom and reflection views at 1080p and Retina; compare GPU vertex/draw timing, image stability and CPU cost. This is existing F30, not proof that the normal imported meadow or all treelines have one giant batch.

### R9. High graphics bundles SSAO and sky reflections without separate player controls

**Source-confirmed control limitation; separate-pass costs unmeasured.** [app/render/high_graphics_profile.gd:106–120](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/high_graphics_profile.gd#L106-L120) enables SSAO and selects sky-sourced reflections whenever High is active. Standard legacy lighting can also select sky reflections ([app/render/atmosphere.gd:1041–1045](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/atmosphere.gd#L1041-L1045)), while its flowing-world environment disables them (`:827–840`), so the profiles do not simply mean reflections on versus off. The graphics mode tooltip presents these together ([app/ui/settings_screen.gd:1235–1239](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/ui/settings_screen.gd#L1235-L1239)). The graphics menu independently controls shadows, runway meadow, lens and lighting options (`settings_screen.gd:365–461, 551–556`), but the inspected saved display preference keys ([app/app_state/display_preferences.gd:93–99](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/app_state/display_preferences.gd#L93-L99)) do not expose independent SSAO or sky-reflection choices. Changing renderer/profile is therefore the available bundle-level tradeoff, contrary to the project's goal of separately scalable lighting/reflections. `app/render/auto_graphics_policy.gd:10–30, 62–83` makes default predictions from a measured RTX 3090 anchor and relative device estimates; capability data explicitly labels most non-anchor rows as estimated ([app/data/gpu/capability.json:53–59](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/data/gpu/capability.json#L53-L59)). Its choice is not independent evidence that a target device meets the budget.

**Improvement and validation.** If isolated GPU ladders show a useful difference, expose narrowly scoped, saved lighting/SSAO and reflection controls with profile-compatible defaults and explicit capability/fallback behavior. Preserve overrides, scene identity, the visual contract and actual renderer routing; do not silently weaken High. Test control persistence, failed renderer/reconstruction, restart, Home/Workshop/Fly and identical physical traces. Use `research/performance/graphics_ladder/README.md` with fixed 1080p and native Retina panels, matched on/off complete workloads and visual comparisons. Existing auto calibration protects some cases, but its GPU/CPU conclusions must be read as estimates of the measured configuration, not universal results.

### R10. Optional High planar water reflection runs a second active viewport

**Source-confirmed optional cost path; no current timing.** It is selected only by High plus `OPENRC_LAKE_REFLECTIONS=planar` ([app/render/lake/lake_planar_reflection.gd:29–30](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/lake/lake_planar_reflection.gd#L29-L30)), so do not describe it as default water rendering or a generally enabled effect. When eligible and in range, it uses a floating-point viewport with 2× MSAA, scales to at most half the main width/height and at most 1280×720, and sets `UPDATE_ALWAYS` while active (`:65–97, 131–147`). At 1920×1080 the scale is 0.5, hence a nominal 960×540 reflection output, before MSAA and other attachments; this is size arithmetic, not a time or memory measurement. Side/depth, view/layer and underwater gates disable it when unnecessary. The normal lake probe is `UPDATE_ONCE` ([app/render/lake/lake_terrain.gd:84–94](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/lake/lake_terrain.gd#L84-L94)); explicit sky edits force refresh ([app/render/atmosphere.gd:887–899](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/render/atmosphere.gd#L887-L899)).

**Improvement and validation.** Existing [docs/plans/advanced-graphics.md:63–75](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/docs/plans/advanced-graphics.md#L63-L75) already retains incomplete historical 720p/RTX 3090 screens and makes this option default-off. First measure the whole frame including this subviewport, separately from root viewport GPU time; `app/render/auto_calibration.gd:65–68, 110–128, 171–176` already watches subviewport activity to block an unsupported auto-up. If expensive, compare bounded resolution or cadence controls against moving aircraft, camera and water reflection artifacts; verify the mirror's clipping and retained-world lifecycle. Use the graphics ladder and GPU/bridge tools on qualified desktop hardware; no supported-platform extrapolation from the historical screen.

## Rejected or corrected leads

1. **Cloud cache slot-shift rebake cascade is already repaired.** `cloud_shadow_map.gd:80–82, 121–147` retargets all sky slots before admission/eviction; the 2026-11-19 report's resolution table records F28 fixed. Do not repeat its old [A,B,C,D] → [E,A,B,C] behavior as current.
2. **Zero-opacity sky layers already skip density/relief.** `sky.gdshader:223–230` has the exact-zero fast path while retaining the composite-density recurrence; F31 is marked fixed. Tiny positive opacity remains a deliberate fade, not automatically removable.
3. **An apparent scene-detail/physics coupling in a source comment is stale.** `scene_detail.gd:1–4` mentions ornament collision changing, but `scenery.gd:247–250` retains collidable instances at all quality levels and `scenery/collision_setup.gd:10–25` builds from the full normalized layout without reading quality. `test_scene_detail.gd:165–195` checks field-tree collision and `test_scenery_trace.gd:34–50` covers scenery identity boundaries. Tests were not run in this audit; a complete same-trace all-presets gate is still appropriate for any future graphics change. Do not claim a current quality-driven collision change from that comment alone.
4. **Off does not necessarily mean every shared cloud asset must disappear.** Cloud-shadows Off zeroes spatial ground/water strength and clears those consumers, but a live sky may still require the shared seed tile (`atmosphere.gd:937–954`); sky/ground modes can be requested independently (`cloud_shadow_map.gd:33–51`). Likewise hidden projected shadows use disabled update modes and reduced targets, and the magnifier disables its SubViewport while hidden (`app/render/camera/magnifier.gd:61–72, 211–215`). A cache, a small placeholder and a visible feature are not proof of continuing full-cost rendering.

## Prioritization

Start with R3/R4/R5 if a cold or transition hitch is captured; use R1/R2 for memory and Low-detail construction. R6–R10 require pass-level GPU attribution before changing visual quality. Built-in subpasses, MultiMesh publication and bounded lazy allocation precede a new native subsystem. [Platform validation](platform-validation.md) defines the required scenes, output sizes and measurement scopes.
