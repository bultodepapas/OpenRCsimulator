## S11 — Home rebinds and reconstructs a same-model shadow

**Trigger and path.** With projected aircraft cues enabled (including the default Auto technique/cue, subject to effective settings), a Home presentation change can commit via [app/ui/home_scene.gd:589-608](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/home_scene.gd#L589-L608), which calls `show_aircraft` for the already selected model. A cached model selection follows the same path ([home_scene.gd:324-337](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/home_scene.gd#L324)). `show_aircraft` retains at most three models and their collected silhouette geometry ([home_scene.gd:199-227,244-250](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/home_scene.gd#L199)), but always calls `Shadow.bind_model`. That function clears pending binding, removes and queues the existing `ProjectedShadow`, and installs a new one if the cue is enabled ([app/render/shadow.gd:130-164,172-183](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/shadow.gd#L130-L164)). With a nonempty collected shape, installation creates a 256-square isolated SubViewport, camera, mesh/materials and articulated-part proxies, connects source signals, and creates a receiver ([app/render/projected_shadow.gd:426-489](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/projected_shadow.gd#L426-L489)). Source-confirmed repeated setup is distinct from the old report's F35 *field* projected shadows.

**Counterevidence and risk.** A cached nonempty shape already avoids collecting the whole silhouette again; an empty shape causes collection to be retried and can retain the legacy-mask fallback instead of a projector ([shadow.gd:142-144,172-180](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/shadow.gd#L142)). With a nonempty shape there is only one active projector per carrier; this does not establish a memory leak, a GPU stall, or expensive work on every frame. When cues are disabled, `bind_model` instead defers materializing the projector ([shadow.gd:152-164](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/shadow.gd#L152)). Hiding then showing the same model itself emits visibility changes; the projector's callbacks and `refresh` implement visibility, exit/reentry, articulated parts, and redraw correctness ([projected_shadow.gd:487-528](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/projected_shadow.gd#L487)).

**Experiment / simple option.** Count projector setup/disposal, allocations and whole-frame gaps for repeated same-model sky/time changes and cached selection; compare A→A, A→B→A, cold/warm and Off/Native/Auto/Projected. If material, first evaluate an idempotent bind for the same live model *and valid unchanged shape/policy*, then apply the normal `Shadow.update` with the new direction/strength; a new multi-projector cache is not needed to test this narrow case. Exercise model/livery swaps, source hide/show, detach/reentry/freed, pose/part visibility, source and policy generations, disabled→enabled/deferred materialization, cancellation and signal counts. Compare images and native GPU/frame traces to catch stale shadow direction, incorrect silhouette or lost cues.

## S12 — Library scans repeat full loads and keep all results until summary conversion

**Trigger and path.** Opening Workshop calls `_refresh_variants()` from `_ready`, and opening Library calls it again even when no edit intervenes ([app/ui/workshop.gd:285-290,2592-2600](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop.gd#L285-L290)). A reload synchronously calls `Store.scan_variants`, then reduces all returned variants to small display summaries ([workshop.gd:1152-1169,1230-1231](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop.gd#L1152)). The scan enumerates UUID directories and accumulates each fully loaded variant ([app/workshop/store.gd:120-160](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/store.gd#L120-L160)). Loading reads/validates manifest and revision JSON, decodes and parses the embedded base, and holds base bytes plus decoded structures ([store.gd:772-875](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/store.gd#L772)); record checks include base64/hash and dependency/recipe validation (`:943-976`). Individual base and record sizes are capped (`:18-21`), but the scan as written has no catalog-entry-count cap. Consequently source work and transient live scan data can scale with library size, with two scans before the user first opens the Library.

**Counterevidence and risk.** The first scan can serve normal Workshop UI, and reload intentionally sees externally added/changed files, malformed revisions, backup recovery and missing favorites. Search and favorites already pass `reload=false` ([workshop.gd:687-701](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop.gd#L687)), so typing does not rescan all saved builds; however, each refresh still loads favorites metadata ([workshop.gd:1152-1156](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop.gd#L1152); [app/workshop/library_preferences.gd:31-35,74-80,94-103](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/library_preferences.gd#L31-L35)). This is transient retained data, not a proven leak; normal users may have few saved builds. `Store.list_variants` and `scan_variants` expose full results, so changing their contracts blindly breaks callers/tests.

**Experiment / simple option.** Profile first Workshop open, first Library open, repeated reopen, search and explicit Retry with zero, representative and large generated libraries; record file bytes read, per-stage timings, allocation peaks and presented-frame gaps. First consider a separate summary-only scan that fully validates each entry and immediately retains only its summary and diagnostics, rather than retaining every full result until the scan completes; keep existing full-record APIs. Avoid reusing a scan based only on revision, ID or timestamp: same-revision tampering, changed dependencies, external creation/deletion, backup recovery and permission changes must remain detectable. If asynchronous/batched work is necessary, use safe native Godot APIs and bounded generations and preserve latest selection, errors, retry, cancel and saved-data validation. Exercise [app/tests/test_workshop_library_unavailable.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/tests/test_workshop_library_unavailable.gd) and relevant Store, interruption and UI suites.

## S13 — Warm thumbnail hits still validate and compile before lookup

**Trigger and path.** In Workshop, opening Library and selecting a readable saved variant calls `Store.load_variant` and then `_thumbnail.request` ([app/ui/workshop.gd:1294-1296,1352-1375,2592-2600](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop.gd#L1294-L1296)). The producer cancels the previous request, duplicates the saved record, runs `Trial.freeze`, and constructs the complete hashed render identity *before* looking up the in-memory texture ([app/ui/workshop_thumbnail.gd:45-63,124-133,162-195](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop_thumbnail.gd#L45-L63)). `Trial.freeze` reparses the source, checks descriptor and presentation, verifies dependencies, compiles the recipe, and checks dependencies/presentation again ([app/workshop/trial.gd:8-44,108-168](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/trial.gd#L8-L44)). Therefore switching A→B→A or closing and reopening Library can avoid redraw on a warm texture hit but still incurs the freeze/identity path.

**Deeper parse path.** On a successful record with a dependency manifest, Store decodes base64 and parses the embedded base during dependency validation ([app/workshop/store.gd:943-976](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/store.gd#L943-L976)), then decodes/parses it again in `_load_from_manifest_source` (`:807-831`). Thumbnail `Trial.freeze` parses those bytes again ([app/workshop/trial.gd:21-31](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/trial.gd#L21-L31)). That is three visible base-JSON parses on this conditional valid-record route before a warm texture lookup, not a count for every malformed or legacy record. A narrow first candidate is sharing a detached validated decode/parse **inside one Store transaction**, retaining all checks, ownership and error order. Do not collapse Trial's dependency checks before and after compilation ([trial.gd:109-116,157-165](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/trial.gd#L109)): they protect against an intervening dependency change. This is already native JSON/hash work; adding a C++ JSON wrapper alone does not remove the duplicate pipeline.

**Miss path and limits.** A miss additionally builds an isolated 320×192 `UPDATE_ONCE` aircraft scene, waits for `RenderingServer.frame_post_draw`, gets its viewport image, copies/normalizes to RGBA8 and creates an ImageTexture ([workshop_thumbnail.gd:15-17,260-318](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop_thumbnail.gd#L15); [app/workshop/thumbnail_cache.gd:33-67](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/workshop/thumbnail_cache.gd#L33-L67)). The cache is per Workshop, bounded at 16 entries/4 MiB; cancel and `_exit_tree` dispose the temporary viewport ([workshop_thumbnail.gd:38-42,74-79,104-105,451-465](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop_thumbnail.gd#L38)). This is neither an unbounded cache nor proof of GPU readback stall. `frame_post_draw` is a render callback, not proof of display presentation. This path is distinct from old F29's cloud-tile readback.

**Experiment / simple option.** Time/load-count selection, `load_variant`, freeze/verification, image capture, conversion/upload and disposal separately for cold and warm A→B→A plus close/reopen Workshop, with representative complex saved variants, cancellation and LRU eviction. Profile native desktop CPU/GPU and present timing, without extrapolating from one renderer. If the warm path dominates, investigate reuse of a previously verified immutable result only under a complete source/dependency/compiler/presentation/renderer identity and explicit invalidation; repeat admission when external bytes or availability can have changed. If miss setup dominates, test reuse of a bounded isolated viewport/world, not the mutable editor preview unless appearance, camera, lighting, identity and isolation are proven equivalent. Preserve generation checks, error reporting, readback ownership, visual equivalence and no stale variants. Do not remove source verification or move rendering calls to an arbitrary thread.

## S14 — Workshop can restore a previously reduced Home backdrop scale

**Trigger and path.** If Home's adaptive budget has already lowered the root viewport 3D scale and still owns it, opening Workshop from Home makes `home` cease to be the stack top ([app/app_root.gd:3524-3558](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/app_root.gd#L3524-L3558); [app/ui/screen_stack.gd:43-62](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/screen_stack.gd#L43-L62)). `HomeRenderBudget._process` then calls `_restore`, writing the player's higher base scale ([app/render/home_render_budget.gd:71-81,202-215,243-246](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/home_render_budget.gd#L71-L81)). The prior Home UI is hidden, but its 3D scene remains as the live backdrop ([app/ui/screen.gd:113-120](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/screen.gd#L113-L120)); the Workshop screen draws a 72%-opaque dim layer and panel ([app/ui/workshop.gd:265-281,384-396](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop.gd#L265-L281)). Workshop also owns a separate 3D preview viewport ([app/ui/workshop_preview.gd:121-140](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop_preview.gd#L121-L140)). This identifies a source-level counterexample in the covered-Home transition; it does not establish a frame-time regression.

**Counterevidence and risk.** Restore is deliberate: the root viewport is shared, settings/resize can take ownership, and flight must receive the player's scale ([home_render_budget.gd:14-19,202-215](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/home_render_budget.gd#L14)). The budget supports only Bilinear or FSR and explicitly excludes temporal reconstruction and MetalFX (`:224-228`). Home must previously have selected a lower step; if not, there is no scale increase. A still Workshop preview uses `UPDATE_ONCE`, not `UPDATE_ALWAYS`; continuous updates are enabled only during optional playback ([workshop_preview.gd:133-140,1341-1363](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop_preview.gd#L133)). The backdrop is intended to remain visible and may be largely covered by the panel; neither hidden work nor a second preview draw every frame is proven.

**Experiment / simple option.** Instrument effective root and preview dimensions, viewport update modes, owner/policy identity, actual visible coverage, process/GPU and presented frame intervals for Home→Workshop→Home and Settings, in matched quality scenes at native Retina pixels and 1080p elsewhere. If the covered backdrop is a material GPU cost, evaluate extending the existing Home budget's *owned* scale to this specific Workshop state, restoring before any competing settings/flight write. Alternatively compare an explicitly approved still backdrop if freshness and UI design permit. Test screen switches, modal stacking, focus/minimize, resize/reconstruction previews and cancel/commit; preserve readability, lighting/animation behavior, settings precedence and temporal-provider history. Do not lower a player's flight or global setting.

## S15 — Trial flights retain a bounded inactive world and editor

**Trigger and path.** On a successful Workshop trial from a paused fixed-wing flight, Root tentatively detaches the previous flight, detaches Home if in tree, instantiates/adds the candidate, stores the previous flight and retains the removed screen entries including Workshop ([app/app_root.gd:3623-3634,3658-3691](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/app_root.gd#L3623-L3634)). That prior world and the candidate can coexist for the duration of the trial. From Home, the detached Home world and editor instead coexist with the candidate. `Main._exit_tree` already disposes some state and side effects ([app/main.gd:3133-3156](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L3133-L3156)), while detached node resources may remain referenced. Return removes/queues the trial, restores the prior flight/Home and screens, and clears retained references ([app/app_root.gd:3928-3972](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/app_root.gd#L3928-L3972)); Root exit explicitly frees detached retained entries/worlds (`:3992-4000`).

**Counterevidence and risk.** This is intentional, bounded transactional retention, not evidence of a leak or that both trees render simultaneously. Some GPU/CPU assets may be shared and some detach handlers release resources; node count is not residency and summing textures across trees double-counts shared RIDs. The old recording stays live only during tentative startup; after successful commit `_commit_detached` calls `previous.close_recorders()` ([app/app_root.gd:3841-3855](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/app_root.gd#L3841-L3855); [app/main.gd:3159-3179](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/main.gd#L3159-L3179)). Failed startup restores the previous live flight; successful commit follows the explicit recording-finalization behavior. Home detach also cancels pending preview work ([app/ui/home_scene.gd:395-406](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/home_scene.gd#L395-L406)).

**Experiment / simple option.** Compare steady and peak uniquely identified resources, app RSS and backend-reported memory before launch, candidate preparation, sustained trial, return and repeated 20/50-cycle soak for Home and paused-flight origins. Identify path-backed shared resources versus generated node-owned resources and include offscreen/driver allocation and Apple unified memory without adding duplicate categories. [app/render/world/world_resource_hold.gd:9-52,73-75](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/render/world/world_resource_hold.gd#L9-L52) provides an existing *disk-backed-only* traversal concept; it is not a complete residency inventory. If material, first look for existing immutable ResourceLoader sharing and safe release/reacquisition of presentation-only transient targets while detached; do not free the retained simulation/session or assume whole-world reconstruction can reproduce exact flight, recording, statistics, rollback/replay, visual reentry or failure recovery. Exercise failed launch, return, quit, lighting, reflectors and changing resource ownership.

## Rejected / qualified leads

- The Home preview cache is explicitly bounded at three model instances with coordinated eviction ([home_scene.gd:45-49,219-227](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/home_scene.gd#L45)), and preview resource loading uses its own bounded ownership and cancellation. Do not call it an unbounded leak; different liveries may legitimately need distinct model nodes.
- Workshop thumbnails have the bounded cache and explicit disposal cited above. GPU readback is an operation, not by itself proof of a stall or a performance bug.
- A still Workshop viewport is not continuously redrawn by default ([workshop_preview.gd:133-140,1341-1363](https://github.com/bultodepapas/OpenRCsimulator/blob/6b2228c7633a34e38cb05d92e3ca50893810e02b/app/ui/workshop_preview.gd#L133)).
- The old 2026-11-19 register already covers process-lifetime vegetation resources (F33), cloud readback (F29), and field-projected-shadow construction (F35); the candidates above identify different owners or triggers. First-pass meadow-Off retention and per-stage indivisible work are also excluded.
- Time/place-derived static caches were not elevated without an ordinary same-process route demonstrating significant unique-key growth; no generic cache-growth or allocation total is claimed.
