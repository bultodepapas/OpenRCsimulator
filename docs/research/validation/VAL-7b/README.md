# VAL-7b — Recorded throttle-step RPM diagnostics

2026-10-07 · **Status: offline tooling verified; real measurements and model validation remain VAL-7.** Owns `research/validation/rpm-step/`. No simulator or aircraft-data changes.

## Outcome

The [reducer and recording contract](../../../../research/validation/rpm-step/README.md) fill the transient gap left by VAL-7a's steady propeller reduction. Supplied steady endpoints and a synchronized command timestamp produce interpolated 10/63.2/90% crossings, a two-crossing first-order lag/delay diagnostic, residuals and sampling-support brackets. Increasing and decreasing steps share the same normalization. Input evidence and exact source/code hashes stay in the report.

Missing crossings or onset, pre-command first crossings, unordered/nonfinite samples and malformed provenance are refused. Negative inferred delay, undershoot, overshoot, reversals and recrossings are exposed without tuning or clamping. Acquisition uncertainties are retained but not propagated; no confidence interval or physical acceptance is claimed.

## Verification

[20 tests](tests.log) cover analytic delayed exponentials in both directions, RPM affine invariance, clock translation/time scaling, irregular sampling, sampling-support containment, missing/plateau/repeated crossings, under-resolution, negative delay, pre-command residuals, malformed inputs, evidence labels and reproducible CLI hashes. The [synthetic report](example-result.json) recovers 0.25 s lag and 0.08 s delay to floating-point precision. Its input is generated by the tests' `fixture()` and is explicitly synthetic.

[Three mutations](mutations.log) were rejected in disposable copies: omitted `ln(9)` conversion, reversed delay correction and selecting the last crossing. The unmodified copied control passed all 20 tests. No deliberately broken source entered the shared tree.

## Method and limits

The official [MathWorks step-response definition](https://www.mathworks.com/help/control/ref/dynamicsystem.stepinfo.html) uses the initial-to-steady response span and defines 10–90% rise time. Its [process-model documentation](https://www.mathworks.com/help/ident/ref/procest.html) defines the first-order model with transport delay. Applying that model gives `t_f = command + delay - tau*ln(1-f)`, hence `tau=(t90-t10)/ln(9)` and `delay=t10-command+tau*ln(0.9)`. This reducer derives those equations directly and adds an independent 63.2% consistency diagnostic; no third-party implementation is used.

The current [legacy RPM update](../../../../app/physics/propulsion.gd) is an exact first-order step without dead time. That explains the comparison quantity, not the real engine's dynamics. A delayed first-order description can miss torque-limited acceleration, asymmetric spool behavior and changing propeller load. Sensor smoothing and servo motion may dominate the apparent response. Real recordings, uncertainty propagation and held-out comparisons remain open; fitting this diagnostic never validates a coefficient against the same record.
