## Physics and controller evidence

Sources below were inspected on 2026-10-21. They support bounded claims, not a universal parameter set. Mutable documentation/product pages must be pinned or captured with hashes during implementation intake.

| Source | Supported finding | Consequence / uncertainty |
| --- | --- | --- |
| [Faessler, Franchi and Scaramuzza, 2018](https://arxiv.org/abs/1712.02402v3) | Identifies whole-vehicle mass-normalized linear rotor drag on a 610 g, 6-inch quad. The reported coefficients vary with trajectory. The separate horizontal-speed thrust correction is not a per-rotor H-force coefficient. | Use as a bounded borrowed prior/comparison. Do not label a per-rotor `-k*Omega*v` law or its coefficient as measured for this five-inch assembly. |
| [Agilicious paper](https://arxiv.org/abs/2307.06100) | Uses a 1 kHz simulator/controller with RK4 and a thrust-stand-identified first-order motor model; reports 39.1 ms response on that setup. | A useful system-identification example, not a universal race-motor constant or evidence that 240 Hz is equivalent to firmware control. Avoid adding the same measured response again as an extra latency term. |
| [NeuroBEM official dataset README](https://rpg.ifi.uzh.ch/neuro_bem/Readme.html), [project](https://rpg.ifi.uzh.ch/NeuroBEM.html) | Supplies 400 Hz motion/kinematics, motor speeds/derivatives and battery voltage; body axes are forward-left-up, world z is up. The README specifies mass 0.772 kg and diagonal inertia 0.0025/0.0021/0.0043 kg m². | Transform frames/quaternion ordering and reconcile configuration before use. Loads are reconstructed from acceleration and mass/inertia, not direct force sensors. Processed data does not provide a complete pilot/FC command tape. No clear dataset redistribution license was established in this review. |
| [NeuroBEM paper record](https://lbfd.github.io/publication/2021-neurobem/) | Compares aerodynamic models using unseen flight segments on its research platform. | Preserve training/evaluation split and metric definitions. Published RMSE values are not pass thresholds for another aircraft; identify what descent/high-speed regimes the selected records contain. |
| [NASA Johnson VRS report](https://ntrs.nasa.gov/citations/20060024029) | Describes an isolated-rotor mean-inflow model with helicopter/tiltrotor application and evidence. | HELI can own the common law, but small-prop transfer, multirotor interference and unsteady propwash remain unvalidated. A mean model does not itself produce measured oscillatory roughness. |
| [BLHeli_32 manual](https://github.com/bitdump/BLHeli/blob/master/BLHeli_32%20ARM/BLHeli_32%20manual%20ARM%20Rev32.x.pdf), [Hobbywing XRotor documentation](https://support.hobbywingdirect.com/hc/en-us/articles/19617357957011-Xrotor-series) | Some specific firmware modes describe regenerative braking; active-braking product claims alone do not identify pack return current on an arbitrary ESC/configuration. | Declare braking torque/loss and pack charging separately; no default regenerative shared-bus law without evidence and charge/voltage limits. |
| [Betaflight Modes](https://betaflight.com/docs/wiki/guides/current/Modes), [Rate Calculator](https://betaflight.com/docs/wiki/guides/current/Rate-Calculator), [Mixer](https://betaflight.com/docs/wiki/guides/current/Mixer) | Acro commands angular rate; centered sticks do not self-level. Airmode maintains low-throttle control. Rate curves and mixer modes are distinct configurable behavior. | Pin the supported curve/mixer semantics. Implement a reduced simulator controller honestly; do not promise identical PID/filter behavior or import every CLI field. |
| [Betaflight firmware/license](https://github.com/betaflight/betaflight), [default licensing](https://github.com/betaflight/betaflight/blob/master/DEFAULT_LICENSE.md) | Firmware is GPL-licensed. | Independent behavior/math implementation is the proposed route. Source ports and bundled comparators require an explicit license review; merely running a comparator separately is not a blanket licensing conclusion. |
| [Blackbox logging documentation](https://betaflight.com/docs/wiki/guides/current/Black-Box-logging-and-usage), [blackbox-tools](https://github.com/betaflight/blackbox-tools) | Logs processed RC/controller/sensor/motor-command and available power telemetry; dropped frames and logging rates need attention. Existing tools decode logs to CSV. | Reuse free tools with their license retained. Establish units, calibration, time alignment and gaps. Do not treat motor commands as measured RPM or processed RC commands as untouched sticks. |

Engineering derivation adopted in the plan: use locked-rotor inertia and relative rotor momentum consistently. External prop torque and relative-spin reaction are distinct terms; motor torque is internal to the combined vehicle. The coupled body/shaft equations need independent angular-momentum and motor-work checks, not only agreement between two transcriptions. Static thrust alone cannot identify prop torque or the full electrical model.

For sampling, the 240 Hz plant/controller baseline is a deliberate reduced model. Refine integration while holding controller update times fixed, then test controller rate/phase separately. A 240 Hz controller's Nyquist limit is 120 Hz; an above-Nyquist firmware filter cannot be replaced by a one-tick delay and called equivalent.

## Godot integration evidence

[Godot 4.7 Camera3D](https://docs.godotengine.org/en/4.7/classes/class_camera3d.html) documents aspect/FOV control. [Advanced interpolation](https://docs.godotengine.org/en/4.7/tutorials/physics/interpolation/advanced_physics_interpolation.html) describes manual camera interpolation; [Node reset](https://docs.godotengine.org/en/4.7/classes/class_node.html#class-node-method-reset-physics-interpolation) addresses teleports. Context7 was queried against the official 4.7 documentation branch, matching this repository's 4.7.2 pin.

Plan implication: reuse the custom simulator's interpolated pose for drone mesh and FPV camera, with one interpolation owner. Reset that history on respawn; do not add engine interpolation over an already interpolated transform. With vertical-FOV projection, horizontal-to-vertical conversion is `2 atan(tan(hfov/2)/aspect)`. Validate with known scene geometry at both supported aspects. These references do not establish native GPU performance or FPV input latency.

## Reconciliation and remaining limits

The specialist review changed the plan in five material ways: dedicated vehicle session instead of fixed-wing branching; transactional body feedback and logging before tuning; real five-inch geometry instead of fixture promotion; evidence-selected braking/control/aerodynamics instead of assumed firmware/propwash fidelity; and licensed downloads before procedural assets. The independent critic also required product retuning after the battery/motor law and a pilot-command replay path that reruns the candidate controller.

This investigation supports an implementable sequence and named gates. It does not deliver a drone, validate hardware, settle all asset licenses, prove a target-host performance budget or establish compliance with any racing rulebook. Those remain in the [active plan](../../../plans/drone-racing.md).
