# SUN-10: primary sources and Godot applicability

Checked 2026-11-15 · [Audit](README.md) · [Plan](../../../plans/sun.md) · [Examples and experiments](experiments.md)

## 1. Version policy

The project pins **Godot 4.8 beta 2**, `cafc17a192acf67903910a68aeb3c076c0907a4b`; [app/get-godot.sh](../../../../app/get-godot.sh) checks its executable identity. [G01: the official release announcement](https://godotengine.org/article/dev-snapshot-godot-4-8-beta-2/) provides release context. This program does not upgrade the engine.

Versioned `/en/4.8/` manual pages could not be retrieved during this research. That is a retrieval limitation, not proof that such documentation does not exist. Exact renderer/API claims below were checked against official class XML and implementation at the pinned commit. Versioned 4.5 tutorials explain established techniques; `/latest/` tutorials are supplementary and can advance beyond beta 2. Exact pinned source wins when these disagree.

Source links support a method or API contract. They do not establish OpenRC performance, visual quality, physical calibration or license compatibility for an uninspected dependency. No external engine, addon, asset or demo was imported into this branch.

## 3. Light transport and production references

| ID / primary reference | Useful idea | OpenRC decision / limit |
| --- | --- | --- |
| **R01** [PBRT 4e: Transmittance](https://pbr-book.org/4ed/Volume_Scattering/Transmittance) | Optical depth integrates extinction along a ray; segment transmissions multiply. | Define beam transmission separately from cloud display alpha. E2 uses the elementary homogeneous relation, not PBRT's full stochastic renderer. |
| **R02** [PBRT 4e: Phase functions](https://pbr-book.org/4ed/Volume_Scattering/Phase_Functions) | Directional scattering and the Henyey–Greenstein approximation; vector conventions matter. | Use a bounded cloud-rim prototype. A single lobe does not reproduce all cloud multiple-scattering features. |
| **R03** [Spencer et al., Physically-Based Glare Effects for Digital Images, SIGGRAPH 1995](https://www.graphics.cornell.edu/pubs/1995/SSZG95.pdf) | Image-space glare can communicate brightness beyond a display's ordinary range. | Supports separate optical presentation effects. It does not prescribe OpenRC recovery seconds or demonstrate RC pilot performance. Existing [SUN-00 sources](../SUN-00/research-2026-10-19.md) retain the original optics derivations. |
| **R04** [Hillaire, A Scalable and Production Ready Sky and Atmosphere Rendering Technique, 2020](https://diglib.eg.org/items/8a3e5350-18b3-46bd-9274-3add5af88c75), [author's publication page](https://sebh.github.io/publications/) | Compact lookup-table representation of sky/aerial perspective and dynamic atmosphere parameters | Candidate for SUN-17 after coherent affordable clouds. Publisher landing-page search/abstract was available; a direct page open returned 403. No claimed reproduction of its performance or full paper implementation. |
| **R05** [Guerrilla: Nubis, Authoring Real-Time Volumetric Cloudscapes, 2017](https://www.guerrilla-games.com/read/nubis-authoring-real-time-volumetric-cloudscapes-with-the-decima-engine), [original presentation](https://advances.realtimerendering.com/s2017/Nubis%20-%20Authoring%20Realtime%20Volumetric%20Cloudscapes%20with%20the%20Decima%20Engine%20-%20Final%20.pdf) | Art-directed cloud structure, lighting, motion and weather integration | Borrow the separation of shape, lighting and transport; do not copy its console millisecond numbers into an OpenRC budget. |
| **R06** [Guerrilla: Nubis³, 2023](https://www.guerrilla-games.com/read/nubis-cubed), [SIGGRAPH course materials](https://advances.realtimerendering.com/s2023/index.html) | Voxel-cloud research for moving through cloud volumes, acceleration and richer lighting | Advanced reference only. Its memory/modeling/engine assumptions are not a free Godot implementation or a baseline requirement. |

Equations in the examples are small engineering derivations from these concepts. Suggested artistic parameters and performance allocations are explicitly proposals. No claim is made that increasing haze, bloom or saturation is intrinsically more physically accurate.

## 5. Source intake rules for future implementation

Pin source revision, engine version, license and local modifications before importing code. Public access to a paper or demo does not automatically grant redistribution rights for its images, videos or supplementary assets. Retain existing project texture provenance and prefer reference-only use where no new asset is needed.

Keep API evidence, local source observations, mathematical expectations, actual rendered results and pilot judgments distinct in each step receipt. An official feature description explains availability; only the implemented OpenRC path and target measurements establish acceptance.
