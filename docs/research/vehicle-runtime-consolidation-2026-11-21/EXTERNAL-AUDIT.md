# Adversarial external-style audit of the VRC plan

**Date:** 2026-11-21. **Reviewed proposal:** [`542d92b304fc3b82678c4a90b848a88d82df0b22`](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/plans/vehicle-runtime-consolidation.md). **Runtime source:** `57abea025f62b20233ca281d58d2acbee4ab8b8e`. **Prior controls evidence:** `895dd4352c5191f1539a8b8f4df1996cd33eb86f`. **Review branch:** `audit/controls-plan-adversarial-2026-11-21`.

## Verdict and scope

**The original plan needed changes before a controls migration.** Its shared-kernel decision and incremental direction were sound, but the proposed abstraction and acceptance language did not fully protect the actual control authority, family transitions or evidence boundaries. The revised [master plan](../../plans/vehicle-runtime-consolidation.md) narrows the first implementation to one fixed-wing status/pause/resume consumer through existing shell/activity admission, and makes every subsequent move conditional on a named control contract and proof.

This review records **10 plan findings: four P1, five P2 and one P3**. All are addressed in the planning documents. That is a documentation disposition, not a claim that runtime defects are repaired or the game is qualified. The five prior GCA defects remain unfixed by this branch, all forty new acceptance cases remain **UNRUN**, and VRC-00…11 remain open implementation steps.

“External-style” means independent adversarial review contexts challenging the proposal and each other. It is not an audit by an external human firm or a certification. Three source-read-only reviewers covered RC controls, architecture/Good Enemy, and evidence/regressions; the lead checked material source arguments, resolved disagreements and edited/verified the integrated artifacts. Helpers were requested with the repository-preferred Terra/max settings; effective provider routing was not independently verified. No reviewer ran the application or edited production code.

P1 means resolve before the affected control/transaction migration because the proposal can otherwise permit an authority/safety regression or carry a known defect through its touched path. P2 means resolve before the affected implementation or evidence claim. P3 is source-document accuracy. These priorities grade **plan risks**, not ten newly reproduced gameplay bugs.

## Findings

### A01 — P1: a session method is not the full admission gate

The original port offered `request_resume(evidence)` and delegated family policy to adapters/sessions. That leaves the actual authority boundary underspecified. Fixed-wing Continue includes AppRoot's screen, radio-menu center and hold checks; airship samples armed input before calling a session method whose default argument is zero sticks; quad checks binding/generation, profile retry and readiness in its activity before `session.resume()`.

An adapter that trusts an earlier `ready=true`, forwards an old neutral sample or calls the session directly could bypass those checks. This is a concrete counterexample to a proposed design, not a demonstration that the current caller already bypasses them. See the [original API](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/plans/vehicle-runtime-consolidation.md#L45-L53), [fixed-wing shell](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/app_root.gd#L4730-L4759), [airship activity](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/vehicles/airship/airship_scene.gd#L598-L611) and [quad activity](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/vehicles/multirotor/multirotor_scene.gd#L849-L878).

**Change:** advisory status plus intent, forwarded through the existing shell/activity and session chain. Current owners revalidate role, connection generation, relevant profile/mapping, focus/capture and family readiness at dispatch and after deferred boundaries. Late work cannot authorize a replacement activity. C01–C04, C10–C12, C24 and C34 specify the main planned witnesses.

### A02 — P2: the shared status contract was assumed rather than established

VRC-01 called a shared session-status snapshot contract “existing.” The source instead has different family surfaces and consumers that inspect live fields. Operational availability can also depend on the current profile or external driver, so a blanket immutable capability description is insufficient. See [the original step](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/plans/vehicle-runtime-consolidation.md#L85-L90), [pause status](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/ui/pause_menu.gd#L492-L555) and [rate availability](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/flight_session.gd#L4232-L4256).

**Change:** characterize current surfaces first, prove the smallest projection for one consumer, distinguish unknown/unsupported/temporarily refused/ready, and keep live availability in its owner. Reset/restore/exit/disposal are deferred. Optional field/observer/view extraction no longer gates a separately complete controls repair. C30 will test detached state and truthful availability; this does not create another registry or lifecycle authority.

### A03 — P1: “input parity” lacked temporal acceptance

The original VRC-03 listed broad input categories but did not define the observable sequence that must remain equivalent. A consumed key event can still be globally polled as a flight axis; a polled zero is not ordinary radio recovery evidence; an unarmed AUX binding is no command rather than a retract request. Raw/unverified fixtures also cannot justify adding neutral dwell to verified gamepads. See [the original scope](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/plans/vehicle-runtime-consolidation.md#L88-L90), [radio event/poll readiness](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/input/rc_input.gd#L244-L384), [held keys](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/ui/held_keys.gd#L1-L28) and [hold/AUX sampling](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/flight_session.gd#L3091-L3145).

**Change:** trace actual event/poll/conditioning/admission order and first accepted command, without inventing one canonical pipeline. Explicit cases cover held keys, capture release, text chords, LOW/OFF/center evidence, shaping/trim ownership, AUX retention and family rate throttle. The trusted same-generation radio-menu verification seed remains valid ([source](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/ui/radio_menu_input.gd#L99-L140)). Sequence testing supplements named cases; it cannot conceal unvisited transitions. Relevant cases are C05–C10, C15–C20, C34 and C40.

### A04 — P1: detailed gates omitted two acknowledged defects

The proposal acknowledged GCA-01…05, but its detailed baseline and migration order referred to only GCA-01…03. Legacy lost updates and tiny admitted ranges matter to the calibration/profile/readiness seams VRC-03 may move. A “repair decision” alone cannot certify an unresolved invariant. See [the original characterization](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/research/vehicle-runtime-consolidation-2026-11-21/QUALITY-GATES.md#L5-L11), [migration order](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/plans/vehicle-runtime-consolidation.md#L100-L106) and [original repair scope](https://github.com/bultodepapas/OpenRCsimulator/blob/895dd4352c5191f1539a8b8f4df1996cd33eb86f/docs/research/game-controls-audit-2026-11-21/REMEDIATION.md#L93-L139).

**Change:** all five have pinned baseline disposition and explicit affected-step dependencies. Quad Pause dispatch, airship menu role clearing and uncached profile retry remain separate from legacy persistence and range admission. C10–C14 specify repaired outcomes. Unrelated status work is allowed to proceed; a change touching an unresolved invariant is blocked until its owning repair passes. Passing an old adverse witness reproduces the bug and is not repaired acceptance.

### A05 — P1: reset, recording and teardown are not interchangeable

The original acceptance broadly promised that rejected reset/restore retains the old recording. Fixed-wing has a specific transactional contract, but airship emits `resetting` before a later reset can refuse, and quad can notify before a later commit/retry fails. Their recorder callbacks can stop on that notification. This source-level counterexample needs an injection witness before claiming an ordinary-player incident or byte loss. See [airship reset](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/airship/session.gd#L192-L236), [airship recorder](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/airship/flight_log.gd#L155-L156), [quad reset](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/multirotor/session.gd#L487-L497) and [quad recorder](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/multirotor/flight_log.gd#L178-L179).

Separately, tentative fixed-wing detach intentionally leaves recordings open so a failed replacement can restore the same live flight. An unconditional common close would break that boundary ([source](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/app_root.gd#L3841-L3855)).

**Change:** keep broader operations in their owners. Later moves must prove refusal versus committed fault, noncredit restore, reentry, tentative detach, failed finalization/export, explicit discard and worker retirement. C27–C29 preserve the actual family contract; stronger preservation requires a separately owned behavior repair. A failed disk operation is never assumed to leave recoverable bytes merely because the interface is idempotent.

### A06 — P2: exact replay needs a source-identity-aware route

The original plan already acknowledged post-conditioning replay limitations and reference fallback. The missing detail was how source-moving PRs satisfy exactness/replay promises: the fingerprint includes `.gd` paths and bytes in simulation, physics and failures, plus commands/spec, and exact mode refuses a changed identity. Explicit candidate mode selects reference and has unsupported domains, including the declared servo candidate restriction. See [fingerprinting](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/flight_log.gd#L435-L449), [identity/domain refusal](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/tools/flight_log_cli.gd#L544-L566) and [backend selection](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/tools/flight_log_cli.gd#L618-L665).

**Change:** exact baseline replay on matching original identity; exact comparison only where identity genuinely matches; otherwise a supported explicit candidate comparison or an owner differential harness, with blocked domains stated. Report mode, completeness, ticks, `solver_changed` and actual backend. Native proof remains separate. C31/C32 apply when state/input/physics/recording identity is affected, not automatically to a pure status view.

### A07 — P2: fixture and completion evidence was too easy to overread

`golden_flights.gd` is a helper, while `test_golden.gd` is the launcher. The golden fixtures and short generated input tapes do not prove every named airplane category, a retained complete live tape or real-device conditioning. Routing tests use fake service/flight/session components, so they do not alone prove the whole assignment-to-activity route. The sample checked command also lacked an expected terminal summary. See [original examples](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/research/vehicle-runtime-consolidation-2026-11-21/QUALITY-GATES.md#L15-L33), [routing fakes](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/tests/test_controller_routing_audit.gd#L1-L54) and [short tape generation](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/tests/test_flight_log_inputs.gd#L31-L38).

**Change:** forty case obligations with explicit fixtures, oracles, owners and UNRUN states; existing suites are starting points. Require a real affected owner/consumer witness, complete expected roster, successful exit and inspected diagnostics. Warnings have an explicit policy, rather than an invented default failure rule. Q0 records missing-resource/timeout/engine-error limits and isolated user/import/process state. The earlier **22/27** result remains historical and incomplete ([receipt](https://github.com/bultodepapas/OpenRCsimulator/blob/895dd4352c5191f1539a8b8f4df1996cd33eb86f/docs/research/game-controls-audit-2026-11-21/verification.json)).

### A08 — P2: route and family differences need explicit policy

Shared service/admission language can conceal supported service-free direct launches, managed-versus-legacy persistence, fixed versus configurable controls and distinct family shaping. Direct legacy calibration can activate before a save and then report `NOT saved`; a universal rollback promise would change behavior. Legacy readers can also collapse absent/unreadable input while writers refuse unreadable input. See [direct gamepad admission](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/flight_session.gd#L1812-L1835), [direct calibration](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/flight_session.gd#L1913-L1922), [helicopter calibration](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/sim/helicopter_flight_session.gd#L1021-L1028) and [legacy persistence](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/app/input/rc_calibration.gd#L327-L374).

**Change:** name the actual Home/direct/trial routes and current owners; preserve accepted differences and separate stronger repairs. Correct airship resume to **low throttle plus centered yaw**, retain automatic quad fallback while held, preserve ordinary frozen rate throttle versus recovery, and distinguish fixed keyboard controls from pending keyboard remapping. Existing fallback source-display qualification stays open. C15–C24 and C34 carry these policies; unobservable physical axes are not given an invented missing-channel detector.

### A09 — P2: response quality cannot be inferred from workload speed

A lower tick cost or fewer callbacks can coexist with a newly buffered input frame. The detailed VRC gate needed to connect to existing input timing, physical-device, usability and package protocols. Those owner protocols already exist; this audit does not claim to invent or execute them ([controller acceptance](https://github.com/bultodepapas/OpenRCsimulator/blob/57abea025f62b20233ca281d58d2acbee4ab8b8e/docs/plans/controller-support.md#L85-L127)).

**Change:** C25–C26 and C33–C39 separate first-command/visible-response measurements, actual physical transport and native OS, package identity, applicable lifecycle soak, accessible EN/ES recovery and pilot evidence. Paired A/B has different pinned source identities and equivalent relevant conditions; physical trials use their own repeatable protocol rather than pretending to replay identical physical inputs. No guessed latency target or speedup is added. USB, Bluetooth and transmitter-off/receiver cases are qualified only where applicable; missing/unobservable capability remains explicit.

### A10 — P3: ten inventory line counts were off by one

Every reported line count included a phantom final empty line. All ten Git blob IDs and top-level function counts were correct. The corrected principal counts are **6,697** for `flight_session.gd`, **5,337** for `app_root.gd` and **4,303** for `main.gd`; no runtime consequence follows from this arithmetic error. The [original inventory](https://github.com/bultodepapas/OpenRCsimulator/blob/542d92b304fc3b82678c4a90b848a88d82df0b22/docs/research/vehicle-runtime-consolidation-2026-11-21/inventory.json) remains in history.

**Change:** regenerate all ten counts using UTF-8 `splitlines()`, update the [table](SOURCE-INVENTORY.md) and [JSON](inventory.json), pin source links and verify the counts/blobs/functions mechanically. Source size remains an inspection aid, not a complexity or speed claim.

## Adversarial decisions and rejected overreach

Reviewers challenged one another before reviewing the integrated draft. Material decisions were resolved against source rather than an objection quota or majority vote:

| Challenged proposal | Counterexample and final disposition |
| --- | --- |
| A shared resume call can delegate only to sessions | Rejected: shell/activity gates supply missing authority. Retain a narrow intent bridge through the actual full chain. |
| All five known bugs must be fixed before any VRC work | Rejected as overbroad: record all five; block only a migration touching the unresolved invariant. Status characterization can proceed independently. |
| Stronger universal neutral/rearm rules make controls safer | Rejected: verified gamepads are immediately ready on valid poll; guarded Fly/restart can already contain intent; quad ordinary hold/fallback differs. Preserve family policy. |
| Every radio poll is untrusted and OFF gates every Continue | Narrowed: trusted same-generation verification may seed finite center/OFF; same-radio mouse/keyboard resume checks center, while command OFF separately gates radio actions. |
| All failed saves retain the previous active profile | Rejected: managed V2 transaction and direct legacy activate-before-save have different current contracts. Report active-but-unsaved truthfully; strengthen only through a separate repair. |
| One refused-reset/close contract can cover every family | Rejected: early recorder notification and tentative detach differ. Preserve per-family commit/recording/lifetime semantics and defer the common API. |
| Exact old-log replay can certify a source-moving candidate | Rejected where identity changes: preserve refusal, use the supported candidate/differential workflow and qualify actual native separately. |
| Broad physical cross-product and tape identity on every PR | Rejected: use touched-seam cases plus applicable release/device rows. Physical timing is separate from deterministic replay. |
| The static checker can print UNRUN regardless of malformed input | Corrected: report actual status counts and refuse generation before writing a matrix from invalid/fabricated case status. Static validation still does not run gameplay. |

Retained strengths are the existing shared kernel/model boundary, capability-driven aircraft data, composition, incremental changes, independent family schemas/recorders, no automatic golden rewrite and measurement before optimization. The audit strengthens those decisions rather than restarting the architecture.

## Deliverables and validation boundary

The [control contract](CONTROL-CONTRACT.md), generated [acceptance matrix](CONTROL-ACCEPTANCE.md), canonical [case ledger](control-cases.json), [quality gates](QUALITY-GATES.md), [migration matrix](MIGRATION-MATRIX.md) and [finding ledger](audit-findings.json) form the review package. The master plan is the only VRC implementation-status authority.

The [static checker](../../../research/vehicle-runtime-consolidation/verify_plan.py) verifies inventory identities/counts, case/finding references, pinned test paths and SceneTree declarations, generated-matrix equality, local/pinned-source destinations and anchors, source ranges, tracked/index application-source stability, historical 22/27 counts and staged/working-tree whitespace. It does not parse/run GDScript or infer that the listed tests cover each proposed case. Ignored caches/imports are outside its unchanged-source claim. See [verification.json](verification.json) for the actual static result and artifact hashes, and the [rerun guide](../../../research/vehicle-runtime-consolidation/README.md).

No production controls, physics, input schemas, vehicle data or scene behavior were modified. No new Godot, replay, native performance, rendered UI, device, pilot, exported-package or CI result is claimed. The branch makes the implementation plan more explicit and reviewable; robust gameplay remains an outcome to demonstrate through the owning repairs and qualified cases.
