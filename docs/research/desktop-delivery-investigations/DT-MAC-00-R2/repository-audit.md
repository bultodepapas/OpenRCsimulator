# Apple renderer and measurement boundaries: repository audit

Audit date: 2026-10-28. Scope: source inspection on the Windows shared tree; no app, native benchmark, Mac, or hardware test was run. This is evidence for the [Apple Silicon plan](../../../plans/apple-silicon-performance.md), not an implementation or qualification. The dispatched baseline was `c953c8c848db7acac4ed33e606ba580e213d4244`; the inspected HEAD was `b56eb5fa3e08ffdb53860a656be7e431b3e2b547`, which adds camera/DLSS history-reset work and other graphics changes. Concurrent edits were present outside this report; later edits to `app/main.gd` and `app/tests/test_camera_history.gd` can shift cited lines. Line references describe the inspected files, not a frozen future tree; recheck the integrated source before implementation. Graph discovery found the frame collector and its callers, but did not index several newer graphics files; those boundaries were checked against current source directly.

**Existing** means code or a test is present, not that it passed in this audit. **Missing** means no corresponding application integration was found in the scoped source. **Unqualified** means the behavior, visual result, API receipt, or performance still needs evidence on the actual Mac and release build. The ordering below identifies integration and evidence risks, not measured bottlenecks.

**Integration-review note:** after this source pass, concurrent uncommitted changes added provider-advertised history-reset routing in `reconstruction.gd`. The DLSS-only descriptions below identify the audited `b56eb5f` behavior; the newer routing was not qualified by this task and establishes no MetalFX reset. Reconcile the combined implementation before execution. Review also identified that bare Forward+ with an empty profile enables High, direct `--frametimes` bypasses Home/display preferences, and export remains Linux-only; the execution plan incorporates explicit common-effects, product-flow and host-workflow checks.

## Engine, renderer, and product selection

- **Existing:** [get-godot.sh:4](../../../../app/get-godot.sh#L4) pins Godot `4.8-beta1`; [project.godot:14](../../../../app/project.godot#L14) declares 4.8; [export_presets.cfg:67](../../../../app/export_presets.cfg#L67) selects universal 4.8-beta1 Mac templates. The shipped project requests Compatibility, a 1280×720 default viewport and 4× MSAA ([project.godot:25](../../../../app/project.godot#L25), [project.godot:61](../../../../app/project.godot#L61)). The configured window is not an actual drawable-pixel receipt or a 1080p qualification.
- **Version gap:** [R1 I08–I12](../DT-MAC-00-R1/02-rendering.md#i08--native-metal-moltenvk-opengl-and-os-version) examines Godot 4.7.2. Re-check its Metal/MetalFX method, OS, driver, device, temporal-scale, history and Metal 4 claims against the *exact 4.8-beta1 source and templates* before turning them into gates. Neither a 4.7 finding nor an exposed enum proves this build/device runs an effect.
- **Existing:** [launch.py:31](../../../../tools/graphics/launch.py#L31) rejects forwarded method, driver and project overrides. Its [command builder:175](../../../../tools/graphics/launch.py#L175) selects only Standard/Compatibility or High/Forward+ and leaves the driver to Godot; [discovery:126](../../../../tools/graphics/launch.py#L126) names pinned Windows/Linux binaries but permits an explicit executable or `GODOT`. [test_launch.py:32](../../../../tools/graphics/test_launch.py#L32) checks ordering, profile metadata and rejected overrides. **Missing:** a controlled Mobile/Metal or same-method Vulkan comparison mode and a receipt for requested versus effective driver in the launcher. Passing unreviewed overrides would break its current profile safeguards.
- **Existing:** [high_graphics_profile.gd:16](../../../../app/render/high_graphics_profile.gd#L16) defines High from the environment, actual Forward+ and a non-headless display. It is more than a renderer selector: [configure:43](../../../../app/render/high_graphics_profile.gd#L43) changes the shadow atlas and [apply_environment:59](../../../../app/render/high_graphics_profile.gd#L59) enables SSAO and sky-reflection behavior. Comparing High against Standard therefore changes visual work as well as backend. Define a truthful common-effect comparison separately, and measure the full High product profile as another case; do not describe Mobile as High to bypass a gate.
- **Existing:** the settings screen offers a 15-second live display/reconstruction trial ([settings_screen.gd:623](../../../../app/ui/settings_screen.gd#L623)), requested/active reconstruction with estimated input/output dimensions ([settings_screen.gd:646](../../../../app/ui/settings_screen.gd#L646)), and a Standard/High restart. [AppRoot:1302](../../../../app/app_root.gd#L1302) restricts that restart to Home with no flight or Workshop; it sets no saved profile/pending marker and [restart_arguments:34](../../../../app/render/high_graphics_profile.gd#L34) selects only a method. This avoids a saved restart loop, but automatic recovery from a failed Mac renderer initialization is **unqualified**. The 15-second in-process trial is not a pre-initialization backend recovery test. [test_high_graphics_restart.gd:62](../../../../app/tests/test_high_graphics_restart.gd#L62), [test_high_graphics_profile.gd:14](../../../../app/tests/test_high_graphics_profile.gd#L14), and [restart_probe.gd:1](../../../../tools/graphics/restart_probe.gd#L1) cover current behavior; the three-process probe needs a native Mac run and new cases for any added choice.
- **Existing policy mismatch:** [scene_detail.gd:12](../../../../app/render/scene_detail.gd#L12) classifies adapter/vendor strings; `apple m` resolves to Medium and unrecognized names to High ([recommend:72](../../../../app/render/scene_detail.gd#L72)). [test_scene_detail.gd:79](../../../../app/tests/test_scene_detail.gd#L79) includes an Apple M1 string. A future capability-led Apple policy must explicitly decide how `auto` migrates, rather than claiming GPU names are already diagnostic only. Preserve explicit user overrides, collision/physics independence, old preference migration and the unknown-device fallback; qualify the resulting choices on real devices.

**Implementation boundary and gate (DT-MAC-02/05/06a, VQ/UI):** extend the graphics launch/restart owner with an explicit, validated research matrix (Compatibility/OpenGL control; Mobile/Metal; Forward+/Metal common features; MoltenVK only as a same-method control), recording requested and effective method/driver without altering normal launches or player preferences. Add negative/duplicate argument and profile-identity tests, then a real Home → restart → recovery probe using isolated preferences and the same final Mac package. Preserve Standard as a reachable recovery path even if a candidate fails before scripts run. Any durable choice needs an explicit transaction and migration design; the current temporary restart alone does not supply it. Test both accepted and unknown/corrupt/future settings and retain input calibration. A common M1 baseline must precede any automatic or higher-quality choice.

## Reconstruction, capabilities, and history

- **Existing:** [reconstruction.gd:6](../../../../app/render/reconstruction.gd#L6) exposes Native, FSR2, FSR3 and DLSS only. [runtime_capabilities:49](../../../../app/render/reconstruction.gd#L49) gates every optional provider on `HighGraphics.active()`; FSR2 checks its enum, while FSR3 and DLSS have additional provider-specific APIs. [resolve:87](../../../../app/render/reconstruction.gd#L87) preserves the request, reports the effective provider and falls back to Native. [apply:161](../../../../app/render/reconstruction.gd#L161) changes the main viewport, restores saved MSAA under Native and assigns AA to a temporal provider. [describe:238](../../../../app/render/reconstruction.gd#L238) reports requested/effective policy, AA, scale and *nominal*, rounded input size. [test_reconstruction.gd:12](../../../../app/tests/test_reconstruction.gd#L12), [test_display_preferences.gd:89](../../../../app/tests/test_display_preferences.gd#L89) and [test_advanced_graphics_settings.gd:114](../../../../app/tests/test_advanced_graphics_settings.gd#L114) provide existing seams for capabilities, fallback, saved modes, UI and secondary-viewport isolation. Their presence is not native-device proof.
- **Missing:** application MetalFX Spatial/Temporal modes and effective MetalFX capability/scale/failure reporting. A scoped literal search found MetalFX only in context within the separate Windows/native [engine.patch:151](../../../../tools/graphics/native/engine.patch#L151), not as an app adapter. No app-owned Metal 4 mode selector was found in the inspected renderer/launch paths. This says nothing by itself about what the pinned Godot engine already implements.
- **Important adaptation:** `resolve()` currently sets `temporal` for every non-Native provider ([reconstruction.gd:100](../../../../app/render/reconstruction.gd#L100)); [capture_settle_frames:147](../../../../app/render/reconstruction.gd#L147) recognizes FSR2/FSR3/DLSS. A Spatial provider cannot safely be added by appending a mode string alone: express provider-specific temporal/AA/sharpening ownership, support and capture-settle behavior, and validate it against the pinned engine rather than assuming that the existing FSR policies transfer. [settings_screen.gd:820](../../../../app/ui/settings_screen.gd#L820) currently disables the entire picker without High, so a supported Mobile Spatial trial requires a deliberate UI and capability-policy change.
- **Existing but limited:** camera view changes, snaps, resets and detected teleports notify a history seam ([camera_rig.gd:122](../../../../app/render/camera/camera_rig.gd#L122), [camera_rig.gd:230](../../../../app/render/camera/camera_rig.gd#L230), [camera_rig.gd:271](../../../../app/render/camera/camera_rig.gd#L271)). [request_history_reset:219](../../../../app/render/reconstruction.gd#L219) counts notifications separately from submissions, and submits only for DLSS when the optional backend method exists; submission is explicitly not SDK acknowledgement. [test_camera_history.gd:16](../../../../app/tests/test_camera_history.gd#L16) checks notification behavior, including no ordinary-movement reset. **Unqualified:** how 4.8-beta1 MetalFX invalidates history for these discontinuities, resize, AA/scale changes, pause/resume and scene transitions, whether an engine API is available, and whether reset reaches the actual scaler. Do not report a notification as a completed MetalFX reset.

**Implementation boundary and gate (DT-MAC-07, VQ):** only after the native 1080p baseline and renderer parity justify reduced pixel work, inspect the pinned engine's exposed support and actual device/build/driver limits. Use the existing adapter and `display.cfg` validation/UI rather than another preference store; allow each provider independently, preserve unsupported saved requests and show the true Native fallback. If Godot does not expose a required fact or acknowledgement, record it as unavailable and resolve the narrow engine-owned gap before claiming support. Extend provider fixtures and preference/UI/restart tests for unknown modes, absent APIs, minimum scales, changed capabilities, runtime failure, temporal versus spatial AA, secondary viewports and no saved-state mutation. Native captures must include motion, propeller/hinges, distant aircraft, foliage, smoke, disocclusion, cuts, reset, teleport, resize, pause/resume and output/UI readability. Compare net performance and memory against Native; no frame generation is implied.

## Timing, resources, and soak

- **Existing:** [frame_samples.gd:5](../../../../app/render/frame_samples.gd#L5) retains monotonic frame intervals and raw per-frame metrics. It rejects discontinuities, changed metric schema and retention overflow ([record_frame:125](../../../../app/render/frame_samples.gd#L125)); `complete` requires a finished sample with no failure ([report:227](../../../../app/render/frame_samples.gd#L227)). Limits are **300 seconds**, 60,000 default frames and 120,000 maximum ([frame_samples.gd:7](../../../../app/render/frame_samples.gd#L7)). Thirty minutes at 60 Hz is about 108,000 frames, but the duration limit already prohibits it; 120 Hz would be about 216,000 frames. Concatenated restarted runs are not one continuous soak. [test_frame_samples.gd:123](../../../../app/tests/test_frame_samples.gd#L123) and [test_frame_capture.py:53](../../../../tools/godot/test_frame_capture.py#L53) cover failure and retained-prefix behavior.
- **Existing, correcting the older plan's broad metadata gap:** [frame_diagnostics.gd:45](../../../../app/render/frame_diagnostics.gd#L45) already records effective renderer **and driver**, adapter, API version and OS when opt-in diagnostics start, including before its Mac Compatibility timing exclusion. It reports scoped viewport CPU/GPU observations, resource estimates and observer state ([sample:83](../../../../app/render/frame_diagnostics.gd#L83)); zero GPU time is ambiguous and timings can lag. Mac Compatibility timers are deliberately unavailable ([frame_diagnostics.gd:162](../../../../app/render/frame_diagnostics.gd#L162)). [main.gd:3275](../../../../app/main.gd#L3275) records method, scene settings, viewport-visible dimensions, refresh, VSync, frame cap, session endpoint, simulation and reconstruction; the driver lives in the optional diagnostics block. These process-loop intervals are not a compositor/presentation trace, and viewport/window dimensions do not independently prove physical Retina drawable pixels. Actual Mac driver, physical pixels, timing availability and observer cost remain **unqualified**.
- **Existing:** [run_checked.py:104](../../../../tools/godot/run_checked.py#L104) can sample the directly launched process with optional pinned psutil. [resource_samples.py:92](../../../../tools/godot/resource_samples.py#L92) uses a platform-generic psutil protocol, not a separate Darwin adapter; it records per-field failures/unsupported values and process identity. It samples RSS, virtual memory, process CPU/I/O where available, system memory and swap ([resource_samples.py:269](../../../../tools/godot/resource_samples.py#L269), [resource_samples.py:372](../../../../tools/godot/resource_samples.py#L372)). The default is 600 samples, maximum 10,000; a capped sample is marked as such ([resource_samples.py:480](../../../../tools/godot/resource_samples.py#L480), [finish:544](../../../../tools/godot/resource_samples.py#L544)). For an uninterrupted 30-minute run, configure sufficient samples and verify the actual stop/coverage status. Direct PID excludes descendants; system swap is system-wide and RSS/GPU allocations may overlap. [test_resource_samples.py:206](../../../../tools/godot/test_resource_samples.py#L206) covers PID reuse, unsupported fields and caps using test seams; actual Darwin field availability, package PID, overhead and pressure/thermal channels need native verification.
- **Existing:** the debug bridge provides a bounded 7,200-frame history ([debug_bridge.gd:138](../../../../app/debug/debug_bridge.gd#L138)), hitch context including pipeline counters ([debug_bridge.gd:1558](../../../../app/debug/debug_bridge.gd#L1558)), and object/resource comparisons ([debug_bridge.gd:1778](../../../../app/debug/debug_bridge.gd#L1778)). Its [soak workflow](../../../../tools/debug/README.md#hunting-stutter-leaks-and-bugs-pt1h-r8) is useful for lifecycle/resource comparisons, not a substitute for an uninterrupted continuous frame/thermal soak or proof of a leak.

**Implementation boundary and gate (DT-MAC-02/03/08, PT/DT):** extend the existing frame collector with bounded chunked/streamed continuous collection and explicit sequence, time continuity, schema, intended duration, finalization and interruption/completion metadata. Preserve short-run format/exit behavior and normal launch paths. Add tests for limit edges, dropped/duplicated/reordered chunks, clock/schema changes, write/flush failure, interruption, cleanup and a complete 30-minute-equivalent synthetic sequence at 60 and 120 Hz without retaining all frames in memory. Validate reducers and resource correlation using the existing checked runner and tests; reject capped, partial or incomplete outputs as qualification. On Mac measure instrumented versus uninstrumented overhead, actual drawable pixels, presentation/pacing with an appropriate native trace, process and system resource channels, thermal/power conditions and missing-field status. Do not sum overlapping unified-memory estimates or infer causality from same-index timing spikes. Two separate uninterrupted 30-minute soaks per accepted baseline/finalist, with comparable starting conditions, remain a hardware gate.

## Rendering workload and resource boundaries

- **Shaders/transparency:** [water.gdshader:115](../../../../app/render/lake/water.gdshader#L115) uses screen/depth textures and a renderer-specific NDC reconstruction branch; verify shoreline depth, reverse-Z, refraction, sky/exposure and edge artifacts on each method. [treeline.gdshader:97](../../../../app/render/treeline.gdshader#L97) and [tree_assets.gd:169](../../../../app/render/tree_assets.gd#L169) use alpha scissor; [near_grass.gdshader:2](../../../../app/render/near_grass.gdshader#L2) renders opaque geometry, and [exhaust.gd:79](../../../../app/render/smoke/exhaust.gd#L79) uses depth-sorted alpha-blended GPU particles with proximity fade. [treeline.gd:150](../../../../app/render/treeline.gd#L150) and [near_grass.gd:255](../../../../app/render/near_grass.gd#L255) use MultiMesh batches. These are plausible inspection points, not measured overdraw or submission bottlenecks. Preserve simulation-clock animation and the different cutout/smoke semantics.
- **Reflections:** [lake_reflection.gd:14](../../../../app/render/lake/lake_reflection.gd#L14) refreshes the normal probe on lighting changes; optional planar capture requires High and an environment request ([lake_planar_reflection.gd:29](../../../../app/render/lake/lake_planar_reflection.gd#L29)). When active it uses a second viewport, 2× MSAA, HDR, scaled and capped size ([lake_planar_reflection.gd:84](../../../../app/render/lake/lake_planar_reflection.gd#L84)); it disables updates when out of view and breaks the texture dependency on exit ([lake_planar_reflection.gd:131](../../../../app/render/lake/lake_planar_reflection.gd#L131)). Root-only GPU timing does not describe the whole multi-viewport frame. Check inactive/active state, exposure, masks, target size and cleanup on each candidate.
- **Memory:** [project.godot:67](../../../../app/project.godot#L67) limits the reflection atlas and enables the ETC2/ASTC import path; its comment is not proof of actual Mac GPU format or resident bytes. The [static and runtime inventories](../../../../research/performance/README.md#runtime-texture-inventory-vq-02a) describe bindings, dimensions and some returned image formats, but CPU image byte sizes are not VRAM; the runtime inventory excludes viewport readback and several routes/effects. Verify current 4.8 tooling, actual imported GPU formats on each device and snapshot identities, then use native captures/resource tools for residency and pressure. Preserve asset color/normal/mask semantics and source provenance.
- **Preparation:** [shader_warmup.gd:7](../../../../app/render/crash/shader_warmup.gd#L7) performs small disposable crash draw samples only for Compatibility; it explicitly skips headless and other methods. [director.gd:108](../../../../app/render/crash/director.gd#L108) invokes it during preparation. [home_preview_resources.gd:88](../../../../app/ui/home_preview_resources.gd#L88) uses threaded resource loading, which is not evidence that every future draw pipeline is compiled. Pipeline compilation counters in the debug bridge are clues for attribution. Revalidate 4.8 renderer-specific pipeline behavior and compare fresh-import, process-cold and warm-cache conditions before adding bounded preparation. Never clear shared system caches to manufacture a cold run.

**Implementation boundary and gate (DT-MAC-05/06, VQ/LU/FW/SM):** first run existing area checkers from [graphics tools](../../../tools/graphics.md) and paired moving 1080p cases on the same scene, camera, light, smoke, aircraft and display. Cover day/night, lake, sky, alpha edges, shadows, secondary viewports and first use. Use target GPU captures and timing/resource receipts to select one variable, then remeasure whole-session pacing, quality, memory and lifecycle; only then consider shadow/reflection resolution, grass/foliage coverage, material variants or pipeline preparation. Preserve cues and compare the common visual set before treating any effect reduction as an optimization. Higher resolutions follow accepted 1080p; 720p is last.

## Ranked integration risks and stop conditions

1. **Stale engine assumptions / false Metal 4 claim:** 4.7.2 research does not establish 4.8-beta1 behavior; stop if source/template identity, method, driver, OS or effective feature cannot be shown. Metal 4 should be an independently verified engine/OS/backend condition, not a chip-name toggle or a second physics path.
2. **Unrecoverable or mislabeled backend:** renderer initialization precedes the app; stop promotion if a failed candidate cannot reach Standard, if effective driver differs silently, or if a comparison changes High effects without declaring them.
3. **Temporal correctness:** unsupported or unacknowledged history resets, motion-vector/AA assumptions and missing moving-image evidence block Temporal promotion. Capability/enum presence alone is insufficient.
4. **Invalid measurements:** partial/capped samples, unidentified physical pixels, observer-induced hitches, unavailable GPU timers, package mismatch or thermal/power drift prevent a performance conclusion. Retain baseline and collect the missing channel.
5. **Visual or memory regression:** reject missing cues, broken lake/reflection/transparency behavior, growth across lifecycle cycles or sustained pressure/swap attributable to the candidate. Do not infer the culprit before attribution.

Relevant software tests are linked above; run the focused checked scripts and launcher/resource Python tests on the exact candidate, then the relevant full suite and native Mac visual, recovery and package gates. This documentation audit ran none of those tests and provides no Mac performance, M1–M5 coverage, MetalFX output, Metal 4 execution or physical-validation claim.
