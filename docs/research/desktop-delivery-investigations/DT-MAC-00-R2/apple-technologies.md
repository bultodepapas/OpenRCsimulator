# DT-MAC-00-R2 — Apple GPU and Metal technologies

**Research date:** 2026-10-28. This is primary-source desk research on a Windows host; no Mac, GPU capture, exported build, pilot test or performance measurement was run. The [DT-MAC execution plan](../../../plans/apple-silicon-performance.md) owns the work and acceptance gates; the [Godot compatibility report](godot-compatibility.md) audits the current engine pin and its renderer boundaries, while [DT-MAC-00-R1](../DT-MAC-00-R1/README.md) retains the earlier investigation. Source publication dates below are distinct from this retrieval date. An API, hardware-family threshold or vendor demo is not evidence of Godot exposure or OpenRC performance.

## What the sources change

1. Preserve the M1/8 GB native 1080p baseline and its Compatibility recovery path. Measure common-feature Mobile/Metal and Forward+/Metal before choosing a renderer or scaler. Metal 4 and a newer chip are not automatic speedups.
2. Apple's **May 21, 2026** [feature-set PDF](https://developer.apple.com/metal/Metal-Feature-Set-Tables.pdf) identifies MetalFX frame interpolation and denoised scaling under both Metal 3 and 4 programming models. Apple's separately indexed [February 5 HTML table](https://developer.apple.com/metal/capabilities/) displays different programming-model values. Use the later dated PDF plus the actual SDK/device queries; do not conclude that frame interpolation intrinsically requires Metal 4.
3. The SDK descriptor floors are macOS 13 for spatial and temporal scaling and macOS 26 for interpolation and denoised scaling. **Each feature has its own runtime support query**, and the Metal 4 command-buffer variant has a separate `supportsMetal4FX` query. OS, family, query, engine build, render method and actual output must all agree.
4. Apple announced a redesigned MetalFX temporal scaler at WWDC26, specifically describing Neural Engine and GPU Neural Accelerator use on **M5 Pro and M5 Max**. The 2026 interfaces and enhancements are not established as configured by the pinned Godot path. Treat them as a separate engine/device investigation, not an implicit benefit for every M5 or for M1. [Apple WWDC26 Metal guide](https://developer.apple.com/wwdc26/guides/metal/).
5. macOS 27 was released on [September 14, 2026](https://www.apple.com/newsroom/2026/09/major-updates-for-apples-software-platforms-are-now-available/). Apple released an [M6 Mac mini on September 22](https://www.apple.com/newsroom/2026/09/the-new-mac-mini-and-mac-studio-are-available-today/); its [M6 iMac](https://www.apple.com/newsroom/2026/10/apple-unveils-new-imac-with-m6/) and [14-inch M6 MacBook Pro](https://www.apple.com/newsroom/2026/10/apple-introduces-the-new-14-inch-macbook-pro-with-m6/) were announced October 27 for November 6 availability. The plan tracks M6 in a separate coverage row alongside M1–M5. The May PDF predates M6 and does not map it to a GPU family; query the actual device instead of guessing a family or qualifying M6 from M5 results.

## Hardware and API capability matrix

Apple's [May 2026 feature-set table](https://developer.apple.com/metal/Metal-Feature-Set-Tables.pdf) maps M1→Apple7, M2→Apple8, M3/M4→Apple9 and M5→Apple10; all are listed for Metal 3 and Metal 4. Metal 4 also requires a supported OS. Godot's 4.7 rendering documentation describes automatic Metal 4 on macOS 26+, but the inspected 4.7.2 and current 4.8-beta1 sources both construct the **Metal 3 command backend** unconditionally. The pinned scaler uses Metal 3 command buffers. Read the actual OS/build and effective driver; do not infer Metal 4 from the OS, GPU family or API string. The [compatibility source audit](godot-compatibility.md#driver-and-feature-matrix) documents the contradiction and precise source revisions.

## Reconstruction and presentation implications

**Spatial.** A spatial scaler uses the current color image and avoids history/motion-vector integration. At 1920×1080 output, 0.85 linear input scale is approximately 1632×918, or 72.25% of output pixels before rounding. The scaling pass, render-target footprint and all non-pixel costs remain; this is not a predicted 27.75% frame-time improvement. Keep UI at output resolution and compare aircraft/marking/foliage readability in motion. Apple specifies texture formats, sizes, color processing and per-device support in the [spatial descriptor](https://developer.apple.com/documentation/metalfx/mtlfxspatialscalerdescriptor.md).

**Temporal.** Apple requires jittered scene color, depth and motion information to accumulate detail; exposure, motion-vector scale and conventions, mip bias, depth direction, reactive content and history lifecycle materially affect output. The scaler exposes a `reset` to discard history. Camera cuts, teleport/reset, resize, pauses, disocclusion, propeller/hinges, wind-driven foliage, smoke and thin distant markings need moving-image review. Use the engine's actual permitted input scale, not an assumed universal minimum. [Apple's 2022 integration session](https://developer.apple.com/videos/play/wwdc2022/10103/), [temporal base protocol](https://developer.apple.com/documentation/metalfx/mtlfxtemporalscalerbase.md).

**2026 additions.** Apple's current DocC metadata dates [jittered motion-vector handling](https://developer.apple.com/documentation/metalfx/mtlfxtemporalscalerdescriptor/isjitteredmotionvectorsenabled.md), [output-resolution motion vectors](https://developer.apple.com/documentation/metalfx/mtlfxtemporalscalerdescriptor/isoutputresolutionmotionvectorsenabled.md) and [input color subrectangle offsets](https://developer.apple.com/documentation/metalfx/mtlfxtemporalscalerbase/colorcontentoffsetx.md) to macOS 27. The [frame-interpolator distortion option](https://developer.apple.com/documentation/metalfx/mtlfxframeinterpolatordescriptor/isdistortiontextureenabled.md) is also macOS 27. These require a compatible SDK, runtime, engine integration and support checks; a base temporal scaler available since macOS 13 does not establish those later properties. Apple's WWDC26 guide describes direct motion vectors, subrectangles and distortion fields, as well as its redesigned neural upscaler; confirm exact device/OS use and whether Godot actually supplies the relevant data before promising the improvements.

**Interpolation.** Apple's [WWDC25 session](https://developer.apple.com/videos/play/wwdc2025/211/) describes generating an intermediate image from two rendered frames plus depth and motion vectors, with explicit UI composition and presentation timing. This can increase displayed cadence while adding latency; it does not increase simulation ticks, input sampling, or the number of independently rendered frames. Apple’s [WWDC26 porting session](https://developer.apple.com/videos/play/wwdc2026/357/) explicitly identifies the latency cost, presentation ordering and the need for evenly paced frames. An RC flight-control evaluation would require measured input-to-photon latency, native and generated frame intervals, UI/marker behavior and artifact/pilot tests under identical control tape. The plan treats this as optional **DT-MAC-12**, a separate renderer/presentation project requiring a qualified real-frame baseline and a product need.

**Denoised scaling.** Apple describes a real-time ray-tracing path that combines denoising and upscaling using noise-free normal, diffuse/specular albedo, roughness, depth and motion auxiliary data. Its [WWDC26 neural-rendering session](https://developer.apple.com/videos/play/wwdc2026/359/) also discusses transparency and masks. Defer for OpenRC unless a separately justified ray-traced effect and its required render buffers are implemented and measured; the Apple9 threshold does not prove those resources exist in the current scene.

## Metal, memory and compilation

Metal 4 uses new command queue and independently encoded command-buffer types, command allocators, argument tables, residency sets, explicit barriers and a dedicated compiler; residency sets also exist in Metal 3. These offer the engine more control, not an application-level performance setting. In Metal 4, resource residency and producer/consumer synchronization are the renderer's responsibility. For a hypothetical engine change, include all resources, lifetimes, hazards, fallback and validation; untracked or premature release can corrupt output even when a GPU command completes. [Apple's Metal 4 session](https://developer.apple.com/videos/play/wwdc2025/205/), [residency sets](https://developer.apple.com/documentation/metal/simplifying-gpu-resource-management-with-residency-sets). Godot already owns these internals; avoid a separate application-side Metal resource manager.

Apple Silicon shares physical memory between CPU and GPU. Shared memory removes a discrete VRAM boundary, not bandwidth, storage-mode, synchronization or capacity constraints. An 8 GB host also runs macOS and other processes; RSS, GPU allocations, compressed memory and swap overlap and should not be added as independent pools. `recommendedMaxWorkingSetSize` is a recommendation rather than installed/available VRAM. Sample system pressure and per-process/resource lifetimes over transitions and the full soak. [Apple storage modes](https://developer.apple.com/documentation/metal/choosing-a-resource-storage-mode-for-apple-gpus), [Activity Monitor memory](https://support.apple.com/guide/activity-monitor/view-memory-usage-actmntr1004/mac), [device allocation](https://developer.apple.com/documentation/metal/mtldevice/currentallocatedsize).

Apple GPUs use tile-based deferred rendering. Tile memory, accurate load/store actions and memoryless attachments can reduce external traffic when attachment contents are not needed after a pass; they cannot replace preserved data required by later passes. Profile the existing MSAA, shadow, reflection and transparent passes before proposing an engine change. Do not assume every multisampled target is already memoryless, or that rendering all effects at a lower resolution is visually acceptable. [Apple TBDR guidance](https://developer.apple.com/documentation/metal/tailor-your-apps-for-apple-gpus-and-tile-based-deferred-rendering).

Shader source/IR, specialized pipeline states and GPU-specific binaries are distinct. [Metal binary archives](https://developer.apple.com/documentation/metal/metal-binary-archives) can trade bundle size for reduced compilation; an OS update can invalidate a binary and trigger IR recompilation. Metal 4 offers scheduled compilation, flexible pipeline state and harvesting; binary archives can be used by Metal 3 and 4. [Compilation API](https://developer.apple.com/documentation/metal/using-the-metal-4-compilation-api), [archive details](https://developer.apple.com/documentation/metal/creating-binary-archives-from-device-built-pipeline-state-objects). These are engine-level candidates only if an attributed hitch warrants them. First compare fresh import, process-cold, first-use and warm runs using Godot's existing pipeline path. Do not delete shared system caches to manufacture cold tests.

## Pacing, power and profiling

At 60 Hz the display interval is approximately 16.67 ms; FPS averages do not reveal presentation bursts, queued frames or input latency. Capture the actual drawable pixel size, display refresh, VSync/cap, effective Game Mode, foreground state, power source and thermal state. `CAMetalDisplayLink` gives a Metal application display callbacks, a drawable and a render/presentation deadline, with controllable frame latency; its rules are not permission for an app script to take over Godot's display loop. [Display-link guidance](https://developer.apple.com/documentation/metal/achieving-smooth-frame-rates-with-a-metal-display-link), [callback restrictions](https://developer.apple.com/documentation/quartzcore/cametaldisplaylinkdelegate/metaldisplaylink%28_%3Aneedsupdate%3A%29). Compare buffer-count or high-refresh changes only as isolated experiments.

Apple says Game Mode is associated with full-screen games configured for it and reduces background competition; fullscreen alone is not proof it is effective. [WWDC25 Game Mode](https://developer.apple.com/videos/play/wwdc2025/209/). Track Low Power Mode and thermal-state changes when available; compare AC and battery separately on the same workload and do not silently modify physics or controls in response. [Power notifications](https://developer.apple.com/documentation/xcode/responding-to-power-notifications).

For attribution, Apple documents the Metal Performance HUD for GPU time, frame interval and memory, Instruments' Game Performance/Metal System Trace, Xcode GPU capture and the Power Profiler where supported. [HUD metrics](https://developer.apple.com/documentation/xcode/understanding-metal-performance-hud-metrics), [Metal performance analysis](https://developer.apple.com/documentation/xcode/analyzing-the-performance-of-your-metal-app), [power profiling](https://developer.apple.com/documentation/xcode/measuring-your-app-s-power-use-with-power-profiler), [WWDC26 performance workflow](https://developer.apple.com/videos/play/wwdc2026/388/). Captures and overlays can perturb the workload, so compare with an uninstrumented run and retain exact tool/OS version. Do not claim an energy value from a frame time or extrapolate Mac results from Windows.

macOS 27 adds MetalFX HUD views for exposure, jitter and motion-vector scales, and Apple demonstrates `gpucapture`/`gpudebug` command-line workflows in [WWDC26](https://developer.apple.com/videos/play/wwdc2026/357/). Its [performance session](https://developer.apple.com/videos/play/wwdc2026/388/) also demonstrates `metalperftrace` look-back collection and summaries and optional `StateReporting` context. Determine whether the actual OS, renderer and tool build expose useful data, verify overhead and retain bounded local artifacts; the session does not establish OpenRC telemetry integration. [Xcode 27 release notes](https://developer.apple.com/documentation/xcode-release-notes/xcode-27-release-notes) describe MetalFX history capture and diagnostic options. These are useful conditional debugging tools, not proof the project path is valid or a reason to require macOS 27 for the baseline. Apple's Game Porting Toolkit 4 demo is a porting aid, not a substitute for Godot integration or final exported-package tests.
