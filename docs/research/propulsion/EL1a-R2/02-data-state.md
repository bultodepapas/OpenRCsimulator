# EL1a-R2 — Electric data and replay investigations

2026-10-10 · **Status:** primary-source review complete; electric schema and checkpoint changes remain planned. Scope: EL1b, EL1d, EL2. Sources accessed 2026-10-10. Read with the [electric propulsion plan](../../../ELECTRIC-PROPULSION-PLAN.md).

## 04 — Can the electric branch be strict in both schema and loader?

**Decision question.** How can `electric_prop` join v1 without silently taking the glow path or accepting unsupported fields?

**Verified findings.** The [schema propulsion branch](../../../../app/data/schema/openrc-aircraft-v1.schema.json#L1237) declares JSON Schema Draft 2020-12, but lists only `glow_prop` and `turbine`; `if turbine / else glowPropulsion` sends every other kind to glow. Runtime [`_propulsion()`](../../../../app/physics/aircraft_data.gd#L708) also defaults missing kind to glow and accepts only those two. `load_file()` calls this loader directly; it does not run the schema, and the schema allows extra fields here. Draft 2020-12 defines `oneOf` as exactly one match; `additionalProperties` only sees properties declared beside it, while `unevaluatedProperties: false` can close a composed branch. Its `integer` type means a number with zero fractional part. Godot 4.7 parses JSON numbers through `String::to_float` into a `double` Variant, so file values arrive as `TYPE_FLOAT`; [`_q()`](../../../../app/physics/aircraft_data.gd#L79) accepts int or float for in-memory parity and rejects nonfinite/out-of-range values. [J1] [G1] [G2]

**EL1b change and rejecting test.** Define disjoint propulsion branches, preserve the missing-kind legacy glow default, and close the electric object plus its motor, ESC, and battery children in both schema and loader. Reuse `{value, unit, kind, source}` for every numeric physical quantity, with explicit units, bounds, provenance kind, and nonblank source; retain cross-field physics checks in the loader. Reject unknown electric keys, mixed combustion/turbine fields, wrong units, missing provenance, nonfinite values, and invalid dimensions/ranges in both routes. Verify that literal JSON `value: 1` passes a dimensionless `number`, while an integer-constrained state value accepts only finite whole-valued numbers after parsing. Keep old glow and turbine fixtures valid and prove electric never falls through to glow. Schema type/range validation cannot enforce motor-loss meaning, force ordering, or cross-field constraints; those remain loader policy. [J1] [J2] [G1]

**Sources.** [J1] [JSON Schema Draft 2020-12 Core](https://json-schema.org/draft/2020-12/json-schema-core), §§10.2.1.3 `oneOf`, 10.3.2.3 `additionalProperties`, 11.3 `unevaluatedProperties`. [J2] [JSON Schema Draft 2020-12 Validation](https://json-schema.org/draft/2020-12/json-schema-validation), §§6.1.1 `type`, 6.2 numeric limits. [G1] [Godot 4.7 `json.cpp`](https://github.com/godotengine/godot/blob/4.7-stable/core/io/json.cpp), `_get_token()` and `_parse_value()`; [Godot 4.7 JSON class reference](https://docs.godotengine.org/en/4.7/classes/class_json.html), Description and `parse()`.

## 05 — Which state may be shared by multiple aircraft sessions?

**Decision question.** Can a loaded electric model safely serve multiple active sessions without shared battery or ESC state?

**Verified findings.** [`AircraftData.load_file()`](../../../../app/physics/aircraft_data.gd#L39) reparses each call into plain dictionaries and packed arrays; it does not load a `Resource`. [`FlightSession._commit_aircraft()`](../../../../app/sim/flight_session.gd#L463) assigns prepared data to the session, while dynamic `aux`, `continuous`, and `modes` belong to the simulation ([`simulation.gd`](../../../../app/sim/simulation.gd#L24)). Godot 4.7 documents that dictionaries are passed by reference; `duplicate(true)` copies nested arrays/dictionaries but still shares Resources. Path-loaded Resources use a global cache, and `resource_local_to_scene` duplicates only during scene instantiation. That does not isolate two flight sessions. [G3] [G4]

**EL1b/EL2 change and rejecting test.** Keep normalized motor, ESC, pack, and propeller coefficients as immutable model definition. Put SOC, polarization voltage, ESC mode, ramp timers, and sample phase in state owned by each `FlightSession`/`Simulation`; never attach them to a cached definition or singleton. If a future cache returns a shared model dictionary, either make it read-only or copy it at the session boundary, and test the ownership contract explicitly. Create two sessions from the same data path, advance only one, then assert the other's state, trace-start metadata, checkpoint, and continuation are unchanged. Also mutate one session's state after taking a checkpoint and prove the checkpoint remains detached. This checks the actual multi-model case while keeping configuration hashes equal for equal models and runtime state independent. Current per-call parsing gives separate derived dictionaries, but the committed model remains mutable by reference; the guarantee currently depends on callers not using model configuration as runtime storage. [G3] [G5]

**Sources.** [G3] [Godot 4.7 Dictionary class reference](https://docs.godotengine.org/en/4.7/classes/class_dictionary.html), Description and `duplicate()`; [G4] [Godot 4.7 Resource class reference](https://docs.godotengine.org/en/4.7/classes/class_resource.html), Description and `resource_local_to_scene`. [G5] Local ownership seam: [`FlightSession._commit_aircraft()`](../../../../app/sim/flight_session.gd#L463), [`Simulation` state declarations](../../../../app/sim/simulation.gd#L24), and [`Simulation.checkpoint()`](../../../../app/sim/simulation.gd#L410).

## 06 — What makes an electric checkpoint identifiable and restorable?

**Decision question.** Which identity and state must survive serialization so a compatible fresh session continues the same trajectory?

**Verified findings.** Simulation checkpoint v1 snapshots tick, timestep, body states, auxiliary/continuous states, inputs, modes, loads, mass, inertia, gravity, and stop tick ([`Simulation.checkpoint()`](../../../../app/sim/simulation.gd#L410)). Flight checkpoint v4 adds shaft-integrator identity; its SHA-256 configuration digest hashes the model, ground, environment, and integrator with `var_to_bytes`. Restore preflights identity and layout; existing tests round-trip native bytes and continue in a fresh session. The encoding excludes Objects and Callables. [G5] [G6]

`model.data_sha256` uses default `JSON.stringify(..., full_precision=false)`; `input_identity.sha256` hashes exact file bytes. A test shows a late digit can change a physics value while colliding in the legacy digest, so keep these identities distinct. Godot documents exact float decoding with `full_precision=true`, but JSON has one number type, writes infinity as `1e99999`, and writes NaN as `null`; retain native bytes for checkpoints. [G7] [G8]

**EL1d/EL2 change and rejecting test.** Version the electric law/state layout in checkpoint identity. Persist all state affecting the next step: SOC/polarization, ESC mode and timers/sample phase, RPM, tick/time, inputs, and RNG. Put electric identity and initial-state metadata in the trace, separate from exact input-file SHA. Round-trip native bytes into a fresh session with the same model, then compare the next N ticks byte-for-byte. Atomically reject missing or changed battery/controller state, model kind/configuration, layout/version, timestep, or invalid discrete values. The flight-physics API currently returns a dictionary and uses `var_to_bytes` for its configuration digest; define persistence and cross-version compatibility in an explicit format contract. [G5] [G6] [G7]
