# R11 Linux verification attempt 01

This is the first canonical Linux `app/test.sh` run for the R11 source snapshot. It failed at AV-15; the result is retained as evidence and is not a passing full-suite gate.

The source snapshot is fixed Git commit `b09aa20016d3dcc8133073e66424313b9bfbf0d7` (tree `5528115a8034a027ed12c5d3f31455e2c039f6ef`) plus the ten explicit R05B paths in [the integrated overlay manifest](linux-r05b-integrated-overlay.json). The `app/sim/flight_session.gd` overlay removes only the concurrent `p51d-mustang-120` runway-list addition, restoring that line to b09; the b09 `test_runway_start.gd` remains unchanged. No other live working-tree changes are in this test identity.

Git archive materialization honored the fixed commit's `.gitattributes`. Each of the 14,893 base blobs was verified by clean-normalizing its checkout bytes back to its Git blob ID. This matters for aircraft descriptors: `.gitattributes` declares them CRLF, and their exact bytes are used by Workshop identity checks. The ten overlays produced 14,896 source files total, excluding the separately pinned engine binary. The external archive was 2,254,551,040 bytes with SHA-256 `723133aa8de4382f70174cb613f7cb97b08bb1dcc2d640db65573515587098d4`. The pinned Godot executable is 4.7.2 (`ed1daf0bf`), SHA-256 `8d106cbe6144c2dc7e881d61d2429c1a8a76e6b22ef48bd5e48dcf934953f71e`.

The isolated checkout passed extraction integrity: 0 added, 0 removed, and 0 mismatched source paths; the archive and Godot hashes also passed. The canonical command was `bash app/test.sh` from `/home/bulto/openrc-r11-b09-r05b-20261014-03`. Aircraft contract/migration, model manifests, exact-byte Workshop checks, Glow profile/installations, P51 inventory, and earlier HELI suites passed before the first failure. The raw integrity and test outputs are retained in [the integrity log](linux-extract-integrity.log) and [the first test log](linux-app-test-first.log); source identities are in [the before manifest](linux-source-before.json), [the post-test manifest](linux-app-test-first-after.json), and [the live delta list](linux-live-delta-vs-b09.json).

The first failure is `AV-15 / GeometryInventoryTests.test_generated_artifacts_match_source_pipeline`. Its `derive_physics.py --check` subprocess reported `app/data/aircraft/sebart_avanti_s_a200.json` stale. In an isolated output directory, the same AV-06 builder emitted the same 104,883 bytes and 3,393 CRLF line endings as the archive checkout, but two content values differ: the checked-in value `0.6414130000000001` is regenerated as `0.6414129999999999` at JSON rows 1967 and 2070. The derivation report is unchanged. This is a floating-point generator reproducibility defect around the AV-17-R2 polar's special-angle factors, not a CRLF mismatch. The concise [byte and content diff](linux-av06-diagnostic.txt), regenerated JSON, and regenerated derivation report are retained. No generator or aircraft-data source was edited for this attempt.

Godot generated 22 `.uid` sidecars during the run; these are listed in the post-test manifest and are the only additions reported. The generator diagnostic briefly wrote into the isolated checkout, then its output directory was removed and `sebart_avanti_s_a200.json` was restored byte-for-byte to the before-manifest SHA-256 `74043c9bc1de35de066bc65b971e85f5e099173f2d9cccec065c6988abbb6b9d`. The separate diagnostic files preserve the regenerated bytes and diff. The shared working tree and source archive were not changed.

This run verifies software behavior only; it does not establish physical validation. The source scope is the fixed commit plus explicit overlays, not the complete live working tree. The live-delta manifest records tracked and nonignored untracked differences against b09; ignored paths are deliberately not enumerated.
