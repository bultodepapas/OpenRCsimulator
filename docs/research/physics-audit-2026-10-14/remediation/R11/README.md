## Intentional reference changes

Four golden flights were re-recorded only after the section-force/wake checks and their independent comparisons passed. The four original fixtures are retained in [`final-scenarios-01/previous-goldens/`](final-scenarios-01/previous-goldens/). [`golden-changes.json`](final-scenarios-01/golden-changes.json) records both hashes, unchanged input tapes, and the R02 reason for each change. Tick counts remain 600, 720, 720 and 1,200. Before refresh, the old fixtures fail under the deliberately changed law; the glide body remains within about 6e-12 m but its auxiliary wake units change. [Before-refresh output](golden-before-refresh/golden.log). The refreshed golden test passes 4/4; this is a regression reference, not the independent proof of the new equations.

Only three modal band centers changed. Their existing 3% tolerance was not widened. An independently composed derivative/Jacobian and SciPy eigensolve establish the new references, including a finite-difference step sweep. The 42 mode checks pass, including the existing nonlinear lag-response test. [Mode evidence and old/new controls](../R02-modes/README.md).

The subsequent [D11g data integration](d11g-root-integration/README.md) regenerates the Stik's three stored rate derivatives from the current local law and updates its generated variants/descriptors. Independent modal calculations justify one additional center change (25 m/s spiral), retaining 3%. Three affected goldens are regenerated with unchanged inputs/policies; the original glide remains unchanged. Old-data and current-data recordings, exact replays and same-input comparisons are retained separately. These references verify software consistency and do not resolve the yaw model discrepancy below.

The [complete D11g control comparison](d11g-root-integration/all-axis-flights/README.md) covers all 28 cases: both aircraft, normal/full authority, neutral and both directions on each axis. All 28 old-data recordings replay exactly, and all 28 same-tape data candidates finish with 1,441 rows each. Independent review of all 40,348 paired CSV rows confirms identical initial body states, tick/time sequences and command tapes, finite results, and the reported position/velocity/rate differences. The 14 Jet comparisons are exactly unchanged; the Stik changes are recorded explicitly. This data-only comparison retains the same solver fingerprint and does not qualify the underlying aerodynamic closure physically.

Failed runs are retained honestly. `final-scenarios-01` refreshed the goldens successfully but its recording verification failed because concurrent ground-vehicle source changed the solver fingerprint between recording and exact replay. `final-scenarios-02` passed the isolated Stik record/replay, then stopped on a comparison-runner path error. Neither is a passing integration gate. `final-scenarios-03` corrects the path and uses an immutable source snapshot; it is the accepted recording run.

## Timestep refinement and cost

[Complete-session timestep refinement](time-refinement/README.md) now covers Stik/Jet at 120/240/480/960 Hz with aligned inputs and identical initial numeric states. All eight three-second runs complete. The measured session trend is approximately first order, and the 240 versus 960 Hz maximum position differences are 8.52 mm and 20.37 mm respectively. This is numerical evidence, not a physical acceptance budget.

[Session-cost measurements](session-cost-20261014-02/README.md) complete six sequential runs on the identified Windows development host, with a separate first pass and three full-checkpoint-verified repetitions per regime. Observed old and corrected timings exceed 500 microseconds per tick; a stale concurrent snapshot job was discovered afterward, so these timings do not establish isolated-host acceptance. Corrected p50 values span 915–1,962 microseconds in these fixtures. This is an open performance gate, not target-machine qualification; allocation traffic, recorder cost and kernel attribution remain unmeasured.

## Remaining release gates

The first canonical Linux attempt exposed [platform-dependent generation of the Avanti's high-angle polar](avanti-generator-portability/README.md). Its four special angles now use analytic factors, and the aircraft/Workshop descriptor were regenerated through their pipelines. Eight scalar values change by at most 2.23e-16; no physical tuning or test-tolerance relaxation is involved. The initial failed run remains part of the evidence.

The next attempt passed that generator check and stopped at [one H4 rate-guard comparison](rate-guard-rounding/README.md). A captured component square differed between general `pow(x, 2)` and direct multiplication, producing a 12-ULP selector difference. The runtime now uses explicit products for those squares; an exact-rational check independently establishes the nearest float64 at the failing input. The exact comparator, frozen reference and golden fixtures remain unchanged. A derived candidate includes this correction and the previously missing canonical polar-builder unittest hook.

The next canonical attempt passed those checks but stopped at a stale catalog expectation that at least one aircraft have no gear. The [contact fixture repair](contact-contract-fixture/README.md) preserves fleet checks and exercises a valid gearless v2 configuration through the real loader. The subsequent immutable [diagnostic remainder](linux-gd-remainder-after-contact-contract.json) completed all 456 later GDScript suites: **434 passed, 22 failed**, including one 60-second RCV powertrain timeout. Source verification found no changed, added or removed paths. This diagnostic is not a passing canonical suite.

Several causes now have separate source-identified repairs: [Jet keyboard onset and sustained endpoint](keyboard-pull-diagnostic/README.md), [servo input-vector fixture](servo-step-diagnostic/README.md), [catalog/controller/field/grass expectations](catalog-fixtures/README.md), [generated lake resource and source stamp](lake-bake-diagnostic/isolated/README.md), and [runway transaction, shaft refinement, Home weather and wheel-session fixtures](start-refinement-fixtures/README.md). Their focused results do not replace the next immutable Linux integration run. The shaft test reproduces the failure only with the newer P-51 ground-effect data; the paired verification explicitly retains those exact bytes instead of claiming an older passing configuration resolves it.
