# 08 · Offline terrain generation and real-elevation pipelines

Date: 2026-10-05. **Question:** which offline tool, and which committed file format, should produce the L12/L13 heightmap (a ~5×5 km area: flat field, gentle swales, treeline belt, hill ring), so that it can be regenerated byte for byte and loaded by the float64 sampler and the renderer alike? And how would a real DEM go through the same pipeline?

## Findings

**Determinism means integers, not a choice of noise library.**
- NumPy guarantees the same random stream only "on the same build of numpy, in the same environment, on the same machine". `Generator` streams may change between X.Y releases ([policy](https://numpy.org/doc/stable/reference/random/compatibility.html) [doc]). FFT-based fBm, such as `util.fbm` in terrain-erosion-3-ways, combines `np.random.rand` with FFTs ([src](https://github.com/dandrino/terrain-erosion-3-ways/blob/master/util.py) [src]), so it cannot be checked byte for byte in CI.
- Integer arithmetic is exact everywhere. I wrote a prototype that uses integers from end to end: a `lowbias32` lattice hash, value noise with an integer smoothstep fade, `math.isqrt` radial masks, and heights in units of 1/256 m. Pure stdlib Python and an int64 NumPy port gave the **same SHA-256** (`a56d60677d7fd02d…`) for a 1251×1251 grid at 4 m [measured].
  - Pure Python took **21.5 s** and NumPy 1.26 took **2.2 s** on the dev VM [measured].
  - Output range: −1.46 m to +50.2 m [measured].
- `lowbias32` is a 2-round integer hash, released under the Unlicense ([hash-prospector](https://github.com/skeeto/hash-prospector) [repo]). SquirrelNoise5 would also work, but its CC-BY-3.0 licence needs credit in the source ([gist](https://gist.github.com/kevinmoran/0198d8e9de0da7057abe8b8b34d50f86) [sec]). `lowbias32` avoids that.
- The repo already follows this pattern: CI runs `compile_geometry.py --check` (stdlib Python 3.12) before `app/test.sh` (`.github/workflows/ci.yml`, line 44) [measured]. A `--check` mode in the terrain generator fits the same pattern, with no pip dependencies.

Core of the prototype (our code, MIT like the repo; `lowbias32` constants are Unlicense):

```python
M32, Q = 0xFFFFFFFF, 1 << 16
def lowbias32(x):                       # skeeto/hash-prospector, Unlicense
    x ^= x >> 16; x = (x * 0x7feb352d) & M32
    x ^= x >> 15; x = (x * 0x846ca68b) & M32
    return x ^ (x >> 16)
def lattice(ix, iy, seed):              # -> [-32768, 32767]
    h = lowbias32((ix * 0x9E3779B1 ^ iy * 0x85EBCA77 ^ seed) & M32)
    return (h >> 16) - 32768
def fade(t):                            # smoothstep on [0, Q], integer
    return (t * t * (3 * Q - 2 * t)) // (Q * Q)
def value_noise(xm, ym, wl, seed):      # integer metres, wavelength wl
    ix, fx = divmod(xm, wl); iy, fy = divmod(ym, wl)
    tx, ty = fade(fx * Q // wl), fade(fy * Q // wl)
    a, b = lattice(ix, iy, seed), lattice(ix + 1, iy, seed)
    c, d = lattice(ix, iy + 1, seed), lattice(ix + 1, iy + 1, seed)
    top, bot = a * Q + (b - a) * tx, c * Q + (d - c) * tx
    return (top * Q + (bot - top) * ty) // (Q * Q)
def ramp(r, r0, r1):                    # 0 inside r0, Q beyond r1
    return 0 if r <= r0 else Q if r >= r1 else fade((r - r0) * Q // (r1 - r0))
# h = (swales*ramp(r,150,300) + (|hills|+bias)*ramp(r,1200,2000)) // Q   (1/256 m)
```

**Erosion is not worth it at this distance.**
- The hill ring sits 1.2–2.5 km from the pilot. A 50 m hill at 2 km spans about 1.4° of view, so erosion gullies would be sub-pixel behind the L2 haze [inference].
- Erosion code also runs on floats with sequential droplets, so its output would have to be committed as-is, without a regeneration check [inference].
- If a Gate asks for erosion later:
  - Port Lague's droplet erosion (MIT, C#/Unity, last push 2024-01) [repo](https://github.com/SebLague/Hydraulic-Erosion) or dandrino's grid simulation (MIT, last push 2022-11; requirements pin TensorFlow 2.5 and GDAL 2.3) [repo](https://github.com/dandrino/terrain-erosion-3-ways).
  - Treat the result as committed art, not as regenerable data.
- SimpleHydrology (C++, needs TinyEngine) says "MIT License" in its README but has **no LICENSE file** [repo](https://github.com/weigert/SimpleHydrology). Avoid it.

**Proprietary and editor-only tools don't fit.**
- Gaea 2.3.1.0 (2026-09-24): Community Edition is "for evaluation and non-commercial use" and exports at most 1024² ([download](https://quadspinner.com/download) [doc]).
- World Machine Basic: "no asset larger than 1025x1025", and any commercial use needs a paid licence ([download](https://www.world-machine.com/download.php) [doc]).
- Neither can run in CI, and neither licence is clear for redistribution in an MIT repo.
- Blender A.N.T. Landscape 0.2.0 (2024-05-14) is GPL-2.0+ ([extension](https://extensions.blender.org/add-ons/antlandscape/) [doc]). Its output can be used freely, but runs aren't reproducible outside Blender. Use it only for sketching shapes.
- Godot `EditorScript` runs only from File › Run in a running editor ([doc](https://docs.godotengine.org/en/stable/classes/class_editorscript.html) [doc]), so it can't run headless. If a Godot-side generator is ever needed, it has to be a `--headless --script` SceneTree script, like `bench_physics.gd`.

**Loading in Godot and exporting.**
- `FileAccess` reads little-endian by default and is "reset to system endianness, which is little-endian on all supported platforms" ([doc](https://docs.godotengine.org/en/stable/classes/class_fileaccess.html) [doc]).
- `PackedByteArray.decode_s16` exists ([doc](https://docs.godotengine.org/en/stable/classes/class_packedbytearray.html) [doc]). The sampler can therefore keep the raw bytes and decode only the 3 vertices it needs per query, with no bulk conversion [inference].
- **Export trap:** non-resource files are exported only when listed in the filter ([doc](https://docs.godotengine.org/en/stable/tutorials/export/exporting_projects.html) [doc]). `app/export_presets.cfg` has `include_filter="data/*.json"` [measured], so a `.bin` file would be **missing from release builds**.
- Size of the 1251² int16 grid [measured]:
  - raw: 3.13 MB
  - zlib-9: 2.34 MB (roughly what git stores)
  - row-delta + zlib: 0.94 MB
- PicaSim uses 513² at 5 m for comparison (research §3).

**Real-DEM pipeline (L17).**
- Sources:
  - CNIG MDT02 (2 m, COG, CC-BY 4.0) ([CNIG](https://centrodedescargas.cnig.es/CentroDescargas/modelo-digital-terreno-mdt02-segunda-cobertura) [doc])
  - USGS 3DEP 1 m (public domain, credit requested) ([catalog](https://catalog.data.gov/dataset/1-meter-digital-elevation-models-dems-usgs-national-map-3dep-downloadable-data-collection) [doc])
- GDAL 3.13.3 (2026-08-18) adds `gdal raster reproject` (since 3.11), with `--output-crs`, `--resolution`, `--bbox`, `--resampling` and `--target-aligned-pixels` ([doc](https://gdal.org/en/stable/programs/gdal_raster_reproject.html) [doc]).
- Pipeline:
  1. Reproject to a metric CRS (e.g. EPSG:25830) on a bbox centred on the pilot. Use `average` when going from 2 m to 4 m and `cubic` when upsampling [inference].
  2. In Python (rasterio 1.5.2, BSD-3, released 2026-09-30, [PyPI](https://pypi.org/project/rasterio/) [rel]): subtract the pilot-spot elevation, then flatten the field with the same integer `ramp()` mask.
  3. Quantise with `round(h*256)`, check the range, and write the same format.
- The float steps in this pipeline aren't bit-reproducible, so the output is committed with its SHA-256 and with provenance (product, tile IDs, credit line). CI checks the hash, not a regeneration [inference].

**Proposed file format `openrc-terrain v1`** (two files in `app/data/terrain/`):
- `field.heights.bin`: row-major (row j along +z, column i along +x), int16 little-endian, value = height × 256 (m). No header.
- `field.terrain.json`, the sidecar:

```json
{"format": "openrc-terrain v1", "cols": 1251, "rows": 1251,
 "spacing_m": 4, "origin_m": [-2500, -2500], "height_scale": 256,
 "dtype": "int16_le", "diagonal": "i0j0-i1j1",
 "min_raw": -374, "max_raw": 12846, "sha256": "…",
 "generator": {"script": "tools/terrain/gen_terrain.py", "seed": 1234,
   "params": {"flat_r_m": [150, 300], "ring_r_m": [1200, 2000]}},
 "source": {"kind": "procedural", "license": "MIT"}}
```

- Every value is an integer, so it stays exact in JSON, in float32 vertices (|h| < 2²⁴/256 m) and in float64.
- int16 covers ±128 m, which is enough for the synthetic ring. A real DEM with more relief would use `"dtype": "int32_le"` (format v2).

## What this changes in LANDSCAPE-PLAN.md

1. **L13: replace "seeded FastNoiseLite" with `tools/terrain/gen_terrain.py`**: stdlib Python, integer-only, `lowbias32` value noise, ring and flat masks via `isqrt`.
   - Proof: `--check` regenerates the file and compares SHA-256 in CI, next to the `compile_geometry.py --check` step.
   - Proof: a NumPy port gives identical bytes (one-off measurement recorded in LEARNINGS).
2. **L12: fix the format now** (`openrc-terrain v1` above): the all-zero file is 1251² int16 + sidecar, and the loader refuses a SHA, size or format mismatch, like the aircraft JSON.
   - Proof: loader tests for a bad SHA, wrong size and wrong dtype.
   - Proof: golden flights unchanged.
3. **L12: add `data/terrain/*` to `include_filter`** in both export presets.
   - Proof: the `export.sh` smoke test loads the terrain and logs its SHA. Without the filter, release builds fall back to nothing silently.
4. **Split L13** into:
   - L13a: generator plus committed grid, with no rendering. Proof: SHA check, plus a heightmap PNG for review written to `captures/`.
   - L13b: render chunks from the same bytes. Proof: mesh-vs-sampler test ≤ 1e-4 m.
5. **L17: add the DEM recipe**: `gdal raster reproject` with a pinned GDAL/rasterio, pilot-relative datum, integer flatten mask, provenance block. Proof: committed SHA, plus a credit line shown in-game.
6. **No erosion step.** Note in L13 that erosion is a Gate-only option and its output is committed art.

- Whether CI time allows the 21.5 s pure-Python `--check` on every push, or whether it should run only when `tools/terrain/` or `data/terrain/` change.
