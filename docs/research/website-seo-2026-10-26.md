# WEB-09 — Static site search guidance

**Reviewed:** 2026-10-26. Scope: the static GitHub Pages site, its Spanish/English routes, and search visibility. This note records official Google Search Central and Microsoft Bing guidance; it does not predict rankings or guarantee indexing.

## Findings

### What changed in 2026

- On 2026-04-20 Google added guidance for "Read more" deep links: make target content immediately visible, avoid forcing the initial scroll position, and preserve URL fragments. WEB-09 uses visible answers with stable section IDs rather than collapsed FAQ panels. See [snippet and deep-link guidance](https://developers.google.com/search/docs/appearance/snippet#read-more).
- Google's FAQ rich result is no longer displayed in Search, effective 2026-05-07; Google removed its FAQ rich-result documentation on 2026-06-15. Keep an FAQ when it answers real visitor questions, but do not add `FAQPage` markup to seek a Google rich result. The dated changes are in [Google Search Central's documentation update log](https://developers.google.com/search/updates).
- Bing launched its AI Performance report in public preview on 2026-02-10. It reports citations, cited URLs, and sample grounding queries across supported Microsoft AI surfaces. Bing explicitly says citation counts do not indicate ranking, authority, or placement. Treat it as an optional visibility measure after site ownership is verified in [Bing Webmaster Tools](https://blogs.bing.com/webmaster/2026/2/Introducing-AI-Performance-in-Bing-Webmaster-Tools-Public-Preview/).
- Google's core AI Search advice remains ordinary SEO. A page must be indexed and eligible for a search snippet to be eligible as a supporting link in AI Overviews or AI Mode; there are no additional technical requirements or special schema for those features, and eligibility does not guarantee indexing or display. Google's AI results are included in the Search Console Web performance report. See [AI features and your website](https://developers.google.com/search/docs/appearance/ai-features), checked on this review date (page footer: 2025-12-10), and [Google's AI search guide](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), updated 2026-07-10.

### Durable guidance that fits this site

- **Use a real URL for each language.** Google recommends separate language URLs instead of changing one URL using cookies or browser preferences. It determines language from visible page content, advises against automatic language redirects, and recommends user-selectable links between versions. Thus a Spanish `/` and English `/en.html` with one language in each page's initial HTML are a good fit; retaining JavaScript for visual controls is fine, but it should not be the only way English content exists. This applies Google's [multilingual site guidance](https://developers.google.com/search/docs/specialty/international/managing-multi-regional-sites) to this static site.
- **Make `hreflang` reciprocal and complete.** Each page must list itself and every alternate using fully qualified URLs; the sets should match on both pages. If one page omits the return link, Google may ignore that relationship. HTML annotations, HTTP headers, and sitemap annotations are equivalent alternatives; Google says there is no Search benefit to maintaining all three. For this small site, put the two `es`/`en` annotations in both HTML heads. A normal sitemap can still list the two page URLs; add the XML language extension only if choosing it instead of HTML annotations. See [localized page guidance](https://developers.google.com/search/docs/specialty/international/localized-versions), updated 2026-09-21.
- **Keep search essentials in the source HTML.** Google can render JavaScript, but rendering happens after crawling and may be delayed; Google notes that not all bots run JavaScript. Its JavaScript guide recommends unique, descriptive titles and meta descriptions, and favors server-side or pre-rendering for speed and crawler compatibility. For WEB-09, keep the page title, description, canonical, language content, FAQ answers, and crawlable `<a href>` links in each static document. Let JavaScript enhance interaction, not supply the only copy or route. See [JavaScript SEO basics](https://developers.google.com/search/docs/crawling-indexing/javascript/javascript-seo-basics).
- **Write the page for people who need the simulator.** Google's AI guidance calls for helpful, reliable, people-first content, clear organization, and text for important information. A short visible FAQ can explain evidenced project facts and current limits. Link to relevant sections with ordinary internal links and stable headings; anchors improve navigation, but are not separate language pages or ranking guarantees. Ensure descriptions and the visible opening accurately summarize each locale. Do not create near-duplicate pages for every query variation. The AI sources above support the content and internal-link recommendations.
- **Treat structured data as descriptive metadata.** Do not add special AI markup or FAQ schema for an unavailable FAQ rich result. Any structured data retained on the page must agree with what visitors can read; Google lists this among its AI/search fundamentals. Search appearance remains at Google's discretion.
- **Measure page experience separately from SEO checks.** This media-heavy site should keep the opening poster and core copy available immediately, while deferring optional turntable and 3D media until needed. Google's Core Web Vitals guidance recommends field targets of LCP ≤2.5 s, INP <200 ms, and CLS <0.1; good results support user experience and align with ranking systems, but are not a guarantee of ranking. Qualify changes with performance measurements at mobile and the project's primary 1920×1080 desktop size; a Lighthouse SEO score is not a performance result. See [Core Web Vitals and Search](https://developers.google.com/search/docs/appearance/core-web-vitals), updated 2025-12-10.

## Priorities for WEB-09

1. Keep Spanish root and English `/en.html` independently useful with complete, visible, single-language copy, distinct titles and descriptions, and self-canonicals. Add a visible language link between them; avoid local-storage or browser-language redirects as the only route to a translation.
2. Put the reciprocal `hreflang` set in both page heads and make the sitemap list only the two public language URLs. Treat the sitemap and annotations as discovery/localization signals, not indexing promises.
3. Keep the FAQ visible in HTML, factual, and scoped to what the simulator actually supports. Do not add `FAQPage` markup. Use section links for navigation rather than creating sitemap entries for fragments.
4. Preserve crawlable HTML links, accurate metadata, and fast initial rendering. After deployment, inspect indexed routes and search queries in Search Console if the property is verified; use Bing AI citation data only as descriptive observations if Bing Webmaster Tools is available.

The 2026 changes include deep-link guidance, measurement and feature availability (Bing's AI citation report and Google's FAQ rich-result retirement). Separate locale URLs, reciprocal `hreflang`, static text, descriptive metadata, internal links, and user-focused performance are established guidance, not a new AI ranking recipe.
