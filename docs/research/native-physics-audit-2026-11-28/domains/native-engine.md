# Native engine and implementation audit

**Baseline** `8d4169f8febfd7d78a028eaa817414217a54f24b`, 28 November 2026. Source and component investigation by the senior native simulation engine developer. All source anchors below are repository-relative and refer to this commit.

The fixed-wing extension can integrate an eligible interval and return its endpoint. The helicopter extension owns continuous stages in a narrower domain. The ground extension evaluates forces through a separate ABI. The production multirotor and airship stages use script. These distinctions determine what to port, what to measure, and what a successful replay proves. Four changes have identifiable native work and a falsifiable acceptance test.

## Findings

### ENG-01 — Record integration ownership on the fleet and performance tapes

**High-priority verification and architecture gap.** An existing stage-coverage assertion is valid for its purpose. Pilot-facing flight selection and fleet results cannot currently distinguish all the work a native-integrated tick still delegates.

The installed stage identity binds binary, sources and lock. The fleet requires native stage and context activity on each tick. `tick_stats().calls` increments after early eligibility/plan returns; it counts neither all requests nor successful endpoints. `answers` increments after endpoint filtering/projection, then `Simulation` commits the returned arrays. Rotor, substep choice on uncovered domains, event transition, post-filter and projection can call script inside an answered integration. The focused tick-driver test already compares answer counts, callbacks and frame bytes. Its more precise proof is not carried by the general fleet receipt. See `app/sim/native_stage.gd:195–205,274–275`, `research/native-kernel/fleet.gd:791–795`, `research/native-kernel/fleet_campaign.py:619–627`, `research/native-kernel/src/nk_kernel.cpp:3473–3517,3536,3555–3559,3598,3659,3672,3688,3708,3792,3802–3814,4018–4027`, `app/tests/test_native_tick_driver.gd:298–335,418–425`.

Add opt-in fixed-width counters to the native stage and tick driver for early declines by reason, integrated answers, faults, RHS stages, native substep decisions and each delegated callback kind. Reuse the existing answer counter. The harness records counter deltas against the host's accepted-tick count and freezes the backend, family, protocol, binary/source, OS/architecture, tape and field identities for the measurement. Record stage-only and reference-only domains explicitly. Keep diagnostics out of authoritative checkpoint bytes. Exhaustively moving every callback can wait for route-specific measurements.

No new force law. This lets a future native port demonstrate exactly which work moved and makes comparisons interpretable. Small-to-medium scope across native counters, fleet/trajectory readers and the performance harness. Per-tick allocation or timing probes could perturb the workload; keep counters native, read at measurement boundaries, and run an instrumentation-off control.

**Acceptance**

For each eligible row, count committed integrated answers and stage-only commits separately; disclose fault/decline reasons and actual callbacks. Deliberately disabling the driver on an otherwise native-stage row must preserve stage activity while changing the integrated-answer count to zero. Dry helicopter produces native stages and zero integrated answers, wet helicopter/reference, interval servo, FPV and airship keep their own status; ground reports its evaluator calls in its own ABI. A refusal may not advance the accepted tick or publish a new checkpoint/state. Run reset, restore, staged refusal, replay and package checks on their eligible platforms. The 500 µs target remains the project's controlled target-host budget. Report true per-tick percentiles separately from batch-mean percentiles and inclusive observer time separately from time to commit.

### ENG-02 — Reuse native event and substep buffers

**Confirmed C++ heap traffic in the component probe.** Its production latency is unmeasured. The one-piece RK4 helper already reuses all five stage buffers. Additional workspaces have shorter lifetimes in the substep and event helpers.

`TickRk4Scratch` is retained by the kernel. The direct integrator uses it, while refined steps allocate a current state and first derivative. Declared events allocate an evaluation copy, tracked candidate, and on a crossing another high-state copy. The resource policy builds event pointer/value vectors and copies the trial endpoint before checking crossings. See `research/native-kernel/src/nk_tick.hpp:114–170,203–239,293–310,333–341,369–386,1004–1042`, `research/native-kernel/src/nk_kernel.cpp:1134–1138,3529–3542,3594–3615,3702–3722`.

One isolated test of the current C++ header used 32 float64 state values at 240 Hz, pre-sized RK/output buffers and an allocation-free RHS. Each case ran twice with the same inputs, counts and output hash. The RHS counts below exclude the precomputed first derivative. Allocated bytes sum requests to scalar C++ `operator new` while the helper executes. They are neither peak memory nor live-flight timing.

| Fixture | Allocations | Bytes requested | RHS evaluations after first | Events |
| --- | ---: | ---: | ---: | ---: |
| Plain RK4, one piece | 0 | 0 | 3 | 0 |
| Plain RK4, eight pieces | 2 | 512 | 31 | 0 |
| Declared event, one clear piece | 4 | 1,024 | 3 | 0 |
| Declared event, eight clear pieces | 25 | 6,400 | 31 | 0 |
| Declared event crossing | 13 | 3,080 | 13 | 1 |
| Three resource surfaces, clear | 11 | 923 | 3 | 0 |
| Three resource surfaces, one crossing | 28 | 3,435 | 16 | 1 |

The declared and resource triggers arrived at 0.0020833333333333333 s and 0.0020833333333333264 s respectively. Their analytic boundary is half a 240 Hz tick. The declared fixture continues its moving derivative through negative *trial* states as required by `app/physics/event_step.gd:1–10`; the transition projects the accepted state to zero. These checks exercise helper mechanics without an aircraft, real-world event frequency, engine callbacks or the package allocator.

Give each admitted kernel instance disjoint, pre-sized buffers for the outer substep, trial, inner root locator and captured high endpoints. Keep the input, trial, rollback snapshot and output distinct across nested calls. Reserve the event list for the already admitted family count; retain the public checked boundary and current iteration/surface budgets. Start with the declared clear-event and eight-piece paths, then resource policy. Profile retained bytes for the largest admitted dimensions before generalizing. Scratch may be dropped on reprepare; any state that affects future physics must remain in the checkpoint contract. MuJoCo documents the same separation of prepared model/data and bounded solver workspace. [MuJoCo simulation initialization](https://mujoco.readthedocs.io/en/stable/programming/simulation.html#initialization)

Fewer allocator calls and copied bytes are directly measurable. Wall-time improvement depends on aircraft, allocator and event frequency. Medium scope; high consequence for accidental aliasing on nested roots and aborted trials. Keep the independently measured RHS order, signed zeros, projections, quaternion normalization and event tie order intact.

**Acceptance**

After preparation, the scoped native helper makes zero scratch allocations for the clear one/eight cases; count publication allocations separately. Crossing cases retain or reduce total allocated bytes, with identical states, event fields, sorted times, refusal bounds and RHS counts. Add two interleaved kernel instances, malformed inputs, simultaneous events, fault-then-retry and restore in the middle of a tape. Run the existing qualified native tick driver, fleet and negative control; instrumented heap results and non-instrumented paired target traces support separate claims.

### ENG-03 — Reuse the same spatial propeller force calculation within one RK stage

**Confirmed duplicate expressions on an admitted fixed-wing route.**

With valid spatial flow, enabled wake, a non-turbine/non-glow source and usable aero, the loads and wake paths both call `prop_thrust_torque(prop_air.velocity.data(), rpm, m.prop, rho)`. If this is a transported-wake layout, the target computes the same tuple a third time. Rotation above the stopped threshold uses two table interpolations and two powers in each helper invocation. The three checked-in stock aircraft files carrying slipstream pieces include the Corsair, Extra and Mustang. The spatial oracle separately constructs a transported-wake fixture. Three calls is conditional and is not a claim that every stock flight uses wake transport. See `research/native-kernel/src/nk_stage.hpp:316–347,392–408`, `research/native-kernel/src/nk_prop.hpp:106–129`, `research/native-kernel/src/nk_kernel.cpp:864–870`, `research/native-kernel/wake_spatial_oracle.gd:34–53`.

Thread the already-calculated three-component result through those consumers for the single stage and exactly matching spatial input. Preserve independent point-vs-datum flow when not spatial, rejected sampling, glow blade elements and turbine branches. A scratch value outside that stage would conflate different poses or event trials. Preserve the independent shaft-torque law: it has different arithmetic order. A deterministic comparison of the unchanged two functions with valid finite Ct/Cp test inputs found 1,813 bit differences out of 4,096. The first torque pair was `0x1.0e3a57b6b926p+0` versus `0x1.0e3a57b6b925fp+0`. See `research/native-kernel/src/nk_prop.hpp:106–129` and `research/native-kernel/src/nk_electric_coupling.hpp:33–49`.

The eligible stage can eliminate one or two identical source evaluations, with no physical law change. Source-level counts do not establish retained machine-call counts or elapsed-time savings on the pinned compiler. Small scope; risk lies in extending the reuse to unlike inflows, rotor-stop handling or separately rounded torque. Requires a qualified spatial-wake build and reference corpus.

**Acceptance**

Count one blade thrust/torque evaluation for the shared spatial point on each eligible stage; keep distinct shaft-law evaluations. Byte-compare all six loads, derivatives, rotor momentum, previews and rejection results across static and transported wake; include displaced/tilted hubs, nonzero body rates, calm/uniform controls, spatial winds, stopped rpm, signed zeros and nonfinite inputs. Run the existing spatial component/stage oracles and target-host receipt-backed paired tapes. Retire the optimization if the maintenance cost outweighs measured stage improvement.

### ENG-04 — Prepare the ground vehicle model once and carry corner geometry through each road query

**Confirmed duplicate C++ computations in the ground evaluator.** Its session-level speedup remains unmeasured.

Each successful call constructs a fresh native model, decodes 32 required scalar fields, one optional scalar and five packed arrays, and reconstructs hull center/radius vectors. `read_model` validates the model; the native solver validates it again. The binding calculates steering acceleration and corner geometry to query the road; the solver recomputes both using the same typed state, controls and model after the batch returns. Both geometry calls are needed only on the current public implementation's route. The road callback receives coordinates and returns surface data. Wet loads and wall handling remain outside this native solve. See `research/rc-monster-truck/native/src/ground_vehicle_native.cpp:82–173,651–702`, `research/rc-monster-truck/native/src/ground_vehicle_kernel.hpp:185–239,743–792`, `app/physics/ground_vehicle/vehicle_dynamics.gd:698–759`.

First introduce a checked preparation of the *stage geometry*: pass its result and the road samples to an internal evaluation function. Keep the public stateless caller's validation. Then give production ground sessions a private prepared native model that owns the normalized static dimensions, inertia and hull arrays. Submit live controls and changed model inputs per evaluation. Nitro creates a shallow model copy with a midpoint-dependent wheel drive torque, fixed drive fade and zero reverse ratio. Its telemetry may use a different current-rate torque. Carry those as explicit typed overrides. Double-buffer a model replacement at reset; refuse stale handles or unguarded mutations before a state commit. The ground sidecar loader uses a process-local evaluator, so a single mutable global prepared model could mix two sessions. See `app/physics/ground_vehicle/nitro_dynamics.gd:119–132,162,224–231`, `app/physics/ground_vehicle/vehicle_dynamics.gd:87–101,198–229`.

The first slice removes a geometry build per valid native stage. The second removes repeated static decoding and validations after independently checking ownership. Medium effort, with greater risk in the prepared-handle API than in the internal geometry-only change. Preserve road callback order, exact query coordinates, response validation, per-call rejection behavior, and water/wall inputs. Ground is a separate ABI/receipt and cannot borrow the aircraft kernel's build evidence.

**Acceptance**

Per valid evaluator call, instrument one corner-geometry solve; after configuration/restore, verify one static decode per owned model epoch. Native A/B outputs and error behavior must match on the same pinned binary/toolchain, including legacy missing brake split, model replacement, simultaneous sessions, electric/Nitro, wet/wall, bumps, nonfinite and malformed road input. Retain the ground reference harness's own numerical tolerance for force channels (absolute 2e-8 plus relative 2e-10), bitwise lake sampling gates and exact same-backend replay. Require Linux and Windows ground-sidecar runs, then profile representative driving and standstill separately. See `research/rc-monster-truck/native/parity_harness.gd:10–11,551–599,671`.

## Guard correction on this baseline

Commit `5f4dbda4` revised the configuration and weather fast-plan builders before the audited tip. Each applicable root receives its own 1,048,576 path-node budget, with dictionary keys included. A refused fast plan keeps the full watch walk; it does not automatically reject an otherwise valid configuration. The configuration capture memoizes completed container pairs including depth and preserves parent-edge/identity checks. Weather capture has its own 65,536-watch and depth-32 caps. The fixed-wing freeze path still watches mutable packed leaves. See `research/native-kernel/src/nk_guard_plan.hpp:83–111,138–144`, `research/native-kernel/src/nk_configuration_guard.hpp:223–242,269–277,335–397,458–473`, `research/native-kernel/src/nk_weather_guard.hpp:55–56,168–183,257–310,405–408`, `research/native-kernel/test_native_admission.gd:340–389`.

The checked-in alternating 24-level doubly referenced test has 16,777,216 paths to its leaf. Counting every container/scalar and dictionary key by the current recurrence gives 78,293,673 nodes for a *complete expansion* of its synthetic root. The preflight stops after the 1,048,577th attempted node at the latest for that root. These are algorithm counts, not measured current admission time, allocations, or player workload. The cap is per root and applies to the fast-plan decision. Memoized capture, full watches, owner checks and coverage outside that function should be profiled separately if preparation is slow. Existing tests already exercise shared mutations, rewired edges, deep aliases and cycles. The previous unbounded-expansion claim is superseded for this path.

## Primary engineering sources

- GCC documents the floating-point contraction control and the semantic changes enabled by fast math. Compiler flags alone cannot establish agreement with a particular engine's library functions and NaN/signed-zero rules. OpenRC's scalar shim also fixes operand ordering, literals and selected platform math. [GCC 13.3 optimization options](https://gcc.gnu.org/onlinedocs/gcc-13.3.0/gcc/Optimize-Options.html), `research/native-kernel/src/nk_math.hpp:1–29,41–115`.
- MuJoCo's maintainers describe allocating intermediate working state up front and bounding its memory. This is precedent for separating model ownership from scratch sizing; OpenRC's event and refusal contracts still define its implementation. [MuJoCo simulation initialization](https://mujoco.readthedocs.io/en/stable/programming/simulation.html#initialization)
- Box2D's author details ordering, target floating-point flags and math functions in cross-platform determinism. This supports platform-specific replay checks for a refactor and reproducible operation order. [Erin Catto, Determinism](https://box2d.org/posts/2024/08/determinism/)
- LLNL's SUNDIALS guidance explains why event functions can require sampling on both sides of a discontinuity. It supports preserving the moving-side continuation and checking actual crossings against analytic fixtures. [SUNDIALS usage notes](https://computing.llnl.gov/projects/sundials/usage-notes)
- Perfetto documents native call-stack and performance-counter sampling on Linux, including how to distinguish instruction/cycle counts from time spent descheduled. These measurements can attribute a gain to event bookkeeping, stage arithmetic or host overhead. [Perfetto CPU profiling](https://perfetto.dev/docs/quickstart/callstack-sampling)
