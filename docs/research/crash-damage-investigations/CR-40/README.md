## Money, choices and persistence

Incident completeness is separate from whole-build coverage. An unrelated missing price cannot poison a resolved local quote; an affected missing price stays unknown. Prices use integer minor units. Existing offer dates and sources remain frozen; unmatched products and foreign currencies are not silently adopted. Unquoted groups use explicit dated USD game allowances. Tax, shipping and recovery are excluded unless supplied by an explicit supported transaction; DIY time is unbilled.

The normal report offers DIY/shop labor and frozen purchase alternatives. Recommended plans search the declared bounded candidate set, including repeated packages, pairs, overlap and unvalued surplus. An explicit package choice means one selected package plus individually priced remaining parts; the UI states that scope. Shared setup is added once, material cash and consumption remain distinct, applicable incurred fees reconcile once, and low/high price bounds remain visible. Shop rates and work durations are authored game policies, not repair-shop quotations. Search limits and missing alternatives cannot claim a global minimum.

`openrc-cost-transaction v1` binds requests and replayable receipts to incident, assessment revision, source, profile, prices, recipes, purchase book and labor policy. The current automatic plan is an estimate, not realized spending. Explicit transactions/fees retain immutable history; explicit UI selections have a bounded rolling quote history with truncation disclosed. Automatic frame-time recalculations retain current state rather than manufacturing cadence-dependent purchase history. Selected recipes are available through the validated transaction/inspection APIs; there is no normal-report recipe chooser or persistent wallet/spares inventory.

Economics checkpoint v3 validates before commit and freezes the books, receipts, modes, choices, summaries and proof. Older paired v1/v2 ledgers are explicitly refused; historical report archives stay view-only. New saved reports use a closed `openrc-accident-report-archive v1` envelope around the v2 report. It retains the active automatic receipt even without a player selection, plus frozen cost-context hashes. Exact payload, request and receipt bytes are checked before presenting current data; selected lines, carried fees, grouped work and derivable complete-plan price bounds reconcile without loading today's catalog. The byte checks detect inconsistency, not authorship, seller accuracy or physical validity. Historical raw v1/v2 reports remain bounded, view-only and visibly unverified. A corrupt saved file is preserved, leaves the last accepted in-memory report intact and shows a passive notice without blocking flight. Previously archived copies do not change when later evidence or catalog files change. Restart creates a fresh ledger, and physics-only restore retains unknown earlier damage history. Reopening the report or selecting the current option never rebills it. Stale explicit selections require review and offer recovery to the recommended plan.

## Authoring and regeneration

The authoritative source is [cost-profiles.json](../../../../research/crash-economics/cost-profiles.json). Its [generator](../../../../research/crash-economics/build_profiles.py), [v3 schema](../../../../app/data/schema/openrc-cost-profiles-v3.schema.json) and runtime `cost_profile.gd` enforce separate contracts. The root is `openrc-cost-profiles v3`, the normalized damage policy is `openrc-game-damage-profile v2` / `local-contact-v2`, and the financial dossier remains `openrc-aircraft-economics v2`. Historical v1 readers and v2 profile schema are preserved; generated files are not hand-edited.

1. Declare every installed financial group, quantity, physical parent, price basis and provenance. Shared parents require a reviewed exact child crosswalk. Do not also charge the old inclusive allocation or add physical mass to itemize a bill.
2. Declare qualified source/probe mappings, construction class and supported channels. Multiple targets require complete independent responses; repair bands require explicit per-target service cash. Declare every propeller follow-up and preserve unknown grouped failed counts.
3. Author sold package quantities, eligibility and source separately from installed quantities. State assumed game availability separately from observed merchant stock/fit. Labor must cover every financial row with a declared rate, duration, one shared setup and evidence.
4. Pin exact reviewed base/registered-pack byte hashes. Source/geometry drift is refused even if IDs match. Review the crosswalk before updating a pin. Arbitrary Workshop sources cannot inherit stock estimates. Preserve legacy catalog, companion-source and generator digests; historical reports keep their own prices.
5. Run `python research/crash-economics/build_runtime.py`; `--check` checks both the closed v1 artifacts and companion. Run affected authoring, profile, incident, transaction, fleet and report checks through the checked runner. A new fixed-wing catalog route requires its own profile.

Runtime bounds include a 1 MiB profile document, 128 financial rows, 256 zones, 64 events/64 KiB per accepted batch, a 128-entry/64 KiB diagnostic journal, 128 recent proofs/open contacts, 16 inspections and a 256 KiB report payload. The escaped archive envelope is bounded to 526,336 bytes, with 384 line items, 512 text entries, depth 24 and a finite node budget. Quote/transaction/package search and checkpoint readers have separate explicit bounds and fail without inventing a price. There is no network lookup in the game assessment path.
