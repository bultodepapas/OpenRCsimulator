# D6 / UI-15: radio calibration setup patterns

2026-11-03 · Research snapshot for the [controller support track](../../plans/controller-support.md). Scope: four established controller setup flows and their usefulness for preventing a wrong axis assignment or a radio throttle reading 50% at LOW. The table describes documented behavior or inspected source; its applicability column is an inference for OpenRC. No products or physical radios were operated for this research. Sources without a stated version or publication date are identified as such and were accessed on 2026-11-03.

## Differences and limits

RealFlight's center-throttle calibration and Mission Planner's throttle-down final prompt serve different procedures; neither establishes a universal neutral position. QGroundControl also documents center-zero and full-down-zero joystick behavior. Betaflight and Mission Planner discuss receiver/channel values, while OpenRC receives OS joystick axes; their channel numbers, pulse widths and pitch sign must not be transplanted directly. Transmitter mixes can cause multiple outputs to move together; RealFlight's manual cautions that radio mixing can overlap simulator mixing. A user-visible preview cannot by itself establish which physical stick the pilot meant to move.

The inspected OpenRC worktree already has a per-function sweep, distinct-axis/competing-axis checks, a LOW return check, and a draft calibration result with a live throttle percentage ([calibration](../../../app/input/rc_calibration.gd), [setup](../../../app/ui/radio_calibration_setup.gd), [controller preview](../../../app/ui/controller_setup.gd)). These observations include uncommitted work and are not hardware qualification. The [first-launch guide](../../FIRST-LAUNCH.md#radio-setup) and [fresh-throttle evidence](D6b-R2/README.md) retain the actual use and arming contracts.

The current candidate adds the separate FULL → LOW verification in recommendation 1 and a readable named draft preview for recommendation 3. The mode-aware diagram in recommendation 2 remains a design option; it is not needed for the current per-function text prompts.

## Prioritized recommendations

1. **P1 — Verify physical throttle across its travel.** In the draft review, ask the pilot to move the *throttle stick* LOW → FULL → LOW while watching the named throttle percentage and identified axis; expect approximately 0% at LOW and 100% at FULL. Offer retry if it does not respond as expected. Keep the existing LOW gate and fresh post-save arming evidence: a stationary wrong axis can also display 0%, so LOW alone is insufficient confirmation.
2. **P1 — Make each assignment unambiguous.** Keep one function at a time and the requested first direction, with text such as “move only throttle” and clear Next/return instructions. Add a mode-aware stick diagram if desired, with a selectable mode and text equivalent; do not assume its mode sets channel order. Surface which axis moved and retain actionable feedback for multiple moving axes, an already assigned axis, insufficient travel and a mix.
3. **P2 — Review the whole mapping before Save.** Show roll, pitch, yaw and throttle as live named outputs with their axis numbers and directions, so the pilot can move each intended stick and spot an unexpected response. Label these as draft values and keep the explicit Use calibration → Save sequence; neither a successful preview nor software tests close physical-radio acceptance.
