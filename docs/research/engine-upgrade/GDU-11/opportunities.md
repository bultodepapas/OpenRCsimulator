# Further Godot 4.8 opportunities for OpenRC

Research checked **2026-10-25** against the official release archive, 4.8 development/beta notes, merged changes and source pinned to `4d10419cacd6d3009976e8f9fd3abd970fd58018`. Latest published 4.8 remains **beta1**, dated 2026-10-15; this is also the project's standard engine. [Official archive](https://godotengine.org/download/archive/), [beta1 overview](https://godotengine.org/article/dev-snapshot-godot-4-8-beta-1/).

Repository inspection: HEAD `72fafe9591b9a0ae0f9b9e3c737ec1ab6d556712`, with concurrent staged ground-physics/crash changes. This investigation changed documentation only: no renderer switch, engine update, imports, performance measurements or runtime feature activation. Context7 returned no version-specific 4.8 library and an unrelated result for FuzzySearch; pinned official source was used for the API claims below.

Standard uses Compatibility; the existing optional High profile uses Forward+ and already enables SSAO, four shadow cascades, an 8192 shadow atlas and PCSS. See [High implementation](../../../../app/render/high_graphics_profile.gd) and [current qualification limits](../../../../tools/graphics/README.md). [Maple coverage preservation](README.md) is already implemented and measured; the following items distinguish additional opt-in work from improvements inherited through the engine upgrade.

Implementation status and acceptance evidence are now maintained in [the incremental implementation record](implementation.md). The proposals below retain the research-time baseline.

## Recommended next experiments

Order reflects concrete product gaps, existing integration points and bounded verification, not measured speedups. All visual acceptance starts at actual 1920×1080, then higher resolutions; 720p cannot qualify the primary target.

| Priority / step | Benefit and integration point | Availability / acceptance |
| --- | --- | --- |
| 1 — GDU-11e, UI | **Find saved builds despite typing errors or reordered words.** Workshop currently applies a contiguous lowercase substring to build name + base-aircraft name in `_refresh_variants()` | New native `FuzzySearch`, all renderers. Preserve stable IDs, favorites, empty-query ordering and current selection; verify duplicate names, accented text, reordered words, typos and no-match cases |
| 2 — GDU-11f, UI | **Keep long aircraft/build titles readable.** Workshop's title and build identity currently use single-line ellipses; Home also displays translated names | Native bounded font fitting, all renderers. Prototype a bounded subset with a plane fallback; test slopes, 9/16 simultaneous marks, primary scorch persistence and reset |

### Exact APIs and implementation constraints

**Saved-build search.** [`app/ui/workshop.gd`](../../../../app/ui/workshop.gd), `_refresh_variants()`, is a demonstrated integration point. `FuzzySearch.search_all(query, PackedStringArray)` returns ranked `FuzzySearchMatch` objects. Defaults include `max_results=100`, `max_misses=2` and score filtering: explicitly account for large libraries and low-scoring valid matches. Maintain a separate ID mapping so duplicate display names cannot select the wrong build. The API is marked experimental, so isolate it behind the library's search helper and pin its behavior with meaningful cases. [Pinned FuzzySearch API](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/FuzzySearch.xml), [implementation PR107126](https://github.com/godotengine/godot/pull/107126). Reuse the existing Workshop UI/library tests and debug-bridge navigation flow.

**Text fitting.** Exact beta1 `Label` properties are `resize_font_to_fit`, `minimum_font_size`, `maximum_font_size`; `get_rendered_font_size()` permits a readability assertion. The release article's `auto_font_size` / `min_font_size` / `max_font_size` names are stale. Apply only to constrained titles first, not flight telemetry. Existing `test_ui_scale.gd` protects 22/26 logical-pixel compact/desktop body sizes and 200% scaling; fitting must respect those accessibility choices. [Pinned Label API](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/Label.xml), [PR116791](https://github.com/godotengine/godot/pull/116791).

**Decals.** The [existing GDU-11 analysis](README.md#other-48-candidates-reviewed) records the eight-per-receiver constraint and the stale `Decal.xml` support statement. [PR118070](https://github.com/godotengine/godot/pull/118070) and the pinned GLES3 implementation establish support. `app/render/crash/effects.gd` is currently being changed by another track; integrate with that accepted contact/presentation behavior rather than replacing it from an old snapshot. Animated decals also exist ([PR115653](https://github.com/godotengine/godot/pull/115653)), but no current requirement justifies adding animation to stationary scorch marks.

**Contact shadows.** Configure `rendering/lights_and_shadows/contact_shadow/enabled` and use a shadow-enabled directional light with `shadow_contact_shadows_allow=true`. Tune `shadow_length`, `surface_thickness` and light `shadow_contact_shadows_blur`. The original PR's separate opacity property was removed before beta1; use the existing `shadow_opacity`. Only visible screen geometry contributes, and thin surfaces can cause bleeding. Do not replace projected/contact-shadow fallbacks or reduce the atlas in the same first experiment. [Pinned settings](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/ProjectSettings.xml#L3176), [PR118045](https://github.com/godotengine/godot/pull/118045), [opacity removal](https://github.com/godotengine/godot/pull/123814). Reuse `tools/shadows/`, the High shadow-energy oracle and [frame diagnosis](../../../tools/graphics.md#frame-diagnosis).

**Multi-bounce AO.** `rendering/lights_and_shadows/multi_bounce_occlusion/enabled=true` is a renderer-startup experiment; changing the project setting after renderer initialization is not proof that the effect became active. Keep it within a separately launched High candidate and preserve Standard. This approximates local reflected color rather than computing full indirect illumination. [Pinned setting](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/ProjectSettings.xml#L3205), [PR115426](https://github.com/godotengine/godot/pull/115426). Compare matched material/aircraft/pilot-station captures and GPU timing with every other setting fixed.

## Conditional benefits and exclusions

- **Texture streaming:** useful for a measured memory bottleneck in High/Forward+ or Mobile; unsupported by Compatibility. The project must select the streamed importer as well as configure the budget. Camera cuts, aircraft swaps and cold-cache traversal need hitch/residency tests. It remains GDU-11d, not a reason by itself to change the default renderer. [Pinned implementation](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/modules/texture_streaming/texture_streaming.cpp#L279).
- **ASTC 6×6 and compression profiles:** potentially useful for the existing Apple Silicon/memory investigation once a native ASTC-capable path is established. `compress/high_quality_mode` affects only ASTC, not current S3TC/BC7 assets. Compare memory, normal maps, paint and alpha-tested leaves on the target; do not bulk-recompress the library. [Pinned importer](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/ResourceImporterTexture.xml#L25), [PR115003](https://github.com/godotengine/godot/pull/115003). Owner DT-MAC/VQ; GDU-11j.
- **Theme sounds:** `Theme.set_sound`, `Control.add_theme_sound_override` and `Control.play_theme_sound` could simplify selected controls. Existing `ui/menu_audio.gd` already supplies two bounded voices, priorities, duplicate suppression, mute and shutdown retirement. A replacement must retain those guarantees and pass `test_menu_audio.gd`; it is not an engine/thunder audio scheduling API. Defer absent a demonstrated maintenance benefit. [PR111455](https://github.com/godotengine/godot/pull/111455), [beta1 API follow-up](https://github.com/godotengine/godot/pull/123867).
- **Editor productivity:** floating main docks, live CanvasItem manipulation, glob file search, focused diagnostic underlines and experimental symbol rename can shorten authoring/debugging. Use existing debug-bridge and layout tests as the runtime authority; do not mass-rename stable aircraft nodes, generated identifiers or string-bound contracts. [Live CanvasItem changes](https://github.com/godotengine/godot/pull/122510), [symbol rename](https://github.com/godotengine/godot/pull/117949), [glob search](https://github.com/godotengine/godot/pull/119103).
- **macOS architecture-specific packages:** the new architecture selector enables a smaller engine payload than universal when delivering only arm64 or x86_64. Current project export remains universal; compare actual archive sizes and package validation before adding a delivery variant. This does not imply faster simulation or replace the beta1 template checks. [PR119708](https://github.com/godotengine/godot/pull/119708).
- **Trail3D, lightmaps and engine physics queries:** native ribbons do not supply smoke advection/buoyancy/presentation-time contracts. No current LightmapGI integration was found, and the moving sun makes a blanket directional-light bake unsuitable. Production does not currently call the new nonallocating `PhysicsDirectSpaceState` queries; they cannot accelerate the separate float64 flight kernel. Reconsider only for an actual rendering/tool query bottleneck. [Trail3D](https://github.com/godotengine/godot/pull/117107), [directional lightmap specular](https://github.com/godotengine/godot/pull/109737), [query APIs](https://github.com/godotengine/godot/pull/113970).
- **Defaults intentionally preserved:** `gui/common/auto_focus_strategy=0` and `input_devices/joypads/ignore_joypad_on_unfocused_application=false` are explicit project settings. New-project defaults do not change the simulator's accepted keyboard/radio policy.
- **Not new stock DLSS/FSR3:** pinned official `Viewport` exposes FSR/FSR2 and MetalFX modes, not the separate experimental fork's DLSS/FSR3 providers. [Pinned enum](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/Viewport.xml), [existing native integration](../../../../tools/graphics/native/README.md). FSR2/MetalFX are not newly invented by this migration.
- **Avoid misleading performance headlines:** the [September CPU optimization article](https://godotengine.org/article/rendering-cpu-optimizations/) discusses Polygon2D work already merged before the 4.8 changeset; OpenRC has no matching Polygon2D workload. Compatibility SSAO also predates 4.8. Embedded shader compression [PR124058](https://github.com/godotengine/godot/pull/124058) can shrink uncompressed engine binaries without shrinking ZIP downloads. None establishes an OpenRC FPS multiplier.

The next small implementation should be the saved-build search, followed by bounded title fitting. The next Standard graphics prototype is terrain-following decals; the next High comparison is one of contact shadows or multi-bounce AO, independently. Preserve the completed maple evidence and keep broad platform/release qualification open.
