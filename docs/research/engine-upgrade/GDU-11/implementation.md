# Incremental implementation of further 4.8 features

Official engine: `4.8.beta1.official.4d10419ca`. Work began 2026-10-25. Feature/API rationale and primary references remain in [opportunities](opportunities.md). Raw logs and captures are outside Git at `D:/OpenRCsimulator-experiments/gdu11-implementation/`.

## GDU-11e — Workshop search

Implemented through `workshop/library_search.gd`. Exact substring matches remain first in library order, followed by score-ranked fuzzy matches; ties use original indices. Duplicate names never serve as identity keys. Empty queries preserve ordering. Spanish composed/decomposed accents normalize only for matching. The result cap follows the eligible library size rather than Godot's default 100. Favorites are filtered before ranking; unavailable favorites retain their disabled load/copy actions and removable metadata.

Verification: `test_workshop_search.gd` passed 13 cases (including duplicate names, reordered words, typos, accents, no matches, short queries and 150 exact/fuzzy matches). `test_workshop_reuse.gd` passed the actual save/favorite/search/selection/profile-copy/deletion flow, including three approximate queries without draft mutation. `test_workshop_ui.gd` passed its full existing UI flow before the next change. These are software behavior checks, not loading-time benchmarks.

## GDU-11f — Bounded title fitting

Implemented for the Workshop heading and current build identity. Home retains its existing wrapping policy. Bounds use scaled theme tokens explicitly: Control theme lookup prioritizes the control's variation even when requesting the base type, which would otherwise make the bounds equal. A fixed preferred line height prevents a VBox from forcing every short title down to the minimum. The build identity retains its full-name tooltip and ellipsis fallback.

Verification: `test_ui_title_fit.gd` passed short, intermediate and overlong text at 100%/200%, bounded overflow and layout convergence; `test_ui_scale.gd` and the complete `test_workshop_ui.gd` passed. Native RTX 3090/Compatibility bridge session `20261025-161637-49185` captured actual 1920×1080 English and Spanish Workshop screens, including a maximum-length build name and 200% text. The enlarged build identity rendered at its 44-pixel minimum within its 44–56 range; the normal heading/build identity remained 28 pixels where space allowed. Captures were inspected for readable text, visible actions and bounded overflow. This is layout evidence on this host, not broad accessibility/hardware qualification.

## GDU-11b — Terrain crash marks

Implemented eight native decals plus eight retained plane slots, with a world-wide eight-decal reservation for crash owners. Headless/older engines and exhausted pools retain planes; an invalid terrain sample also selects the finite legacy plane. Slot zero remains the primary scorch throughout recycling. The fixed-wing director provides the accepted terrain sampler read-only; both representations align to its normal. Ground and lake basin join render bit 17; aircraft/wreck geometry does not. No physical contact, damage, fuel or simulation state is changed. The existing smoke texture supplies the mark mask; no new asset was generated.

The optional lake mirror excludes the new receiver bit as well as the original basin bits, while ordinary terrain remains visible through layer 1. Its regression uses a full-mask main camera and checks that the basin still receives decals without entering the mirror. Crash shader warmup draws a disposable decal against the production ground material in its own world, preserving live pools/seeds.

Verification: `test_ground_marks.gd` passed headless and native RTX 3090/Compatibility controls at actual 1920×1080. All sixteen marks visibly reach a single tilted receiver, including a run with the production ground shader; layer-mask negative controls remove all eight projected marks, and camera motion retains all sixteen. Tests cover ninth-mark fallback, two-owner budget, primary persistence, invalid samples and reset. `test_crash_effects.gd` passed 66 checks, `test_crash_energy.gd` 225, native warmup 18, and `test_crash_integration.gd` 202 each headless/native across the fixed-wing fleet. `test_lake_planar_reflection.gd` passed 75 checks after the layer correction. Native fleet audio used Dummy; this does not establish playback quality. Captures: external `decals/slope/` and `decals/production-material/`.

## GDU-11g — High contact-shadow experiment

Implemented as an explicit native High experiment: `OPENRC_CONTACT_SHADOWS=on`. High keeps it **off by default** because beta1 failed the production visual gate. Invalid/unset requests and Standard retain the accepted ordinary shadows. The experiment uses Short rays, thickness 0.01 and blur 0; atlas, cascades, sun energy, opacity and SSAO remain unchanged. This is functional integration with a safe default, **not accepted default visual adoption**.

Paired six-view 1080p captures exposed new stipple/banding on pavilion walls and floor with the default Medium/blur-1 settings. Blur 0 removed stochastic blur but retained bands. Thickness 0.001/0.0001 reduced them; 0.00001 also removed the measured contact contribution (zero darkened oracle samples), so that apparent cure was rejected. Short rays still left wall artifacts. Pinned beta1 has no separate receiver bias/normal rejection in the contact compute pass; retuning ordinary shadow maps would not resolve this pass. [Pinned sampling code](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/servers/rendering/renderer_rd/shaders/effects/screen_space_contact_shadows.glsl#L191).

The final experiment passed 87 native profile checks, including explicit opt-in, malformed requests, Standard isolation and reconfiguration back to the safe default. The native 1080p contact oracle detected 198 darkened samples with Short/0.01/blur-0, retained an offscreen caster's ordinary shadow (luminance 0.196 off/on versus 0.604 unshadowed), and preserved clear sunlight. These functional checks do not override the failed visual gate. The earlier shadow-energy oracle passed with zero sampled channel difference. Full-scene capture logs retain the existing seven-Texture-RID ReflectionProbe warning in both treatments.

The initial Medium/0.01/blur-1 experiment had eight alternating static flightline timing runs, each with 10 s warmup and 5 s sampling. Median GPU times: 1080p off 2.170/2.276 ms, on 2.305/2.311 ms; 1440p off 3.193/3.227 ms, on 3.398/3.237 ms. These measure the rejected initial candidate, not the final Short experiment or flight FPS. Raw images, settings receipts and controls remain under external `contact/`. Broad motion/screen-edge acceptance and default activation remain open for an engine fix or a demonstrably cleaner candidate.

## GDU-11h — Forward+ multi-bounce occlusion

Enabled `rendering/lights_and_shadows/multi_bounce_occlusion/enabled` in `project.godot`, before renderer initialization. Product High selects Forward+; Compatibility and Mobile ignore this option. A bare technical Forward+ launch also inherits it, even without the High environment flag. No shared override-file rewriting or late GDScript toggle is used. Existing SSAO radius/intensity/power/detail, direct-light influence, exposure, materials and shadow maps are unchanged. This is a local albedo-aware ambient-occlusion approximation, not full GI. [Pinned setting](https://github.com/godotengine/godot/blob/4d10419cacd6d3009976e8f9fd3abd970fd58018/doc/classes/ProjectSettings.xml#L3205).

Frozen copies contain 5,011 files after serial imports and differ only in that startup Boolean. Six production views per treatment/profile were captured in fresh processes at actual 1920×1080, with contact shadows off. High shows restrained ambient brightening around benches and pavilion joints: maximum RGB changes are +11/255 in pavilion and +15/255 in windsock. No pixel darkens by more than 1/255. Aircraft-ground peaks at +4/255, so these views do not demonstrate a substantial gear-recess improvement. Independent still review found no new striping, altered shadow shape, silhouette/horizon loss or water regression.

Standard's aircraft-ground, flightline, pavilion and windsock images are pixel-identical. Pilot differs at two pixels and lake at 786 pixels, all by at most 1/255. Repeating the unchanged Standard baseline produces 945 one-level lake differences and 28 flightline differences (seven above one level, maximum four), confirming small native run variation without changing this option. Do not describe the complete Standard set as byte-identical. These are bounded still comparisons, not motion, full platform or hardware qualification. Raw controls are under external `ao/`.

The real Home restart probe passed Standard → High → Standard in three native processes at 1920×1080 with preferences unchanged. All three retain the startup option in configuration; only Forward+ consumes it. Contact shadows remain off in all three default-profile receipts. The editor-binary path was exercised; this is not packaged-release relaunch proof.

Eight alternating off/on/on/off static flightline runs (10 s warmup, 5 s sampling each) measured median GPU times on RTX 3090: 1080p off 2.195/2.246 ms, on 2.198/2.173 ms; 1440p off 3.375/3.406 ms, on 3.406/3.387 ms. No incremental cost is resolved above the observed run variation, and no FPS gain is claimed. Samples and report hashes are retained in [the compact comparison](implementation-evidence/ao-comparison.json); these are offscreen diagnostics, not full-flight performance qualification. Final native High profile checks passed 87/87, and the existing unoccluded shadow-energy oracle again measured zero sampled channel difference. The known seven-Texture-RID warning remains in both full-scene High treatments.
