### UI-FS-03 unresolved stale writer-lock recovery

A valid JSON lock PID is parsed as a float, but acquisition accepts only `TYPE_INT`; both a live owner and a known exited child owner are therefore classified as malformed/read-only. Correcting that check alone is unsafe: the pinned Linux engine's `OS.is_process_running()` rejects non-child PIDs, so it cannot prove that an independent app has exited. This agrees with the [engine API's child-process contract](https://docs.godotengine.org/en/stable/classes/class_os.html#class-os-method-is-process-running). Reproductions are retained in `state/lock_repro.gd` and `state/pid_probe.gd` below the local evidence directory. No store/lock implementation changes were retained. A follow-up needs validated numeric PIDs, trustworthy process/namespace identity, live-owner and concurrent-reclaim tests, and conservative handling of legacy ambiguity and unsupported platforms. The current read-only protection remains in place; crash recovery of statistics is not qualified.
