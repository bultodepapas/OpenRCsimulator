# Telemetry operations audit — 2026-11-22

Source reviewed: [`7940a4081e10994f34c858c4acac3d7a1a271464`](https://github.com/bultodepapas/OpenRCsimulator/tree/7940a4081e10994f34c858c4acac3d7a1a271464), the parent of the audit-only branch. Findings are inherited source behavior, not changes introduced by this audit. The checks below use synthetic input and do not contact the deployed receiver, GitHub, Google, or any production host. In particular, they do not establish the current deployment's timezone, credential permissions, backup contents, alert routing, or health.

The operational path reviewed is receiver snapshot → host inbox → scheduled dashboard build → private HTML and health report → independent monitor, plus GitHub history collection and backup, GA4 collection, firewall/timers and release CI. The local flight HUD also uses the word telemetry, but it is a separate display path; its bounded review belongs to the client and HUD report. Existing [19 November](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/research/telemetry/TELEM-AUDIT-2026-11-19/README.md) and [21 November](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/research/telemetry/TELEM-AUDIT-2026-11-21/README.md) audits are historical observations, not proof that current production still has the same state.

## TA22-O01 — High: actionable receiver warnings do not reach the independent health check

**Trigger and impact.** The dashboard creates warnings for an overdue daily rollup, raw rows approaching the 48-hour limit, unapproved releases, rate limiting and 24-hour ingestion silence. Its machine-readable report copies only alerts marked `critical`; if GitHub and website sources are healthy, those warnings leave overall status `ok`. The external checker therefore reports success while operators may still have time to recover an overdue rollup, and while admission or rate-limit problems may be preventing intended collection. The human-facing page does show the warnings, so the failure concerns the independent automated health path.

**Evidence.** [Dashboard warning generation](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/dashboard.py#L257-L298); [only critical alerts are selected for health](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/dashboard.py#L2179-L2206); [independent checker evaluates that report](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/check_dashboard_health.py#L23-L45). The [deployment guide](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/README.md#L52-L56) accurately describes the current report as carrying critical receiver alerts; it does not claim that warnings are propagated.

**Offline evidence.** At synthetic 2026-11-21 12:00 UTC, the fixture supplied an accepted previous day with no rollup, a 47-hour oldest logical raw row, four rejected unapproved-release batches and three rate-limited batches. All other sources and timestamps were healthy. The result included four warning titles and an 11-hour recovery window, while machine health reported `health_status: "ok"`, `receiver_issues: []`, and `monitor_failure: null`. [Captured result](../../../../research/telemetry/audit-2026-11-22/evidence/python-probes.json).

**Expected behavior and acceptance.** Include actionable receiver warning categories and their severity in the machine-readable report; define which ones cause the external check or a separate alert to fail, with a notification owner. Test the full report-to-check path for every category, including a rollup early enough to recover before its deadline, and rehearse actual delivery separately. The 19 November audit identified release, proxy and rollup risks; its later mitigations added visibility and manual checks. The 21 November observation found no receiver issues at that moment, but did not qualify delivered warnings. The current [plan](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry.md#L129-L131) already leaves alert delivery open.

## TA22-O02 — Medium, conditional: GA4 OAuth login can write a world-readable refresh token

**Trigger and impact.** The local OAuth login creates its output directory and writes an `authorized_user` JSON file containing a refresh token and client secret without specifying restrictive permissions. Under a POSIX `022` umask, the file is created as `0644` and a newly created parent as `0755`. If all ancestor directories also permit traversal, another local user can read the file and use its analytics read-only grant. The outcome depends on the local umask and ancestor ACLs; Windows ACL behavior and production credential permissions were not inspected.

**Evidence.** [OAuth login and credential write](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/ga4.py#L510-L574); the [setup guide](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/README.md#L58-L67) tells the operator to store it outside the repository but does not enforce private filesystem access.

**Offline reproduction.** With `OPENRC_AUDIT_TMP` set to a disposable directory, [`ga4_credential_permissions_probe.py`](../../../../research/telemetry/audit-2026-11-22/evidence/python-probes.json) substitutes a fake browser, loopback server and token exchange, uses only synthetic credentials and runs with `umask(022)`. It reports `new configuration directory mode: 0755` and `credential file mode: 0644`. The temporary enclosing directory is private; the output demonstrates the modes, not an actual disclosure.

**Expected behavior and acceptance.** Create or replace the secret with owner-only permissions from the moment it is written, and handle an existing target's permissions and applicable platform ACLs explicitly. Add a POSIX test under umask `022` that checks the resulting mode and a separate platform-appropriate permissions test. Neither prior telemetry audit established this particular local-file permission condition.

## TA22-O03 — Medium: backup validation can accept an archive the dashboard cannot restore

**Trigger and impact.** The off-host verifier checks SQLite physical integrity, schema version, four table names and a nonempty observations table. It does not establish the columns, archive identity or restorable content needed by the consumer. A structurally incomplete but SQLite-valid file can be kept as a validated backup and only fail when needed. The container-side backup check is less strict. Existing backups are retained after an ordinary failed transfer, but that does not protect against a malformed archive that passes these checks.

**Evidence.** [Container backup and checks](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/ct/backup_archive.py#L17-L40); [off-host validator](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc_stats_backup.py#L32-L46); [actual dashboard loader](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/github_archive.py#L153-L175). The backup test's [synthetic archive schema](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/test_openrc_stats_backup.py#L34-L45) itself omits required consumer columns. The deployment guide calls for a [disposable restore exercise](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/README.md#L78-L82).

**Offline evidence.** The backup validator accepted a temporary database with version 2, four required table names and one observation. The dashboard archive reader failed on the same file with `OperationalError: no such column: asset_glob`. [Captured result](../../../../research/telemetry/audit-2026-11-22/evidence/python-probes.json).

**Expected behavior and acceptance.** Validate the expected repository/pattern, supported schema and required consumer queries, then restore a disposable copy through the same reader and compare representative observations and timestamps. Include a physically valid, structurally incomplete archive and a wrong-identity archive as rejection cases. The independent GitHub backup pipeline was added after the historical 21 November observation; the current plan separately leaves archive restore proof open.

## TA22-O04 — Medium, conditional: local-time backup can run after the UTC export and pull

**Trigger and impact.** The dashboard container's daily backup timer has no timezone suffix and thus follows its local timezone. The exporter and independent pull timers specify UTC and demand a file named for the current UTC date. On a container configured for UTC−05, the 02:55 UTC export and 03:15 UTC pull happen before that day's container backup at 07:40 UTC. The earlier attempts fail instead of copying the previous day. Both transfer services retry after failure every 15 minutes, so they can recover after the container backup appears; until then there is no new off-host copy. An actual deployment failure depends on the container timezone and service state, neither of which was inspected here.

**Evidence.** [Container 02:40 timer](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/ct/openrc-stats-backup.timer#L4-L6); [host 02:55 UTC export timer](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc-stats-backup-export.timer#L4-L6); [second-host 03:15 UTC pull timer](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc-stats-backup-pull.timer#L4-L6); [UTC filename and today's-only handoff](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc_stats_backup.py#L24-L29) and [export, serve and pull](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc_stats_backup.py#L79-L109). Retry settings are in the [export service](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc-stats-backup-export.service#L11-L15) and [pull service](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc-stats-backup-pull.service#L16-L23).

**Offline reproduction.** With `TZ=America/Bogota`, `systemd-analyze calendar --base-time='2026-11-22 02:00:00 UTC' '*-*-* 02:40:00' --iterations=1` reports the next container event as `2026-11-22 07:40:00 UTC`; the same command for `*-*-* 02:55:00 UTC` reports `2026-11-22 02:55:00 UTC`. No system units were installed or started.

**Expected behavior and acceptance.** Specify a shared timezone or explicitly order the stages by successful completion, retaining bounded retries and previous copies. Check calendar expressions under UTC and non-UTC container settings, and rehearse a missed container backup, delayed export and later successful recovery. Record the actual deployed timezone and a dated second-host restore receipt; the earlier audits do not establish either for this pipeline.

## Separate local ground-vehicle recording

The garage's **Record telemetry** action starts a local recording of vehicle controls, simulation state and physical channels. This recording is separate from opt-in product batch transmission. It has [a 600-simulated-second limit and a separate sample cap](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L19-L26), with accepted samples and assisted recovery events retained in memory. [Start, stop, generation-bound discard and export](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L977-L1086) gate replacement of unexported data; [reset, restore and exit callers](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/vehicles/ground/ground_scene.gd#L943-L1035) attempt export before replacing a run. CSV and JSON files go under `user://rcv/` and metadata carries model, course, solver, clock and integrity information. The [existing session tests](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/tests/test_rcv_session.gd#L412-L467) cover ordinary export, name rejection and collision; other focused tests cover caps, interruption and departure failures. This audit inspected their source but did not run the ground recording or rendered workflow tests, qualify native filesystem ACLs, or prove crash-durable publication of the two-file pair.

## Other operational boundaries and unverified evidence

- **Backup scope and retention.** The independent backup chain copies the GitHub history database, not receiver `raw.sqlite` or `aggregates.sqlite`: see [container source](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/ct/backup_archive.py#L17-L24) and [host handoff](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc_stats_backup.py#L79-L109). The receiver guide separately requires raw-store exclusion and describes an aggregates-only backup with 180-day expiry. No production aggregate backup or all-copy expiry is established by these source checks. The dashboard also keeps floor-gated private insights in snapshot/state/HTML files; their persistence if refresh stops and any host/container snapshot copies require inventory. The [21 November audit](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/research/telemetry/TELEM-AUDIT-2026-11-21/README.md#L10-L13) explicitly limited its retention observation and left the all-copy drill open.
- **Blocked WAL checkpoint.** The 21 November fix records a busy checkpoint and retries; it does not expose that state in the dashboard's logical-row-based retention status. If a reader continues to block truncation after logical deletion, old bytes can remain readable in WAL without the status reporting their age. The [purge loop](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/services/telemetry/openrc_telemetry/cli.py#L68-L84) and [logical status](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/services/telemetry/openrc_telemetry/cli.py#L123-L139) need a delivered persistent-failure alert and a full-copy drill; this is not proof of a live retention breach.
- **Release and CI controls.** [Telemetry contracts](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/.github/workflows/telemetry-contracts.yml#L3-L19) are described by the workflow comment as nonrequired; actual repository branch-protection settings were not queried. Receiver-to-Godot E2E skips without its configured engine. [Release publication](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/.github/workflows/ci.yml#L1258-L1287) does not depend on that workflow. Per-tag receiver admission and package inspection remain [manual checklist gates](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry.md#L87-L92). The [public health workflow](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/.github/workflows/telemetry-health.yml#L19-L38) returns success when the current endpoint variable is empty, although previously released clients retain their packed endpoint; it otherwise tests liveness, not data admission. Its empty-variable result must not be interpreted as health of existing builds.
- **Snapshot credential minimization.** The [host script](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/deploy/host/openrc-stats-snapshot.sh#L4-L11) and [dashboard launcher](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/tools/telemetry/dashboard.py#L86-L93) export every `OPENRC_TELEMETRY_*` setting even though their comments say tokens stay out. `OPENRC_TELEMETRY_REPORT_TOKEN` shares that prefix. This passes an unnecessary secret into the receiver-account snapshot subprocess when configured; no token output or external disclosure was observed. Use an explicit settings allowlist.

The audit lead separately ran the existing Python and core Godot checks and a real loopback client-to-receiver test; their aggregate results and limitations are recorded in the main audit. Tests and source review do not verify production ACLs, proxy isolation, effective timer state, alert delivery, actual backups, or native-platform consent qualification.
