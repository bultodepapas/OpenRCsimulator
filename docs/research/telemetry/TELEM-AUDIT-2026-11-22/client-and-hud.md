# Telemetry client, HUD and local recording audit — 2026-11-22

This report assesses the repository client at [`7940a4081e10994f34c858c4acac3d7a1a271464`](https://github.com/bultodepapas/OpenRCsimulator/tree/7940a4081e10994f34c858c4acac3d7a1a271464), not a live deployment or any particular installed package. All baseline source links below are immutable permalinks. Five medium findings concern product telemetry; a sixth medium finding concerns local HUD terrain, and one low finding concerns local recording failure cleanup. The session-boundary case was already identified for qualification on November 21; its cross-boundary consequence is reproduced here. No runtime fixes are included.

## Scope and evidence

The review traced all `app/telemetry/*.gd` modules, the consent screen and Settings wiring, AppRoot admission and observation contexts, event producers, export configuration, focused telemetry tests and the measurement, consent and retention contracts. It compared the [November 19 findings](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/research/telemetry/TELEM-AUDIT-2026-11-19/README.md#L30-L49) and [November 21 open evidence](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/research/telemetry/TELEM-AUDIT-2026-11-21/README.md#L30-L34). The local HUD, ground plot and local recording lifecycle received a separate source review, recorded below.

The lead ran the synthetic probes below using the checked runner, Godot `4.8.beta2.official.cafc17a19`, headless on Linux, with an isolated project assembled from baseline source. They used injected clocks and data, no production origin or real player profile. Each probe exited zero, printed its expected `REPRODUCED` marker and produced zero engine diagnostics. The retained probes were rerun successfully using the [portable Godot harness](../../../../research/telemetry/audit-2026-11-22/run_godot_probes.py), which assembles a disposable project and records a source-hash manifest and checked-run logs. A zero exit means the baseline defects reproduced; it is not a passing correctness result. The consent permission case requires a non-root POSIX user. The existing focused admission, contract, queue, sender and service checks also passed on this isolated source copy. Passing those checks does not cover the boundary cases below.

## Findings

### TA22-C01 — Medium: performance windows can mix contexts

**Condition and impact.** Resize the window, change a pacing limit, or change another relevant context during the same mode and vehicle. A completed window can combine observations from both contexts and report the context sampled at closure for the whole event. This makes resolution and pacing comparisons misleading even when each event passes the wire schema. A same-aircraft reset is another lifecycle boundary whose timing and warmup need separate coverage.

**Evidence.** The [data contract](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/data-contract.md#L94-L100) requires complete windows to span 30 seconds in unchanged context and specifies warmup after a scene or configuration transition. The service [keys windows only by mode and vehicle](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L260-L279), then [samples batch context when appending an event](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L374-L388) using [live display, pacing, graphics and input values](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L438-L460). The Home probe switched from 1920×1080 to 3840×2160 after 15 steady seconds and observed one complete 30-second event labeled `2160p`. The same service path serves flight windows; the probe did not exercise a rendered resize.

The service [closes an activity on a detected reset](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L328-L340), but does not make that reset a window-key change. A restart after Pause can likewise retain exhausted warmup. This reset consequence is source inspection, not a separate executed probe.

**Confidence:** high for the reproduced resolution boundary; the restart/warmup consequence is source-traced.

**Remediation and acceptance.** Close the old window as partial at each material context or reset boundary, retain its original context, and begin a fresh window with the specified warmup. Exercise resolution, VSync, cap, graphics and input changes independently, including a same-vehicle reset and Pause → restart. Assert neither a complete window nor its context crosses a boundary. **Prior status:** new boundary defect; the earlier U2 finding concerned discarded context, not this attribution error.

### TA22-C02 — Medium: session rotation migrates open observations

**Condition and impact.** Cross midnight UTC or the four-hour limit with an open window or activity. The active token is not retired at the boundary itself; when a later event triggers rotation, that event can carry observations from before the boundary into the new epoch. This weakens the promised time-bounded grouping and can attribute a pre-boundary event to the later token.

**Evidence.** The [identity contract](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/data-contract.md#L24-L36) calls for rotation at either boundary, without migration of old observations. The only rotation decision is in [`_append`](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L374-L395); it does not split the open [window or activity](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L316-L371). The epoch probe observed the old token still active on the first post-midnight frame, followed by rotation on a later event. The new token's activity summary held 48 active and simulated seconds and one takeoff recorded before the boundary. Existing [rotation tests](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/tests/test_telemetry_service.gd#L263-L289) allow 31 seconds for a later event and do not test in-progress exposure.

**Confidence:** high for the reproduced UTC activity case; the four-hour boundary follows the same source branch and needs its own timed regression.

**Remediation and acceptance.** Retire the active epoch when the boundary is detected, close or safely discard partial observations under their original epoch, and begin fresh accumulators. Preserve already sealed old-epoch batches only for their remaining existing lifetime. Test exact midnight and four-hour boundaries with an open window, activity, error counter, idle/minimized state and in-flight or queued old batch; ensure pre-boundary facts never enter the new epoch. **Prior status:** explicitly listed as open evidence in the November 21 audit; now reproduced with an activity counter.

### TA22-C03 — Medium: one accident can count twice

**Condition and impact.** A nonterminal fixed-wing accident later escalates to terminal. The semantic detector emits the original `CRASH` and a revised `CRASH` for the same accident, but telemetry increments for both. A single model-aircraft accident therefore contributes two crash counts to the activity and downstream aggregates.

**Evidence.** The [detector](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/statistics/detector.gd#L455-L477) intentionally produces revision 0 and then revision 1 for one accident, as its [existing fixture](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/tests/test_ground_flight_events.gd#L96-L112) establishes. [Statistics forwards](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/statistics/service.gd#L260-L264) the semantic events on its [accepted-event signal](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/statistics/service.gd#L329-L332); [telemetry counts every `CRASH`](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L156-L167). The probe used valid output from the actual detector: the same accident's two revisions produced a count of 2, and `[1, 1]` when separated by a real slice transition.

**Confidence:** high: the controlled test used valid detector events and the actual telemetry consumer, including a slice transition.

**Remediation and acceptance.** Count an accident once while allowing its severity or terminal status to evolve, retaining bounded deduplication across slice boundaries and clearing it appropriately at activity/reset and consent boundaries. Test nonterminal → terminal revision, duplicate delivery, a second independent accident, and escalation across a slice. **Prior status:** new client measurement defect; no change to the underlying detector's event contract is implied.

### TA22-C04 — Medium: paused simulation can count as active flight

**Condition and impact.** A focused flight is frozen by a simulation-level pause while the scene remains active and no shell menu is on top. The telemetry context tests tree pause, loading, focus and menus but not the session's own simulation pause. The service may continue accruing active wall seconds, complete flight cadence windows and five-minute usage slices while simulated time is stationary. This can inflate usage and distort simulated-versus-active comparisons.

**Evidence and limit.** [AppRoot's eligibility predicate](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/app_root.gd#L3269-L3306) omits `session.sim.paused`; the [service increments active time](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L282-L294) whenever the supplied context is eligible. Ordinary crash presentation or the accident report can [disable automatic restart](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/main.gd#L1313-L1365), and [a crash pauses simulation](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/flight_session.gd#L3820-L3838). The [architecture](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/architecture.md#L59-L59) describes paused observations as ineligible. This is a source trace, not a rendered test proving the precise crash-screen state on each platform.

**Confidence:** high in the eligibility code and accumulator trace; actual rendered crash-screen timing remains unqualified.

**Remediation and acceptance.** Derive telemetry eligibility from the actual activity's paused state as well as shell visibility, with explicit handling for each supported vehicle family. Exercise a paused session with focus and no menu, a terminal crash, calibration or other holds, and resume; check that active seconds and complete flight windows do not advance while paused. Follow with a rendered ordinary-release crash-path check. **Prior status:** new client eligibility finding; the earlier quit-loss finding is separate.

### TA22-C05 — Medium: pending-age notice and active-request deadline disagree with behavior

**Condition and impact.** The player-facing [privacy notice](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/ui/telemetry_screen.gd#L19-L24) says pending data stays in memory for at most ten minutes. The service can hold an observation before sealing and then give the sealed batch a new ten-minute lifetime; a busy request can also survive the queue deadline. The latter directly conflicts with the explicit cancellation requirement. The notice and detailed lifetime table do not use the same scope for unsealed counters.

**Evidence.** Periodic sealing operates on [pending events](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L188-L199), but the queue [sets `created` when the batch is pushed](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_queue.gd#L41-L49). The pending-age probe records t=0, seals at t=60 and retries at t=659 after a valid Retry-After; the original event is still eligible. This demonstrates a conflict with the plain notice, while the [detailed table](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/data-contract.md#L122-L130) explicitly allows unsealed counters to remain for the current session and assigns ten minutes to the sealed queue. Do not treat every unsealed counter lifetime as violating that detailed table.

Independently, the [queue deadline contract](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/data-contract.md#L34-L36) requires canceling an in-flight old-session request at its original deadline. Expiry is reached via [queue push or begin](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_queue.gd#L59-L75), and service processing skips `begin` when the sender is busy. The in-flight probe started a retry at 599 seconds, observed the item and sender still active at 600 with zero cancels, then received an accepted 202 at 601. The fake request's two-second span is within the real sender's five-second timeout. Existing [queue tests](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/tests/test_telemetry_queue.gd#L39-L57) cover explicit expiry but do not exercise owner cancellation at the deadline.

**Confidence:** high for the controlled age and fake-sender timing cases; actual network receipt and operating-system sleep behavior were not measured.

**Remediation and acceptance.** Reconcile the notice with the approved treatment of unsealed observations; if the ten-minute player promise applies to them, propagate their earliest eligible deadline into each batch. Enforce the original sealed deadline while busy, cancel the request and fence later callbacks on expiry or eviction. Test a retry just before expiry, a response just after expiry, eviction of an active batch, and pre-seal observation age. **Prior status:** new clarification and in-flight deadline finding; it does not assert a server-side retention failure.

### TA22-H01 — Medium, conditional: local HUD height omits RC-track relief

**Condition and impact.** A flight has the optional raised RC circuit enabled and is above its relief. The contact/camera terrain includes the circuit, while the flight overlay samples only the underlying field. HUD height above ground is consequently overstated by the omitted local circuit height. This can change the airborne classification and `STALL`/`LOW` warning thresholds. This is a local instrument/display issue; this HUD value is not a field in the product telemetry batch.

**Source evidence.** Flight startup [resolves the circuit](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/main.gd#L849-L851) and [installs the matching surface in the session](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/main.gd#L1100-L1103). The camera's ground sampler explicitly [composes base terrain with `RcTrack`](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/main.gd#L2469-L2474). However, the [overlay entry point](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/main.gd#L2477-L2483) calls a snapshot whose [terrain sample](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/render/overlays/overlay_manager.gd#L608-L615) uses only `session.ground_surfaces`. The [track composition](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/physics/ground_vehicle/airfield_track.gd#L146-L152) adds `overlay.height_m` to the base height; [HUD calculation](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/render/overlays/telemetry.gd#L50-L52) subtracts the supplied terrain height from aircraft altitude. The error therefore equals the omitted relief at that location.

The [warning logic](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/render/overlays/telemetry.gd#L109-L118) consumes this AGL. Existing [RC-track fixtures](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/tests/test_rc_track_flight.gd#L73-L89) describe a bank above 0.5 m where contact differs from the flat field. Those fixtures were inspected, not executed in this audit. The pure overlay math test supplies its own terrain value and does not establish that the real caller supplies the composed terrain.

**Confidence and limit:** high for the producer/consumer mismatch, conditional on enabled nonzero track relief. No rendered circuit flight, warning transition or new physical measurement was run. Flat-field behavior is not implicated.

**Remediation and acceptance.** Provide overlays with the same authoritative composed terrain sampler used for contact/presentation, preserving coordinate and unit conventions. Test flat field, sloped field, disabled circuit and multiple enabled-circuit points, then verify AGL and airborne/LOW/STALL transitions through the actual snapshot caller. Keep physics source unchanged unless a separate physical defect is established. **Prior status:** new local HUD integration finding.

### TA22-L01 — Low, conditional: a failed metadata write leaves an orphan temporary recording

**Condition and impact.** Local ground recording successfully writes its CSV temporary file, opens/creates its JSON metadata temporary file, and then encounters a metadata write or flush error. The failure branch removes only the CSV temporary file. A partial `*.json.tmp` can remain, and a later export using that exact basename is refused as an existing output. Normal interactive retries use a fresh timestamped name and keep samples in memory, so this does not establish permanent data loss or that every retry is blocked.

**Source evidence.** [`export_recording():1045–1086`](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L1045-L1086) rejects existing final or temporary paths at 1061–1063, but its metadata-error branch at 1070–1073 removes only `csv_temp`. [`_write_new_file():1372–1380`](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L1372-L1380) can create the file before returning the write error. Unlike the later rename-error paths, this branch has no JSON-temp cleanup. The [interactive caller](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/vehicles/ground/ground_scene.gd#L1110-L1130) normally selects a new timestamped basename and explicitly reports that a failed export remains in memory.

**Confidence and limit:** source-confirmed cleanup omission under a specific write failure. No disk-full, failing filesystem or rendered export was exercised. This local user-triggered recording does not send these files through the product telemetry receiver.

**Remediation and acceptance.** Clean up every temporary file owned by this attempted export on each failed branch, preserve in-memory samples, and make cleanup failures visible without deleting a preexisting user's output. Inject a failure after creating the metadata file and verify no owned temporary artifact remains, both same-name and fresh-name retries can succeed after recovery, and existing-file preservation still holds. Existing tests that replace the whole exporter with a failure result do not cover this internal failure point. **Prior status:** new local recovery finding.

### Local recording controls and interpretation

The source review also traced the explicit garage/F9 recording action, prepared-session/backend admission, bounded capture, interruption handling, reset/replay guards and managed exit. Recording requires a [healthy prepared session with no unsaved recording](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L977-L1009), stores [controls, state and physical channels](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L1089-L1124), and exports a bounded basename under `user://rcv/` with [model/course/solver identities, timing and hashes](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L1321-L1368). Duration/sample caps and retained failure prefixes are valuable controls; the export cleanup finding does not invalidate them.

The ground suspension plot is a separate bounded local view. Its [samples are indexed and drawn uniformly](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/vehicles/ground/telemetry_plot.gd#L12-L44); do not infer fixed-time spacing from the picture alone. No additional material defect was established in that plot or the textual telemetry panel. Ground recording/exit tests, physical channel meaning, native ACLs and crash-durable two-file export were not executed or qualified here.

## Confirmed residual risk: unsuccessful consent persistence

If a directory prevents both removing an existing grant and writing its replacement, disabling still closes the current process but cannot guarantee a durable decline. The consent store [attempts removal and then writes a temporary file](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_consent_store.gd#L36-L52); the service [reports a save error and retries removal](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_service.gd#L134-L146). The isolated non-writable-directory probe observed `on` → `off`, save error 12, persisted `enabled`, then a new service instance `on` again. This is an operational limitation, not a new unconditional contract violation: the [architecture](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/architecture.md#L63-L69) and [Settings copy](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/docs/plans/telemetry/consent.md#L40-L48) already disclose it. Keep a regression for simultaneous remove/write failure and verify the warning is visible in the actual release UI.

## Other interpretation and coverage limits

Schema 2's physics-backend field for fixed-wing and helicopter activities comes from `stage_backend_status()`, through `NativeFallback.summary().kind` and the bounded [wire mapping](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_contract.gd#L74-L88); the refusal text is not sent. [AppRoot](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/app_root.gd#L3285-L3297) reports `not_applicable` when that method is absent. Ground sessions have a [separate backend identity](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/sim/ground_vehicle/session.gd#L1674-L1675), but actual native admission in a shipped ground activity was not demonstrated here. Treat this as a coverage question before interpreting its backend table.

The November 19 non-16:9 resolution gap is partially addressed by [pixel-count bands](https://github.com/bultodepapas/OpenRCsimulator/blob/7940a4081e10994f34c858c4acac3d7a1a271464/app/telemetry/telemetry_hardware.gd#L106-L118); Retina coordinate space remains unqualified. Five-minute slices mitigate but do not eliminate short-use and quit loss. Reviewed-locale and technical-route exclusions remain documented population limits. No result here establishes real hardware overhead, platform-specific consent usability, physical display pixels, or present-day deployment state.
