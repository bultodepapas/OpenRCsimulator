# T07 — Coalesce requests and own each generation

**Researched:** 2026-11-17. Recommendations are proposed; no runtime improvement is measured here. [Twenty-investigation index](README.md).

**Question.** How can the selected preview, possible future speculation and an accepted launch share useful work without duplicate engine requests or stale publication?

**Search queries used.** `site:pkg.go.dev golang.org/x/sync/singleflight duplicate call suppression shared cancellation`; `site:docs.godotengine.org ResourceLoader load_threaded_request dependencies cache status thread safe scene tree`; `Godot 4.8 beta 2 ResourceLoader load_threaded_request reuse user token get thread code github`.

**Evidence and limits.** Go's [singleflight package](https://pkg.go.dev/golang.org/x/sync/singleflight) describes one execution for concurrent calls with the same key and sharing of the result; its `Forget` operation allows a later execution even while an earlier one may exist. That is a transferable duplicate-suppression pattern, not a Godot feature or a cancellation policy. Godot's [ResourceLoader API](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html) describes request, status and retrieval; the [background-loading guide](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html) says early retrieval can block. These Godot pages are live stable documentation, not pinned to OpenRC's engine. Inspection of the [4.8-beta2 request implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/io/resource_loader.cpp#L700-L810) and [collection implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/io/resource_loader.cpp#L932-L1000) at the exact engine hash verified the ownership details. The user-token lookup uses the passed path and a repeated request increments its user count; collection decrements it and removes the token at zero. Task bookkeeping also has a local path, so path aliases must not be assumed equivalent. Accessed 2026-11-17.

**OpenRC seam.** [HomePreviewResources.request](../../../../../app/ui/home_preview_resources.gd#L48) already replaces the previous callback, reattaches a same-path current intent to the active load, and keeps only the latest queued path. It submits with `use_sub_threads=false`, polls, collects terminal loaded/failed work, and discards obsolete results. [HomeScene](../../../../../app/ui/home_scene.gd#L319) increments a generation, checks vehicle and skin plus tree lifetime after awaits, and releases stale candidates. The owner survives Home replacement; ordinary cancellation suppresses a consumer rather than canceling I/O. This is already a useful latest-intent implementation, not a missing generic singleflight library.

**Proposed application.** Preserve that owner and serial engine-request constraint. Only if a later feature actually has multiple simultaneous consumers, add a bounded request record containing normalized canonical resource identity, type/cache mode and admitted immutable content/import revision, owner of the one engine request, terminal state and independently removable consumer tokens. Consumer records carry the generation and purpose (preview, speculation or accepted launch). A new explicit request matching active work attaches without making another engine call. Completion is collected according to the pinned API contract once per admitted owner request; deliver only to still-live authorized consumers, and recheck generation, tuple/revision and lifetime immediately before mutation. A consumer cancel detaches it; a queued speculative request is dropped; an active owner stays alive and drains. Failure is delivered once to current consumers and a later retry creates new owned work. Do not collect an invalid/unowned status as though it were another request.

The semantic revision key is an application correctness check: Godot's resource cache remains path-oriented. If the same path is replaced while an older version is active or retained, a revision field alone cannot force the engine to return new bytes. Prefer immutable versioned paths for the full dependency closure. If replacement in place is unavoidable, serialize the transition, retain the exact accepted old snapshot or use a qualified reload boundary, and reject/recover on a mismatch without mutating live consumers. A speculative callback must never replace an accepted launch or a newer explicit preview. Preserve independent model/material ownership even when immutable resources are shared.

Different application keys do not permit concurrent engine requests for one normalized engine path. Incompatible revisions, type hints or cache modes wait for the current path owner to drain, then revalidate or use the qualified reload boundary. Do not attach an incompatible consumer merely because its path string matches. Keep the existing global serial limit while this contract is qualified.

**Counterexample and experiment.** Blindly removing the key on cancellation can allow another request for the same path before the first drains; tying the shared operation to the first transient viewer can also starve a still-valid launch. Against the existing broker as control, exercise A→B→A while A is in flight, same-path different-skin consumers, incompatible same-path options/replaced revisions, success/failure, invalid status, alias paths, cancellation, Home detach/replacement, launch adoption and shutdown. Count physical request calls versus owned terminal collections, callback deliveries, stale commits, released owners and peak references. Use a controlled slow completion, then native first-draw and burst measurements where the behavior changes. A discarded or partially loaded result is reported separately from a hit.

**Decision.** Keep current single-owner/latest-wins logic for **UI-VS-00/02**; add multi-consumer coalescing only when **UI-VS-10** or another measured need requires it. Reject overlapping engine requests for one path even when application keys differ, unbalanced ownership, canceled publication, stale revision substitution, or complexity without measured value. **UI-VS-01** owns exact accepted launch identity; **UI-VS-05** owns reservations and retained bytes. No performance gain is claimed from the pattern alone.
