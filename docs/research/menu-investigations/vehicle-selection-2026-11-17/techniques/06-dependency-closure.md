# T06 — Audit the asynchronous dependency closure

**Researched:** 2026-11-17. Recommendations are proposed; no runtime improvement is measured here. [Twenty-investigation index](README.md).

**Question.** After the selected GLB is reported ready, which work can still block the visible preview, and which dependency is safe and worthwhile to prepare earlier?

**Search queries used.** `site:docs.godotengine.org ResourceLoader load_threaded_request dependencies cache status thread safe scene tree`; `site:docs.godotengine.org thread safe APIs scene tree instantiate sub-thread ResourceLoader load threaded dependencies`; `Godot background loading version 4.8 beta thread get_dependencies get status`.

**Evidence and limits.** Godot's [ResourceLoader reference](https://docs.godotengine.org/en/stable/classes/class_resourceloader.html) documents resource dependencies, status polling across frames and retrieval; [background loading](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html) warns that retrieval before completion can block. Its [thread-safety guide](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html) distinguishes scene-tree, resource and GPU operations. These live stable pages are useful API guidance, not proof of exact 4.8-beta2 internals; the dependency representation was also verified against the [pinned engine source](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/doc/classes/ResourceLoader.xml). Confirm runtime behavior in the implementation fixture. Accessed 2026-11-17.

`ResourceLoader.get_dependencies()` is a starting inventory of declared resource edges, not a complete execution trace: runtime-selected paths, raw file reads, archives, computations, and render-driver work need separate observation. Its documented dependency strings can contain UIDs and fallback paths; an inventory must resolve these carefully, traverse recursively with a visited set, and report missing/unresolved entries rather than claim completeness. Imported scene contents and package remaps also warrant a package check. None of this establishes that every dependency is a separate cold disk read or that texture upload has completed.

**OpenRC seam.** [The broker](../../../../../app/ui/home_preview_resources.gd#L23) resolves a selected GLB hint, then owns one `PackedScene` request and terminal result. [HomeScene](../../../../../app/ui/home_scene.gd#L436) subsequently calls the full builder on main. [AirplaneBuilder](../../../../../app/render/airplane.gd#L76) loads registry and builder scripts, performs selected-livery/derived validation and reads aircraft data; [ImportedModel](../../../../../app/aircraft/imported_model.gd#L17) loads generated geometry and the scene, then instantiates it. [VehiclePaint](../../../../../app/render/vehicle_paint.gd#L227) can load texture paths; [CustomSkin](../../../../../app/aircraft/custom_skin.gd#L324) reads and inspects an archive. Other activity builders take different branches. These are source facts, not measured bottlenecks. The existing [audit](../code-audit.md) supplies the branch inventory and the [protocol](../benchmark-protocol.md) defines phase endpoints.

**Proposed application.** Build a per-tuple diagnostic ledger joining the recursive declared-resource inventory to *observed* runtime stages: path resolution, raw manifest/proof/hash I/O, dynamic script/texture selection, archive inspection and decoding, instantiation/bindings, presentation geometry, attachment and first draw. Include source/vehicle/skin revision, cache state, thread, start/end, and failure. Mark an edge as declared, observed, conditional or unresolved; do not label unobserved paths absent. Use existing external observation or owner-reviewed instrumentation so hashed builders are not silently changed. After attribution, trial early preparation of only the dominant eligible resource under the existing request owner and scene-load gate. A texture requires an explicitly typed ownership path; the present broker's `PackedScene` storage is not a generic asset service. Keep validation and immutable identity checks at use.

**Counterexample and experiment.** A completed GLB may already contain the relevant assets while the expensive operation is synchronous validation, a large surface read, or first draw. In E0, compare fresh-process, first-visit, resource-retained/node-miss and preview-retained states on the pinned renderer at 1080p; record exclusive main-thread spans, overlapping load intervals, individual blocking frames, queue wait and requested first draw. Do not add nested spans. Compare a selected-path-only candidate against the same asset and environment with the new preparation disabled. Cover imported jet, procedural model, car, airship and custom skin, including absent/corrupt dependencies and package export. Report missing instrumentation, observer overhead and distributions as prescribed by the protocol.

**Decision.** Use the audit first, under **UI-VS-00**. Reject an early-load candidate if the measured end-to-end improvement is within variation, the worst frame or launch/peak memory regresses beyond the plan's gates, a resource is used without exact validation, or dependency ownership cannot drain safely. A closure inventory alone is not an optimization or proof of responsiveness. Route a proven appearance-only improvement to **UI-VS-03**, generated presentation data to **UI-VS-04**, and byte admission to **UI-VS-05**.
