# T18 — Mesh delivery, geometry complexity and LOD

**Research date:** 2026-11-17. **Status:** proposal; no runtime measurements. [Twenty-investigation index](README.md).

**Question.** Which source geometry and imported-mesh choices could reduce a measured selection bottleneck without breaking aircraft bindings, and which apparent compression wins only reduce transport bytes?

**Searches actually run (2026-11-17):** `Godot glTF EXT_meshopt_compression KHR_draco_mesh_compression support source import mesh LOD`; `site:github.com/KhronosGroup/glTF EXT_meshopt_compression KHR_draco_mesh_compression codec decode specification fallback`; and `"godot" "EXT_meshopt_compression" "KHR_draco_mesh_compression" glTFDocument required extension 4.8`.

## Evidence and limits

- [Khronos's EXT_meshopt specification](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Vendor/EXT_meshopt_compression/README.md) describes compression of buffer views and optional fallback data. Its codec can reproduce the encoded vertex/index streams exactly, but common preprocessing such as quantization or reordering is a separate decision. A file can require the extension when no valid uncompressed fallback exists; including both forms can diminish package savings.
- [Khronos's Draco extension](https://github.com/KhronosGroup/glTF/blob/main/extensions/2.0/Khronos/KHR_draco_mesh_compression/README.md) compresses a mesh primitive and requires a decoder. The specification warns that vertex order and count can change and specifies failure when a required extension is unsupported. A smaller GLB is not evidence of faster scene instantiation, smaller uploaded buffers, preserved triangle-map identity or an OpenRC improvement. Codec settings, image share of the file, decoder startup and hardware affect the result.
- [Godot's scene importer](https://docs.godotengine.org/en/stable/classes/class_resourceimporterscene.html) separately exposes `meshes/force_disable_compression` and generated LODs. This is Godot's imported-mesh option, not proof of glTF Draco or meshopt decoder support. LODs can reduce drawn detail at distance; generating them may increase import/output work and does not establish reduced initial scene load or resident geometry. The documentation is current, so confirm actual imported beta2 output.

The pinned beta2 [core extension registry](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/gltf/gltf_document.cpp#L7008-L7027) omits these names and aggregates registered extensions; its [required-extension check](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/gltf/gltf_document.cpp#L7399-L7419) refuses an unsupported required extension. Registered modules/plugins may extend the core list, so this is not by itself proof about every possible build. Independently, OpenRC [Creator preflight](../../../../../app/workshop/creator/glb_preflight.gd#L8-L15) requires no required extensions and rejects both Draco and EXT meshopt even as used extensions ([policy](../../../../../app/workshop/creator/glb_preflight.gd#L55-L60)); the product route does not admit them. A third-party decoder or relaxed preflight is not part of this proposal.

## OpenRC seam and proposed application

The checked [jet import sidecar](../../../../../app/assets/aircraft/avanti-s-a200/avanti_s.glb.import#L28-L32) has `generate_lods=true` and `force_disable_compression=true`; inspect the actual result before changing either. [ImportedModel](../../../../../app/aircraft/imported_model.gd#L17-L35) loads and instantiates the selected scene, then walks and validates named nodes. Home also [collects projected-shadow faces](../../../../../app/render/projected_shadow.gd#L37-L78) and may [snapshot individual surfaces](../../../../../app/ui/home_preview_geometry.gd#L6-L63); one surface read is indivisible. Therefore measure nodes, mesh instances, surfaces/material splits, vertices and indices as well as bytes. Merging everything to reduce surface count may make individual work slices larger and violate articulated hinges, paint targets, crash sections or bounds.

As a conditional owner-led experiment, choose one measured heavy source and alter only one factor at a time: imported-mesh compression, unnecessary source geometry, or eligible surface/node structure. Rebuild through its existing asset and generated-manifest pipeline, with all skin, node/hinge, crash-map, source/hash, bounds and launch contracts intact. Do not replace physics geometry or hand-edit generated assets. A lightweight separate preview representation is a different investigation; render LOD alone does not make it happen. Keep ordinary admitted geometry if no qualified engine/Creator decoder exists.

## Experiment and decision

Use [E0/E6](../benchmark-protocol.md): unchanged asset/import/package as control versus one regenerated candidate, alternating on the same 1080p host before above-1080p checks. Record GLB, imported resource and exported package bytes; import time, disk read/decode, model construction, geometry/face-snapshot time and largest indivisible read; first correct draw, frame tails, CPU/RSS and GPU buffer estimates. Compare silhouettes, control-surface motion, skin targets, shadows, node hierarchy and declared triangle-map or section identity. Use five alternating fresh-process pairs and at least 20 warm transitions for screening; protocol tail qualification is larger.

Reject broken import or proof, any lost binding/skin/crash behavior, visual regressions, increased whole-workload cost or effects within measurement variation. **Recommendation:** attribute under **UI-VS-00**, then consider an owner-reviewed **UI-VS-09** geometry/import experiment. Do not switch to meshopt/Draco or promise that automatic LOD shortens loading on the basis of external engine examples.
