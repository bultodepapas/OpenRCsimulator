# T16 — Target-native texture blocks versus Basis Universal

**Research date:** 2026-11-17. **Status:** proposal; no runtime measurements. [Twenty-investigation index](README.md).

**Question.** When a selected vehicle's texture loading is measured as costly, does an offline, platform-specific GPU-compressed import reduce end-to-end selection cost enough to justify additional package variants, compared with the existing portable Basis Universal route?

**Searches actually run (2026-11-17):** `site:docs.godotengine.org image import GPU compressed Basis Universal transcode platform texture formats export`; `site:registry.khronos.org KTX 2 Basis universal UASTC ETC1S transcode runtime GPU KHR_texture_basisu`; and `site:docs.godotengine.org Godot image importing export s3tc bptc etc2 astc platform desktop mobile vram compression`.

## Evidence and limits

- [Godot's image-import guide](https://docs.godotengine.org/en/latest/tutorials/assets_pipeline/importing_images.html) distinguishes disk-oriented Lossless/Lossy, GPU-native VRAM Compressed and Basis Universal. Basis can be smaller on disk but is transcoded at load into a GPU-supported format; resulting residency can be similar to a native block format, not proportional to compressed source size. The guide describes S3TC/ETC2 defaults and notes that its high-quality BPTC/ASTC setting is disabled under Compatibility. These are current documentation rules, not a guarantee of this project's actual beta2 output or supported GPU formats.
- The [pinned beta2 `GLTFState` enumeration](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/gltf/doc_classes/GLTFState.xml) identifies embedded-image handling value `2` as Embed as Basis Universal; extraction to individually imported images is an editor operation and behaves differently at runtime. The checked [jet sidecar](../../../../../app/assets/aircraft/avanti-s-a200/avanti_s.glb.import) and [F4U sidecar](../../../../../app/assets/aircraft/f4u-corsair-250/f4u_corsair_three_tone.glb.import) both contain that value. This confirms the recipe, not the actual fresh-import/export representation or measured transcode cost; inventory those before attribution.
- [Khronos KTX 2](https://registry.khronos.org/KTX/specs/2.0/ktxspec.v2.html) is a container, not a synonym for one codec: its contents can include native GPU formats or universal data. UASTC data requires transcode or decode to a GPU-supported format. At the pinned beta2 source, the [glTF KTX extension](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/gltf/extensions/gltf_document_extension_texture_ktx.cpp#L33-L66) names `KHR_texture_basisu` and reads KTX images; the [built-in registration](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/gltf/register_types.cpp#L135-L145) includes that extension. This engine path does not establish that every export, device or arbitrary KTX2 is qualified.

The source and documentation are engine/format evidence, not a timing comparison. A native-block asset can still incur package decompression, I/O, staging and upload; storage savings can win on slow disks while transcoding loses on a CPU-limited host. A pre-encoded block format is not automatically zero-work or visually equivalent.

## OpenRC seam and proposed application

[Home's broker](../../../../../app/ui/home_preview_resources.gd) loads the selected scene; [ImportedModel](../../../../../app/aircraft/imported_model.gd#L17-L35) later instantiates it. [CustomSkin](../../../../../app/aircraft/custom_skin.gd#L181-L238) instead decodes PNGs, generates mipmaps and creates ImageTextures; changing stock scene import settings does not optimize that distinct route. Creator's [preflight](../../../../../app/workshop/creator/glb_preflight.gd#L8-L15) and [extension policy](../../../../../app/workshop/creator/glb_preflight.gd#L55-L60) reject `KHR_texture_basisu` for user GLBs despite the engine extension: do not conflate engine capability with admitted untrusted content.

Only after attribution, let the VQ/asset owner produce a single otherwise-matched imported stock candidate with actual platform-appropriate native blocks and one portable Basis control. Preserve color space, alpha, normal-map orientation, mips, materials and visual identity. Generate through the aircraft owner pipeline, including sidecar/manifest/proof hashes; never hand-edit generated geometry or physics. [Project settings](../../../../../app/project.godot#L61-L78) enable an additional ETC2/ASTC import variant for the Mac export; that flag alone does not prove which variant each machine receives. Verify a clean export for Compatibility and Apple Silicon Mobile/Metal, including renderer fallback.

## Experiment and decision

Use [E0/E6](../benchmark-protocol.md): compare identical source art, dimensions, mips, materials, selection sequence and output quality with only the import representation changed. Record cold and warm source/import/package bytes, import time, resource-read/decode or transcode CPU spans, staging, upload and selection-to-first-correct-draw, memory peak/plateau and actual GPU format. Record OS/driver/cache state, and separately account for unique texture sharing; GPU counters are not automatically physical residency. Start at 1080p and review fine markings, alpha edges, normal maps and day/night; test above 1080p afterwards.

Screen five alternating fresh-process pairs and at least 20 warm transitions; qualify tails per the protocol. Reject if any package/visual/identity check fails, or if complete-workload improvement does not exceed variation, extra package cost is unacceptable, or peak memory/launch materially regresses. **Recommendation:** conditional **UI-VS-09**, after **UI-VS-00/05** attribution and memory accounting; retain the existing route and Creator policy until a candidate passes. No current performance gain is asserted.
