# T17 — Texture tiers, residency and mip streaming

**Research date:** 2026-11-17. **Status:** proposal; no runtime measurements. [Twenty-investigation index](README.md).

**Question.** Can a bounded texture-resolution policy keep browsing and the selected preview within observed memory limits, while preserving a correct full-quality flight path on Compatibility and Apple Silicon Mobile?

**Searches actually run (2026-11-17):** `Godot 4.8 texture streaming compatibility mipmaps stream budget beta2 official`; `site:github.com/godotengine/godot/pull/113429 texture streaming budget compatibility mip loaded`; and `site:docs.godotengine.org Godot image importing export s3tc bptc etc2 astc platform desktop mobile vram compression`.

## Evidence and limits

- [Godot's image-import guide](https://docs.godotengine.org/en/latest/tutorials/assets_pipeline/importing_images.html) explains that generating mips makes smaller samples available and a full chain adds roughly one third to base-level storage. That is a sampling choice, not a policy that unloads the largest levels. The pinned beta2 [texture importer property documentation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/doc/classes/ResourceImporterTexture.xml#L77-L86) says `mipmaps/limit` is unimplemented; it is not a residency cap.
- The upstream [streaming implementation discussion](https://github.com/godotengine/godot/pull/113429) describes a separate streamable import type, enabled streaming, GPU feedback and budget/minimum-resolution choices. It says the implementation loads and swaps whole textures rather than using sparse partially resident allocations; if allowed minimum resolution cannot fit, the budget is not an absolute guarantee. This is an implementation discussion, not proof of beta2's measured peak or Metal behavior.
- The project's [beta2 source analysis](../loading-research.md#godot-48-texture-streaming) identifies streaming and its budget enforcement as off by default and Compatibility as unsupported in the [pinned implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/texture_streaming/texture_streaming.cpp#L224-L286). [Godot's experimental latest importer documentation](https://docs.godotengine.org/en/latest/classes/class_resourceimporterstreamedtexture.html) also requires streaming to be enabled and textures to be imported for it. Latest documentation can change and must not be treated as a beta2 API guarantee; test the actual beta2 build and the application's Apple Silicon Mobile/Metal path separately.

For an ideal square texture and matching full mip chains, halving both dimensions makes the texel total approximately one quarter; block alignment, non-square edges, metadata, upload buffers, drivers and shared ownership change actual bytes. Removing the two smallest mips does not achieve that saving. Keep appropriate mip generation for 3D sampling and test the chosen lower *base* resolution, not just a filter or a mip bias.

## OpenRC seam and proposed application

[LiveryPicker](../../../../../app/ui/livery_picker.gd#L58-L136) already loads one thumbnail per frame, but eventually loads all available cards; [HomeScene](../../../../../app/ui/home_scene.gd#L194-L255) retains up to three vehicle/skin models. [CustomSkin](../../../../../app/aircraft/custom_skin.gd#L370-L390) generates mips from admitted PNGs; that fact does not make those runtime ImageTextures streamable. This investigation concerns the sizes and ownership of actual texture resources, independent of any separate proxy-model presentation design.

Under **UI-VS-05/06**, admit a bounded visible-window thumbnail pool keyed by content revision, size and rendering recipe. A thumbnail remains a truthful selection cue, not proof of model or launch readiness. If E0 shows selected full-preview textures exceed a target budget, trial one explicitly generated lower-base-resolution texture tier for that preview; distinguish it from the flight asset and keep a truthful fallback when the tier is missing or unqualified. Use content-versioned resource paths and avoid mutating a shared full-resolution material. Reserve old plus new resources and staging before swapping, release only when owners drain, and keep Creator/custom-skin admission and exact identity checks unchanged.

A texture tier can backfire: its actual scene/dependency closure must avoid loading the full-resolution texture first, including an embedded GLB image. Applying a smaller override after the original full texture was imported adds overlap. A full texture retained elsewhere can also prevent any steady saving. Verify first-load resource/format traces as well as post-swap owners. A tiny marking or alpha edge can become illegible even when total image error looks small. Do not claim lower residency before observed ownership and quality checks. Dynamic streaming remains a later, separate Mobile/Forward+ experiment; Compatibility must have a working explicit budget/thumbnail fallback without it.

## Experiment and decision

Use the [E0/E4/E6 protocol](../benchmark-protocol.md) with the original full import as control and one size-tier candidate, on native 1080p first. Match model, lighting, framing, materials, renderer and skin; compare first draw, selection latency, mip/upload phase, block-format estimates, OS RSS/system available memory and observed texture/buffer counters. Record unique owners, old/candidate/staging peak, post-eviction plateau, missing tier and A→B→C→D→A. Inspect markings and aliasing at 1080p and higher, with day/night and low-memory fallback. Compare a cold selected visit and warm reuse; use the protocol's alternating samples and report variation.

Reject if appearance/identity or the full launch is wrong, peak grows without justified benefit, a budget cannot be enforced, recovery is ambiguous, or the complete workload fails to improve beyond variation. **Recommendation:** **UI-VS-05/06** for bounded ownership and thumbnails; **UI-VS-09** for a measured tier; defer streaming to a separately qualified experiment, never a dependency for the primary Compatibility route.
