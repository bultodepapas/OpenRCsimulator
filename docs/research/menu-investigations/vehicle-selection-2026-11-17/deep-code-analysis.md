# Deeper code analysis: remove repeated work before expanding caches

**Review date:** 2026-11-17. **Status:** source analysis and proposed experiments; no runtime changes or new timing measurements. **Source:** [main at a7de9b35676d891bc2034cc344b910d9e1ef9c61](https://github.com/bultodepapas/OpenRCsimulator/tree/a7de9b35676d891bc2034cc344b910d9e1ef9c61), Godot 4.8-beta2. This is the third review round, following the [initial audit](code-audit.md) and [twenty technique investigations](techniques/README.md). The [implementation plan](../../../plans/vehicle-selection-performance.md) remains authoritative.

## What changes in the recommendation

The strongest new opportunities are specific redundant operations, including work outside the resource loader. Home requests full statistics histories for five scalar fields; identical selections invalidate useful preparation; one catalog activation updates every row three times; a retained model still recreates its projected-shadow renderer. Some builders also perform preparation that a parked menu model never consumes.

Start with those narrow seams. A larger RAM/VRAM cache, more worker threads or fleet preloading would preserve much of this avoidable work and can increase peak memory. The existing metadata-first catalog, compatible appearance transaction and byte-admission plans remain necessary for 100+ vehicles, but they do not replace fixing these call paths.

**Evidence boundary:** a verified function call, loop or allocation is not a measured bottleneck. Counts below are structural and explicitly scoped. No percentage gain, millisecond saving or performance ranking by elapsed time is established. The experiments measure complete user-visible transitions, including the work before feedback and after attachment.

## D01: Compact statistics summaries

**Observed.** [Home refreshes statistics before its selected labels](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L1347-L1405). It requests `query(selected_id, "lifetime")` and `query("", "lifetime")`, then reads only `airborne_seconds`, `completed`, `crashes`, `best_streak` and `available`. Both queries run even when the selected activity is unsupported and its text is immediately replaced by the unsupported message.

[Service.query](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/statistics/service.gd#L637-L676) returns a deep copy of its cached dictionary on every call. The default [reducer includes history](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/statistics/reducer.gd#L9-L87), copying matching records as it constructs that history. Therefore warm Home refreshes copy the all-pilot history and the selected-aircraft history, although neither is rendered. This scales with accumulated flights as well as vehicle count.

**Smallest candidate.** Use the existing `summary(id, "lifetime")` API for these labels and skip the unsupported per-vehicle summary. It already invokes the reducer with `include_history=false` and deep-copies only a compact result. The cold summary path still validates and reduces the ledger and [sorts terminal entries for streaks](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/statistics/reducer.gd#L238-L249); it is not constant-time and does not remove two cold reductions. Follow the existing [HUD summary/query compatibility adapter](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/render/overlays/overlay_manager.gd#L525-L534), or explicitly narrow Home's generic service contract and update fixtures. A query-only fallback retains its old cost.

**Correctness.** Summary supplies all five fields, but its active-flight airborne time uses a live monotonic delta; it need not be bit-identical to a cached query. Do not enable the reducer's trusted mode merely to save validation. Normal activity completion, reset and deletion clear both caches; flush/write-receipt handling is different and needs parity checks. Home currently has no statistics-change subscription, [Statistics Back only pops its screen](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/app_root.gd#L3535-L3543), and [translation refresh omits the active selected ID](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L1768-L1773), causing that helper to choose the remembered aircraft. Explicitly refresh the actual selection on return/translation; reproduce stale labels after reset/delete before choosing a scoped signal subscription or return hook.

**E19 / UI-VS-00, 01.** Compare five formatted fields and availability across empty/large valid ledgers, alias IDs, aircraft/activity selection, idle/live time, flush, rollback, read-only, reset and deletion recovery. Count reductions, validated records and copied history records separately for cold and warm cases. Measure input-to-label draw and allocations; a warm summary should copy no history. Keep correctness and timing results separate.

## D02: Idempotent pending preview intent

**Observed.** [A catalog activation always emits its request](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L805-L830), including the already selected ID. [AppRoot refreshes Home and requests a preview](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/app_root.gd#L1074-L1106); Home clears its skin-choice identity even when selection has not changed. [HomeScene.request_aircraft](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L319-L350) increments the generation, discards a private candidate and cancels its callback before checking a retained result.

The existing broker [already reattaches a compatible same-path active load](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_preview_resources.gd#L48-L68). The new issue is higher in the lifecycle. A repeated A request can discard completed builder work. If A's engine request completes after cancellation but before reattachment across the two frame waits, [the broker drains it without retaining it for a valid consumer](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_preview_resources.gd#L116-L139). A subsequent request may resubmit that path; engine cache or another owner may still avoid disk I/O. This is a conditional interleaving, not a claim that every repeated click reloads the file.

**Smallest candidate.** Make preview preparation idempotent for the same canonical source/vehicle/skin/content revision while its current owner and pending state remain valid. Keep the existing generation and candidate; refresh only UI state that actually changed. Do not return early from the entire explicit selection action: it can commit a retained aircraft preference, retry a failed save, restore focus or clear a compatibility notice. An explicit Retry, failed/suspended preparation, replacement at the same path or a new Home lifetime must still start valid work.

**E20 / UI-VS-01, 02.** Repeated A during every yield/load/build stage; controlled completion inside the cancellation gap; A→B→A; failure→Retry; save failure; same-path replacement and Home detach/recovery. Count generations, builder starts, candidate disposal, engine request/terminal collection pairs and useful completion. Accept only preserved selection/persistence behavior with less duplicate preparation; this is not a new multi-consumer loader.

## D03: One selection UI transaction

**Observed.** On an attached, ready Home, a normal catalog activation executes `_update_catalog_texts()` in [the optimistic request](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L805-L816), again in [_refresh_selection](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L1398-L1454), and again in [_update_texts](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L1984-L2009). Each [loops over every catalog row](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L874-L885), resolving names/metadata and assigning text, tooltip and pressed state. That route performs **3N row visits**: 39 for 13 rows, 300 for 100. Arrow navigation skips the optimistic pass and has a different count. This excludes other work and does not prove three rendered layouts.

At least three responsive-layout calls are queued on the normal successful ready-Home route: `_update_texts` refreshes the stock notice and queues layout itself, and AppRoot's post-save notice queues it again. [_set_stock_selection_notice](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L1820-L1826) has no pending-layout guard. More error/notice routes may add work. Deferred calls are scheduled calls, not an application-level deduplication mechanism; equal text assignments may be optimized internally, so profile actual layout/render effects.

**Smallest candidate.** Separate selection styling from translated catalog text. For unchanged roster/locale/text scale, update the old and new selected rows and the selected pane once. Build one dirty-state transaction for selection, skin, notices and responsive layout, with an explicit pending-layout flag that clears when applied. Preserve full invalidation for locale, roster revision, content, resize and theme changes. Coalescing must publish immediate selected identity and retain native focus and scroll reveal.

**E21 / UI-VS-01, 07.** Instrument row visits, lookup calls, queued/executed layout work, property changes and first feedback draw for catalog and arrow routes separately. Check error notices, retained-stock selection, locale/text scaling, resize and focus/scroll restoration with 13/100/1,000 metadata entries. This improves the current control tree before or alongside virtualization; it does not make the current tree viewport-bounded by itself.

## D04: Default skin resolution and the missing latency interval

**Observed.** [resolve_livery](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/render/airplane.gd#L275-L312) always obtains every livery choice, including custom archive inspection. For `wanted == ""`, its resolver returns `""` regardless of the choices. The enumeration therefore cannot change the returned identity for that case.

The ordinary [Fly route resolves the livery at lines 1384–1385](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/app_root.gd#L1384-L1422), before `_loading_started_usec` is set at 1404 and before the loading surface is pushed. [feedback_usec](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/app_root.gd#L1725-L1736) is measured from that later timestamp. It is a useful internal phase metric, but excludes resolution and other earlier handler work. Reporting it as complete input-to-feedback latency would conceal precisely the delay under investigation.

**Smallest candidate.** Return the existing default identity immediately for an empty wanted skin. Keep independent admission and fresh model/skin validation at build/launch; an empty identity is not evidence of a valid asset. For nonempty desired skins, retain exact availability/identity rules until the admitted metadata work is implemented. Do not replace current content validation with a stale Home list.

Add a timestamp at accepted UI activation and an observer for the first actually rendered matching feedback. Preserve the existing phase timestamp with an accurate name; measure `event → loading surface construction → first feedback draw → first correct preview/flight draw`. Signal-driven automation must be labeled as such, not hardware input latency. The user-facing delay is reduced only if the complete interval improves.

**E22 / UI-VS-00, 01.** Empty/default versus named stock/custom, no installed skins versus 32 valid installed skins, and malformed unrelated archives. Assert identical default identity and later rejection of invalid selected assets; count enumerations, archive inspections and bytes before feedback. Include ordinary aircraft, helicopter and non-Home route guards. The early return is an output-equivalent fast path, not permission to weaken launch admission.

## D05: Initialize Home once from its actual selection

**Observed.** [_home_setup](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/app_root.gd#L744-L788) resolves the actual aircraft skin through [_livery_for](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/app_root.gd#L1220-L1222). Constructing Home ends by [selecting its default aircraft](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home.gd#L747-L749). AppRoot then installs livery preferences, selects the actual aircraft again and only afterward applies a remembered activity. The selection refresh clears the choice identity and rebuilds it.

For an ordinary default-aircraft Home with no activity, the current sequence can enumerate that family's choices **three times**: setup resolution, constructor selection and installed selection. A different remembered aircraft enumerates its family twice plus the constructor's unrelated default family. A remembered activity still pays default/remembered-aircraft initialization before its final activity selection. These are call counts, not three guaranteed costly ZIP scans: empty directories and family support change the work inside each call. D04 removes the setup enumeration when the desired skin is empty, but does not solve constructor replay.

**Smallest candidate.** Give Home one complete, resolved initial selection/preferences snapshot before deriving labels, skins and details. Either use an explicit initialization method with delayed first refresh, or a compatible constructor argument and one final commit. Reuse metadata only within the accepted revision; retain standalone/test construction defaults and a valid initial scene skin. One initial transaction should not expose an intermediate wrong-aircraft label or launch tuple.

**E23 / UI-VS-01, 06.** First launch and Home recreation with default aircraft, different aircraft, saved car/quad/blimp and unavailable custom skin. Count family enumeration and UI refresh passes and observe the first displayed/launchable identity. Include changed directory contents, stale preference recovery and statistics-service installation. Compare D04 and D05 separately so their benefits are not double counted; keep full-state persistence and newer update-channel settings intact.

## D06: One verified skin inventory transaction

**Observed.** The MoonRunner/X8 compatibility route uses two alias directories. [Inventory merges matching filenames](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/aircraft/custom_skin.gd#L130-L178) after `_same_archive` verifies identical bytes; each [_path_for](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/aircraft/custom_skin.gd#L241-L259) repeats that comparison. `_same_archive` hashes both complete files after its size/limit checks. [_load_id](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/aircraft/custom_skin.gd#L307-L334) then reads an immutable archive snapshot for [_inspect](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/aircraft/custom_skin.gd#L337-L396), which writes temporary ZIP bytes, inspects contents and computes another digest.

For **32 distinct valid archives, each identically duplicated in both alias directories**, there are 64 directory entries, 32 inventory pair comparisons and 32 per-choice pair comparisons: **128 whole-file SHA-256 calls** just for alias equality, plus 32 selected snapshot reads/ZIP inspections. More generally, `D` compared duplicate pairs and `K` attempted duplicate choices cause `2 × (D + K)` file-hash calls on this successful comparison path. Invalid files, unequal sizes, early failures and admission limits change that count. The limit is 32 successful choices, not 32 inspection attempts. Enumeration uses `decode_textures=false`; it reads PNG data/dimensions but does not decode pixels or generate mipmaps.

**Smallest candidate.** Make the inventory operation return an internal verified path/alias receipt and reuse its bounded immutable snapshot/digest during that same enumeration. First remove duplicate comparison inside one operation; persistent index reuse remains T01/T14 work. Process archives incrementally: keeping 32 maximum-size archives at once would trade I/O for a large memory peak.

**Correctness.** Preserve whole-inventory conflict refusal, deterministic sorted first-32-valid admission, 128-entry and archive/pixel limits, filename-hash checks and full validation at actual application. Concurrent replacement/removal must not turn an old alias receipt into permission to read unchecked new bytes. Explicitly decide whether both directory entries are snapshotted for the transaction or revalidated before consuming a selected snapshot; metadata/mtime equality alone does not prove content equality.

**E24 / UI-VS-06, AC/skin owner.** Equal/different aliases, collision/rename, mutation during enumeration, invalid files before the 32nd success, corrupt ZIP and cap boundaries. Compare exact accepted IDs/order/errors, file bytes, hashes, temporary writes and peak retained snapshots. A source-count reduction is useful only if complete navigation cost and invalidation remain correct.

## D07: Reuse the Home projected-shadow renderer

**Observed.** A retained aircraft root does not imply retained presentation objects. [show_aircraft always calls Shadow.bind_model](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L194-L255), including a model-cache hit. [bind_model detaches and queues the old projector for deletion](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/render/shadow.gd#L134-L183) before installing another when the cue and shape permit it. [ProjectedShadow.setup](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/render/projected_shadow.gd#L137-L184) constructs a 256×256 MSAA viewport, private 3D world/environment, camera, proxy and receiver geometry/materials. Driver allocation/retirement is not measured by this inspection.

**Smallest candidate.** First consider a same-source/same-shape binding fast path. Then compare one Home-owned projector that rebinds source and immutable shape instead of rebuilding its viewport/world on every selection. Do not create one live viewport per cached vehicle. Separate retaining the renderer from reusing its rendered mask: a changed pose, light direction, shape or visibility may require a redraw even when the viewport survives.

**Correctness.** Disconnect the old source's signals and connect the new source; reset the shape/signature when necessary, handle stale/freeing sources, preserve cue off/on and Home teardown. Hide/show currently invalidates projection state, so a mask cannot be declared reusable merely because a node ID matches. The current [cache test](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/tests/test_ui_home_preview_cache.gd#L1-L61) checks model reuse and attached projector state, but that assertion is not a proof that the projector instance itself survived.

**E25 / UI-VS-04, 05.** A→B→A, repeat A, different skins/shapes, lighting changes, policy toggles, pending retirement and Home exit. Record projector/viewport instance IDs, allocation counts, redraws, pending retired objects, observed process/GPU peaks and first correct draw. Require unchanged shadow alignment/opacity/neutral-pose behavior. This is a more targeted first reuse experiment than transferring entire Home roots across screen lifetimes (T13).

## D08: Look up qualified light layouts before computing them

**Observed.** On an uncached night aircraft, [_build_requested_preview](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L436-L485) builds geometry and awaits `_prepare_light_layout` before inserting the candidate. Only the subsequent `show_aircraft → _update_aircraft_lights` path [looks for a compatible cached layout](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L278-L314). An eligible hit may therefore replace a layout after the async path has already computed it. This ordering differs from the synchronous `show_aircraft` path exercised by the existing cache fixture.

**Smallest candidate.** After the candidate's required neutral pose/propeller setup, attempt a qualified layout lookup before snapshot/worker computation. Require the same proof at every late lookup, including direct `show_aircraft` and the [no-worker fallback](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L359-L366). Otherwise an unproven variant can compute correctly and receive an older weak-key match at attachment, or skip computation in the direct path. Preserve a fresh accepted layout; when neither that nor a qualified cache entry exists, use the appropriate existing async or synchronous fitter. Recheck generation/content immediately before commit. Share compact immutable layout evidence; [each light attachment still owns its kit and authored anchors](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/render/world/aircraft_lights.gd#L774-L798).

**Critical limitation.** The current key includes a manifest hash, imported-builder qualification, local node transforms and landing-anchor state. It does not hash vertex positions. A common manifest plus equal hierarchy/rest transforms is not sufficient proof that two different livery GLBs produce identical derived geometry. Initially reuse only evidence for an exact accepted base mesh/revision, or require the model owner to generate an explicit equivalence identity covering all layout inputs. Do not enlarge the current cross-livery assumption as part of this optimization. Test a deliberately changed vertex layout with otherwise equal counts/transforms.

**E26 / UI-VS-04, 11.** Exercise both the production asynchronous request and direct-show/no-worker paths: night first miss, qualified second skin, cache eviction, changed pose/geometry/hash/anchor and cancellation. Count snapshots, worker submissions and layout computations as well as first draw. Assert the final attached kit/layout in every route, not only that a worker ran. A verified eligible hit should avoid redundant computation; an unproven variant must compute and retain its own result through attachment. Extend the existing cross-livery parity fixture to both lookup sites. Disable the optimization if preserving its proof costs more than the useful work it avoids.

## D09: Make the numeric-worker barrier stage-specific

**Observed.** [_build_requested_preview waits while preview_geometry.busy](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L436-L469) before it builds any uncached model. The private geometry computation uses value snapshots and has one drain owner; [cancel_for drops its callback without preempting the worker](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_preview_geometry.gd#L102-L146). Yet this path needs the numeric night-layout stage only for an eligible non-vehicle, non-rotorcraft aircraft at night. [_prepare_light_layout already waits for its worker slot](https://github.com/bultodepapas/OpenRCsimulator/blob/a7de9b35676d891bc2034cc344b910d9e1ef9c61/app/ui/home_scene.gd#L489-L507).

Consequently, an obsolete expensive night layout can hold up an uncached car, quad or daylight candidate even though that new preview will not use this stage. Retained-model hits take another path; the claim is scoped to misses through this barrier.

**Smallest candidate.** Keep single-worker ownership and terminal drain, but reserve/wait at the actual numeric stage. Permit earlier main-thread model work only when the admission ledger can cover the old snapshot/worker plus the new candidate and CPU pressure permits it. There is no free-overlap assumption: moving the barrier can increase contention and memory peaks and may be rejected on constrained hosts.

This numeric barrier is distinct from the dedicated flight-scene ResourceLoader safety gate. Do not unpause the preview resource broker while that scene job is active, kill the worker, or allow abandoned results to reach the new selection. A changed night/day setting and Home teardown must still cancel consumers safely.

**E27 / UI-VS-02, 05.** Hold a controlled old numeric job; request a car, quad, daylight aircraft, night aircraft and retained hit separately. Measure wait reason/duration, admitted overlap, old snapshot plus candidate peak, frame cadence and matching final draw. Include light-setting changes, rapid reversal and Home exit. Accept only a complete latency improvement within the same qualified memory/concurrency policy; keep the original barrier as fallback if pressure or contention dominates.

## D10: Reuse verified inputs within one build
