## 21. Native ENet DTLS setup and the missing trust bootstrap

**Useful material.** The [pinned ENetConnection documentation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/doc_classes/ENetConnection.xml#L88-L101) requires server `create_host_bound` → `dtls_server_setup(TLSOptions.server(key, cert))`, and client `create_host` → `dtls_client_setup(hostname, TLSOptions.client(trusted_chain, expected_name))` → `connect_to_host`. [TLSOptions](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/doc/classes/TLSOptions.xml#L25-L40) validates the CA chain and expected name; `client_unsafe` makes validation optional and skips name checking. The pinned wrapper actually rejects a null client options object, despite documenting a null default, so pass an explicit client configuration and check all errors.

**New finding.** [High-level `create_client`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/enet_multiplayer_peer.cpp#L76-L104) calls `connect_to_host` before exposing `host`. However [vendored `enet_host_connect`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/host.c#L245-L263) queues CONNECT; it does not itself flush it. Creating the high-level client, setting DTLS before *any* poll or flush, and proving behavior is therefore a candidate experiment, not documented-order support. Mesh/custom adapters require separate routing and server-identity proof. An independently verified certificate/CA and expected name are required; self-signing or copying a certificate from the same unauthenticated discovery response proves no host identity. No exact leaf-fingerprint enforcement is established by these APIs. DTLS server authentication plus a bearer capability does not authenticate a named guest.

**Next experiment — optional MP-03, judgment 2–4 days.** Before advertising confidential Internet invites, try explicit options and immediate setup on pinned native builds, with capture: require encrypted traffic, independently provisioned trust, and rejection of wrong CA/name, plain ENet and altered records without fallback. The [application auth timer starts when the peer is added](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/multiplayer/scene_multiplayer.cpp#L357-L362); it does not bound pre-connect DNS/DTLS. Test the protocol's separate owner connect deadline, five-second auth deadline, cancel and late completion. Stop on ordering, identity, fail-closed or interoperability uncertainty. Local test certificates add no service fee; public identity distribution is unselected and may add cost.

## 22. High-entropy invitation capabilities

**Useful material.** Pinned [Godot Crypto](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/doc/classes/Crypto.xml#L78-L109) offers cryptographically secure `generate_random_bytes` and `constant_time_compare`; the [bundled implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/mbedtls/crypto_mbedtls.cpp#L524-L533) calls `psa_generate_random`. [RFC 6750](https://www.rfc-editor.org/rfc/rfc6750.html#section-1.2) describes the essential bearer property: possession suffices; that principle applies here even though this is not an OAuth protocol.

**Finding and candidate.** Generate 16 independent random bytes per invitation, fail closed if the returned length is not exactly 16, encode as 32 fixed hex characters, parse strict length/alphabet, and use the engine comparison. The existing 64-bit room incarnation is public and distinct. If bytes are uniform, even one million independent guesses against one fixed 128-bit token have probability at most about `10^6 / 2^128 ≈ 2.94 × 10^-33`; entropy does nothing against observation, theft, replay, host impersonation, or denial of service. Share the capability through a user-chosen private channel. Never put it in public room listings, telemetry, logs, crash reports, error messages, or URLs sent to third parties.

For MP-03 candidate admission, issue at most four simultaneously active, individually revocable, single-use tokens, each expiring after ten monotonic minutes. Retire atomically on successful admission or host teardown. Add a global and per-source token bucket alongside the existing one pending applicant/five-second deadline; candidate starting limits 30 attempts/minute globally, five/minute/source with small bursts, tuned for shared NAT and accessibility. These limits are implementation judgments, not DDoS protection, and a hostile peer can exhaust availability. Do not design a custom password protocol.

**Next experiment — MP-01a/03, judgment 1–2 days.** Fixture tests must reject malformed/expired/revoked/replayed tokens, preserve redaction, and bound failed admissions. Then, only after verified host-authenticated encryption from 21, test the complete invite flow and active impersonation. Plain ENet exposes the capability and does not authenticate either endpoint; friendly LAN remains explicitly limited. Bundled crypto adds no hosted service or account cost.

## 23. ENet MTU, fragmentation, and pre-application limits

**Useful material.** The [pinned bundled ENet constants](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/enet/enet.h#L220-L224) set a 1,392-byte default ENet MTU, 32 MiB maximum packet and 32 MiB waiting-data threshold; the adjacent pinned `thirdparty/enet/enet/protocol.h` constants allow negotiated MTUs 576–4,096 and up to 1,048,576 fragments. These are engine limits, not OpenRC limits. Godot's public wrapper reports a 16 MiB `get_max_packet_size`; it is not a path MTU or pre-reassembly admission guard. [ENet reassembly](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/peer.c#L956-L992) checks whether already-waiting data exceeds the threshold *before* allocating the next packet, so it is a threshold, not a strict total-memory ceiling.

**Finding.** [RFC 8085 §3.2](https://www.rfc-editor.org/rfc/rfc8085.html#section-3.2) warns about IP fragmentation; [RFC 8899](https://www.rfc-editor.org/rfc/rfc8899.html) describes DPLPMTUD and RFC 8200's IPv6 minimum link MTU is 1,280 bytes. A 1,392-byte ENet UDP payload plus 40-byte IPv6 and 8-byte UDP headers exceeds 1,280 before DTLS or tunneling. Even a 128-byte pose cannot prove every datagram fits: ENet can aggregate commands and acknowledgments, and DTLS adds overhead. There is no demonstrated DPLPMTUD or exposed Godot setter for this host MTU/reassembly limit.

**Next experiment — MP-02/03, judgment 2–4 days for investigation; engine/adapter changes unestimated.** Preserve the existing 128-byte pose and ≤1,024-byte control envelopes. For public stranger rooms, initially require independently enforceable limits of ≤2 KiB transport record, ≤64 KiB aggregate reassembly per admitted peer, ≤4 KiB before admission, one pending admission, ≤64 KiB/s per peer with 16 KiB burst, and ≤128 processed datagrams per poll; these are provisional engineering budgets, not existing enforcement. Aim for ≤1,200-byte UDP payload on the tested path, including aggregation and DTLS, not a universal PMTU guarantee. Test oversized/incomplete fragments and captured IPv4/IPv6 under reduced MTU; pass only when allocation, CPU, rate, and actual datagram limits hold before application decoding. Stop public admission if the stock transport cannot enforce them. Existing equipment only; no service fee.

## 24. Throttle, send results, and bounded backpressure

**Useful material.** The [pinned peer API](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/doc_classes/ENetPacketPeer.xml#L117-L127) exposes `throttle_configure`: ENet adjusts unreliable-send probability using reliable RTT and configured bandwidth. [Host construction and bandwidth code](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/host.c#L13-L25) defines incoming/outgoing limits in bytes per second, zero meaning unlimited; they also affect the reliable in-flight window. Godot exposes host `bandwidth_limit`, per-peer throttle and statistics. These knobs are not proof of fairness, delivery, an absolute incoming firewall, or bounded queues.

**New correction.** In the [pinned high-level send](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/enet_multiplayer_peer.cpp#L333-L413), `put_packet` invokes `ENetPacketPeer::send` and flushes but ignores that lower-level return before returning `OK`. Thus even local queue acceptance is not proved by a successful high-level return, much less remote receipt or application. Existing application ACK-after-apply remains necessary. The unreliable channel is explicitly unsequenced; entity sequence guards remain required.

Keep one replaceable latest unsent pose per entity/recipient; skip missed 20 Hz deadlines rather than enqueue a burst. Keep at most eight unacknowledged controls and the existing five-second ACK deadline; failure closes or degrades the connection, never adds an unlimited application retry queue atop ENet reliability. Expose bounded telemetry for bytes, drops, throttle and RTT; acknowledge that public Godot API does not expose or cap all transport queue bytes. Avoid promising a hard Internet bandwidth ceiling from throttle alone.

**Next experiment — MP-02a/04, judgment 1–3 days.** Test a connected peer under controlled loss, slow receive and temporary poll stalls; include deliberate lower-send failure through a test adapter. Pass if the latest pose replaces old unsent data, controls either apply once or time out visibly, memory/poll work reaches a measured plateau, and no `OK` becomes a delivery claim. Stop public use if transport growth cannot be bounded. Built-in engine code; no vendor or hosted cost.

## 25. Endpoint grammar, IPv6 zones, and DNS cancellation

**Useful material.** [Pinned `connect_to_host`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/enet_connection.cpp#L84-L112) accepts a separate address and 1–65,535 port and calls blocking `resolve_hostname` when given a name. The [IP class](https://docs.godotengine.org/en/stable/classes/class_ip.html) also provides queued resolution, status, result and erase APIs. The [pinned IPv6 parser](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/io/ip_address.cpp#L62-L123) handles colon-form IPv6 but rejects a `%zone` suffix; do not claim scoped link-local join support without a suitable adapter and platform tests.

**New finding.** The [pinned resolver implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/io/ip.cpp#L79-L106) releases its lock during lookup, then checks only whether the slot is `WAITING`; `erase_resolve_item` marks the slot `NONE`. If a canceled in-flight ID is immediately reused, an old lookup can complete into the newly waiting slot. A UI session generation alone cannot detect that misattributed answer. The implementation also has a fallback that resolves inline if its thread has not started; async behavior must be verified on the actual build.

Offer separate host and numeric port fields; if accepting pasted combined endpoints, parse `[IPv6]:port` brackets explicitly, never split all colons. Reject control characters, empty/wildcard remote hosts, invalid brackets, unsupported `%zone`, and out-of-range ports; cap input at 253 host bytes and 5 port digits. Resolve asynchronously first, pass a selected numeric result to ENet, retain the original name for TLS verification. A canceled/timed-out lookup must keep its ID reserved until it completes, then discard and erase; bound abandoned lookups and report resolver unavailability rather than recycling unsafe IDs. A stalled DNS worker can still stall future lookups; direct IP remains usable.

**Next experiment — MP-02b, judgment 1–2 days.** Unit-test IPv4, compressed IPv6, bracket syntax, scoped rejection, invalid input and port boundaries. With a deterministic delayed resolver, cancel A then request B; require B never receives A and the UI deadline returns without blocking. Stop hostname support on a stale-result or blocking failure. No DNS provider, account, or paid service is required.

## 26. Desktop firewall, local-network privacy, and export settings

**Useful material.** [Microsoft](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/rules) documents inbound firewall rules and user/admin prompts; profiles and policy can change the outcome. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) says local-network privacy on macOS began in 15: sending UDP unicast to a local address requires access, while receiving unicast alone does not. A host still has to send responses. The operation may initially fail while a prompt is pending; retry within a bounded deadline. Apple recommends an Apple-issued signing identity for reliably tracking macOS program identity, and says the iOS multicast entitlement is not required on macOS.

**Pinned export finding.** OpenRC's `app/export_presets.cfg` at the stated commit lists Linux x86-64, Windows x86-64, and universal macOS; macOS explicitly chooses `codesign/codesign=1` and `notarization=0`. In [pinned Godot export code](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/platform/macos/export/export_plugin.cpp#L501-L541), `1` selects built-in ad-hoc signing. The same code defaults app sandbox and network client/server entitlements to false, and provides `application/additional_plist_content` for a future `NSLocalNetworkUsageDescription`; the preset does not explicitly configure those fields. Verify the resulting bundle rather than assuming defaults or current permissions. If a later build enables App Sandbox, configure and test both network-client and network-server entitlements for UDP. A future [Flatpak](https://docs.flatpak.org/en/latest/sandbox-permissions.html) has its own `--share=network` permission; a normal Linux export is not automatically a Flatpak.

**Next experiment — MP-02c, judgment 2–3 days plus available native testers.** Inspect built plist/signature and test allowed/denied local access, pending prompts, retry and both host directions on each intended OS/build, including Windows private/public profiles and a sandboxed package only if adopted. Report OS/build/signing and generic connection failure honestly; do not automatically modify firewall rules or ask users to disable protection. Stop claims for any untested combination. Ad-hoc/local testing has no added service cost; Apple-issued distribution signing may require a paid program and is outside the zero-cost core.

## 27. Strict control JSON before Godot parsing

**Finding.** In the pinned Godot build, the [JSON parser](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/io/json.cpp#L201-L540) converts numbers to `double`, accepts trailing commas and overwrites earlier duplicate keys. Thus `{"id":1,"\u0069d":2}` loses evidence of the duplicate and integer `9007199254740993` cannot survive exactly. [RFC 8259](https://www.rfc-editor.org/rfc/rfc8259.html) specifies JSON grammar and warns that duplicate-name behavior differs. The pinned [`PackedByteArray` conversion](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/variant/variant_call.cpp#L747-L753) discards the UTF-8 decoder's error; the [decoder](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/string/ustring.cpp#L1756-L1922) skips a leading BOM, replaces malformed bytes, and stops at NUL. Checking the resulting dictionary alone is too late.

**Decision.** For the existing four-byte prefix and ≤1,024-byte total limit, scan the bounded bytes first: validate UTF-8 without replacements, reject BOM and raw NUL, then enforce RFC grammar, decoded-key uniqueness per object, valid escapes/surrogates, no decoded NUL and container depth ≤4, counting the root as depth 1. The scanner must understand strings and escapes; a bracket-counting regex is insufficient. Only then call `JSON.parse`, validate allowed fields and ranges in detached data, and commit atomically. Keep u32 fields exact and finite; use the plan's bounded decimal strings for microseconds/ticks. Feed serialized escaping and both raw/decoded byte lengths into investigation 37's per-message budget, without deciding that schema here.

**Next experiment — MP-01a, estimated 1–2 days.** Compare a bounded independent Python `json.loads(..., object_pairs_hook=..., parse_constant=...)` oracle and the future Godot scanner on duplicate escaped keys, `[1,]`, raw/escaped NUL, overlong/truncated UTF-8, surrogates, `1e999`, 2^53±1 and depths 4/5. Wrap the oracle with the same pre-depth and Unicode checks and explicit finite/range rules; Python defaults alone do not enforce this policy. A post-decode round trip, `bytes == bytes.get_string_from_utf8().to_utf8_buffer()`, is a useful fixture, not a substitute for pre-validation. Pass only on agreement for the specified stricter policy and zero mutation on refusal; stop if scanner and engine disagree on accepted values. No install, service or new dependency; Godot is MIT and Python is used as a local test oracle. No parser was run in this research.

## 28. International player names and literal UI

**Finding.** Godot's pinned [`LineEdit` limit](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/scene/gui/line_edit.cpp#L2466-L2474) uses `String.length()`, not encoded UTF-8 bytes. Sixteen `é` characters need 32 UTF-8 bytes, while their JSON escape spelling may occupy more wire bytes. The pinned [RichTextLabel implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/scene/gui/rich_text_label.cpp#L7576-L7589) parses markup when BBCode is enabled; the official [BBCode example](https://docs.godotengine.org/en/4.5/tutorials/ui/bbcode_in_richtextlabel.html#escaping-user-input) explains escaping. [Unicode UAX #9](https://www.unicode.org/reports/tr9/tr9-52.html) describes bidirectional isolation.

**Proposed policy.** After strict decoding, accept a nonempty, at-most-32-byte UTF-8 display name. Reject C0/C1 controls, U+2028/U+2029, and explicit bidi embedding/override and isolate controls U+202A–U+202E and U+2066–U+2069; return a clear input error rather than silently truncating. This is an explicit usability tradeoff: some legitimate formatted names use those controls, and the 32-byte cap also excludes some longer international names. Permit RTL letters, accents, combining marks, emoji, ZWJ/ZWNJ and directional marks; do not normalize or case-fold without a separately pinned policy. Render the name in a separate plain-text control from trusted status and entity ID, or use trusted bidi isolation with no user-provided terminator. A displayed name is not an identity or authentication claim.

```gdscript
# name_label is a RichTextLabel; a plain Label is also suitable.
if display_name.to_utf8_buffer().size() > 32:
    return false # show a clear validation error
name_label.bbcode_enabled = false
name_label.text = display_name
```

**Next experiment — MP-01a/02b, estimated 0.5–1 day.** Check Latin, Arabic/Hebrew, Persian ZWNJ, accented/decomposed text, emoji sequences, brackets/BBCode and 31/32/33-byte boundaries; verify RTL cannot reorder adjacent trusted ID/status. Pass on literal readable output and identical local/host acceptance; stop on script shaping regressions, invisible-only ambiguity or unwanted translation. The proposed policy needs UX review; existing Godot needs no install or paid service. No visual or engine test was run here.

## 29. Bounded exploration of admission, reset and pause

**Useful material.** Lamport's [TLC/Apalache overview](https://lamport.org/tla/tools.html) distinguishes explicit-state and symbolic checking. The upstream [TwoPhase specification](https://github.com/tlaplus/Examples/blob/master/specifications/transaction_commit/TwoPhase.tla) models sent messages as a set and explicitly allows receipt twice, with no effect on repeated receipt. That safety-only abstraction is instructive, but a set loses order and multiplicity: OpenRC needs an explicit bounded queue or separate actions to expose overtaking and duplicates. TLA+ tools have an [MIT license](https://github.com/tlaplus/tlaplus/blob/master/LICENSE); pin and check a tool release before any later import.

**Decision.** Start with an existing-Python standard-library breadth-first state exploration; no new tool is necessary. Model two applicants competing for one slot, two connection generations and two flight epochs, with bounded delayed/duplicate events. Actions include HELLO/ACCEPT/AUTH_ACK, cancellation, commit/refuse reset, pause heartbeat, final PAUSED pose, baseline and old completion. Check one owner per slot, no mutation by old generation, no future-epoch motion before baseline, and at most one final correction per status revision. Retain a shortest counterexample, state count, depth, initial conditions and transition definitions.

```python
while queue:
    state, trace = queue.popleft()
    assert invariant(state), trace
    if len(trace) < 12:
        for event, next_state in successors(state):
            if next_state not in seen:

```

## 30. Cancellation and stale async completions

**Finding.** The pinned [GDScript await implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/gdscript/gdscript_vm.cpp#L2560-L2655) connects a one-shot continuation to the awaited signal; a logical cancel flag does not itself stop a worker or close its resources. The [SceneTree timer](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/scene/main/scene_tree.cpp#L794-L818) is tree-owned and emits later when processed. Current [AppRoot exit handling](../../../app/app_root.gd#L3462) already compares request/dialog generations; [Main's preparation cancellation](../../../app/main.gd#L637) drains an owned operation without awaiting a coroutine belonging to the detached session. Neither is a multiplayer implementation.

**Decision.** Give each host/join attempt an owner and monotonically increasing local generation, separate from the wire room nonce. On cancel/Home/quit/disconnect, invalidate the generation first, close admission, prevent new work, disconnect owned signal connections, and queue idempotent peer/socket/replica teardown after the current `SceneMultiplayer.poll()` returns. Track in-flight loading/worker resources independently of whether a callback ever arrives. A late completion may dispose only its own unadopted result and cannot touch a replacement session. Use monotonic deadlines checked by the owner; a timer is a wakeup, not cancellation, and a blocked event loop cannot execute it on time.

```gdscript
func _join_finished(gen: int, result) -> void:
    if gen != current_generation or shutting_down:
        dispose_unadopted(result)
        return
    pending_events.append(result) # apply outside poll/callback
```

**Next experiment — MP-02a/b, estimated 1–2 days.** Use the existing checked runner with controlled completion seams: cancel before and during loading, retry with the same peer ID, timeout as completion fires, disconnect during poll, Home, quit and a never-emitted signal. Pass when no old UI/state change occurs, each owned resource is retired once, and offline controls return safely. Stop if worker ownership or teardown after an indefinitely blocked process cannot be bounded. Existing engine/tools; no service or install. Experiments remain pending.

## 31. Reliable transport is not an applied control

**Finding.** Pinned [`send_bytes`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/multiplayer/scene_multiplayer.cpp#L439-L455) returns the send-command result, not a remote state-commit receipt. ENet's [packet path](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/enet_multiplayer_peer.cpp#L333-L392) selects reliable transport and flushes outgoing data; it does not validate ROOM or apply BASELINE. Godot's [signal emission](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/object/object.cpp#L1256-L1313) allows callbacks during emission, while [`poll()`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/multiplayer/scene_multiplayer.cpp#L81-L143) invokes application processing. Reentrancy must be an explicit state-machine concern.

**Concrete failure.** Suppose a test transport or callback synchronously reports the ACK for ROOM 1 from inside `send()` before the sender inserts ID 1 into `pending`: the ACK is ignored, the subsequently inserted entry never clears, BASELINE 2 remains gated, and the five-second timer fails a successful exchange. This is a deliberately reentrant seam, not a claim that stock ENet receives a network ACK synchronously. Similarly, notifying observers before committing the expected receiver ID can let a reentrant duplicate apply ROOM twice.

**Decision.** Allocate the contiguous per-direction ID and reserve pending capacity *before* invoking the adapter. A send failure must fail/teardown the generation without leaving a sequence gap. On receive, validate and commit the whole operation plus next ID before observer notification; then ACK successful application. Duplicate applied IDs must not mutate and may re-ACK; gaps and unexpected ACKs follow an explicit bounded failure policy. ACK ROOM after its own roster/config commit, without waiting for BASELINE or READY; otherwise gating BASELINE on that ACK deadlocks. READY additionally requires local load and required baselines. Retire pending state on generation renewal and reject old ACKs. Defer destructive actions until poll returns.

**Reconnect refinement.** Pinned ENet checks [address/session fields](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/protocol.c#L1024-L1050), but its [session mask is two bits](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/enet/protocol.h#L52-L53). Do not infer indefinite old-wire separation from a local callback generation. The protocol now requires a fresh client-attempt challenge echoed by ACCEPT, a fresh host connection nonce echoed by AUTH_ACK, and the current connection context on every post-auth JSON frame. Binary poses retain never-reused entity ownership and baseline/sequence guards. Replay old ACK/control/pose bytes through repeated reconnects; exploitability is untested, and public nonces do not authenticate cleartext peers. Investigation 37 includes their byte cost.

**Next experiment — MP-01b/02a, estimated 1–2 days.** Force inline/delayed/duplicate ACK, observer reentry, send failure, stale generation, and ID 6 before 5. Fill all eight pending slots; refuse the ninth or hold an unassigned update in a separately bounded/coalesced slot, with no unbounded retry list. Never coalesce already assigned IDs. Each ≤1,024-byte control yields at most 8,192 framed control bytes in eight slots; retain the plan's separate 64 KiB overall cap. Pass only with one commit per ID and timely cleanup after five seconds. Existing tools only; no install or service. No transport test was run.

## 32. Liveness, ENet pings and NAT refresh

**Finding.** [RFC 4787 §4.3](https://www.rfc-editor.org/rfc/rfc4787.html#section-4.3) requires conforming ordinary UDP mappings to last at least two minutes, with a well-known-port exception and an outbound-refresh requirement; actual middleboxes can differ. [RFC 8085 §3.5](https://www.rfc-editor.org/rfc/rfc8085.html#section-3.5) discourages generic keep-alives, recommends no faster than 15 seconds when needed and slight jitter, and advises graceful recovery from broken sessions. The pinned [ENet defaults](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/enet/enet.h#L226-L239) are a 500 ms ping interval, timeout limit 32, minimum 5,000 ms and maximum 30,000 ms. Its [actual ping/timeout logic](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/enet/protocol.c#L1351-L1649) has queue/receive conditions and retransmission backoff, so those constants are not a guaranteed periodic ping or fixed disconnect deadline.

**Decision.** Retain 1 Hz entity-state HEARTBEAT and a five-second steady-state direct-connection detector. The host times guests and owns removal; guests time the host and separately mark aircraft stale without editing membership. After local auth, immediately send `SESSION_HEARTBEAT`, repeat at 1 Hz, and allow a bounded 10-second peer-activity grace before ordinary controls: remote auth completion can arrive later. ACCEPT supplies room/connection context for manual joining. First fresh, context-valid, phase-legal peer traffic confirms activity and starts steady-state liveness. Keep session heartbeats through loading/READY, bounded to 120 seconds including grace; afterwards suppress the idle fallback only when phase-valid traffic supplies liveness. These are application messages, not generic NAT refresh; measure aggregate ENet/probe/status traffic. A paused owner can poll; a blocked/sleeping one cannot. Silence alone cannot identify the cause; end safely and re-admit after loss.

**Next experiment — MP-02c/04, estimated 1–2 days plus the existing soak.** Record last-valid time, sequence, poll gaps and disconnects for delayed final auth completion (4.5 s), lost first heartbeat, manual join, 10-second pauses, healthy >5 s pre-baseline load, blocked load, sleep and burst loss. In three processes, keep host/A live while B is silent: only the host removes B. Under hypothetical independent 2% loss, five missed 1 Hz packets have probability `0.02**5 = 3.2e-9` per specified window; correlated loss/scheduling invalidate treating that as a real false-positive rate. Pass only with correct startup/live/frozen/loading behavior, bounded cleanup and measured false-disconnect exposure. Stop Internet qualification on unacceptable traffic/false positives. Existing machines/tools; no experiment, install or service was run.

## 37. Control-message size, escaping and late-join budgets

**Useful material.** [RFC 4648 §4](https://www.rfc-editor.org/rfc/rfc4648.html#section-4) defines padded Base64; a 128-byte pose therefore occupies `4 × ceil(128/3) = 172` characters. Python's [JSON encoder](https://docs.python.org/3.12/library/json.html#json.dumps) documents compact separators, Unicode escaping and nonfinite-number policy. These are useful for an independent size model, not proof of Godot's serialization or of a valid control schema.

**Delivered evidence.** The standard-library [control_budget.py](../../../research/multiplayer/control_budget.py) and [18 generated cases](../../../research/multiplayer/control-budget.json) count UTF-8 JSON plus the four-byte prefix, including the new per-connection context. The exact candidate four-pilot ROOM with 32-byte quote-only names is **842 bytes**; one BASELINE is **414**, and a bundled ROOM plus four baselines is **2,500**, which fails the 1,024-byte limit. Separate ROOM + four BASELINE frames total **2,498 bytes**, excluding ACK/auth/transport overhead. They require distinct contiguous IDs and ROOM application/ACK before dependent baselines; the per-shape maximum-ID placeholder is not a usable session sequence. Pre-baseline heartbeat and HELLO/ACCEPT/AUTH_ACK shapes are also measured.

Size depends on spelling: four accented names are 714 bytes in the direct UTF-8 candidate, 970 when ASCII-escaped; legal six-byte escapes for every ASCII name character make the same four-name shape **1,354 bytes**. Eight quoted names fail at **1,226**, while eight plain ASCII names fit at 970. These are specific counterexamples, not a proof that every four-player schema fits or every eight-player schema fails. Unknown `padding` shapes isolate exactly 1,024/1,025 bytes; neither is an admitted message. Synthetic Base64 content is deliberately not a valid pose.

**Decision / next experiment — MP-01a/04, 0.5–1 day within codec work.** Keep individual bounded baselines, measure the actual Godot encoder, pin exact allowed fields/digest coverage, and test largest allowed serialized values plus malformed inputs from 27. Pass only if each supported shape fits before transport and the pending window stays bounded. Reject oversize input before decoding; do not truncate names or silently raise the envelope. No packages or service; the final schema and runtime codec remain pending.

## 38. Fast rolls can alias between valid quaternion snapshots

**Useful material.** The pinned [Godot slerp implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/math/quaternion.cpp#L106-L155) flips a negative dot-product endpoint to select the shorter path. The official [Quaternion documentation](https://docs.godotengine.org/en/stable/classes/class_quaternion.html#class-quaternion-method-slerp) requires normalized inputs. **Delivered counterexample.** [rotation_sampling.py](../../../research/multiplayer/rotation_sampling.py) and [five analytical cases](../../../research/multiplayer/rotation-sampling.json) use a constant single-axis rotation, without running a flight. At 100 rad/s across 0.05 **simulation-seconds**, the true rotation is 286.478898°, but the equivalent shortest endpoint rotation is −73.521102°; midpoint orientation error is **180°**. This is inside the proposal's broad per-component outer guard, not a measured stock-aircraft rate. At 40 rad/s across 0.1 simulation-seconds the same problem appears; relating that gap to one lost 20 Hz wall-time sample assumes a 1:1 simulation/wall ratio. A full turn between endpoints can appear stationary.

**Decision / next experiment — MP-01c/04, 1–2 days within motion qualification.** Retain 20 Hz as an unqualified starting candidate. Compare accepted stock trajectories after resampling at 20/30/40/60 Hz with loss and slowdown. The analytical errors compare equal simulation-time fractions; interpreting these as wall-time fractions requires linear simulation progression within that bracket. Prove or conservatively bound rotation over supported gaps; endpoint rates and tick-sampled quadrature alone do not establish a within-tick bound. A path-length bound below π excludes wrap ambiguity but does not prove ≤2° error for changing axes/acceleration; include the π tie. Freeze/mark stale beyond a qualified gap or revise rate/representation if the target fails. Do not switch blindly to `slerpni` or feed network state into the solver. ## 39. Background loading does not guarantee continuous networking

**Useful material.** Godot's [background-loading tutorial](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html) warns that `load_threaded_get()` blocks if called before completion. Its [thread-safety guide](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html) limits active SceneTree access from workers. OpenRC already has [frame-yielding preparation and owned loading jobs](https://github.com/bultodepapas/OpenRCsimulator/blob/08f948265d40d83fbb4726a302b9e1c9490ccfce/app/app_root.gd#L1735-L1793), so reuse those boundaries. **Finding.** `PROCESS_MODE_ALWAYS` allows processing during a tree pause; it does not run a callback while its thread is blocked. The proposed once-per-render network owner consequently stops forwarding, polling and emitting status during an indivisible main-thread load, shader/driver stall or OS sleep. Even a threaded resource load does not make later instantiation, texture upload or scene construction automatically nonblocking. A five-second deadline cannot execute on a frozen owner. The other peers may already have ended the session when that owner resumes.

**Decision / next experiment — MP-02b/c, 1–2 days within lifecycle work.** Instrument monotonic gaps between polls and staging checkpoints during cold/warm loads, worker-start refusal, cancel/retry, host/guest menus and 1 s/over-5 s injected stalls. Use the existing preparation owner; publish PAUSED before a known transition and keep frame-yielding work bounded. A pause still needs status/liveness, so it is not an exemption from the failure detector. On lost connection, invalidate its generation and require fresh admission; never flush a stale pose/control backlog after resuming. Pass if peers remain correctly live/frozen or follow the documented bounded loss/offline path, with no unsafe auto-resume. For the first LAN slice, leave before unsupported loading operations. Moving `SceneMultiplayer.poll()` to a worker requires a separately reviewed transport-only ownership design; defer it. Existing machines/engine tools only; no threading or runtime experiment was executed here.

## 40. Compression is an optimization with recovery costs

**Useful material.** Pinned [ENetConnection documentation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/doc_classes/ENetConnection.xml#L37-L45) requires a matching compression mode on peers; the [implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/modules/enet/enet_connection.cpp#L474-L523) dispatches bounded-buffer decompression and supports none, range coder, FastLZ, Zlib and Zstd. The official [mode guidance](https://docs.godotengine.org/en/stable/classes/class_enetconnection.html#enum-enetconnection-compressionmode) cautions that Zstd is inefficient for packets below 4 KiB. Glenn Fiedler's original [snapshot-compression tutorial](https://gafferongames.com/post/snapshot_compression/) explains smallest-three quaternions and deltas from an acknowledged baseline; its cube precision choices are not aircraft qualifications.

**Decision.** Keep the 128-byte independent snapshots and explicitly use **no ENet compression** for the first measured LAN baseline. At four pilots, host pose egress is `(4−1)² × 20 × 128 = 23,040` application bytes/s; at eight it is 125,440, before all transport/control/retry overhead. These [capacity calculations](../../../research/multiplayer/capacity-results.json) do not justify another dependency or establish an Internet capacity. Preserve the existing float64 datum and float32 quaternion contract until a versioned alternative passes measured error and byte targets.

Delta coding introduces per-recipient baseline knowledge: if A is lost and B is encoded relative to A, B cannot be decoded. It needs acknowledged bases, bounded history, expiry, full-snapshot recovery, reset/epoch handling and independent source-versus-forwarded state. A host cannot assume every guest received the same base. Transport compression is a different layer; its decompression still occurs before application guards and cannot satisfy the hostile-input limits in 23 by itself.

**Next experiment — optional MP-07, 1–2 days for comparison only.** Capture the uncompressed four-pilot baseline, then compare none/range coder on identical synthetic and recorded traffic, measuring actual datagram bytes, CPU and loss recovery. Only if bandwidth is a demonstrated bottleneck, separately estimate a versioned quantization/delta codec and test packet/base loss, late join and malformed decompression. Stop if savings are immaterial or motion/recovery regresses. Built-in codecs add no hosting fee; source/example licensing still requires review before copying. No compression benchmark or dependency import was performed.
