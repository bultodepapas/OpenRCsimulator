# HELI-07: finite drive proxy

**Date:** 2026-10-13. **Status:** implemented and software-verified; engine and aircraft validation remain open.

The runtime drive is an explicit one-speed, torque- and power-limited proxy in [drive.gd](../../../../app/physics/rotorcraft/drive.gd). It prepares only data supplied by the aircraft loader; it contains no aircraft-specific default. At positive shaft speed it bounds commanded engine torque by the configured torque cap and `Pmax / Ωengine`, then applies the declared gear ratio and efficiency. At zero speed it remains finite and uses no RPM floor. The proportional governor targets the configured main-rotor speed; its nonzero steady speed error is expected under a P-only law.

The X-Cell research profile identifies `engine_torque_max_nm = 1.2 N·m`, `engine_power_max_w = 1800 W`, engine/main ratio `8.3`, gear efficiency `0.9`, nominal rotor speed `167 rad/s`, and the throttle curve as **estimated** inputs generated by [derive.py](../../../../research/helicopter/xcell/derive.py). They are trainer-surrogate estimates, not measured X-Cell engine data. The torque estimate was raised from `0.9` to `1.2 N·m` because the production-loader trim at the old cap could not reach the requested nominal speed under the estimated hover load.

The generated preset now trims from its actual v2 data through [rotorcraft_data.gd](../../../../app/physics/rotorcraft_data.gd), using same-stage terrain height and wake direction. At the solved hover the test records `Ω = 167.729 rad/s`, engine torque `0.962 / 1.200 N·m`, engine power `1338.8 / 1800 W`, `1.780 N·m` of remaining net main-shaft torque capacity, and `461 W` of power-cap margin. This establishes software-model authority for the configured hover case; it does not validate a real engine or aircraft.

The source paper, Gavrilets, Mettler and Feron, [*Dynamic Model for a Miniature Aerobatic Helicopter*](https://users.encs.concordia.ca/~bwgordon/mit_heli_report.pdf), derives rotor-speed coupling and discusses throttle-proportional power and `P/Ω` engine torque (printed pp. 12–14). Those equations motivate the boundary, but this finite proxy is intentionally regular at stop. It has no separate engine-speed state, starter, clutch, or freewheel slip. The runtime telemetry `one_speed_lump_preserved` only says zero-drive hold retains the configured rotor-speed state and its declared coupled inertia. It does not assert that engine inertia is included.

The generated shaft inventory contains the main-rotor and tail-rotor estimates only. Engine spin inertia is excluded because its signed spin axis is not established by the source data. A true disengaged engine cannot keep its reflected inertia inside a shared rotor-speed state; adding that behavior requires measured engine inertia and axis plus a separate engagement model.

Verification: `test_heli_drive.gd` passes 16/16 checks on Linux and Windows. Coverage includes torque and power caps, delivered power, governor response, finite stopped-speed behavior, shaft losses, and the explicit hold-proxy semantics. Generator tests and `derive.py --check` also pass. The source inventory and equations for the coupled solve are in [HELI-08](../HELI-08/README.md).
