# AV-17-R2 controller route audit

Date: 2026-10-14  
Scope: read-only audit of the gamepad-to-flight-command path after the report that pulling up causes an unexpected roll and loss of control. No runtime or profile data was changed. The code graph identified the relevant route, but its stored snippets did not match the working tree; findings below use the current source files.

## Findings

The saved profile under this installation's `user://controller_profiles.cfg` is `Gamepad Mode 2`. Its flight channels are pitch axis 3, roll axis 2, yaw axis 0, and throttle axis 1. Pitch and roll both use calibrated `[-1, 0, +1]` centered ranges, `invert: false`, deadzone `0.08`, and expo `0.30`; throttle is a centered `stick_rate` channel with inversion. These are the shipped Mode-2 defaults (`app/input/controller_profile.gd:31-73`). The supplied feedback log identifies an `XInput Controller` using a gamepad profile; its logged GUID and vendor/product pair match this saved profile's association. The saved profile contains separate channel axes and no evident pitch/roll misassignment.

The code route does not combine pitch and roll samples. `FlightSession._input()` forwards each joy-axis event to `RcInput.on_motion()` (`app/sim/flight_session.gd:569-575`); `RcInput.poll()` samples axes independently (`app/input/rc_input.gd:250-300`); and `_stick(name)` normalizes and conditions only the axis named by that channel (`app/input/rc_input.gd:330-336`; `app/input/controller_profile.gd:352-384`). Profile validation rejects duplicate flight axes (`app/input/controller_profile.gd:294-345`). The session assigns the four returned values separately to `commands`, then forms simulation inputs in roll/pitch/yaw/throttle order (`app/sim/flight_session.gd:1481-1496, 2091-2097`). The servo step likewise sends each of the first three commands to its matching servo slot (`app/sim/flight_session.gd:2695-2699`). No direct controller-path pitch-to-roll cross-axis operation was found.

The normal-rate path is significant. The product launcher chooses `normal` unless `--rates=full` is supplied (`app/main.gd:467-478`). Avanti normal settings are 50% aileron, 50% elevator, and 80% rudder travel, with aircraft expo `0.20`, `0.40`, and `0.60` respectively (`app/data/aircraft/sebart_avanti_s_a200.json:1425-1463`; source provenance points to the SebArt manual, p. 4). For a connected gamepad in normal mode, `FlightSession.flown_commands()` applies those travel fractions but skips the aircraft expo stage because the gamepad already applies channel expo (`app/sim/flight_session.gd:2027-2030, 2053-2061`; `app/input/commands.gd:55-71`). With the stored profile, gamepad expo remains `0.30` on pitch and roll. Thus there is no intended double-expo; however, if this run used `--rates=full`, the Avanti's 50% elevator and aileron travel reductions were absent. The feedback log does not record the launch rate option; the on-screen `Rates` indicator is the direct check.

The supplied log contains a tip-stall event at 20 m (`α 14°`, 27.4 m/s, bank −26°) and a spin event at 138 m (`α 17°`, 60.1 m/s, bank −21°), in addition to a hard-landing event. These entries show high-angle-of-attack departures with bank in the same run log, making an aerodynamic roll departure plausible. They do not include raw stick axes, accepted commands, surface positions, or maneuver timestamps, so they do not establish that either event followed the reported pull-up.

## Assessment and discriminating evidence

The saved mapping and source route do not substantiate software pitch-to-roll mixing. The strongest current possibilities are a high-angle-of-attack aerodynamic departure or a difference between the expected physical stick and the axis being moved. An unrecorded `full` rate selection would expose the full Avanti throws, twice the normal-mode command travel, although it would not itself cross-couple the axes. The saved profile's non-inverted pitch sign is visible, but this log does not establish which physical stick direction the pilot used or what pitch command it produced.

On a controlled replay, check the `Rates` indicator and watch pitch/roll commands and servo positions while moving only the physical pitch stick. If the roll command and aileron positions remain neutral as the aircraft starts rolling at high angle of attack, the controller route is cleared for that event and investigation should move downstream to aerodynamics. If roll command or aileron position changes with pitch-only input, capture the device's axis calibration and correct the profile mapping/sign before flight.

Evidence limits: the checked local profile was read narrowly and device identity values were omitted; the feedback log is event-only, not an input trace. The game UI was not automated or changed, and this audit does not demonstrate physical validation of the Avanti aerodynamic model.
