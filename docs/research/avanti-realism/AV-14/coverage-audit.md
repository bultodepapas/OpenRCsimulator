# AV-14: Avanti S flight-behavior coverage audit

2026-10-12 · AV-14 · Read-only static audit of controls, rendering, damage, reset/replay and ground support. No Godot runs or production edits were made. The Avanti remains an experimental, unvalidated model; software checks below establish implementation consistency only.

## Prioritized findings

| Priority | Finding | Why it matters |
| --- | --- | --- |
| High | AV-07 maneuvers bypass the session ground/crash tick and do not require complete traces. | A behavior can meet its threshold in a finite prefix and still be reported as passing after the requested maneuver ended early. Hull contact is checked by `FlightSession._physics_process`; `Maneuvers.fly` calls `sim.step()` directly. The Avanti test does not install a collision world, so that path does not replace the missing session check. |
| High | The Avanti “360° loop” criterion integrates body pitch rate `q`. | `∫q dt` does not prove that the flight path made a planar loop. | Medium-high | Stall and spin checks establish limited trace conditions, not full maneuver behavior. | The clean-stall check only asks whether α passes the model's stall-start angle. | Medium-high | Idle/glide coverage does not exercise an approach or an in-flight turbine restart. | The “glide” L/D check is `Trim.solve`, not a flown glide. ## What is implemented and already covered

The live primary controls are roll, pitch, yaw and throttle. `FlightSession` samples keyboard/radio inputs in its physics callback, adds trim, and advances actual servo state in `_pre_step`. Trace v3 records commanded and actual normalized roll/pitch/yaw surfaces, RPM, state and loads, but it does not record each left/right surface angle separately. The render path reads `session.surfaces()` and passes the positions through `Commands.hinge_rotations` and `AirplaneBuilder.apply_surfaces`; the Avanti adapter converts those rotations back to degrees and moves the named hinges. The Avanti scene verifier at `research/avanti-s/av02/verify.gd` checks visual mesh bounds, panel triangulation, loft normals, sampled fence/aileron clearance, hinge signs and travel, fixed pivots, reset-to-rest, and the visual-only flap range. It exercises the AV-02 model directly. The shared catalog test calls the production adapter but hard-codes its “surfaces deflect” result to `true`, so a broken Avanti adapter path can still pass. No existing check sends radio/keyboard input through the Avanti scene and observes the resulting rendered hinges or individual differential surface outputs.

`test_avanti_handling.gd` checks the experimental start trim and data, differential throws, hands-off stability, in-flight throttle step, roll response, estimated level-speed limit, glide trim, short idle energy loss, loop-rate integral, stall-start crossing, spin-entry/recovery trace thresholds and rotor momentum. Several checks are deliberately internal consistency checks: their predictions use the same Avanti data and turbine law as the simulation. They are not independent aircraft measurements.

Visual geometry coverage and physical geometry coverage are separate. `research/avanti-s/av02/verify.gd` has useful visual construction contracts, but it does not validate AV-06's generated mass locations, tensor inertia, aerodynamic reference stations or force model. AV-07 checks only broad mass/span/inertia ranges derived from the same AV-06 inputs and generator. The current AV-06 generator has identified geometry/inventory corrections awaiting AV-15: its exposed-tail area filter uses the tuple's height where the span station is intended (the reported centroid moves from 0.8668 m to 1.0146 m aft when the domain is corrected); paired aileron/flap/elevator servos are represented by centered uniform boxes spanning empty space; and the swept-wing MAC leading-edge station is chord-squared weighted, with its geometric definition under review. There is no independent analytic area/first-moment or paired-mass/tensor oracle in the current Avanti checks. Until those corrections and independent fixtures land, existing handling thresholds cannot distinguish a flight-response change caused by the model from one caused by these source-data assumptions.

The shared suite already exercises useful Avanti lifecycle seams:

- `test_checkpoint.gd` includes the Avanti in its per-aircraft loop. It turns the engine mode off, captures/restores a checkpoint, checks that reset returns to the running start, replays 80 ticks exactly, and verifies reload restores initial RPM.
- `test_wheel_session.gd` asserts that the Avanti stays gearless and has no wheel state. `test_ui_runway.gd` sanitizes runway selection for the Avanti. Trace metadata tests verify turbine identity and the absence of wheel metadata.
- Generic crash tests exercise hull contact, impact snapshots, crash hold and restart. They use other aircraft; the Avanti handling test does not call that lifecycle.

These shared checks do not constitute Avanti landing, terrain, obstacle-contact or turbine ECU validation. The aircraft JSON describes gear-up, in-air start only, and `FlightSession` restricts runway starts to the Ugly Stik. The default flat-ground rule still treats an Avanti crash-hull point touching the plane as a crash when the session tick runs.

## Evidence gaps and false confidence in AV-07

`Maneuvers.fly` disables input, resets the trimmed session, writes scripted commands and advances `sim.step()` directly. It does not call `FlightSession._physics_process`. That callback owns the ordinary `touches_ground`/`_crash` check and crash countdown. `test_avanti_handling.gd` only calls `session.setup(DATA)`; it does not install a collision world whose tick-boundary callback could catch contacts. Thus AV-07's “real session loop” comment is accurate for the shared physics integrator and servo callbacks, but not for the full session lifecycle or its flat-ground crash rule.

The test helper `_finite` checks only altitude, speed and p/q/r values and never checks the requested row count. The maneuvers do not assert `sim.fault_reason`, `sim.paused`, `session.crash` or an exact `duration / dt + 1` trace length. A finite partial trace can therefore satisfy a threshold reached early. `_finite` also returns true for an empty trace because it has no non-empty guard; some later checks index trace rows, so this case is fragile rather than a guaranteed all-green pass. Window helpers `_min` and `_max_rate` also hard-code 240 Hz, so their windows are wrong if this test is reused at 480 Hz.

The loop criterion at `test_avanti_handling.gd` lines 135–141 accumulates `q_radps * dt` and calls a full turn a loop. Replace that claim with geometric trajectory evidence: transform velocity to world axes, unwrap flight-path angle, report vertical-plane deviation/cross-track motion, altitude and speed through the maneuver, and only call it a completed loop when the path itself demonstrates a turn in the intended plane. Keep the existing result as a body-rate integral if useful, but label it accordingly.

The stall check at lines 143–153 is explicitly an α-through-stall-start probe. It does not establish lift break, post-stall departure or recovery. The spin check at lines 155–177 measures peak α and total angular-rate magnitude, then final α/rate and height loss. It does not establish a stable spin or show that opposite-rudder recovery changed the motion; add signed yaw/rotation history and recovery-window metrics, and describe it as a scripted stall-rotation response unless the trace demonstrates a sustained spin.

The glide calculation calls `Trim.solve("glide", ...)` and derives L/D from the solved `gamma`. The idle maneuver is only 2.5 s and checks the mechanical-energy slope after 1.5 s. Neither case covers a descending approach, speed control, flare, touchdown or go-around. The idle-to-95% 2–4.5 s bound is calculated by `_spool_time` by repeatedly calling `Turbine.spool_step` itself; it is not an independent restart observation. Current turbine shutdown is a single `engine_running` mode bit: when false, `_pre_step` leaves RPM at zero on the next step. AV-05b is needed before a realistic relight/restart or flameout case can pass.

## Proposed AV-14 verification matrix

Every flight case should record aircraft/config identity, start trim, input command, actual servo output, RPM, state/loads and case duration. Disable automatic crash restart explicitly. For each tick, feed the scripted command, call the session callback, stop on crash/fault, then step the simulation. Require a continuous trace with exactly `roundi(duration / dt) + 1` rows, finite values across every column, and a clear no-crash/no-fault result for cases expected to stay airborne. Start loops/stalls/spins with enough altitude and separately report the minimum ground margin. Run at 240 and 480 Hz and compare descriptive metrics; do not turn convergence into physical validation.

| Area | Probe and assertion |
| --- | --- |
| Controls and animation | At the Avanti's documented high throw and selected low-rate fractions, pulse all three axes in both signs; record command-to-servo slew and verify rendered hinge motion and return-to-neutral through `AirplaneBuilder`. Assert explicitly that flap and gear command/animation/aerodynamics are unavailable in this data version. |
| Ordinary flight | Repeat hands-off trim; throttle-up and idle transitions; and guided left/right turns, cross-control slips and counter-roll recovery. Use Avanti speeds from the current plan. Report derived-model response and per-case completeness, not external acceptance. |
| Idle and engine-off | Fly a sustained idle descent and a separate engine-off glide from a `glide` trim. Report speed, sink, energy proxy and remaining ground margin. Test that resetting from a forced engine-off state restores the ordinary level start exactly: tick 0, valid start state, engine running, start RPM and trimmed throttle. Also confirm a deliberate glide trim/reset remains engine-off. Mark mid-air ECU restart/flameout cases unsupported until AV-05b exists. |
| Stall and spin | Use slow-flight speed reduction plus power-off stall entry; report α, speed, load, angular rates, lift/stall indicators and post-input recovery window. Probe both rudder directions for stall-rotation response. Do not label either result “stall recovery” or “spin recovery” without trajectory evidence and complete traces. |
| Loop and inverted | For pitch-pulse cases, report q integral as a body-rate metric and independently test flight-path/position geometry in a vertical plane, cross-track deviation, speed and ground clearance. Report inverted trim only if the six-axis solve converges; otherwise retain an unavailable reason. |
| Reset, replay and crash | In a fresh Avanti session, checkpoint at a named trim boundary, run a fixed 240-tick command sequence through the full session callback, restore a serialized copy, replay the same sequence and compare checkpoint bytes. Then force a valid Avanti crash-hull contact; check crash capture, pause and the exact 1.5 s countdown, then exact tick-0 restart state/RPM/engine mode. Existing `test_checkpoint.gd` covers shorter Avanti physics-only replay; this adds full session lifecycle evidence. |
| Unsupported ground route | Assert `landing_gear` empty, `anchor_count()==0`, `wheel_count()==0`, and no wheel state. Direct runway selection must fail with the unsupported-aircraft reason and stay stopped rather than silently falling back; the one-shot `reset_on_runway` helper must return false and restore the airborne trim. Do not claim taxi, takeoff, landing, braking, retract or field-surface handling. |

This matrix does not establish real-flight accuracy. The source plan still marks geometry, turbine presentation, flap/gear simulation, fuel burn and independent physical contrast as open; preserve those limits with every generated report.
