# LU-00 — Scenery implementation audit

Date: **2026-10-11**. **Status: research complete; implementation has not started.** The owning [landscape plan](../../../plans/landscape-upgrade.md) is pending.

## Existing renderer and data path

`render/field.gd` calls `Scenery.attach`. The scenery loader validates `app/data/scenery/default.json` before `Scenery.build` creates the visual-only field layer. `Scenery.build` batches static prefab and model triangles into spatial mesh cells; moving parts become separate mesh instances. `Models.arrays()` reads the committed `openrc-scenery-model v1` meshes under `app/data/scenery/models/`. Placements carry units, evidence kind and source; the loader enforces runway, flight-box, safety-zone and tree-clearance rules. The existing `app/scenery/` layer is owned by the Scenery and Field Life track, so coordinate any changes there with [SCENERY-PLAN](../../../SCENERY-PLAN.md).

## Current content

| Content | Present state |
| --- | --- |
| People | 13 figures: 2 pilots, 5 pit members, 3 seated spectators and 3 on the pavilion veranda. `Prefabs._person` creates deterministic seeded height (1.62–1.88 m), skin/clothing/hair or hats, and standing, seated or transmitter-holding poses from blocks, beams and blobs. They are static and use the same cell batching as other prefabs. There are no reusable human assets. |
| Cars | 11 parking placements choose among four baked Quaternius CC0 models: sedan, hatchback, SUV and sports car. Each placement gets seeded paint. Nine positions form a close, nearly parallel row (mostly 2.25–2.75 m spacing, with one 5.25 m gap; headings mostly 177–181°); two are offset and angled. This already gives body and color variation, but most of the row reads uniformly aligned. The current data has 11 cars and no separate van, while the scenery reference plan describes 5–8 cars and a van. Decide which count/layout the upgrade should target before changing placements. |
| Parked aircraft | All 4 current aircraft catalog entries are represented once under the pit shelters: Ugly Stik, Extra 300S, P-51D and Avanti S. Each baked model is a read-only snapshot of the aircraft team's builder, reduced for scenery to 2,139–3,781 triangles and stored as `fleet_*.json`; the default layout maps each aircraft ID to one placement. There is no gap in today's fleet coverage. The mapping and bake list are explicit, however, so a future catalog addition will not appear automatically. |
| Shrubs and shade | 6 deterministic procedural bushes surround the pavilion; 10 broadleaf shade-tree placements sit behind the car row. A flower border is present. Bushes are three overlapping ellipsoids with theme-aware green; the larger tree meshes and flowers are handled by the existing scenery layer. |

The source layout is `app/data/scenery/default.json`; `tools/scenery/place.py` checks the authored placement layout. Vehicle derivatives and their CC0 provenance are in `app/data/scenery/models/` and `assets/scenery/PROVENANCE.json`. Aircraft snapshots are generated by `tools/scenery/bake_fleet.gd`, which calls the public model builder through `app/scenery/fleet.gd`; do not edit generated model arrays or aircraft-team geometry by hand.

## Bounded implementation seam

Add `app/scenery/people.gd` for the human geometry, pose definitions and a small idle animation. Hook it only from the existing `person_*` dispatch in `Prefabs.build`; keep the scenery schema, loader rules and static batching intact. The current prefab contract returns separate moving-part records, and `Scenery.build` already sends them through `_motion_node`. If people need a new motion mode, add one narrowly scoped mode to that path and `app/scenery/motion.gdshader`, driven by the existing `sim_clock` (and wind only where useful) so pause and repeatable captures remain coherent. Start with pilots' hands/head and a restrained stance shift; keep most bodies static and batched. Measure draw calls and primitives against the existing scenery budgets before adding more moving figures.

Natural parking can be handled in the existing placement generator and data: update the `cars` group in `tools/scenery/place.py` and regenerate/check `app/data/scenery/default.json`, using the existing four models and seeded paints. Preserve the validated parking zone, aircraft/pilot sightlines and tree clearances. For the fleet, keep `Models.FLEET`, the default fleet list and baked snapshots synchronized with `AircraftCatalog.ids()`; extend `app/tests/test_scenery_build.gd` with a set-parity/exactly-once check so every catalog entry remains parked when the catalog grows. Shrub changes can stay in `Prefabs._bush` and the same placement group unless a distinct plant asset is justified.

Existing visual and performance references are [SC-03](../../scenery-implementation/SC-03/README.md), especially its `postcards.png`, draw/primitive budgets and repeated scenery captures. The pilot-view budget is at most 40 added draws and 150,000 primitives; the current north pilot view adds 30 draws and 65,148 primitives. Keep animation within that remaining margin and re-run the scenery-on captures. The project-wide ownership and document registry is [docs/README.md](../../../README.md#tracks-plans-and-step-ids).
