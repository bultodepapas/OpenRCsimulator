Compatibility is a concrete art constraint. Godot documents no HDR rendering, volumetric fog, or `CompositorEffect` support in this renderer. The project’s 4.7.2 research and probes found alpha-to-coverage and alpha hash are no-ops in GLES3. Use opaque geometry for dense plants; reserve alpha scissor for sparse cutout silhouettes. Do not build the field around blended leaf cards, volume effects, or a Forward+-only flare. [Renderer feature table](https://docs.godotengine.org/en/4.7/tutorials/rendering/renderers.html) · [3D rendering limits](https://docs.godotengine.org/en/4.7/tutorials/3d/3d_rendering_limitations.html) · [local foliage findings](../../landscape-investigations/04-trees-and-impostors.md) · [local grass findings](../../landscape-investigations/05-grass-rendering.md)

MultiMesh draws are efficient but cull as one object, so distant instances should be divided into spatial cells. That matches the measured scenery pipeline. Keep placement, material, and shader output deterministic: project shaders use `sim_clock` / `wind_vec`, never shader `TIME`. A deterministic image is not a hardware performance result; both Gate L and Gate SC still have target-hardware acceptance open. [Godot MultiMesh guide](https://docs.godotengine.org/en/4.7/tutorials/performance/using_multimesh.html)

## What already exists

The landscape and scenery plans already cover nearly every requested content family. The landscape track supplies the procedural sky and sun, horizon, ground, grass, hills, terrain data, and a readability capture suite. `L14` plans float64 tree collision proxies but is still pending. Its current collision scope is trees only.

The scenery track is on by default, but Gate SC acceptance remains open. It already has 11 parked cars in four Quaternius body styles, procedural spectators and pilots, a detailed pavilion and two shelters, farm buildings, animals, flower margins, meadows, trees, turbines, pylons, and a church landmark. Four baked parked-aircraft snapshots cover the current catalog: Avanti S, Extra 300S, P-51D, and Ugly Stik. The aircraft snapshots come from this repository’s model teams. Their meshes are generated offline, not live model nodes. [Scenery status and steps](../../../SCENERY-PLAN.md#open-steps) · [Landscape status and steps](../../../LANDSCAPE-PLAN.md#open-steps)

The old source-asset plan was careful about license proof. It replaced people and farm-building downloads with original procedural models while exact archive license files were unavailable. The Quaternius farm-animal archive did have a CC0 license read and recorded. This is why the existing field can already look populated without distributing uncertain source archives.

Other open work is owned elsewhere: `SC-18` has turbine and flag motion but awaits some wind-driven props; animated spectators are optional `SC-21`; `L15` vegetation motion waits for the wind track. `TIME-OF-DAY-PLAN` owns time, twilight, night progression, and optional glare. `FIELD-WORLD-PLAN` already has a first field-light and aircraft-night-kit slice, with owner flight gates still open. Do not create a second clock, sun, or night-lighting system in the landscape-upgrade track. [TOD status](../../../TIME-OF-DAY-PLAN.md) · [field-world status](../../../FIELD-WORLD-PLAN.md)

## Collision and lighting integration

Scenery’s current rule is visual-only; the loader rejects colliders until the physics capability exists. Preserve that boundary. Godot’s 3D collision guide recommends primitives for smaller objects and says concave/trimesh shapes are slow, hollow, and intended for static bodies. Those engine `Shape3D` nodes are not the flight solver: simulation state, ground contacts, and impact snapshots use float64 arrays. New aircraft-obstacle collision should therefore be a physics-owned feature with a float64 proxy catalog derived from the same quantized placement records as the render scene. The landscape plan’s `L14` trunk-and-crown cylinders are the existing first slice. Test swept high-speed contacts; do not assume a visual mesh, MultiMesh, or Godot static-body collider is authoritative for a fast simulated airplane. [Godot collision guide](https://docs.godotengine.org/en/4.7/tutorials/physics/collision_shapes_3d.html) · [`impact_snapshot.gd`](../../../../app/physics/impact_snapshot.gd) · [L14](../../../LANDSCAPE-PLAN.md#open-steps)

For lights, extend the existing shared world snapshot. Time progression and sun/clock implementation remain with TOD/FW. LU-03 consumes the shared sky direction and exposure for scene-local fittings. The earlier suggestion to consider glare as a later optional step is superseded by LU-04, which implements it as a separately gated shader approximation. Compatibility does not support compositor effects, so glare still needs occlusion, aircraft-readability, and target-display evidence. The existing sun disc and halo are part of the current sky; they are not evidence that a lens flare was already implemented.

## Handoff for the upgrade plan

1. Start from existing scene data and plans. Most requested static field content already exists. Treat any remaining aesthetic gap as a current-capture finding: the older SC-01 bake-off called the grass uniform, but landscape work since then includes L9c surfaces and L9e filtered turf microstructure. Do not reopen a stale finding without a fresh reference capture.
2. Keep the established asset family: proven CC0 archives and original procedural models, with exact source/license/hash records. Use third-party assets only after a small Compatibility bake-off.
3. Grow collision in the physics track from L14’s tree proxies. Render placement and float64 collision data should share one deterministic source, with swept-flight checks and coarse per-prefab proxies.
4. Evaluate one combined field in the existing L0/L6c/SC capture suite: readability first, then draw/primitive/frame-time evidence on owner hardware. Software-renderer repeatability alone does not close Gate L or Gate SC.
5. Let TOD/FW own time and sun state; LU-03 consumes the shared state for airport fittings, while LU-04 provides an optional, independently gated shader glare effect. Keep one review target for the complete field across day, dusk, and night.
