## Examined claims not promoted to bugs

- **More than two current stock Stiks:** not found in the audited source. Technical enumeration is deliberately broader; compatibility/saved routes must not be mistaken for Home stock selection.
- **Deleting three old glow files is harmless:** contradicted by active generated, economic, replay, comparison and saved-document consumers. No deletion or ID aliasing is delivered.
- **Basic should secretly use the NITRO .61 shaft model:** it intentionally preserves the prescribed-RPM reference. Different propulsion semantics should remain explicit.
- **Propeller animation must run twice as fast at 10 FPS:** not established. The engine's process delta is capped by the physics-step budget; the earlier wall-delta assumption was incorrect. Actual timeline recording is needed. The corresponding low-FPS Doppler claim is also unproven under the default cap.
- **Old quad and airship input reports are automatically current:** current source contains changed readiness/focus paths. Their older allegations were rechecked rather than copied as new defects; shared raw-axis behavior still merits seam-specific qualification.
- **Passing tests prove realistic Stik feel:** false inference. The tests confirm declared software behavior and constraints; hardware, pilot, target-airframe, native/backend and physical model qualification remain separate.

## Recommended implementation sequence

1. Preserve the published baseline and receipts. Land the bounded runner/documentation repairs through normal review.
2. Resolve CTRL-01/02 with session regressions and native device traces; review ORG-02/03 as small independent product/evidence changes.
3. Measure the actual mass/CG/inertia/control installation and electrical/propeller envelope. These measurements constrain several otherwise confounded feel parameters.
4. Develop PHY-01/02 and the high-speed installation review as isolated shared-kernel candidates, with exact replay identities and power/force checks before pilot evaluation.
5. Address lateral/induced-flow and stall modeling as coupled physics work, with bounded mathematical closures, refinement and held-out aircraft evidence. Avoid a coefficient-only patch to match one trace.
6. Profile target systems, then optimize only demonstrated costs while retaining correctness, replay and full-session performance evidence.

Each open row is an actionable audit result, not an implicit request to merge unqualified physics. The [validation plan](research-sources-and-validation.md) defines how the evidence can advance from software reproduction to physical/pilot acceptance.
