# Flight-test runner review

Reviewed 2026-11-15 against baseline `ad21070798bfb9658785576a9c0b8bfc9a71fc7f` and the lead's then-current, uncommitted `research/flight-test/run.py` / `test_run.py` changes. This was a read-only review of those source paths. The observations below describe that intermediate diff; the lead is preparing a follow-up patch. No Godot flight or native test was run by this reviewer.

## Confirmed observations

1. **Wrapper selection/completeness improvement.** At the reviewed revision, Python reads the current `_run("name", ...)` dispatch calls and derives 40 unique names in source order (`run.py:57–62`; `flight_test.gd:126–167`). It rejects empty, unknown, mixed unknown, and duplicate `--only` values; rejects empty and duplicate aircraft selections before launch; and compares actual profile keys with expected names (`run.py:85–103,150–175`). This addresses the lead's demonstrated wrapper exit-zero failures for the current card. A test whose result is present but `valid: false` remains a reported result rather than a run failure, as documented; roster completeness must not be confused with physical validity.
2. **Inherited direct-route gap.** `research/flight-test/README.md:57` documents direct GDScript invocation. At review, `flight_test.gd:71–72,184–186` accepted arbitrary `--only` names, skipped nonmatches, and `:168–169` wrote its resulting profile and exited zero. The Python fix alone therefore did not protect direct callers. Recommendation: a shared authoritative case roster and equivalent direct validation before output/session work, with tests for empty, mixed unknown, duplicate and valid ordered selections. A refactor must preserve the exact case order, callables, card version and scientific behavior; compare an actual recognized case with the unchanged baseline.
3. **Inherited path-boundary bug, reproduced in a disposable mocked run.** At review, explicit aircraft arguments were stripped/checked for emptiness and duplicates but were not required to name a catalog entry (`run.py:85–89,126–127`). `fly()` used the supplied value as `out / aircraft` and always wrote `run.log` (`:138–148,176`), even when the child failed. An absolute aircraft token or relative traversal can escape `--out`. A Python-only reproduction used a `TemporaryDirectory(prefix="variants_audit_guard_", dir="/workspace/scratch/d289586b400e")`; created `<temp>/outside/run.log` with `preserve me\n`; called `RUNNER.main()` with `--out <temp>/output --aircraft <temp>/outside --only aero_sweep`; mocked Godot to return exit 2 and stderr `ERROR: unknown catalog aircraft\n`; and caught the wrapper's `SystemExit`. Observed `wrapper_exit: 1` but `<temp>/outside/run.log` became `ERROR: unknown catalog aircraft\n`. The temporary directory was removed, and no existing user or repository file was touched. Validate all explicit IDs against the current catalog and safe identifier syntax before engine/output work; validate IDs returned by `--list` before using them as paths too. Test absolute/traversal attempts and retained bytes on an existing outside sentinel.
4. **Inherited incomplete-summary presentation.** `run.py:196–207` includes every present profile in `summary.md`, including a profile the new roster check has marked failed. `run.json` and process status do report the mismatch, but the generated summary column itself is not labeled incomplete. Consider excluding failed profiles from the summary or labeling them clearly, while retaining the actual failed profile and log for diagnosis. This is not an exit-zero claim under the reviewed patch.

## Review limits

- The case parser uses a formatting-specific regular expression. It matches all 40 current dispatches exactly; if source syntax is refactored, make the parser fail closed on unrecognized/duplicate entries and test parsing alongside the new direct route.
- The aircraft catalog currently resolves twelve fixed IDs from `data_paths()`, including one rotorcraft; direct `--list` applies actual `FlightSession` admission, so catalog membership alone is not proof a listed aircraft can fly the fixed-wing battery.
- The reproducer substitutes only the engine response and uses real Python filesystem/path behavior; it establishes the unsafe wrapper write after a failed child, not a Godot or physical-flight result.
- No claims are made about tests the lead ran separately, final patch quality, full-suite status, aircraft realism, or hardware qualification.

The missing-summary console message now says it is unavailable when no run qualifies. The root documentation for these contracts was also updated.

I compared every original dispatch against the new registry using `git show HEAD:research/flight-test/flight_test.gd` and extracted `(name, callable expression)` pairs: **40 old, 40 new, exact ordered equality**. This is a static comparison; engine parse, dictionary iteration, arguments and executed-maneuver equivalence need the lead's live checks. The Python roster parser reads the same literal dictionary; formatting deviations should fail closed through selection/roster mismatch, rather than being treated as proof of a completed card.

I reran the same disposable absolute-path sentinel reproduction against the updated wrapper. It exited `2`, retained the outside bytes, did not create the output directory, and called neither engine finder nor engine. In a second disposable mocked run, a valid-looking but partial `aero_sweep` profile for `--only aero_sweep,trim_sweep` caused wrapper exit `1` and `test_roster_matches=false`; the profile was retained and no `summary.md` was created. Both use mocked Godot and only temporary scratch files. The independent safe-ID syntax check also applies to values returned by `--list`; the lead is checking real catalog discovery, including the rotorcraft probe, with the pinned engine.

The lead reports 14 Python test methods and a pinned parse pass; those are the lead's checks, not executed by this reviewer. Direct malformed-request smoke, full discovery and a recognized-maneuver comparison were still in progress when this status was written. No additional source change is requested based on this static review. Ordinary card runs load the electric Stik's ideal `entry.data`; a pack run requires the explicit `--data` override and must be labeled accordingly (`flight_test.gd:96–105`).
