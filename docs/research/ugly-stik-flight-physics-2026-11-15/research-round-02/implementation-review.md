## Reviewed closures and limits

1. **Interrupted card runs.** The runner now decodes and labels separate captured stdout/stderr streams, retains the log before profile interpretation and records a per-aircraft receipt, child exit, profile error and capture completeness (`research/flight-test/run.py:49–57,181–256`). Its default catalog-discovery path also records an explicit failure log and manifest on timeout, launch failure or an invalid roster (`:148–171`). My injected `TimeoutExpired` cases verified that both byte-stream markers and a receipt survive for both a selected-aircraft job and catalog discovery; both return exit 1. The test fixture is synthetic and uses no Godot. The implementation does not claim that independently captured streams preserve their original cross-stream interleaving. Real disk failures may prevent writing a receipt; the change does not guarantee durability when the output filesystem itself is unavailable.

2. **Malformed profile and peer isolation.** `profile_io.py` rejects duplicate JSON names, nonfinite numbers, malformed primary structures and duplicate/missing table case identifiers; the runner catches the supported profile-read errors. The lead's `test_failed_profile_does_not_erase_successful_peer` addresses a bad profile rejected at that boundary, with a good peer retained. A separate previously reported synthetic edge remains **fail-closed**: one structurally accepted `point_roll` row with a string in an otherwise numeric set can make the aggregate `summarize.py` reducer raise `TypeError`. I reproduced a two-job case: the manifest and both job receipts remain, `summary_error` records the failure, campaign exit is 1 and no partial `summary.md` is published. Consequently do not claim that every good peer is summarized after **any** possible reducer failure; the narrower peer-isolation test concerns a profile rejected before aggregation. This remaining reduction limit is not a silent pass and is not evidence that a stock profile has such a value.

3. **Comparator identity and coverage.** `compare.py:25–53` keeps typed tuple identities for metric paths and table case/field paths, rather than concatenating punctuation into a key; duplicate cases and JSON keys are refused. The default roster is the union, while explicit baseline scope reports excluded candidate-only aircraft. My earlier synthetic collisions—nested `wind/mps` versus the single key `wind.mps`, and two different case/field combinations that print similarly—now show added/removed fields and return exit 1 under `--fail-on-change`, rather than incorrectly saying unchanged. Empty comparison returns exit 2. A profile declaring a different aircraft than its directory, and a matching profile accompanied by a timeout receipt, each return exit 2. Profile-only legacy comparisons remain allowed but visibly identify unverified provenance. A separate scan of 18 retained original audit profiles found 820 table rows with no missing or duplicate case IDs; this is a bounded compatibility sample, not an exhaustive historical-format audit.

4. **Scenery comparison and unknown evidence.** `scenario_report.py:111–171` rejects ambiguous frame keys, distinguishes missing/invalid accepted source claims and verifies the actual bytes against each declared image hash for matched frames. The comparison records current-only/previous-only coverage and labels no overlap or partial overlap rather than calling it identical (`:174–240`). I verified an invalid repeated source digest/mode becomes `unknown`. The focused tests cover missing/tampered images, differing dimensions and incomplete overlap; they use synthetic fixtures, not a rendered acceptance capture.

5. **Sync observations and historical receipts.** New sync rows retain `ok` for compatibility and carry an observation count and explicit outcome. In my two-pilot-frame fixture, no cross-camera pair, constant-RPM interval or ground shadow sample yields three `UNKNOWN` checks instead of vacuous passes. `sync_check_outcome` and `sync_receipt_status` give an observed `FAIL` precedence over `UNKNOWN`; otherwise unknown stays unknown (`scenario_report.py:54–108,281–307,360–364`). A complete legacy nine-check receipt without observation counts is still shown as its declared pass/fail, accompanied by “legacy observation coverage unverified.” That is a compatibility choice, not retrospective proof that every old check had a qualifying sample.
