# S2-01 — Pinned Godot/SDL input backend

**Decision: prototype/measure first.** The pinned source shows that ordinary Godot axis polls read an event-fed cache, not an independent hardware snapshot. It also narrows the stale-event concern: the SDL driver drops events for a removed SDL instance, but already-converted Godot events can lack an origin generation when buffering is in use. Preserve the different verified-gamepad and raw-radio policies; neither a poll count nor a silence timeout proves hardware health.

## Initial values and polling

In exact [`JoypadSDL::process_events`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/drivers/sdl/joypad_sdl.cpp#L124-L230) (IN2-S02), a joystick is opened and its axis state reaches `Input::joy_axis` through SDL motion events. The file contains no `SDL_GetJoystickAxisInitialState` call. SDL gamepads use their mapped events; raw joystick events for an SDL-recognized gamepad are skipped, and gamepad triggers are normalized separately (`:45–50,223–229,257–272`). This is an engine mapping distinction, not a guarantee that all radios are raw joysticks.

The pinned [vendored SDL axis implementation](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/sdl/joystick/SDL_joystick.c#L2505-L2566) (IN2-S05) provides a concrete startup counterexample. For an axis without prior initial state, its first nonvirtual value becomes SDL's initial/value/zero and the initial-event check returns without posting motion when the difference is within the jitter threshold. Subsequent movement beyond that threshold can send the stored initial value and then the changed value. This path has exceptions: SDL preinitializes certain zero-centered/HIDAPI/XInput/RAWINPUT/WGI devices (`:1418–1450`), and virtual devices have an explicit exception. Do not extend the first-value result to every controller or assert the application has observed a specific device. An [upstream tracker comment](https://github.com/godotengine/godot/issues/105417) reports the zero-until-moved behavior on an OpenTX RadioMaster Pocket with macOS and a 4.8-dev custom build `b56a918` (2026-08-25, IN2-S12). It is a device- and build-specific report, not a beta2 or OpenRC hardware test.

At the Godot layer, [`get_joy_axis`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/input/input.cpp#L612-L624) returns `_joy_axis` or `0` if no entry exists or input is disabled (IN2-S03). It does not call SDL or return availability. `Input::joy_axis` drops identical values, creates a motion event, and `parse_input_event` may buffer it (`:1792–1811,1964–1971,1624–1662`). During final event parsing Godot writes `_joy_axis` **before** dispatching that event (`:1071–1075,1127–1131`). The motion event contains the Godot slot, axis and value; no SDL instance ID, report counter or timestamp is carried by this path ([`input_event.h`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/input/input_event.h#L52-L95), IN2-S08).

OpenRC's `app/main.gd:798` disables accumulated input during ordinary flight initialization; the pinned engine's default `input_devices/buffering/agile_event_flushing` is false ([`main.cpp`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/main/main.cpp#L3698-L3699), IN2-S10), and this project declares no override. In that ordinary configuration a motion event is parsed and dispatched immediately; a subsequent default `Input.get_joy_axis` reads the same Godot cache, subject to intervening events or resets. The prior injected event/poll disagreement remains valid at OpenRC's replaceable `read_axis` seam; **this inspection does not show that exact sequence occurs normally in the stock Godot route**. Other startup, UI, test, or changed-buffering routes can differ. Repeated polls do not create additional reports, and distinct motion events are not a complete hardware-report stream because both SDL and Godot suppress some duplicates.

## Connections, queues and focus

The driver allocates `Input::get_unused_joy_id`, maps `SDL_JoystickID` to the Godot slot and erases the mapping when the SDL device is removed ([driver](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/drivers/sdl/joypad_sdl.cpp#L124-L170), [`close_joypad`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/drivers/sdl/joypad_sdl.cpp#L319-L331)). [`get_unused_joy_id`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/core/input/input.cpp#L2435-L2442) picks the first free slot; `Input` reserves 16 slots (`input.h:106`, IN2-S04). On disconnect, Godot zeros the slot's axes and defers `joy_connection_changed` emission (`input.cpp:694–762`). [SDL documents](https://wiki.libsdl.org/SDL3/SDL_JoystickID) a distinct, non-reused connection instance ID (IN2-S11), so the same Godot slot is **not** the same identifier. Once removal has erased the old mapping, a later SDL event carrying the old instance is skipped by this driver. This narrows R03's hypothetical old-SDL-event problem.

When Godot event buffering is enabled, however, an event already converted to an `InputEventJoypadMotion` retains only its reusable Godot slot; it has no SDL instance/generation to recheck at final dispatch. Source order permits an already-buffered event to survive a later disconnect/reset and potentially be parsed against a reused slot; whether such ordering happens in an actual supported workflow is untested. `flush_buffered_events` also releases its lock during delivery (`input.cpp:1673–1686`), so an app-level stamp at dispatch or an assumed drain is not by itself origin proof. The ordinary flight configuration above parses immediately, so do not claim that buffered counterexample was reproduced there. Linux's [main loop](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/platform/linuxbsd/os_linuxbsd.cpp#L1017-L1026) pumps display then SDL before iteration; Windows [pumps SDL](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/platform/windows/display_server_windows.cpp#L4539-L4547) and later [flushes input](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/platform/windows/display_server_windows.cpp#L4618-L4621) (IN2-S14, IN2-S15). Those loops do not establish hardware event timing or all scene routes.

On application focus notification, [`SceneTree`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/scene/main/scene_tree.cpp#L935-L947) calls `release_pressed_events` before propagating the notification to nodes (IN2-S09). That function flushes buffered events and, if the ignore-joypad setting is false, retains the axis cache (`input.cpp:1705–1733`). OpenRC explicitly sets that setting false. Consequently `Input::joy_axis`'s focus gate does not reject an axis solely for focus loss (`input.cpp:393–395,1792–1797`). The vendored SDL [`SDL_PrivateJoystickShouldIgnoreEvent`](https://github.com/godotengine/godot/blob/cafc17a192acf67903910a68aeb3c076c0907a4b/thirdparty/sdl/joystick/SDL_joystick.c#L2307-L2318) returns false in both branches; the keyboard-focus check is commented out. These code facts do **not** prove that a particular OS/device sends background events. They explain why the earlier injected LOW-event/LOW-poll focus case is a real policy risk if such input is delivered while unfocused.

## What changes in R01–R03

| Investigation | Updated conclusion |
| --- | --- |
| R01 | The stock default poll is now identified as Godot's event-updated cache. Startup zero without an axis event is a concrete source path; initial-value availability in SDL is not passed through by this driver. The injected event/poll mismatch is not established in normal immediate-dispatch flight. |
| R02 | Repeated calibration reads can unquestionably resample the same Godot cache entry. Counting delivered motion events also cannot be called counting independent hardware reports; first/duplicate events can be suppressed. Preserve low-rate/held-axis usability and measure actual report cadence before changing policy. |
| R03 | SDL instance IDs and recyclable Godot slots are explicitly distinct. Removed SDL-instance events are filtered after map removal; already-converted buffered events have weaker origin identity. Focus/background handling is now a pinned source fact, while actual device delivery and exact session outcomes remain untested. |

For the next implementation decision, test a real backend or deterministic engine fixture through **both** immediate and buffered modes: initial nonzero/zero and held controls, first movement across the SDL threshold, rapid disconnect/reconnect with the same Godot slot, focus loss/background LOW/HIGH, remap, a quiet radio, and the existing verified gamepad path. Record SDL instance and Godot slot at the earliest available seam and independently observe stick position; an event's receipt-time epoch is not its origin. Require explicit Continue as currently intended and keep preflight surfaces distinct from motor readiness. If stronger live health is needed, obtain a qualified backend health signal or report counter; initial-state availability is not an ongoing heartbeat.

**Disposition: prototype/measure first.** Exact source now supports a narrower causal model, but no hardware report, queued-slot reuse occurrence, or physical-controller qualification was performed in this round.
