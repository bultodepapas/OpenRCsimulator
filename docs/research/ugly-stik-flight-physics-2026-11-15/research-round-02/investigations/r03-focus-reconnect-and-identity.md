# R03 — Focus, reconnect and controller identity

**Decision: prototype/measure first.** Treat selection, connection generation, mapping and focus as separate authority boundaries. An event that happens to be dispatched after a boundary cannot automatically be attributed to the new connection; its originating epoch must be established by the backend or a verified boundary protocol.

**Second-round update.** [S2-01](../second-round/s2-01-pinned-input-backend.md) inspected the exact beta2 source. The SDL driver removes the old instance-to-Godot-slot mapping on disconnect, so a subsequent SDL event with that old instance is skipped. An already-converted **buffered** Godot event lacks the SDL instance and generation; a cross-reconnect delivery remains a conditional, untested case, not a demonstrated ordinary-flight defect. On focus notification, Godot flushes buffered events before notifying nodes; with this project's false ignore setting it retains the axis cache, while actual background delivery remains OS/device-dependent.

## Existing owner and lifecycle

`ControllerRegistry.update_devices` marks vanished devices disconnected, clears selected roles and increments a handle's generation on reconnect or identity change; ambiguity changes can also invalidate generation (`app/input/controller_registry.gd:18–111,199–228`). `ControllerService.attach_session` binds the selected flight role and generation, and `_confirmed_gamepad_connection` checks current focus, role and generation (`app/input/controller_service.gd:169–196`). `FlightSession.apply_controller_selection` disconnects the old reader, invokes its paused failsafe, then connects the explicitly selected profile. `controller_disconnected` clears calibration and pauses; `controller_focus_lost` clears/requires fresh radio evidence, disables AUX and pauses (`app/sim/flight_session.gd:1957–2003`).

The [prior checked input follow-up](../../follow-up-01/input-contract-and-repair-plan.md) showed a conditional hole: after the last focus-loss reset, injected LOW event plus LOW non-integrating poll can arm a raw radio while still paused. Actual OS background delivery and unintended flight were not observed. `FlightSession._input` forwards only Godot device/axis/value and `RcInput.on_motion` has no focus epoch. Direct `use_profile` deliberately retains radio diagnostic axis history while resetting arming; managed selection reconnects and clears it. Neither retained `_seen` nor bare device ID is a fresh mapping lease.

## Upstream behavior and limitations

The [SDL3 joystick ID contract](https://wiki.libsdl.org/SDL3/SDL_JoystickID) says an SDL instance ID changes on reconnect and is never reused within the app (since 3.2.0, IN-S11). Godot's [Input docs](https://docs.godotengine.org/en/latest/classes/class_input.html) identify its own connected device IDs and say enumeration order may change across restarts (latest/unstable, IN-S03). S2-01 confirms that Godot maps SDL instance IDs to its own first-free, reusable slots, so Godot's ID does not inherit SDL's no-reuse rule. GUID/vendor/product/name can identify a family or mapping, not uniquely distinguish identical units; [Godot's controller guide](https://docs.godotengine.org/en/latest/tutorials/inputs/controllers_gamepads_joysticks.html) gives a same-chipset generic-controller example (IN-S13).

Godot's latest guide states its 4.8 new-project default ignores joypad events when unfocused (IN-S13); this project's `app/project.godot:42` explicitly sets `ignore_joypad_on_unfocused_application=false`. SDL's separate [background-event hint](https://wiki.libsdl.org/SDL3/SDL_HINT_JOYSTICK_ALLOW_BACKGROUND_EVENTS) is configurable (3.2+, IN-S12). The first-pass documentation alone did not establish beta2 focus behavior. S2-01 now shows that with this project's setting false, the pinned engine preserves the Godot axis cache across its focus-release path; actual event delivery on each OS and device remains untested. Godot [issue #112802](https://github.com/godotengine/godot/issues/112802) documents a Windows hot-plug failure reported for 4.4–4.5.2-rc and not reproduced by that reporter on Linux; the issue is now closed/archived (2025, IN-S14). It motivates a versioned native regression, not a claim that beta2 has the same problem.

## Authority proposal and counterexample

Introduce a session-owned token such as `(selected role, connection generation, mapping revision, focus epoch)`. Invalidate input authority at disconnect, remap and focus loss; record focus-in and explicit Continue separately. Gate qualifying evidence to the **origin** of the new epoch, not merely the time of callback dispatch. An already-converted buffered Godot event with a reused slot could be delivered after reconnect and be falsely tagged as new if the app stamps it only on receipt. S2-01 establishes the separate SDL mapping-removal guard; it does not reproduce this buffered Godot-event scenario in the ordinary immediate-dispatch flight route. If Godot cannot expose an origin identity or a verified drain/barrier, qualify a backend snapshot or keep the case unknown; flushing without verified semantics is not a proof. Any policy must preserve focused verified-gamepad handling, radio absolute throttle and ordinary menu-hold semantics. Arming a motor and allowing preflight surface inspection are distinct session policies.

On focus loss keep the existing immediate pause and AUX disable; evaluate whether focus-in must start a new authority epoch so LOW observed while unfocused cannot satisfy recovery. Require fresh evidence appropriate to the device and explicit Continue where already required, without forcing stationary axes to emit events. High throttle after any pending LOW must revoke that evidence. A policy that blindly discards all background input can also make a deliberate calibration or menu workflow unusable; specify those owners independently.

## Acceptance

Use injected-session tests for an already-converted buffered event delivered after remap/disconnect, the old SDL-instance filter and an immediate-dispatch control, same numerical handle/new generation, two identical GUID/name devices, mapping changes, low/high throttle across focus transitions, unplug while held, reconnect while held, sleep/wake, paused polling and explicit Continue. Include managed and direct paths, AUX switches and a quiet radio; do not claim origin protection unless the test supplies an actual origin token or demonstrates the proposed barrier. On each supported OS, record native beta2 event and enumeration traces plus independent hardware motion, focus timestamps and mapping. Validate actual device identity behavior with one and two similar devices and report unknowns.

**Disposition: prototype/measure first.** The owner-generation structure is useful now, but safe queue attribution and live snapshot semantics remain backend-specific; no new universal freshness guarantee is justified.
