# R11 — Induced flow and spanwise coupling

**Decision: prototype/measure first.** The current speed normalization has a demonstrable symmetry/domain issue, but replacing it with an unconstrained division is not production-ready. Source review 2026-11-15, baseline `08f0c08348395c0d6d9f7e224f66460828f59a7f`; no new solver runs.

## What code does

`aircraft_data.gd::_induced_map()` builds an inverse Weissinger-derived strip map and fits its slope to the authored whole-aircraft attached `CLa` after an estimated tail share. `strip_influence()` and `effective_angle_map()` describe this precomputed closure. `aero.gd::_wing_flow()` computes each station's chord-normal speed `sqrt(f0²+f2²)` but normalizes all source weights by the **largest full 3D** station speed. The source weight also decreases as a station stalls; `_local_loads()` applies it only to off-diagonal map terms. At uniform flow and pure sideslip β, all section-plane speeds are equal but their weight is `cos β`; at 25° this is about 0.906. This is a mathematical property of the local approximation, not measured evidence that one particular flight is 9.4% wrong. The global/local blend and existing induced-drag term must also be considered.

## External cross-check and tradeoffs

[QBlade 2.0.9.7's lifting-line/free-vortex documentation](https://docs.qblade.org/src/theory/aerodynamics/lifting_line/lifting_line.html) [PHY-S18] forms each element's relative flow from freestream, motion and induced velocity and calculates vortex effects through Biot–Savart; a finite vortex core prevents the singular near-core velocity. [OpenFAST OLAF's theory and implementation documentation](https://github.com/OpenFAST/OpenFAST/blob/main/docs/source/user/aerodyn-olaf/OLAFTheory.rst) [PHY-S19] distinguishes vortex regularization from physical viscous diffusion and documents several core models. These are rotor wakes, not direct proof that their complete models transfer to a six-strip fixed wing. [BYU VortexLattice.jl](https://github.com/byuflowlab/VortexLattice.jl) [PHY-S29] is a maintainer-described open implementation with optional finite core, arbitrary velocity fields and rotations; it is a potential offline cross-check for attached inviscid flow, not a separated-flow oracle. The repository identifies its license as MIT; pin an exact revision and review its complete terms and dependencies before any reuse. No code import is recommended here.

A source-circulation-to-local-receiver-velocity relation motivates replacing the global maximum by a receiver-aware local flow treatment, but a denominator approaching zero can explode precisely where yaw or rotation stops/reverses one strip. A common-plane normalization fixes the uniform pure-sideslip example but still does not resolve source/receiver disparity. Regularization can create its own arbitrary scale; a free vortex wake supplies more physics at substantially greater state, cost and validation burden. The existing global lift/drag calibration can conceal local errors and double count induced drag if a new wake is simply added.

## Integration and acceptance

First make an isolated offline candidate with explicit source circulation, receiver local velocity and signed frames. Compare a stationary wing at zero and nonzero uniform sideslip, mirror cases, pitch/roll/yaw rate gradients, one nearly stationary or reversed station, density scaling, and off-axis flow. Require finite continuous limits and correct mirror symmetry, not just agreement at straight flight. Document why each regularization is used and vary its scale. Compare sectional lift and total forces/moments to a separately configured lifting-line/VLM oracle within its attached domain across spanwise discretization, and check a geometry-refinement sequence without refitting coefficients each time. Evaluate aerodynamic work/drag consistency and avoid spuriously creating energy; include stagnation and reverse-flow limitations explicitly.

An eventual opt-in shared-kernel change must coordinate `wing_wake_velocity`, tail downwash, ground-effect scaling, optional polar and local/global blend; verify stage/replay behavior, derivatives, convergence and CPU cost on target hardware. Validate held-out measured wing/aircraft moments before claiming improved physical fidelity. No production map, donor data or external code is changed by this investigation.
