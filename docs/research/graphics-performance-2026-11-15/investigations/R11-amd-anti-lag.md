# R11 — AMD Anti-Lag: DirectX SDK versus native Vulkan

2026-11-15 · External source investigation against application baseline `e488ef7653e8dd0f0a2e7db18e396bb4da0aaccc`. **Decision:** retain AMD as a conditional native Vulkan feasibility study after a measured need. The public Anti-Lag 2 DirectX SDK sample cannot simply be inserted into OpenRC's Windows/Vulkan fork or a native Linux renderer; `VK_AMD_anti_lag` is a distinct Vulkan extension with its own feature and lifetime contract.

## Implementation findings

The DX11 sample registers `PreMessagePump`, creates one zero-initialized persistent context, enables its UI only after `Initialize` returns `S_OK`, calls `Update` before the message pump with enabled and optional FPS-limit arguments, and deinitializes on device destruction. The header looks for the 64-bit AMD driver interface and initializes the state disabled. Its `Update` sends state only on changes, while still issuing the per-frame call required by that interface. The SDK repository documents Windows 10/11, RDNA 1 or newer, and driver minima for its DX11 and DX12 integrations. This is real DirectX code, not an implementation of a Vulkan extension.

The separate Vulkan reference exposes `VkPhysicalDeviceAntiLagFeaturesAMD` and `vkAntiLagUpdateAMD`. Enable the `antiLag` feature only after querying the selected device. The input-stage call may block before input processing. If presentation information is supplied, send a matching frame index with the present stage immediately before `vkQueuePresentKHR`; mode and optional `maxFPS` are distinct controls. The Dagor source implements separate input and present calls with the same supplied `frame_id`, and has an explicit Off state and a no-support path. It is a useful pattern, not evidence of correct attribution in Godot or support on a particular driver.

AMD's current product page advertises a newer SDK and Vulkan support, whereas the inspected public SDK repository at the pinned commit demonstrates DX11/DX12. The naming does not prove that `VK_AMD_anti_lag`, that newer SDK's Vulkan package, and all drivers have identical semantics or support. Inspect the exact package, license and driver capability before using its name. FSR reconstruction does not activate Anti-Lag. The SDK issue describes differing FPS-limit behavior with frame generation in specific experiments; it does not apply automatically to OpenRC, whose trial currently disables FG.

## OpenRC mapping, deliverable and stop

The [existing native package](../../../../tools/graphics/native/README.md) is NVIDIA/Windows/Vulkan and D3D12-disabled. The [flight reader](../../../../app/sim/flight_session.gd#L1332) samples at fixed ticks while render frames may contain multiple ticks. A Vulkan candidate needs an engine-owned pre-input call and correctly associated present stage across threads, plus feature/function checks, explicit Off, resize/device-loss cleanup and an ordinary fallback. Do not put a blocking update in GDScript per physics tick, run multiple vendor pacers, change physics, or assume Windows support establishes Linux support.

After the common 1080p baseline and a simple cap/VSync comparison show a material gap, first return a small feasibility decision for one named AMD GPU, OS, driver, renderer and exact API. If the feature and boundary exist, a single off-by-default candidate may use existing diagnostics for mode, stage ID and lifecycle checks, then paired Off/On tests. Follow the [validation plan](../06-validation-and-benchmark-plan.md): preserve pacing and frame-time distributions, physical transmitter-to-[patch](../../../../app/input/latency_patch.gd#L147) and transmitter-to-visible-control endpoints, 30 transitions per condition for screening, and a 100-transition cross-session p95 target with uncertainty. Driver-reported or software latency is a separate endpoint.

Stop with fallback if the selected extension, feature, driver or correct frame association is missing, or if evidence cannot distinguish an improvement from uncertainty. No new SDK/tool installation or broad AMD/Linux support claim follows from this source study.
