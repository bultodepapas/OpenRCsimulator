## New decisions enabled by deeper source reading

1. **The timing repair has concrete lifecycle scope.** The regular debug bridge, FrameDiagnostics and GOD TEST can overlap. A probe must release stored tokens even for detached SubViewports, and normal bridge exit must release its regular interest. Counting users without opaque tokens and viewport epochs is insufficient. The full caller map and source lines are in [09 §1–2](09-timing-and-drs-design.md#1-existing-entry-points-and-newly-resolved-hazards).
2. **A report field can break the existing recorder.** FrameSamples requires a fixed finite-numeric key set and stores float64. Unknown timing needs an explicit validity representation; directly adding `null`, text, changing keys or an imprecisely converted 64-bit ID can invalidate captures. Preserve old raw data while correcting its freshness interpretation; test Main and Godtest plus v2/v3 consumers. See [09 reporting](09-timing-and-drs-design.md#compatible-reporting).
3. **The public RD frame counter is not a shortcut to coherent viewport timing.** The exact pin retrieves old timestamp-slot results and overwrites the slot index during begin-frame processing. This is a source-ordering concern requiring a targeted proof, not a reproduced engine bug. Never combine independently polled values into a fabricated fresh sample; within M0 either establish the associated native record or close static-only. See [09 §3](09-timing-and-drs-design.md#3-timing-identity-what-the-pinned-engine-actually-exposes).
4. **DRS range and settings behavior must be designed together.** A strict 0.85 floor plus an existing 0.85 fixed choice normally leaves one rung; Quality at 2/3 is below the floor. Preserve both the saved scalar ceiling and actual integer dimensions. Settings preview already waits for stable scale identity, so dynamic writes must pause during that transaction. See [09 §4–5](09-timing-and-drs-design.md#4-provider-legality-and-one-scalar-actuator).
5. **Reflex has separate functional, vendor and physical evidence.** The actual local patch composition, supported Sleep even Off, token capture and serialized state changes have to survive failure and teardown. The searched flash-trigger path is incomplete/unverified, while F13 PCL ping is distinct. A missing vendor flash check does not prevent a properly executed F6 radio/display comparison. Direct CLI and Home use different settings routes. See [10 §1](10-reflex-and-ray-integration-design.md#1-reflex-actual-ownership-and-ordering).
6. **Ray tracing needs a lighting integration and a scene producer.** The pinned Forward+ directional-light attenuation offers a candidate sun-only hook. Ordinary scene buffers are not automatically AS-ready, a compositor is not a complete scene/light interface, and query-only support does not establish the pin's SBT/pipeline path. The experiment must replace the selected sun visibility exactly once, preserve other lighting and reject incomplete flight coverage. See [10 §2](10-reflex-and-ray-integration-design.md#2-direct-sun-ray-tracing-real-seams-and-limits).
7. **Existing capture tools have comparison rules.** `native_summary.py` reduces a homogeneous condition; it is not a mixed-mode A/B comparator. GOD TEST currently uses both timing consumers. F6 live optical rejects scripted/frame/capture diagnostics and has a valid normal-Home overlay route as well as the direct route. [11](11-test-and-execution-playbook.md) makes these prerequisites explicit instead of inventing another collector.

3. Run the smallest affected scripts with their **actual** success markers, inspect engine errors even on exit zero, and exercise the Main/Godtest recording seam if the sample schema changes. Do not reflexively launch the full flight/physics suite for an isolated presentation repair.

5. Close M0 with its next product decision.
