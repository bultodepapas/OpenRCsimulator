# Graphics handoff: test and execution playbook

2026-11-15 · Execution guide for the proposed work in [05](05-integrated-implementation-plan.md) and its acceptance protocol in [06](06-validation-and-benchmark-plan.md). Source reviewed at repository `725cb17585475999d3c5ef01f0af41643b3d0c36`, application baseline `e488ef7653e8dd0f0a2e7db18e396bb4da0aaccc`. These are instructions and falsifiable tests, not a report of a GPU, flight or latency result. Existing track owners and their gates remain authoritative.

## Start and stop

Start with one available reference machine, actual 1920 × 1080 drawable output and the existing 60 Hz profile. Establish the ordinary active-flight baseline and choose **one** product question. M0 has a maximum of five engineering days in total for timing repair and initial attribution; leave with `proceed`, `static-only`, or `blocked/defer`, and either select the first fixed-provider correction or the existing Reflex work, or record why the baseline stays. Do not spend M0 building a new recorder, profiler, dashboard, service or telemetry framework. Additional native qualification is still required before a support claim.

Freeze the complete candidate and imported resources before a long run. Record the full application/tree identity including local changes, engine and template hashes, native patches/SDK/runtime and package identity, OS/driver/GPU/CPU, power and thermal conditions, window/present/refresh/VRR state, actual drawable and internal sizes, scene, input, camera, requested and effective settings, and checked logs. Distinguish measured pixels from estimates. Prepare snapshots before timing and run no competing workload. Preserve failures, exclusions and incomplete reports.

On an enrolled host obtain the [test-queue grant and session handle](../../../tools/testqueue/README.md#jobs-and-session-ownership), not merely a debug port; keep ownership through verified teardown. Resource/performance capture needs an appropriately qualified **exclusive inherited** attempt; an ordinary checked-script preset or an interactive session handle is not a general admission mechanism for arbitrary performance commands. In particular, `session_baseline.py` has no standalone queue adapter on an enrolled host. If the needed admitted path is unavailable, stop that hardware row and use a private/unenrolled qualified host or report it blocked. Never bypass the authority, change a claim, or treat an `UNKNOWN` attempt as finished.

The direct command examples below are executable only where their prerequisites exist. The audit checkout used to write this page is sparse: `research/performance/` exists in Git at the stated revision but is absent from its working tree. Use a complete checkout containing the candidate for those commands. A pinned Godot installation, prepared imports, configured test pool, GPU, display, NVIDIA package and radio/camera are **not** implied by the examples.

## Card 1 — Smallest software checks

For independent reviewed headless scripts, prefer `sim_test_launch` → `sim_test_status` → same-ID `sim_test_recover` where the pool MCP is available. Retain the unique request ID, wait for `source_frozen: true` before editing the candidate, then inspect every checked result, cleanup and artifact. The MCP defaults to the caller's OS. When MCP is unavailable and a pool is configured, this example declares Linux explicitly and batches scripts whose actual success text contains `0 failed`:

```sh
python3 tools/testqueue/testctl.py pool run --platform linux --timeout 300 \
  --script res://tests/test_frame_diagnostics.gd \
  --script res://tests/test_frame_samples.gd \
  --script res://tests/test_frame_draw_progress.gd --require '0 failed'
```

`test_render_probe.gd` instead prints `all render probe checks passed`, so do not add it to a batch requiring `0 failed`. Submit it with that literal marker. Choose the actual required OS; the CLI otherwise defaults to `any`. A headless checked pass is not a native GPU timing pass. Graphics, performance, interactive and composite suites keep their separate admission paths. See [pool completion and recovery](../../../tools/testqueue/README.md#mcp-checked-batches).

For a private/unenrolled machine with the pinned engine and prepared imports, the existing checked runner is the equivalent focused fallback. Run each affected script and use a fresh output parent:

```sh
python3 tools/godot/run_checked.py --out-dir tmp/graphics-handoff-checks \
  --label frame-diagnostics --timeout 300 --require-text '0 failed' -- \
  "$(app/get-godot.sh)" --headless --path app --audio-driver Dummy \
  --script res://tests/test_frame_diagnostics.gd
python3 tools/godot/run_checked.py --out-dir tmp/graphics-handoff-checks \
  --label render-probe --timeout 300 --require-text 'all render probe checks passed' -- \
  "$(app/get-godot.sh)" --headless --path app --audio-driver Dummy \
  --script res://tests/test_render_probe.gd
```

Read `report.json`'s `ok`, completion and `engine.log`; `complete` or an engine exit code of zero alone is insufficient. Parse changed production GDScript with the same runner and `--check-only`, and select the affected consumers below. A new checkout needs the pinned-engine import in [shared tools](../../tools/shared.md#engine). Repeat a check only when its inputs change, it fails or its evidence is inconclusive. Required CI remains separate from focused checks.

**M0 schema trap:** `main.gd` merges `frame_diagnostics.sample()` into the per-frame `raw_metrics` passed to `FrameSamples.record_frame`. That collector requires a fixed set of string keys and finite integer/float values; `null`, booleans and string reasons fail collection, and values are stored as float64. Do not insert a textual scope or nullable ID into that dictionary or add/remove a key partway through a sample. Put run-wide descriptions in report metadata; if per-frame states are needed, use a stable, explicitly versioned numeric encoding and a separate validity state so an unavailable value cannot become a valid zero. A completed-frame ID that cannot be represented exactly in the chosen numeric format must stay unknown rather than be silently rounded; float64 cannot exactly represent every integer above 2^53. Check stream metric/name limits and the producer, v2/v3 consumers and historical compatibility before choosing an encoding. Current viewport timers do not supply a proven completed-frame ID merely because the application polls them.

The Python checked-runner fixtures are an available local plumbing check, not an application or graphics test:

```sh
PYTHONPATH=. python3 tools/godot/test_run_checked.py CheckedRunnerTests
```

This exact command passed 21 tests in the sparse audit workspace. Directly running the same file without `PYTHONPATH=.` failed an import in one fixture in that environment; module-style invocation also failed its `run_checked` import. The corrected run did not execute the optional `NativeGodotTests` or any GPU work.

```sh
python3 -B -m unittest discover -s research/performance/graphics_handoff -p 'test_drs_reference.py' -v
```

This is a no-GPU, no-engine contract example, not an M0 collector, a production implementation or an additional native qualification gate. A production port must independently exercise the real owner and the cases below.

## Card 2 — Required new or extended test cases

These are **proposed cases**, not existing files or currently passing tests. Extend the existing tests named in Card 1 where practical. Establish expected outputs from a separately stated contract or hand-calculated fixture before calling the implementation; comparing a function to itself, checking only a setter/getter round trip, or treating a mock's positive result as proof of GPU behavior is circular.

The later [community execution map](13-community-driven-execution-plan.md#1-what-the-forum-round-changes) supplies 17 concrete reported failure cases and case-specific negative controls for these same boundaries. Select only those relevant to the chosen change. In particular, a fixed-scale resize comparison is conditional on the selected question; MetalFX's proven empty generation can correctly retain `initial_history` with no explicit reset request; and the pinned Reflex patch drains draw N before applying its post-sync mode change. The new cases do not create an additional mandatory M0 campaign or a new profiler.

| Boundary | Smallest discriminating oracle and negative controls |
| --- | --- |
| Shared timing ownership | With a recording fake of the rendering-server switch and one live viewport: A start, B start, A stop must leave B enabled; final B stop disables once. Repeat B/A stop order, duplicate starts/stops, two viewports and independent generations. Remove or reparent a live measured SubViewport before probe stop: its stored lease must be released, not lost by rescanning the current tree. Destroy A's viewport, create another, and prove late release of the old lease cannot turn off the replacement even if an identifier is reused. Test the consumers and nested bridge/ablation interests together, not just the lease helper; then observe both in a native run. |
| Numeric values vs evidence | Missing, negative, NaN, infinity and ambiguous zero cannot become a valid fresh GPU sample. Keep raw/invalid counts and reasons. A positive value without completion identity remains freshness-unknown. Two polls with the **same completed ID** cannot be two fresh samples; two distinct completed IDs with the **same duration** can. A poll sequence is not a completed-frame ID. Do not invent a sample timestamp when the API supplies none. |
| Producer → frame collector | Inject a supported valid numeric sample, unavailable numeric sample plus explicit validity, and invalid string/null/bool or changed keys through the real producer/collector seam in both v2 and v3. A supported sample completes and round-trips its meaning; malformed schema fails visibly and never produces a successful report. A large ID that loses float64 precision cannot become an invented exact identity. Verify an old report stays readable with unknown freshness. |
| Generations / stale data | After resize, scene/provider/viewport replacement or loss, inject a late old-generation result. It cannot update the new generation's controller or imply a successful current render; no poll may use a freed viewport. Unknown age, unavailable timer and backend fault suspend adaptive feedback with a visible reason while preserving the user's request. |
| Reduction / compatibility | Starting from independently constructed valid v2 and v3 fixtures, alter one field at a time: `complete=false`, wrong source/build/scene identity, missing metric, nonfinite or bad shape, duplicate/missing stream chunk, wrong hash, hidden/no-draw interval, or old metadata with no freshness. Require refusal of the relevant comparison or an explicit historical/unknown scope, never a fabricated fresh value. Keep valid historical reports readable without widening their claim. |
| DRS policy, only after admission | Use hand-authored sequences: sustained valid over-budget; sustained under-budget; one spike; threshold noise; CPU-bound target miss/cap wait; stale and repeated IDs; provider failure; resize; preview/Revert; user Off; floor reached. At high input rates also alternate short and long GPU samples in both phases: a bounded sampler must not silently select only favorable values through periodic aliasing. Assert declared bounds, maximum adjustment frequency, hysteresis/settling rules and reason, no per-frame disk writes, and no physics/input mutation. Expected transitions must be stated independently of the policy code. Explicitly check the floor can miss the target rather than label a miss successful. |
| Scale and integer sizes | Independently calculate expected size for 1920 × 1080 and an odd output at each chosen ladder step, plus values immediately on either side of a truncation boundary using the pinned engine's actual scalar conversion/rounding. Check floor, ceiling, monotonicity and repeated integer dimensions, then verify actual target dimensions on the named native backend. A nominal `Reconstruction.nominal_input_size` estimate or a provider's advertised range is not proof of an allocated size or a legal temporal transition. |
| Temporal/provider lifecycle | Test first frame, cut, disocclusion, scale and output changes, suspend/resume, device/provider fault, settings Revert, and scene change against the provider's actual reset contract. Check native fallback and saved-request preservation; a successful enum or fake dispatch is not the image oracle. |
| Pending-apply deadline | Withhold both samples and the application callback after issuing a proposal. An independent monotonic owner deadline must retire the pending transaction and request fixed restoration without waiting for another drawn frame. A late old acknowledgement cannot revive it; the fixed fallback must be observed before a new epoch starts. The offline specimen has no scheduler, so calling its timeout path manually tests policy only. |
| Reflex / frame ownership | In a testable fake SDK, `Off → On → Boost → Off` checks requested vs accepted states, Sleep even Off, and failure → safe Off. Deliberately delay a queued render/present until the next simulation frame and verify its original token, including out-of-order/failure/shutdown; prohibit simultaneous SDK state/options calls and two independent pacers. SDK counters and markers require a separate real-fork test. |
| Optional RT, after its checkpoint | A tiny independently specified scene has a ray with a known hit and instance, an occluded ray, a miss and an offscreen caster. Check transformed/moving and removed geometry plus resource-generation changes; validate raw visibility as well as final output. A full-scene raster fallback remains the safe result if alpha/deformation/scene coverage is missing. |

Before integrating a fix, verify the new regression fails under a deliberate isolated mutation of the relevant behavior, such as releasing the shared switch on A's first stop, accepting a repeated completed ID, or using the next frame's Reflex token. Make mutations only in a disposable copy; they are not edits to the candidate. Remove them and rerun the changed test. This checks that the oracle can detect the failure it names, without requiring mutation of unrelated code.

## Card 3 — Native frame screen and interpretation

Prerequisites: full checkout and pinned native editor/imports or the named package, real display/GPU, verified 1080p drawable, quiet machine and admitted exclusive execution. Start with the [existing native frame-diagnosis command](../../../research/performance/README.md#cpu-gpu-and-memory-diagnosis), which uses `run_checked.py`, `--frametimes`, `--frame-diagnostics`, `--warmup=10`, `--t=60` and `frame_diagnose.py --report … --log … --out …`. The current default v2 writer can overwrite an existing path; use a fresh output for **every** run. Retain the runner's checked report, engine log and frame report; reject error records, missing completion, cap-limited prefixes, absent draw progress and changed identity. The diagnoser's `valid` is a data-integrity verdict, not a GPU or active-flight qualification.

Run the screen as at least three alternating A/B pairs, each with 10 seconds warmup and 60 seconds measured wall time; predeclare the primary full-workload metric, protected metrics, useful-effect threshold and at most one repeat campaign for a named uncertainty. The documented `--scripted` option is a repeatable **rendering diagnostic**, not active flight or exact input replay. For active flight, follow the [existing sustained-flight fixture and reducer](../../../research/performance/README.md#repeatable-active-flight-dt-mac-03), or the normal player route when the question requires it. GOD TEST is another existing active-flight screen, for example `python3 tools/godtest/godtest.py run ugly-standard --resolution 1920x1080`; it snapshots its inputs and reports phases, but its event-ended frame report cannot be fed to the fixed-duration native-summary gate, and it does not qualify a release package or physical latency. Inspect its coverage and outcome, not command completion alone.

Reduce each homogeneous condition with the existing `native_summary.py --input <condition-directory> --out <new-summary.json> --require-1080p`, where its applicable duration, three-run and active-flight rules are met. The reducer intentionally rejects mixing reconstruction/provider/scale, renderer, engine, adapter, scene and other identities in one campaign. Compare separately validated condition receipts by matched block, explicitly allowing **only the intended treatment** to differ; do not describe `--compare-circuit` as a generic graphics-mode comparator. Its 1080p gate checks a window size and render-target **estimate**, not physical drawable or scanout pixels. Verify those separately.

Use p50/p95/p99/max, hitch counts and between-session paired variation; no favorable run is silently discarded. The established 60 Hz profile gates include process-loop p95 ≤18 ms, p99 ≤25 ms and simulation/wall ratio 0.99–1.01 where applicable. For a formal VQ optimization, require the existing 5% gain in the predeclared complete-workload metric, exceeding paired variation, or a named reproduced hitch/memory fix. Do not infer every-refresh delivery from those thresholds. A short pass is a screen, not the owning endurance or release gate.

Triage before adding features: an insensitive frame time when the scalable pixel workload changes, a CPU/tick bottleneck, a cap/VSync wait, stale GPU readings, or an already sufficient fixed mode favors fixed/retained baseline over DRS. A root-viewport GPU reading is delayed and freshness-unverified; subviewport last readings can be stale and cannot simply be summed into a per-frame cost. Use the existing debug bridge's `render`, `frames`, `layers` and bounded `ablate` for separate diagnosis; its real GPU ablation deltas are not significance or causation proof. Until the timing lease conflict is repaired and verified, do not deliberately run debug render timing and `--frame-diagnostics` as simultaneous owners. GOD TEST itself currently starts the debug bridge and `FrameDiagnostics` against the root viewport; its runs do not close the shared-ownership or fresh-GPU-feedback gate, and bridge measurement must not be toggled during the run. Compare observer-off/on in separate matched blocks; the proposed process-loop p95 overhead ceiling is 0.2 ms with uncertainty. If freshness or overhead is unresolved, fixed-provider work may continue with the limitation recorded, but adaptive feedback stays ineligible.

## Card 4 — Reflex and F6 are three different observations

1. **Software:** run the selected checks in Card 1. On the actual custom Windows/Vulkan NVIDIA debug build and compatible hardware, use the [existing smoke script](../../../tools/graphics/native/README.md#nvidia-reflex-trial) through the owned bridge: `python tools/debug/debugctl.py run tools/graphics/native/reflex-smoke.txt --fail-on-error`. It exercises Off/On/Boost/Off, successful Sleep and marker progress; read actual requested and accepted modes, failure and token results. A debug-template bridge is needed; an ordinary release-template executable does not expose it. SDK acceptance is neither an optical result nor vendor certification. The exact SDK flash verification remains a distinct open gate if unavailable.
2. **Native frame/presentation:** compare Off, On and Boost within that same build and matched cap, VSync, window/refresh and load; include the simple cap/VSync control. Record pacing, thermal/power and any available presentation evidence. A comparison to the official engine changes the engine too, so it cannot isolate Reflex. Actual GPU completion, OS presentation and display scanout are different boundaries.
3. **Physical optical:** use live transmitter input and the existing [F6 camera procedure](../../research/radio-input/F6a/README.md#owner-camera-protocol-f6-still-pending). In a normal Home flight enable Pause → Session options → Flight overlays → **Latency camera marker**, retaining the player graphics preferences. Alternatively, direct `-- --latency-patch --latency-axis=0 --latency-threshold=0` uses the technical route and ignores saved display preferences; `OPENRC_NVIDIA_REFLEX=off|on|boost` is the direct route's startup request, not proof of accepted mode. Confirm mode and presentation conditions outside the timed optical trial.

For **both** physical routes, `--trace`, `--capture`, `--scripted`, `--frametimes` and `--visual_pose` are incompatible with the live optical marker. Never combine them or present diagnostics from another run as simultaneous optical evidence. Use separate matched diagnostic blocks. Film the same stick and screen at known camera rate, exposure and position; fix threshold, transmitter/transport, display scan location and monitor conditions. A gray marker is inactive; verify the axis has fresh samples and crosses black/white. A white marker at exactly the threshold is normal, not a measured duration. Label stick-to-patch and stick-to-first-visible-control-response separately; aircraft motion adds flight dynamics.

At least 30 filmed transitions per condition is a screen; target at least 100 per condition across repeated sessions for a descriptive p95, while recording rejected transitions and uncertainty. At 240 fps one camera frame is about 4.17 ms; include frame quantization and other endpoint/scan uncertainties. A 1 ms observed difference cannot be resolved from that interval alone. Compare distributions and between-session variation against a **predeclared** useful difference; report inconclusive when uncertainty overlaps it. Missing camera/radio does not stop an unrelated fixed-provider correction, and a mouse/PCL/software number cannot fill the physical F6 row.

## Card 5 — Finalist, rollback and evidence

For a reconstruction finalist compare Native, best eligible fixed mode and adaptive only after its prerequisites pass. Check the moving small-aircraft silhouette and attitude against sky, terrain and trees; low approach, zoom/pan/cut, propeller or rotor, smoke, vegetation and applicable water/auxiliary views. Inspect event-centered scale-transition windows, reset/ghosting, p95/p99 and the floor's residency. A faster isolated GPU pass cannot override worse full-frame tails or lost readability. Exercise resize/fullscreen, minimize/restore, focus, scene/provider changes and at least 20 warm ownership cycles where the existing finalist protocol specifies them. Keep the separate 50-cycle and 30-minute desktop-package obligations for release qualification.

For any failed capability, stale/invalid feedback, allocation or provider fault, restore the last safe static/raster mode and explain the effective fallback while preserving the saved request and the user's Keep/Revert choice. Do not change the fixed 240 Hz float64 simulation, input ownership, vehicle data, or goldens to compensate for rendering. If the bug changes a shared physics/input boundary, use the existing relevant replay and regression gates rather than assuming this visual-only contract held.

Record one compact decision in the owning evidence home: objective and exact identities; baseline/candidate and predeclared metric/threshold; actual completed checks, exclusions and raw receipt locations; paired distributions and uncertainty; clarity and lifecycle observations; whether SDK/optical/package rows actually ran; and `accepted for named configuration`, `experimental`, `retain baseline`, or `inconclusive` with next owner. Missing target hardware or incomplete data stays open. No supported platform, 1080p GPU result or physical improvement is conferred by this playbook.
