  formatted rows. `to_csv()` retains its existing API. Both use the same header and
  row formatter, preserving column order, metadata, nine-decimal values, UTF-8 and
  terminal LF. Recording rows stay available after save; failure/retry, invalid-data
  refusal before opening, explicit-path overwrite and automatic staged publication

  sized. This bounds row formatting, not total recording memory.

  `7171aef8111aa7005267d3eb2bff64caa311ffdb`: two-entry LRU, 4 MiB logical source-geometry

  bounds exclude live meshes, arrays under construction, upload staging and driver

  Identical baked PortableCompressedTexture2D metallic/roughness slots share one
  successful image retrieval within a material. Failure retries and generic texture
  paths remain intact. This removes cold-build work without retaining another image
  cache. Native transfer cost and rendered quality remain unmeasured here.

## Interactive telemetry chunks — C7 / HELI-16 continuation

The next phase starts from `f96f9e678`, which incorporated the preceding work.
Interactive **T** starts now opt into a shared raw-float64 chunk store. Scripted and
analysis `start(meta)` callers retain their existing in-memory mode. No solver,
tick ordering, physics quantity, texture import or graphics setting was changed.
[Continuation receipts](memory-2026-11-08-chunks-evidence.json) retain the tested
source hashes, commands and failed/exploratory runs separately.

Each full chunk has at most 1 MiB of numeric payload and at most 4,096 rows, chosen
after the actual schema is known. One writer owns at most two queued chunks,
including the in-flight chunk; the trace owns a filling tail and readers cache at
most one decoded chunk. Thus retained numeric buffers are bounded by 4 MiB.
Admission explicitly duplicates the array because Godot packed-array arguments are
shared references. Temporary conversion, decoding and file buffers are separately
bounded by packet size; **4 MiB is not total process memory**. Packet metadata is
capped at 64 KiB; live visual metadata itself remains variable sized.

The worker handles immutable data and files only. Admission never waits for queue
capacity. Pressure or I/O failure stops capture before accepting the next sample,
reports **INCOMPLETE**, and keeps every accepted queued/disk/tail row for retry.
Logical row counts and first-sample predicates are independent of the tail buffer,
preserving schema initialization, glow event deltas, weather timing and float64
readers. A stop joins the writer and streams the accepted prefix; even a failed
spool can be exported to a writable CSV destination from retained queued data.
Publication success, not merely writing `recording.partial`, permits later cleanup.

Chunk packets carry recording identity, schema, encoding, length and SHA-256.
[Recovery](../../tools/trace/README.md) validates a contiguous published prefix and
publishes a staged CSV into a newly reserved directory. Both `recovery_complete`
and `trace_capture_complete` are false. Mixed recordings, corruption, gaps and
source changes between validation and export are detected. An output write/flush
failure publishes no final CSV. Lexically normalized destinations inside the live
spool are refused; symlink/junction aliases are not resolved by this destination guard.

Explicit discard first checks ownership and atomically moves the complete spool
into a reserved disposal directory. Failure before that move preserves the trace;
after it, discard is complete and any residual cleanup path/error is retained in
status/logs. Saved teardown validates ownership before removing files. Cleanup notes
are logged; the existing active-recording HUD shows REC rather than cleanup details.

`value()`/row-wise export remain bounded. Explicit `to_csv()` still materializes a
whole CSV, and the helicopter's public `rows` compatibility getter materializes a
full-history snapshot in chunk mode. Neither is the interactive recording hot path.
Crash recovery cannot reconstruct an unpublished queue, filling tail or later metadata
edits; flushing/renaming is not a power-loss durability guarantee. Stop/teardown can
wait for OS I/O completion. Native frame-pacing and long-session/platform qualification
remain open. Ground replay tapes and F10 recording are outside this implementation.
