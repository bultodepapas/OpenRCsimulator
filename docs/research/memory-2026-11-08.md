## Implemented and checked

- **C7:** `Trace.save()` formats numeric rows in batches of at most 65,536 characters
  plus one oversized row. It no longer builds a whole-record CSV or a list of all
  formatted rows. `to_csv()` retains its existing API. Both use the same header and
  row formatter, preserving column order, metadata, nine-decimal values, UTF-8 and
  terminal LF. Recording rows stay available after save; failure/retry, invalid-data
  refusal before opening, explicit-path overwrite and automatic staged publication
  keep their existing contracts. Metadata, including visual history, remains variable
  sized. This bounds row formatting, not total recording memory.
- **RCV-43:** reused the exact implementation and tests from audit commit
  `7171aef8111aa7005267d3eb2bff64caa311ffdb`: two-entry LRU, 4 MiB logical source-geometry
  admission, unknown/oversize bypass and explicit clearing. A live scene retains its
  mesh. Stock fixture: 18,159 vertices, 105,240 indices, 1,147,320 proxy bytes. These
  bounds exclude live meshes, arrays under construction, upload staging and driver
  allocations. This preserves useful reuse; no ordinary-cycle leak was established.
- **SC-09-R2:** reused the same commit's shared parked ORM snapshot helper and tests.
  Identical baked PortableCompressedTexture2D metallic/roughness slots share one
  successful image retrieval within a material. Failure retries and generic texture
  paths remain intact. This removes cold-build work without retaining another image
  cache. Native transfer cost and rendered quality remain unmeasured here.

The failed-save/new-T data-loss warning in A31 is already addressed by the current
generation-aware recorders and publication helper. The 54-check manual integrity
suite rechecked both actual T handlers, retry, explicit discard and departure recovery.

## Next work, in order

1. **C7 / HELI-16 manual storage:** design schema-aware immutable chunks and a bounded
   writer queue with durable spool, explicit backpressure/incomplete status and
   accepted-prefix recovery. Current live rows and visual metadata still grow with
   duration. Preserve reader/metadata/finalization contracts; no silent ring truncation
   or automatic post-save clearing. The initial 8 MiB raw-payload proposal requires
   actual schema accounting and separately bounded formatting. Qualify every row,
   write failure, stop/restart/exit, retry and shutdown before integration.
2. **VQ-02a / DT-MAC-04d / RCV:** the Monster Car 2 color, emission and MR sidecars still
   select lossless import with full 4096² mip chains. Trial VRAM-compressed mode 2
   in an isolated import, preserving resolution, mips and channel/color semantics.
   Check actual sampled formats/fallback, paint/markings, night emission and PBR
   response at native **1920×1080**, then package and transition peaks on Compatibility
   Windows/Linux and Mobile/Metal. The audit's roughly 256 MiB RD estimate is conditional
   format arithmetic, not measured residency. No lossy import was promoted here.
   Existing [texture inventories](../../research/performance/README.md#runtime-texture-inventory-vq-02a)
   are useful but their runtime scene excludes ground vehicles and CPU image sizes
   are not GPU allocations; extend that owner instead of creating another profiler.
3. **RCV session history:** preserve exact replay using a versioned segmented tape or
   disk spool; current session-long tape/checkpoint amplification remains open.
4. Keep A28 Stik samples, audio and cloud work with its existing owners; reproduce
   Natural Random cache staleness on disposable data before adding retention policy.

Memory policy remains useful active resources plus measured transition reserve and
bounded optional reuse. Do not scale every cache with installed capacity or add
overlapping RSS and GPU counters. Native budget/pressure integration remains open;
fixed known caps and existing fallbacks stay in effect.
