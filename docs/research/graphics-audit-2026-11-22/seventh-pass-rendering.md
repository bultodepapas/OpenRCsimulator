# Seventh pass — new scenery and paint costs

Pinned main: `843f357c07af842054f3ccd6728f93beca9a57ef`, compared with sixth-pass pin `85a2475f60029a4b6b09f23f643119bceea84a45`. The finding investigation used source inspection and offline arithmetic; the separate headless integration checks are recorded in the main report. No new rendered GPU benchmark was run. The counts below describe source-level work, not measured GPU instructions, transactions, visible primitives or frame time.

## X01 — the default planted hedge is one long MultiMesh

The new `club-perimeter` is a 1.35 m high hedge with ten authored segments totalling approximately 953.791 m ([layout](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/data/scenery/default.json#L738-L770)). For the matching default field, scenery is enabled by default and this group is dispatched as planted; explicit scenery Off, another eligible custom layout, or an ineligible field changes that reachability ([options and field eligibility](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/scenery.gd#L57-L102), [attach](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/scenery.gd#L192-L201), [dispatch](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/scenery.gd#L586-L593)).

For each tier, applying `max(height * tier_spacing, path_length / 1024)` and rounding each segment independently gives:

| Scenery tier | Cards | Card-mesh triangles | Per-build instance setter calls |
| --- | ---: | ---: | ---: |
| Low | 768 | 1,536 | 2,304 |
| Balanced | 906 | 1,812 | 2,718 |
| High | 1,023 | 2,046 | 3,069 |

The 1024 is a candidate cap, and planted returns before the wild-hedge tier caps of 64/128/256; it is not a claim that the old wild hedge formerly had those exact counts in this layout. The counts follow the ten segment lengths from JSON and the [layout calculation](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/imported_hedge.gd#L170-L247). Scene detail Low maps to Low, Medium to Balanced, and High/Extreme to High ([profiles](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/scene_detail.gd#L19-L27)).

A single `QuadMesh` and `MultiMeshInstance3D` owns the whole planted row; three setters populate each card and shadows are disabled ([construction](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/imported_hedge.gd#L39-L91)). This is one source batch, not hundreds of draw calls. It has no section-level visibility split in this path. The vertex shader billboards the cards and adds a planted-only flyover tilt; the fragment samples an alpha-scissored atlas ([shader](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/assets/landscape/vegetation/impostors/bush_common_4view.gdshader#L10-L55)). Group-level culling makes spatial partitioning worth measuring: a view intersecting a small part of the current batch can still submit cards elsewhere in the large group. The card geometry is modest, and normal clipping can reject off-screen primitives even while the group is submitted. This establishes an attribution experiment, not a severe geometry bottleneck. Actual renderer behavior, overdraw, fragment coverage and cost must be checked on target hardware.

A hedge is also one `_advance_group` step, and the field's staged build checks its 16 ms budget only after that step returns ([builder](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/scenery.gd#L394-L418), [dispatch](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/scenery.gd#L586-L593), [budget](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/field.gd#L263-L278)). These operations may affect a loading-frame tail, but their duration is unmeasured.

Try a small number of Godot spatial MultiMeshes, e.g. compare 64 m and 128 m cells with the existing one-batch control. Preserve all placements, stable IDs, ordering, per-instance custom data, silhouette and metadata; bounds must include every billboard orientation and flyover tilt, including at cell boundaries. Account for more nodes, draws, potential batching/LOD changes and different culling. The current [countryside test explicitly asserts one batch](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/tests/test_countryside.gd#L45-L53), so any change must intentionally replace that assertion with reviewed bounded-batch and identity/visual checks. Existing [hedge checks](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/tests/test_imported_hedge.gd#L118-L155) also cover metadata, source geometry and shadow behavior.

This is a hypothesis, not an established FPS gain. The prior [tree split control](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/docs/research/visual-quality-implementation/L6a-R1/README.md#L73-L85) increased draws and visible primitives and changed images for a different compact population. Compare it with the new hedge, not as its performance result. Measure live flight, walking/chase and high-angle views; report group visibility, submitted primitives, draws, GPU/CPU frame p50/p95/p99 and loading stages. Start at 1920×1080 on old Windows and Linux integrated GPUs; Apple Silicon native Retina is separate. Keep internal and output pixels and renderer identity explicit.

## X05 — optional Chapa Noble detail with zero remaining contribution

`chapa_noble` is a selectable Turbo Lumber finish, not the default ([skin list](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/data/vehicle_paints.json#L697-L730)). When the material is applied or reapplied, its `detail_enabled` parameter is false at Low and true at Medium, High and Extreme ([application](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/timber_stock_paint.gd#L35-L51), [shader parameter](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/timber_stock_paint.gd#L107-L116)).

The shader's striation and flake mottling each evaluate four `hash_cell` calls, then mix the result into the initial constant 0.54. Independently, the striation result has zero contribution when its maximum derivative component is at least 1.2; the flake result has zero contribution when its maximum derivative component is at least 1.0 ([hash and noise](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/assets/vehicle-paints/turbo-lumber-evolution/chapa_noble.gdshader#L70-L80), [filter](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/assets/vehicle-paints/turbo-lumber-evolution/chapa_noble.gdshader#L349-L362)). In real arithmetic, `airflow * 960` corresponds to approximately 1/960 m, or 1.042 mm per pixel, of maximum airflow component change. This is a scale estimate, not an exact replacement guard: use the computed derivatives of `flakes` and the shader's own 1.0 threshold. Over `H_s` eligible striation and `H_f` eligible flake fragments, this is `4 H_s + 4 H_f` source hash evaluations potentially avoidable, not proof of equivalent GPU instruction or timing savings. Pixel coverage and frequency are unknown.

Test independent exact-zero guards in the native GPU shader, retaining the 0.54 defaults and all other material/texture paths. Compute **both** derivative rates before varying branches and reconverge before later `weather()` calls, which themselves use derivatives; `mottling` has no derivatives. Do not use a looser threshold. The scaled coordinates, derivatives and original noise must have a finite, defined result; finite upstream coordinates alone can overflow after multiplication. A NaN result mixed with zero need not become 0.54. Keep the original calculation wherever eligibility is unproved. Interpolation, compiled reconvergence/helper lanes and divergent-branch costs still require proof. A material built or reapplied at Low already skips both proposed detail calculations and therefore gains nothing from these two guards. A live quality transition needs a separate material-lifetime check. Compare Low, Medium and High with close-up Workshop and live distant/moving views, moving control surfaces and shader compilation. This is analogous to the existing shared grass noise guard, and much narrower than the default scenery opportunity.

## Screened, lower-priority leads

The runway-meadow colony setting is separate from authored ground-cover parcel shading; its Off state does not remove the parcels. Use the actual layout/scenery predicates when attributing their cost.

- The new meadow is bound as four parcels in the default field and evaluated in the existing ground pass, with extent, per-parcel bounds and inset early-outs ([binding](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/field.gd#L375-L408), [shader](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/meadow_surface.gdshaderinc#L15-L30)). Its mottling also resolves exactly to 0.5 once footprint reaches `0.9 / 0.073` ≈ 12.33 m/pixel. The possible skipped four-hash noise is a source-level observation; the very large footprint and bounded parcel area make this a weak priority without pixel coverage. The worn-path caller has additional quality and shoulder guards; don't treat it as a full-screen cost.
- The Avanti Élan 35 door-liner shader performs inner-detail arithmetic before mixing it with the exterior, but it is limited to selected skin and small retract-door surfaces, while brushed grain is already disabled at Low ([binding](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/data/vehicle_paints.json#L1942-L1948), [door nodes](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/data/vehicle_paints.json#L1993-L2051), [shader](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/vehicle_door_liner.gdshader#L27-L68)). Do not present it as a general FPS bottleneck or blindly branch around its `fwidth`.
- New fence decoration adds geometry, but the builder also groups long fence runs into larger cells ([source](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/scenery/scenery.gd#L567-L584)). Draw-versus-culling tradeoffs and actual scene contribution need measurement; no standalone regression was established. Sixth-pass W02/W03 track findings were not reclassified as new work.


## Primary engine references and reproduction

Godot documents MultiMesh visibility as a whole-object decision and identifies spatial grouping as an option, with draw overhead as the tradeoff. The [MultiMesh class](https://docs.godotengine.org/en/4.7/classes/class_multimesh.html) and [optimization guide](https://docs.godotengine.org/en/4.7/tutorials/performance/using_multimesh.html) support the mechanism, not a measured win for this layout. They describe Godot 4.7; the project uses 4.8 beta2 and still needs its own backend checks.

The [Godot shader-function reference](https://github.com/godotengine/godot-docs/blob/master/tutorials/shaders/shader_reference/shader_functions.rst) documents derivative assumptions and nonuniform-control-flow limits. It supports keeping derivative calculations outside divergent guards; it does not prove generated shader equivalence.

[Retained arithmetic](seventh-pass-arithmetic.json) reproduces all three hedge card counts in both authored float64 and a separate float32-vector arithmetic model. Neither model launches Godot. [Reproducer](../../../research/performance/graphics-audit-2026-11-22/reproduce_seventh_pass.py) · [Main report and priority](seventh-pass.md).


## Current-main disposition of the earlier paint findings

The new lower-resolution atlas mechanism is already useful source work, but it does not close the JETI-specific V02/V03 findings. JETI still selects its four 4096²/4096²/2048²/2048² albedo paths at every Scene-detail level (41,943,040 base texels), and both forced `lod_bias = 16` overrides remain. Its image bytes changed after the fifth-pass snapshot, so older compressed file sizes and hashes must not be described as current. The new 1024² JETI fuselage roughness texture is detail-gated; Low uses its registered mean instead. Actual selected LOD, texture residency and timing remain unmeasured. [JETI bindings](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/data/vehicle_paints.json#L1808-L1865) · [LOD application](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/vehicle_paint.gd#L103-L113) · [Roughness gate](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/vehicle_paint.gd#L247-L271).

For **Élan 35**, Low and Medium select the 4096² fuselage and 4096×2048 wing atlases; High and Extreme try 8192² and 8192×4096, with the low image as load-failure fallback. These two source images total 25,165,824 versus 100,663,296 base texels: 75% fewer in the lower pair. The [PNG-header witness](seventh-pass-arithmetic.json) retains the eight current source images and their SHA-256 identities. This is implemented selection, not measured resident RAM/VRAM or proof that a previously used high texture has left all caches. It is a reusable implementation route for V02, not evidence that JETI already uses it. Élan also retains its own two bias-16 overrides. [Selection](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/render/vehicle_paint.gd#L211-L219) · [Élan variants](https://github.com/bultodepapas/OpenRCsimulator/blob/843f357c07af842054f3ccd6728f93beca9a57ef/app/data/vehicle_paints.json#L2195-L2214).

The fifth-pass Timber cache observation also remains historical: the registry now has five named coverings. Its per-mesh/surface/covering/detail cache can retain more than one coat after direct reapplication. Normal Home uses separate livery-keyed roots and retains at most three, so this does not establish unbounded accumulation or a leak. Preserve source references, reapply semantics and teardown in any memory experiment.
