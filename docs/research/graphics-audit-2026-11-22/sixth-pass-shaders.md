## W02 — independent zero-weight detail paths still contain texture samples

### Production route and guards

The ground-vehicle scene configures the actual field material before building the track. The shared flight track creates a private field-material copy and binds the RC maps, preserving the field's appearance. `AirfieldTrackView.build` duplicates the configured material, enables `rc_track_surface`, supplies the analytic track shape, and disables terrain relief because physical road normals already exist. It does not use the simple fallback gravel shader when the configured ground material is present. Track vertex alpha carries coverage metadata, not transparency. Sources: [ground scene](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/vehicles/ground/ground_scene.gd#L430-L463), [flight track](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/rc_track_field.gd#L20-L59), [material binding](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/rc_ground_material.gd#L5-L27), and [track view](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/vehicles/ground/airfield_track_view.gd#L36-L69).

`ground.gdshader` computes the explicit world-position gradients before its varying surface branches. On any fragment with positive dirt coverage, it calls `rc_dirt_sample`: two albedo, two normal and two roughness `textureGrad` expressions. The normal data's only contribution in this caller is through `rc_project_normal(..., 0.55 * photo_weight)`. The same dirt fragment then runs the track finishing function, which performs a fine albedo lookup before multiplying its grain contribution by `near_detail`. Its fine normal lookup already has a guard. Sources: [ground fragment](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/ground.gdshader#L295-L382), [sample helpers](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/rc_ground_detail.gdshaderinc#L18-L55), [track finish](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/vehicles/ground/track_surface_detail.gdshaderinc#L12-L60).

Flight/quad Auto resolves to track Off; explicit enable and a compatible field are required. Car course preparation can install the matching field's track independently. Therefore W02/W03 are not default costs in every aircraft flight. [Flight option](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/scenery/rc_track_option.gd#L41-L65).

Let `p` be the maximum length of the two world-position gradients, in metres per pixel, and `d` the camera distance. The existing weights imply:

| Existing exact-zero condition | Data with zero downstream contribution | Source lookup expressions potentially avoidable |
| --- | --- | --- |
| `photo_weight == 0`, including `d >= 65 m` or `p >= 0.12` | Coarse dirt normal-map values | 2 |
| `near_detail == 0`, including `d >= 45 m`, `p >= 0.13`, or coverage `<= 0.18` | Fine dirt albedo grain | 1 |
| Both predicates hold | Both of the above | 3 |

The predicates must remain independent. At 45–65 m, coarse normal detail can still matter. At `p` in `[0.12, 0.13)`, fine color can still matter in a close, sufficiently covered fragment even though the coarse normal weight is zero. A `0.001` threshold would change some existing fine color; the current `> 0.001` guard applies to **fine normals only**.

For `P_n` eligible coarse-normal fragments and `P_c` eligible fine-color fragments, the source-level opportunity is `2 P_n + P_c` lookup-expression evaluations per rendered frame. Actual texture transactions depend on compilation, filtering, cache behavior, helper invocations and branch execution. The track's screen area is unmeasured. It is incorrect to multiply this count by every screen pixel or call it a three-texture bandwidth saving.

### Smallest useful native-shader experiment

First compare only the zero-weight sampling guards. Preserve UV offsets, gradients, color spaces, roughness, lane marks, cloud shadow and haze. When the coarse normal weight is exactly zero, use a finite placeholder **only for the unused map inputs**, retaining the existing projection, blend and normalization. Incoming interpolated `NORMAL` need not be unit length, and partial dirt coverage still uses the original blend. Replacing the whole expression with `NORMAL` or `base_normal` is not the conservative experiment. Admit finite, nondegenerate geometry explicitly or demonstrate the same signed-zero/nonfinite behavior at degenerate tangent frames.

The lake bank also calls `rc_dirt_sample` and uses the normal when its photo weight is positive. Preserve the helper's current default behavior or create an explicitly selected ground-only path; do not remove normal reads globally. [Lake consumer](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/lake/bank.gdshader#L80-L108).

Existing M07 already investigates skipping one anti-tiling sample when its interpolation weight is exactly zero or one. W02 tests a different downstream-zero condition that can remove **both** normal samples, plus the independent fine-color sample. Benefits overlap; do not add them without a combined comparison. Existing M05 owns shared grass derivative/footprint work. [Prior mathematical lab](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/external%20Audits/mathematical-optimization-lab.md#L398-L412).

The driver may already eliminate part of this work, or a varying branch may cost more than cached samples. Inspect compiled shader/counters where available and use alternating whole-frame captures. The proposal uses the existing native GPU shader path; a CPU/GDExtension port of per-fragment work is not appropriate.

## W03 — full dirt coverage overwrites the shared grass color computation

The shared fragment initially computes `rough_grass_colour`, club turf, optional parcels/surface colors and turf detail, then assigns `ALBEDO = col`. Later `ALBEDO = mix(ALBEDO, dirt_color, dirt_weight)` removes the finite initial color's mathematical contribution when `dirt_weight == 1`. Under the default anti-tiling setting the base grass includes two texture samples plus procedural color variation. The existing global terrain-quality and pilot-anchor work does not specifically establish elimination of this overwritten track-interior color. [Initial color and final mix](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/ground.gdshader#L265-L378), [grass color](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/grass_surface.gdshaderinc#L31-L80).

This is reachable, not merely a hypothetical shader uniform. The track sampler returns coverage exactly one inside its lane; the mesh writes `COLOR.a = 1 - coverage`, and the ground vertex restores coverage. At the default tabletop point N39/E−4, radius 6 and lane half-width 1.6 produce lateral offset zero and exact coverage one. Neighboring interior vertices also reach one, so interior triangles can have uniform full coverage; shoulders remain fractional. Sources: [sampler](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/physics/ground_vehicle/airfield_track.gd#L171-L195), [band](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/physics/ground_vehicle/airfield_track.gd#L342-L355), [mesh metadata](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/vehicles/ground/airfield_track_view.gd#L157-L174), [coverage conversion](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/vehicles/ground/airfield_track_view.gd#L262-L265), and [existing point check](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/tests/test_rcv_airfield_track.gd#L96-L105).

**This candidate has more correctness risk than W02.** Some initial work also affects normals. `untiled` and `filtered_vnoise` contain derivatives; wrapping the existing grass-color function in a coverage branch can invalidate derivatives at triangle/shoulder boundaries. Separate color-only computation from retained normal work, explicitly prepare every required derivative before divergence, and preserve reconvergence. The `anti_tiling <= 0.5` path also uses implicit-gradient `texture(grass, uv)`: merely preparing explicit derivatives does not make that sample safe inside a varying branch. Keep the implicit lookup in uniform/reconverged flow, or separately qualify a `textureGrad` replacement with appropriately hoisted gradients against the original LOD/filter behavior. Alternatively explore a separately owned exact-interior material/mesh partition, but account for additional geometry, draws, seams and construction cost; a new material is not automatically faster. Preserve the physical mesh/contact contract and opaque transition. Test W03 independently before combining it with W02.

## Required evidence before adoption

Use the [RC ground owner plan](../../plans/rc-ground-closeup.md), existing track/material/flight checks and actual Bisonte/MONSTER CAR 2 chase/orbit views. Include the shared airplane track, fractional shoulders, banks, grazing angles, all zero-weight boundaries, daylight/headlights, lake bank, moving cameras and first-use compilation. Record track pixel coverage, internal/output resolution, renderer, imported texture formats, median/P95/P99 frame time and GPU time where reliable. Windows and Linux iGPUs at 1920×1080 come first; Apple Silicon native Retina is a separate gate. A headless parse or RTX result cannot qualify old integrated hardware.

Official references support the method, not a measured project gain: [Godot GPU optimization](https://docs.godotengine.org/en/stable/tutorials/performance/gpu_optimization.html) discusses fragment and texture costs; [shader functions](https://docs.godotengine.org/en/stable/tutorials/shaders/shader_reference/shader_functions.html) defines explicit gradients and warns about derivatives in nonuniform control flow. Retain those semantics during any optimization.
