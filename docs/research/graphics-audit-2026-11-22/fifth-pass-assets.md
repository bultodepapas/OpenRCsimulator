## V01 — Selected stock paint textures load inside an indivisible model-build unit

**Reachability and work.** Selecting JETI Ruby in Home requests the selected livery (`app/app_root.gd:1215-1251`). On a model-cache miss, the Home resource broker resolves a stock paint to the default aircraft GLB rather than its paint textures (`app/ui/home_preview_resources.gd:23-46`). It asynchronously requests that single `PackedScene` (`:98-105`). After two frame boundaries and resource completion, the staged Home flow calls `_build_model` synchronously, yielding only after it returns (`app/ui/home_scene.gd:326-373,441-455`; `_build_model` at `:268-269`). `AirplaneBuilder.build` constructs the imported asset and calls `VehiclePaint.apply` (`app/render/airplane.gd:95-104,123-126`). Its per-apply path cache sends each distinct bound texture through `load(path)` once (`app/render/vehicle_paint.gd:100-102,148-150,176-189,263-266`). JETI binds four distinct albedo paths (`app/data/vehicle_paints.json:1798-1833`), and `app/tests/test_vehicle_paint.gd:656-673` checks the actual catalog build and active textures. Separately, an ordinary stock flight calls the same builder inside the `Preparing aircraft` stage (`app/main.gd:3499-3511`).

**Limits and existing protections.** The file cache is per application, the Godot resource cache may already hold assets, the Home model itself can be a cache hit, and scene/paint load may complete cheaply. Neither the source calls nor 1,403,551 combined source-PNG bytes establish actual reads of that volume, a GPU upload, a frame stall, or FPS impact. The broker has an active-request/drain policy, a two-scene ownership bound and suppresses obsolete completions (`home_preview_resources.gd:48-68,107-149`); Home also bounds three preview models. Its existing path logic is explicitly a hint and normal provenance checks still run. This paint-specific selected path refines, rather than duplicates, generic staged-unit finding R3 and is not the earlier S13 Workshop thumbnail-validation path.

**Smallest experiment.** Instrument each paint-resource lookup plus the whole indivisible build, first visible frame, loading gaps and total ready time; compare fresh process and warm process/engine cache as well as Home's A→B→A, eviction and actual flight entry. If a paint lookup is material, assess admitting only the selected paint's texture dependencies into the existing bounded engine `ResourceLoader` staging mechanism before main-thread application, or another small engine-native staged route. The present broker is specifically typed to `PackedScene`; extending it is a design change, not a claim it already supports texture requests. Preserve requested-generation ownership, supersession, cancellation/draining, bounded residency, selected-only loading, failures, normal provenance checks and main-thread scene mutations. Extend `app/tests/test_ui_preview_resources.gd`, `test_ui_preview_requests.gd`, `test_flight_loading.gd`, and `test_vehicle_paint.gd` for cold/warm, rapid switches, missing resources, Home exit and flight takeover. Measure on native Windows/Linux at 1080p and Apple Silicon Retina, with frame/presentation, CPU and GPU/upload attribution; no native C++ wrapper is indicated.

## V02 — New paint maps coexist with source materials, with conditional retained-memory pressure

**Source evidence.** JETI applies a copied material while preserving the original via `vehicle_paint_origin` metadata and replacing active texture properties (`app/render/vehicle_paint.gd:135-151,176-192,206-223`). The imported model's mesh remains intact: stock paints repaint the default GLB rather than replacing it (`airplane.gd:95-104`), so its surface materials remain attached to the mesh as well. On a valid JETI model, the four selected atlases are source PNGs of **4096×4096, 4096×4096, 2048×2048 and 2048×2048**; their IHDRs were read directly from Git objects and report 8-bit RGB. This is **41,943,040 base texels**. An entire mathematical mip chain contains 55,924,052 texels; this is a texel count, not a resident-byte measurement. For illustration only, with conventional 4×4 blocks, exactly 8 bytes/block including tail blocks would be 27,962,080 bytes (26.67 MiB) and 16 bytes/block would be 55,924,160 bytes (53.33 MiB). These are alternative hypothetical layouts, not detected formats or memory-use bounds. All four checked sidecars request `compress/mode=2`, mip generation, and `s3tc_bptc`/`etc2_astc` formats; the active platform's actual format, mips and memory are unknown. The original GLB also has embedded material images; source-resource references do not prove their GPU residency or active shader sampling.

**Lifecycle and limits.** Home caches by `aircraft#livery`, keeps one visible plus two recent model roots and hides/disables the others (`app/ui/home_scene.gd:45-47,199-227,326-344`); flight builds its own model independently (`:199-200`; `main.gd:3499-3511`). Thus several selected liveries, or a retained Home plus a candidate flight, can have live references at once. Shared imported meshes, resources, texture RIDs and engine caching can substantially reduce real allocation versus summing roots. JETI-specific atlases are distinct paths, but do not infer separate allocations or a leak. Home cache is deliberately bounded and the origin supports restore, later paint layers and isolation. This is a concrete new-content extension of the existing VQ-02a inventory / DT-MAC-04d retained-resource work, not a recommendation to remove mipmaps, compression, original metadata or model reuse.

**Smallest experiment.** Use and, if needed, extend the existing VQ-02a runtime texture inventory to enumerate path/identity/format/mips and actual active versus merely referenced materials through Home JETI, two other liveries, flight startup, return, eviction, and free; pair unique-RID/driver counters and process RSS without adding overlapping unified-memory categories. Compare cold/warm and peak/steady states, with capture and driver tools where supported. Only if memory or stalls are material, compare one generated, role-correct lower-resolution livery atlas or other source-pipeline variant against the original, retaining readable decals and ownership; do not patch generated output or mutate shared material resources. Validate all four maps, color space/filter/mips, switching/eviction and source identities, with moving 1080p and Retina close/far views. `test_vehicle_paint.gd`, `test_ui_home_preview_cache.gd`, `test_ui_preview_requests.gd` and `test_flight_loading.gd` cover relevant existing contracts; add an attributed byte/resource identity check where needed.

## V03 — JETI's stripe-preserving LOD bias requests higher geometry detail on two nodes

**Source evidence.** The new registry sets `node_lod_bias = 16.0` for `fuselage_core` and `vertical_tail_fixed` (`app/data/vehicle_paints.json:1783-1789`). `VehiclePaint.apply` takes the greater of the node's saved bias and the skin value and restores its original when switching away (`app/render/vehicle_paint.gd:103-112`). The comment explicitly says this prevents simplified geometry from distorting narrow UV stripes. It is applied regardless of Scene detail; Low/Medium/High normally set a viewport mesh-LOD threshold of 4/2/1 px (`app/render/scene_detail.gd:19-27`). The pinned Avanti GLB names both target nodes: the source glTF primitives contain **34,295 and 3,515 base triangles respectively**, 37,810 total, and 20,938 summed POSITION entries. The sidecar requests generated LODs (`app/assets/aircraft/avanti-s-a200/avanti_s.glb.import`); those source counts are not proof of imported LOD availability, current selected triangles, draw calls, GPU load or FPS. JETI adds the fixed tail target to the pre-existing REVOC fuselage override; the existing test covers REVOC bias restoration and larger caller bias (`app/tests/test_vehicle_paint.gd:617-647`), while JETI tests its materials (`:656-673`).

**Smallest experiment.** First count actual imported surface LODs, per-node selected primitive counts, full-frame CPU submission and GPU time at matched 16 versus cautiously reduced bias on each node, across close preview, taxi and recorded flight projected sizes. Prove the cost before choosing a change. If material, sweep the lowest bias that preserves the intended markings, or use an owning-source generated UV-preserving LOD so the viewport policy can select fewer triangles without distorted stripes. Keep a fallback to current bias where the LOD or visual proof is missing, preserve names/articulation/asset manifest and restore original bias on paint switch. Add JETI checks for both target nodes, transition to/from REVOC and factory, and preservation of a pre-existing larger bias. Compare moving captures for stripe shape, shimmer, silhouette and orientation at 1080p and Retina; test all scene-detail levels and actual renderer/GPU. TT-21 already repaired Lumber LOD loss and measured its own geometry; this separate Avanti paint tradeoff should not reopen that completed repair.

## Ruled out as standalone findings

The new JR Servos shader's Medium/High branch contains three source texture expressions each for foam normal and roughness (`jr_servos.gdshader:44-47,133-136`), and its decal function contains a texture expression, but source expressions do not establish compiled sampling cost or execution count. Low disables that detail branch at paint application (`timber_stock_paint.gd:35,89-96`) and the factory Timber material already uses triplanar foam maps (`timber_visual_details.gd:83-98`), so no incremental GPU bottleneck is established. Its coat cache and explicit retained overrides are bounded by the one current registry covering and detail states, preserve neutral transforms, and have an explicit renderer-teardown purpose (`timber_stock_paint.gd:41-69`; `airplane.gd:262-276`; `test_vehicle_paint.gd:153-169`). Do not report those as an unbounded leak or propose dropping required retention. Mip generation and GPU-oriented compression already exist for both new decal atlases and all four JETI images. Earlier VQ-02a, TT-04-R1 and TT-21 work supplies existing evidence and guards.
