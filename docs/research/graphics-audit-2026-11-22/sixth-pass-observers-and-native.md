## W01 — quantified continuation of F17: spatial-weather statistics at accepted ticks

**Status and novelty.** The earlier [F17 audit](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/docs/research/performance-audit-2026-11-19/README.md#L438-L456) already identifies accepted-tick statistics and air-data work while the widget is closed. This pass follows that known consumer into the spatial station sampler and quantifies its conditional work and refusal contract. It extends F17, wind F14 and A6/O5; it is not a new independent finding or an invention of weather batching. The normal eligible fixed-wing statistics observer needs airspeed and a finite/invalid decision at the accepted endpoint. In spatial weather, however, `FlightSession.air_data` builds a full stage-oriented spatial-air receipt. This work remains in GDScript even when an admitted native solver executes the flight stages. Actual total time and speedup are unmeasured. Treat native batch or scalar projection as an experiment; preserving all current refusal behavior is mandatory.

This includes numerical work and result construction, not evidence of any particular number of physical allocations.

For a successful **powered conventional** airframe there are six wing, horizontal-tail, vertical-tail and propulsion station queries, plus datum = **10 `wind_world` calls per sample**. A powered tailless airframe reserves but does not query the horizontal slot, so **9**. These counts follow the six-wing geometry and the conditional skip ([`aero.gd:20`](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/physics/aero.gd#L20), [`wind_aircraft_flow.gd:193–245`](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/physics/wind_aircraft_flow.gd#L193), [`:300–328`](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/physics/wind_aircraft_flow.gd#L300)); `bench_spatial_wind.gd:593–595` encodes the same conditional count. **Why a simple shortcut is unsafe.** `Air.compute` on the datum alone can return a finite V when a tail or propulsion station falls outside the provider domain, returns invalid data, overflows local flow, or the model/geometry/density is refused. The existing `stage_air` failure makes `air_data` return nonfinite Air; `sample.valid` then blocks the detector's continuity/credit. Preserve the current station calls, their ordering where dynamically observable, geometry and state/time checks, full finite/refusal behavior including qbar, zero/tailless slots, malformed models/providers, fallback and live derived-session overrides. `test_observer_wind.gd` has overridden session/provider examples. A full accepted receipt could be shared only if it is actually produced for the *same* accepted state, time, weather/turbulence and configuration and remains valid at the consumer's callback. Even exact tick equality alone is insufficient: `events_located`, the session's earlier stepped callback, `contact_events_changed`, eligibility callbacks and other listeners can run before sampling; [`_on_sim_stepped`](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/sim/flight_session.gd#L2580) commits contacts and emits notifications. Also preserve [Environment.wind_world](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/sim/environment.gd#L50-L69) and its per-point turbulence callable, which the session installs even when its current output is empty; an earlier native-stage guard is insufficient after intervening callbacks. ## Lower-priority HUD triage

The optional `cruise_efficiency` navigation widget re-reduces its bounded ten-second history; the default Pilot preset does not select it, and it already stops sampling/reset history when closed. The concrete loop is [`navigation_data.gd:32–71,76–120`](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/render/overlays/navigation_data.gd#L32): a full typical 10 Hz window is around 100 dictionary segments and capped at 120. The unchanged-timestamp path still checks electric/ground-speed validity first, then reduces the retained segments; an invalid same-time reading intentionally resets history. This is a **lower-priority, unmeasured profiling lead**, not a separate recommended FPS finding. A rolling accumulator can change floating-point summation, partial oldest-segment clipping, threshold/status and caller-owned result semantics; a ring alone does not avoid the reduction. Existing hidden/paused/window/reset and rendered-cache checks are in `test_navigation_data.gd` and `test_navigation_widgets.gd`. [HUD-13-R6/R8/R9](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/docs/plans/flight-overlays.md#L143) already documents its bounded history, 10 Hz, hidden-sampling and change-driven rendering, and [the global plan](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/docs/plans/global-performance-visual-quality.md#L328) requires attribution before HUD/history micro-optimization.


## Native kernel watchlist: measure before expanding interfaces

The shared-kernel screen found two narrower boundaries. Neither is established as a bottleneck. The existing external memory audit already owns RK workspace copies, stage validation and the continuous-scratch pointer proposal; the shared kernel also caches its inertia inverse. [Existing work](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/external%20Audits/ram-and-gpu-memory-review-2026-11-07.md#L223-L251).

### Packed inputs are split before the joint native stage

On an admitted native joint stage, `Simulation` slices the combined state into body and continuous arrays before each callback; the C++ entry then copies those values into its own scalar/scratch representation. In a successful one-piece, event-free RK4 tick with the legacy-RPM Stik's three continuous values, there are eight input slice calls containing `4 * (13 + 3) * 8 = 512` logical bytes/tick, or 122,880 bytes (120 KiB) per simulated second at 240 Hz. Native conversion copies a further 512 logical bytes/tick. This is payload arithmetic, not allocated capacity, bus traffic or timing. The initial derivative is already reused as RK4 k1. [Dispatch](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/sim/simulation.gd#L474-L483), [native binding](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/research/native-kernel/src/nk_kernel.cpp#L1753-L1773), [RK4](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/app/physics/integrator.gd#L28-L35).

A declared, qualified packed-input native callback could remove the split slices; it should retain scalar conversion rather than reinterpret an arbitrary packed-array pointer as the kernel scalar type. Keep the existing detached-slice callback for generic/reference models. Preview outputs retain a detached body slice and diagnostics use separate arguments, so a zero-copy claim is too broad. Measure the complete callback, ownership and allocation path before paying for a new interface, backend/checkpoint qualification, fault/rollback and replay tests. The small 120 KiB/s logical payload does not itself justify the change. [Preview ownership](https://github.com/bultodepapas/OpenRCsimulator/blob/85a2475f60029a4b6b09f23f643119bceea84a45/research/native-kernel/src/nk_kernel.cpp#L1774-L1805).

### Successful helicopter contexts use generic key validation

An admitted helicopter handoff builds an eight-field dictionary and duplicates inputs and trim. Native validation obtains the outer and trim keys and compares them with ordered allowed-name lists. Stock hover gives `36 + 15 = 51` name comparisons; a ground start gives `36 + 13 = 49`, or 12,240/11,760 comparisons per simulated second at 240 successful handoffs.
