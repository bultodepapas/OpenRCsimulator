## V04 — An ordinary shell input event repeats action-metadata copies and binding work

**Reachability and work.** With an initialized controller service and no ground-vehicle activity, [AppRoot._input](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/app_root.gd#L2803-L2847) routes each non-echo keyboard key, joystick motion, or button event past the type filters through `_sync_controller_generic_actions`. This includes unrelated/foreign-device events and keyboard use with no flight controller selected. For a complete default map, that function loops over **37** action IDs and calls `action_definition` once per ID; that accessor calls `duplicate(true)` on each retrieved metadata dictionary even though the loop only asks for its `context`. Thirty IDs have flight/both context and then construct an identity containing a separate binding duplicate and generation lookup ([router](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/app_root.gd#L2651-L2666), [definitions and accessor](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/controller_actions.gd#L44-L83), [accessor and cached definition map](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/controller_actions.gd#L420-L421)). These are **37 metadata duplication calls and 30 binding duplication calls per qualifying event with the 37-entry map**, not measured allocations, and additional routing can do more. Event rate is device, keyboard and OS dependent; no fixed event/s is assumed.

The event-local cache already keeps one profile snapshot per device and one effective-binding map per device/context, so do not claim every use reloads storage. The first needed map is rebuilt according to the selected source: no selected device uses `default_bindings()`, an empty/unconfigured profile uses `clean_radio_bindings()`, and a configured profile calls `effective_bindings()` with defaults, explicit actions, AUX reservations, capability-dependent automatic bindings, and validity checks ([AppRoot](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/app_root.gd#L2414-L2444), [effective_bindings](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/controller_actions.gd#L165-L232)). Separate event resolution scans bindings and applies hysteresis. There is no evidence this path dominates a frame.

**Candidate.** Profile the full router and individual `effective_bindings`, metadata-copy, identity-sync and resolution spans during actual radio motion, gamepad and keyboard use. A narrowly scoped first experiment is a scalar context/mode accessor reading the existing definition map, while keeping the detached public `action_definition()` API. Another is comparing existing identity scalars and binding against the current map before making a replacement detached binding, only if no observable ordering or callback behavior changes. A native batch resolver is worth considering only if whole-boundary timing, marshalling and exact ordered semantics beat the engine/GDScript path; Godot dictionary duplication is already an engine operation. Do not merely add a native call per action. A cross-event compiled-binding cache is a larger, higher-risk experiment, not a prerequisite for the scalar change.

**Safety and validation.** Do not skip identity reconciliation on foreign/no-device events: it clears old OFF requirements and tracks remaps. Preserve logical/physical key distinction and modifiers, full action order, opposite axis signs and release hysteresis, keyboard events, per-role/menu context, capture, capability changes, explicit unbind and AUX reservations, focus, loss/reuse of ID/generation, held throttle cut/restart/rates, and same-event callback/reentry. Profile and role changes may clear event caches synchronously; rate/restart/flight callbacks and virtual menu delivery can change screen and other state mid-dispatch. Do not cache across a callback unless the dependencies and invalidation are proven. The public metadata and effective maps must remain detached: [test_controller_extended_actions.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/tests/test_controller_extended_actions.gd#L40-L61). Existing [test_controller_audit_shell.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/tests/test_controller_audit_shell.gd#L69-L101) checks one-event snapshot and held edges; [test_controller_routing_audit.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/tests/test_controller_routing_audit.gd#L64-L125) changes aircraft capabilities without changing controller identity. Run these plus `test_controller_rates.gd`, `test_radio_menu.gd`, `test_radio_menu_service.gd`, and explicit nested/reentrant signal and profile-rollback cases on a candidate. Keep release backlog/context changes and per-event delivery order ([radio dispatcher](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/app_root.gd#L2517-L2555)).

**Prior overlap.** Separate from T09 Controls eligibility leases and D07 state polling. Historical D6b-R2 measured an older `RcInput` event handler/engine dispatch under synthetic conditions ([report](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/docs/research/radio-input/D6b-R2/cost/README.md)); its numbers do not measure or quantify the present AppRoot route.

## V05 — Quad reads unused keyboard flight axes while a radio or pad supplies them

**Reachability and work.** On each non-scripted quad sample, including hold samples, [the activity](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/vehicles/multirotor/multirotor_scene.gd#L1130-L1148) calls the input adapter. [MultirotorInput.sample](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/multirotor_input.gd#L518-L561) polls its connected RcInput and then always calls `read_keys`. The default `_read_keyboard` reads four two-key flight axes via `Keyboard.read_raw` plus E, M and F for arm/mode/turtle ([multirotor_input.gd:110–120](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/multirotor_input.gd#L110-L120), [keyboard.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/keyboard.gd#L5-L15)). When `radio.connected` at the branch, the four keyboard flight-axis values are not used to construct roll/pitch/yaw/throttle; keyboard E/M/F **are still used**, including arm and mode edge memory even when an AUX switch owns the operation ([lines 562–580](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/multirotor_input.gd#L562-L580)). For the built-in reader that is eight flight-axis key-state calls per sample whose values are unused in this branch. At 240 such callbacks/s, the conditional arithmetic is 1,920 calls/s. It is neither an input-latency nor an FPS measurement; `scripted_pilot` bypasses this sampler altogether.

**Candidate.** For the known built-in reader only, try a small built-in-engine-backed shortcut-key read at the same point and cadence when the connected-controller branch is the one that will consume the sample; keep the full default keyboard read on keyboard control. Preserve the three shortcut reads, their order, every hold sample, and source-generation/rearm policy. Do not replace or skip an injected `read_keys` Callable: it can provide the entire dictionary, have side effects, change source during the call, and is explicitly used by tests. Any optimization must prove the selected route remains correct if `read_axis`/`read_button` callbacks change connection state. Input key reads already call Godot built-ins; an extra extension crossing for three keys may cost more, so compare both complete paths and only use native batching when it wins without changed observation ordering.

**Validation.** Instrument or provide a test seam for the built-in reader itself: tests that replace `read_keys` exercise only the required custom-reader fallback. Extend [test_mr_input.gd](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/tests/test_mr_input.gd#L32-L38) and `test_multirotor_arm_mode_aux.gd` with built-in vs custom reader call witnesses; keyboard, gamepad, raw radio, source switch/disconnect/reused ID, AUX-owned E/M/F, key held through pause/resume/focus, held ON/OFF and reentry from readers. Compare every returned `pilot`, `raw`, actions, generation, armed/mode/turtle state and actual session boundary; do not substitute fixed-wing conditioned expo or its virtual throttle because the quad deliberately uses pre-expo controls. Run `test_mr_activity.gd` and numerical/tick-input checks on any implementation. Target-device CPU and presented frame results remain open.

## V06 — Fixed-wing absolute throttle can be normalized three times in one ordinary callback

**Reachability and work.** On a connected, configured, armed, non-gamepad absolute radio/joystick without calibration or hold, `RcInput.poll` normalizes the polled throttle to check low-arm state ([rc_input.gd:377–402](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/rc_input.gd#L377-L402)). The fixed-wing session then calls `sticks()`, which calls `throttle_position()`, and later calls `throttle_position()` again for `raw.throttle` ([rc_input.gd:445–467](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/rc_input.gd#L445-L467); [flight_session.gd:3113–3135](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/sim/flight_session.gd#L3113-L3135)). For an unchanged valid absolute-throttle profile/value, `channel_value` reaches the same endpoint/inversion calculation ([controller_profile.gd:684–706](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/controller_profile.gd#L684-L706)). This is **three normalizations per qualifying callback**, or 720 per 240 callbacks/s, not 720 measured allocations or a present-frame cost. Unarmed, error, nonfinite, hold, calibration, and gamepad stick-rate branches differ; stick-rate throttle integrates and `throttle_position` reads that integrator. No claim applies universally to all vehicles.

**Candidate and counterexample.** Profile normalization and complete input callbacks first. Explore reusing a just-computed scalar only within a proven no-callback same-input window or with an exact fresh-dependency proof and safe fallback. The later `raw.throttle` cannot blindly equal `commands.throttle`: a held throttle cut intentionally zeros commands, and `_apply_rate_switch()` can synchronously emit `rate_profile_changed` between those reads ([flight_session.gd:4242–4251](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/sim/flight_session.gd#L4242-L4251)); an externally supplied observer could reenter, change the live profile/axes, or cut/reconfigure. That is a required counterexample, not an observed mutation by a production subscriber. The inspected recording subscriber records the rate change. Flight recording subscribes to this signal ([flight_log.gd:153–158](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/sim/flight_log.gd#L153-L158)). On an absolute radio, unarmed commands may be zero while the raw value remains nonzero; on stick-rate gamepad throttle, `controller_throttle_cut()` resets the integrator before the raw read (`flight_session.gd:2023–2028,3130–3135`). Thus raw is not universally a pre-cut value. Capturing once per frame or caching only on profile ID is wrong. Native scalar evaluation is unlikely to be automatically worthwhile after crossing costs; preserve float64 operations and exact ordering if evaluated.

**Validation.** Compare commands, the raw value at its actual read point after throttle-cut handling, rates notification, AUX, accepted input/tick/checkpoint, errors, arming and observer output with normal/reversed endpoints, off-center/endpoint inputs, invalid/nonfinite events, low evidence, gamepad rate and trigger modes, AUX changes, pause/focus/disconnect and callable-driven mutation. Add a rate-profile listener that changes throttle or profile, and compare reentrant current-source behavior before/after. Run `test_rc_input.gd`, `test_rc_fault_boundaries.gd`, `test_controller_conditioning.gd`, `test_edgetx_rates.gd`, `test_controller_pause_recovery.gd`, and fixed-wing input/live-flight plus numerical/parity gates. Existing ORFL replay starts after conditioning and alone cannot prove live mapping or pilot feel. This repeats no servo guard or input-tape finding.

## Scope, other callers and rejected shortcuts

- `RcInput.poll` performs one active profile/snapshot equality check per eligible connected poll, but **full profile validation is guarded by an observed mismatch or not-ready condition**, not run on every ordinary poll ([rc_input.gd:298–322](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/rc_input.gd#L298-L322)). An immutable/versioned profile could avoid some comparisons only with an explicit compatible mutation/ownership design: [fault-boundary test](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/tests/test_rc_fault_boundaries.gd#L66-L78) requires direct valid mutation to rearm and invalid mutation to refuse; the helicopter mode gate also compares the snapshot before confirmation ([helicopter session](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/sim/helicopter_flight_session.gd#L1196-L1204)). An ID-only hash/version or validation-once shortcut is unsafe. Native Variant equality is already an engine operation and no cost is attributed. I did not promote this guard as a standalone optimization lead.
- Aircraft session uses the input sampler at physics callbacks ([flight_session](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/sim/flight_session.gd#L3091-L3118)); helicopter uses its own physics callback and shared RcInput ([helicopter](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/sim/helicopter_flight_session.gd#L867-L893)); airship uses its own adapter ([airship input](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/airship_input.gd#L104-L117), [activity](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/vehicles/airship/airship_scene.gd#L685-L698)); the quad uses its own pre-expo adapter; HX-700 mechanics inspection polls from the inspector rather than a flight kernel ([inspector](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/render/rotor/hx700_controller_input.gd#L135-L168)). Ground vehicles instead use `GroundVehicleInput` and the registry/gamepad path, not RcInput ([ground activity](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/vehicles/ground/ground_scene.gd#L504-L509), [ground input](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/ground_vehicle_input.gd#L14-L53)).
- The quad's shared RcInput also integrates a gamepad stick-rate throttle even though its flight adapter separately uses pre-expo rate input. That internal integrator is observable through the shared `radio.throttle_position()` / `sticks()` API; removing it changes state and is not an accepted proposal without an ownership/API contract. Its behavior is related to the existing drone-racing plan's concern about duplicated expo; no fourth lead is claimed.
- `ControllerService.refresh` is every 0.5 seconds and hot-plug immediately triggers a refresh; it enumerates connected devices and updates normalized registry records before its guarded store check ([service](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/controller_service.gd#L50-L96), [registry](https://github.com/bultodepapas/OpenRCsimulator/blob/0f859b5f358f4807877ec8bd7fe8009bc3856d3f/app/input/controller_registry.gd#L16-L90)). T09 owns repeated Controls store leases. Do not suppress generation/identity, disconnect edges, external store changes, ambiguity checks or callbacks based on unchanged IDs.
- Ground scripted controls and airship scripted sticks are substituted **after** the normal sampler, while the quad script bypasses its normal sampler. This can affect how scripted traces are interpreted; no elimination is proposed because samplers affect safety, held input, loss and observable state. Do not infer active live input cost solely from a scripted benchmark.
- D07 already owns ten-axis/128-button shared polling and live gamepad-verifier work. Input readers are Callables, switch channels are reread after the 128-button scan, and custom readers can change between calls. Blind snapshot reuse or event-only held-state reconstruction would change sampling, release, custom-reader, focus or continuity semantics. Radio UI uses deferred event batches and a release backlog, checks its context again after each delivery, and may stop the batch; preserve those operations and ordering, including reentry.
- All performance/latency claims require actual controller and keyboard use on the target OS/architecture, paired complete callback and presented-frame tails, actual native/reference backend, identical sample traces and focus; observe input-to-photon separately. No source-level call count establishes material FPS impact. The helper profile was requested as Terra/max by the lead; effective runtime is unverified.
