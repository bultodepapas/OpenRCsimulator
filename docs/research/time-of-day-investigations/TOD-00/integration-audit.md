# TOD-00 Integration Audit

**Status:** Read-only repository audit. **Date:** 2026-10-10. **Evidence limit:** Source inspection only; no tests or app runs were performed.

## Current integration seams

- **Interactive launch:** [app/app_root.gd](../../../../app/app_root.gd) loads preferences on the no-argument Home route, then `start_flight()` passes `weather_config`, aircraft and start choice to [app/main.gd](../../../../app/main.gd). Home's `weather_requested` signal opens a draft/apply [WeatherDialog](../../../../app/ui/weather_dialog.gd). A static clock can follow this path, but it should remain separate from the physical weather dictionary.
- **Preferences:** [app/app_state/preferences.gd](../../../../app/app_state/preferences.gd) stores UI and flight settings in `user://settings.cfg`. It accepts schemas 1–3 and derives the saved outer schema from the weather format. Adding a clock therefore needs an explicit migration/schema policy; preserve v1/v2/v3 weather values and retain the future-schema no-overwrite behavior. Existing [app/tests/test_ui_atmosphere.gd](../../../../app/tests/test_ui_atmosphere.gd) is the active contract for legacy preservation, schema behavior, draft cancellation, and Home-to-flight handoff.
- **Direct/automation launch:** any user argument selects direct flight (`AppRoot.wants_direct_flight()`), so traces, captures and `--quick-flight` bypass preferences. [app/main.gd](../../../../app/main.gd) parses arguments into a dictionary; `_weather_options()` recognizes weather flags, while other unknown flags can go unused. A TOD option needs its own validation and launch property. It must not pick up a saved interactive clock implicitly.
- **Physical atmosphere:** [app/physics/atmosphere.gd](../../../../app/physics/atmosphere.gd) computes uniform density from field elevation, temperature, QNH and humidity. [app/physics/wind_config.gd](../../../../app/physics/wind_config.gd) and [app/physics/wind_field.gd](../../../../app/physics/wind_field.gd) own weather inputs, wind sampling and air density. Keep the visual clock independent: time-of-day must not silently change air density, engine charge, trim, turbulence or flight traces. The field schema currently has no latitude, longitude or timezone, so a clock-to-sun mapping is a declared local visual convention unless location data is added.
- **Simulation clock:** [app/sim/simulation.gd](../../../../app/sim/simulation.gd) derives time from fixed ticks. `FlightSession.reset()` returns to tick zero; pause/focus/menu holds freeze the session; crash restart resets it. [app/render/shader_clock.gd](../../../../app/render/shader_clock.gd) intentionally publishes this simulation time, wrapped at 1024 seconds, for deterministic tree/grass motion. Keep that contract; store the selected time-of-day as separate flight/render context. If progression is later added, derive it from simulation time and an explicit rate so pause and restart remain deterministic.
- **Trace/checkpoint boundary:** [app/sim/flight_session.gd](../../../../app/sim/flight_session.gd) owns physics weather metadata and physics-only checkpoint fingerprints; [app/sim/trace.gd](../../../../app/sim/trace.gd) validates weather/atmosphere metadata and writes trace headers. Static TOD is render-only, so it should not enter the physics checkpoint hash or the weather schema. If recorded visuals need reconstruction, store a separate TOD/render-context metadata key via `main.gd`'s `_trace_meta()` and capture evidence; custom-atmosphere traces currently require `metadata_schema = openrc-flight-meta v5`, so avoid bumping that schema without updating its reader contracts.
- **Scenery/captures:** [app/render/field.gd](../../../../app/render/field.gd) calls [app/scenery/scenery.gd](../../../../app/scenery/scenery.gd)'s `Scenery.attach()`. Scenery is opt-in and visual-only; `Scenery.build()` currently reads sun direction during construction. Existing capture manifests and `capture_evidence()` in [app/main.gd](../../../../app/main.gd) record light direction/energy, `clock_s`, simulation time and CLI arguments, providing a place to record TOD explicitly. Keep `test_scenery_trace.gd`'s invariant that scenery does not change physics traces.

## Risks and useful proof points

- Keep clock selection's draft/apply/cancel behavior coherent with weather setup. Do not make opening or applying an untouched TOD control upgrade old weather data.
- A restart should repeat the same selected static clock; a pause should leave lighting unchanged. `sim.time()` must continue to drive shader motion and physics timing.
- The current [app/tests/test_atmosphere.gd](../../../../app/tests/test_atmosphere.gd) checks the shared sky/fog/ground/sun equations at the fixed `Spec.ATMOSPHERE` values. Preserve its equality checks while adding time cases; it is an active user file. [app/tests/test_ui_atmosphere.gd](../../../../app/tests/test_ui_atmosphere.gd), [app/tests/test_atmosphere_flight.gd](../../../../app/tests/test_atmosphere_flight.gd), [app/tests/test_atmosphere_cli.py](../../../../app/tests/test_atmosphere_cli.py), [app/tests/test_weather_cli.py](../../../../app/tests/test_weather_cli.py), [app/tests/test_shader_clock.gd](../../../../app/tests/test_shader_clock.gd), [app/tests/test_e2e_input.gd](../../../../app/tests/test_e2e_input.gd), [app/tests/test_scenery_trace.gd](../../../../app/tests/test_scenery_trace.gd), and the visual-evidence/capture checks cover the main boundaries.
- The rendering audit also reports three cross-track hazards: `main.gd::_capture()` projects the sun shadow by dividing by `sd.y` near the horizon; `Shadow.footprint` clamps sun elevation and bases alpha only on aircraft height, so a night shadow remains; and ground/near-grass materials copy lighting/fog uniforms at construction, including duplicates. Scenery contact shadows are also baked from the sun at construction. Static TOD must be resolved before those builds; any later progression needs explicit updates and a horizon-safe shadow policy.
- [LANDSCAPE-PLAN.md](../../../LANDSCAPE-PLAN.md) already names **L19, “Time of day and weather”** (per-pixel Hosek-Wilkie sky and matching fog). The TOD plan should link to L19 and state how its first static selectable-clock increment fits that existing umbrella.

## Suggested incremental order

1. Define a validated static clock value and default, with deterministic day, twilight and night mapping. Keep it distinct from weather and simulation time.
2. Thread the value through Home draft/settings, `app_root.gd`, and `main.gd`; define the preference schema migration while preserving weather configurations and future-schema protection.
3. Add a direct CLI override for headless traces/captures, with strict invalid-input refusal and no preference reads/writes on automation routes.
4. Record the selected TOD in capture evidence and trace metadata without changing physics trace rows or checkpoint fingerprints. Prove repeatable captures at representative daylight, twilight and night values, plus pause/restart behavior and unchanged scenery-on/off physics traces.
5. Treat day progression as a later opt-in step after the static clock gate; give it a separate rate and deterministic simulation-time source.
