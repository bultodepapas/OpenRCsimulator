# OpenRC Simulator v0.1.0-rc4

This experimental alpha adds a flyable Avanti S turbine aircraft, expands the P-51's propulsion and ground model, and incorporates the project-wide technical audit and revised roadmap. It includes all changes since rc3. Pilot validation remains open.

## Highlights

- **Four flyable aircraft:** Ugly Stik 60, Extra 300S .60, P-51D Mustang 1/4 and SebArt Avanti S. The Extra, Mustang and Avanti remain experimental.
- **Avanti S first flight:** turbine thrust and spool response, generated aircraft data and handling checks. Starts in the air with the engine running, flaps up and gear up; ECU start/stop, fuel consumption and working flaps/retracts are future work.
- **P-51 refinements:** updated geometry and finish, shaft-balance RPM, calibrated propeller estimates, thrust angles, P-factor, tail slipstream and tailwheel handling. Automated envelope and ground maneuvers cover the implemented cases; they are not real-flight validation.
- **Ground foundations:** spring/damper gear contact, tyre friction, steering and field-dependent rolling resistance. This is groundwork for takeoff and landing; a validated player-facing runway-start circuit is still planned.
- **Physics efficiency:** redundant load evaluation removed and rigid-body derivative allocations reduced, with trajectory-preservation checks. Performance still needs measurements on supported user hardware, especially for the more expensive P-51 path.
- **Audit and roadmap revision 5:** saved reproductions and findings, a corrected dependency order, explicit evidence repairs and a bounded next milestone: one independently checked Stik ground circuit. New crash work starts with a factual contact snapshot; structural damage and wreck effects remain planned.

## Verification and its limits

The pre-release checks include the complete headless app suite, generated-data freshness checks, golden flights, frame-rate independence and model contracts. GitHub Actions runs the app and archived prototype checks, rendered capture checks and exports for Windows, Linux and macOS. Export checks inspect packaged resources, verify build identity, run the Linux executable and check the macOS universal/ad-hoc-signed bundle.

The audit separates these engineering checks from physical validation. In particular, the damping-regime test deliberately characterizes a known discrepancy; a green suite does not establish realistic handling. The trimmed-flight smoke checker also has documented incomplete/non-finite-input gaps. These repairs are scheduled, not claimed fixed in rc4. Native Windows/macOS sessions, a physical USB radio, target-GPU performance and the human readability gate still need owner evidence.

## Known limitations

- Flight-model parameters contain estimates and borrowed data. Roll-response discrepancies, approach-regime damping, matched propeller measurements and independent flight validation remain open.
- The rigid-body RK4 kernel is fourth-order with frozen auxiliary inputs; the coupled P-51 shaft/session update currently shows first-order convergence. The revised state contract and shaft integration are future work.
- Rolling creep remains; true wheel stiction and the complete Stik runway-start/landing acceptance are pending. Hull contact or excessive gear travel can still trigger the existing crash/reset behavior.
- Wind, persistent structural damage, fuel burn and full engine/ECU operation are not implemented. Trees remain visual only.
- The current audio is a placeholder. Orientation readability and frame pacing must be assessed on the player's display and hardware.

For useful feedback, record the build, aircraft, radio/OS/GPU, setup time, trim behavior, attitude readability and frame-time report. Distinguish repeatable behavior from subjective handling impressions.
