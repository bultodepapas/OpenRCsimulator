# OpenRC Simulator v0.2.8

Early-alpha software release. Vehicle models remain experimental. Automated checks and replay agreement do not establish physical accuracy, target-hardware performance or pilot acceptance.

## Changes since v0.2.7

- Hardened native-backend admission, configuration guards and flight-log replay. Flights retain their selected backend identity; incompatible recordings or changed native inputs are refused explicitly.
- Added guarded Apple Silicon native-evaluator development workflows, exact replay checks and a required macOS ARM64 source-correctness CI gate. The qualified M1 source-editor route is separate from the public macOS download, which continues to use the GDScript reference flight evaluator. [Scope and remaining gates](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/docs/research/native-kernel/DT-MAC-04n4/README.md)
- Renewed AI-companion compatibility against the guarded solver using retained input tapes, and verified historical publication fixtures without replacing their goldens.
- Improved development performance diagnostics with bounded process-resource sampling and matched early/final flight windows. These tools do not establish a general performance improvement or hardware qualification.

## Downloads and known limits

The release provides Windows x86_64, Linux x86_64 and macOS universal ZIP archives, `release-manifest.json`, `linux-abi.json` and `SHA256SUMS`. Verify the complete downloaded set with the manifest and checksums. Archives are unsigned; the macOS app is ad-hoc signed, not notarized. Keep its sibling reference receipt beside the extracted app. [First-launch guide](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/docs/FIRST-LAUNCH.md)

The engine remains official **Godot 4.8-beta2**, a prerelease. Qualified Linux fixed-wing/helicopter configurations can use the native evaluator; unsupported configurations retain the GDScript reference. Windows and public macOS flight packages use the reference path. [Backend scope](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/research/native-kernel/README.md#normal-flight-backend-selection)

The FPV quad, 5 m blimp and Aircraft Creator retain their experimental limits. The quad uses estimated plant data; race records are local practice results, not published-rule compliance. The Creator still lacks its numerical qualification gate. The electric Stik 6S has no reviewed landing-statistics profile. Existing weather schema 7 compatibility and recovery rules continue to apply. [Drone scope](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/docs/plans/drone-racing.md) · [Creator limits](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/docs/AIRCRAFT-WORKSHOP.md#aircraft-creator-experimental) · [Settings recovery](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/docs/TOOLS.md#preference-file-recovery)

The Stik reference-doublet sideslip screen and R02 yaw comparison remain pending. Native desktop/device acceptance, downloaded macOS quarantine behavior, sustained target-GPU performance and physical flight validation remain separate from automated checks. Rendering and UI qualification prioritize 1920×1080. [Release gates](https://github.com/bultodepapas/OpenRCsimulator/blob/v0.2.8/ROADMAP.md#execution-order-and-release-gates)
