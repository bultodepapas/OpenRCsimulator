# Flight Simulator import: milestones and contingency evidence

**Date:** 2026-11-17. **Status:** proposed implementation/qualification contract; no milestone below is completed by this documentation. **Owner:** Aircraft Creator, using existing AC-FS-01…15 and shared owners. The [feature plan](flight-simulator-aircraft-import.md) owns architecture/scope; the [wizard](flight-simulator-import-wizard.md) owns product behavior and W01–W19; the [26 source-code cases](../research/aircraft-creator/flight-simulator-2026-11-16/code-investigations-2026-11-17.md) own dated evidence. M1–M8 are delivery groupings of existing work, not a second implementation track.

## Completion rules

The first complete feature remains **select a supported Flight Simulator source → automatic in-app translation/conversion → questions only for unresolved choices → editable RC aircraft → qualified checked flight → save, Home, restart, edit a new revision and fly**. W01 requires zero follow-up questions for complete, uniquely resolvable supported input with an applicable declared RC profile. Source selection and final Save/Fly are ordinary actions. A prepared GLB or externally executed script cannot stand in for the advertised automatic source.

M1–M5 are partial engineering outcomes. M6 may qualify an exact unsaved trial for a stated mode, while the complete feature remains partial. **M7 is the first completed bounded automatic release**; M8 adds separately qualified capabilities. Research/AC-FS-00 is delivered, but does not count as M1 acceptance. Independent checks must verify positive supported cases as well as precise refusals; passing only rejection tests does not establish compatibility.

Every milestone receipt names: implementation commit/tree; exact source/fixture/profile/recipe versions; applicable AC-FS owner and gate; expected output/oracle prepared before the candidate run; actual evidence and resource observations; outcome `pass`, `fail`, `blocked`, `not-run` or a justified capability-specific `not-applicable`; unresolved limitations; and which dependent receipts a change invalidates. A summary, screenshot, successful process exit or compiler acceptance cannot replace missing evidence.

## M1: Corpus and shared contracts

**Work:** AC-FS-01/02, coordinated with AC-CV-05/07 and AC-13/14/19. **Entry:** AC-FS-00 evidence and agreed first conventional RC topology.

- **Deliver:** an exact candidate source profile, original independent fixtures, and a named authorized real-source candidate with revision, selected variant, required base/texture/generated artifacts, expected exterior/control inventory and separate code/asset terms. Record whether it is authoring source, assembled source or built package; a folder name is not that classification.
- **Deliver:** versioned capture/observation, property-level provenance/override, raw-edit/history, source-closure and publication-reconciliation contracts. Each changing shared reader has an owner and migration/refusal rule; the source adapter cannot add undocumented dictionaries to closed readers.
- **Evidence:** fixture inventory and independent expected values; dependency closure/permission record for the real candidate; reader-version counterexamples; bounded draft/receipt round trips; an explicit unresolved-decision register. The [profile/receipt fields](#required-profile-and-evidence-records) below must have concrete values where this milestone owns them.
- **Exit:** shared contract scope is reviewable, the real-source candidate and remaining closure/permission gaps are named, and each gap has its AC-FS owner and discriminating check. A candidate is not yet a qualified W01 source.
- **Stop/reopen:** no identified usable real-source route, unresolved file-level code provenance for a proposed dependency, or unowned shared reader changes blocks the affected adoption decision. Synthetic interface work may continue; M7 stays blocked until the exact real source is complete and authorized. Reopen affected records on source, provenance or schema changes.

## M2: Bounded source resolution and report

**Work:** AC-FS-02/03. **Entry:** M1's capture/resolution contract and relevant fixture subset.

- **Deliver:** deterministic selected-root capture, version-qualified dependency/variant/livery/overlay resolution, active model/LOD selection and an attributed effective-configuration report. Preserve overridden and invalid declarations. Recognize generated artifacts, unresolved runtime dependencies and unassembled model ingredients without running their build/code.
- **Evidence:** C01/C02/C04/C05/C06/C07/C11/C14/C20/C25 plus existing capture race, malformed token, cycle and missing-base cases. Independently calculate the expected effective declarations and exact captured closure. Verify an in-root parent reference succeeds while actual escape does not.
- **Exit:** exact supported source-report fixtures resolve without unnecessary *source-resolution* prompts; all unavailable dependencies have specific outcomes. A prepared-GLB association can support an explicitly partial engineering draft.
- **Stop/reopen:** ambiguous precedence, unstable capture, unknown essential semantics or missing required closure prevents complete analysis. Ask only for an actionable location/selection; an unimplemented dialect needs a capability outcome. Changes to roots, bytes, rules, variant or livery invalidate affected resolution receipts.

This milestone cannot claim W01 or successful automatic model/flight conversion merely because its source report asks no questions.

## M3: App-owned conversion runtime decision

**Work:** AC-FS-04, with AC-FS-01/02 and desktop/dependency owners. **Entry:** M1/M2 plus the minimum expected geometry/material/rig and source-profile contract.

- **Deliver:** one selected, version-pinned redistributable conversion implementation and its dependency manifest, or an evidence-backed narrower profile. State which work is an in-process library, bounded worker or engine operation. No player-installed Blender, Python CLI, Microsoft SDK or ModelConverterX dependency may be necessary for the advertised automatic path.
- **Deliver:** explicit decoder/material/extension coverage, stage interfaces and source/output limits. Pin finite numeric resource and responsiveness thresholds on named target hardware **before** the production corpus campaign. Missing thresholds cannot pass the gate.
- **Evidence:** C08–C19 and C21–C25 where applicable; independently authored asymmetric geometry/material/normal/UV fixtures; complete standards diagnostics when used; strict Creator re-admission; expected-parts and source-to-output correspondence; measured conversion, serialization, decode and preview costs. Compare against an independent reference, not solely another tool using the same decoder.
- **Exit:** the chosen implementation actually performs the required bounded normalization and can ship on every target intended for the first release. Record alternatives rejected and the precise unsupported source forms. A library's README or a manual export does not close this milestone.
- **Stop/reopen:** unresolved redistribution scope, silent loss/repair, unsupported essential extension, nonterminating work or exceeded budgets requires implementation change or a new narrower advertised profile. Preserve failed evidence. Tool/codec/version/options/profile changes reopen dependent qualification; do not raise a failed threshold retrospectively and reuse the previous campaign.

## M4: Automatic exterior, materials and controls

**Work:** AC-FS-05/06, coordinated with AC-17. **Entry:** M2/M3's qualified source and conversion subset.

- **Deliver:** automatic active exterior/LOD selection, justified closure reduction, material conversion and source-to-normalized-to-engine node correspondence. Resolve uniquely qualified rigid control bindings automatically; ask only when a supported choice remains ambiguous.
- **Evidence:** C02–C05/C07/C09–C13/C17–C19/C22–C24, the independently testable visual/binding/source-integrity slices of W05/W09/W10, and independent neutral/midpoint/end-point/propeller-direction expectations. Confirm all retained resources, not only visible triangles, satisfy admission. Exercise a same-name node-index swap and a selected tiny scene with an oversized orphan. W10's physical-byte preservation and readiness-invalidation assertions close only after M5/M6, and its full journey remains an M7 gate.
- **Exit:** an admitted visual with measured correspondence, explicitly complete/limited exterior and motion status, and reusable editable source observations. Repeated runs with identical semantic inputs follow the documented determinism policy.
- **Stop/reopen:** missing expected parts, unsupported required material/pose behavior, irreducible resource excess or unprovable bindings yields a specific limited/refused result. Never promote a static fallback to completed movement. Source, LOD, graph, material or recipe changes invalidate affected visual and binding evidence.

## M5: Automatic editable RC construction

**Work:** AC-FS-02/07, with the applicable AC-14 history slice and AC-FS-10 draft integration. **Entry:** M1–M4 and supported geometry/topology.

- **Deliver:** automatic applicable RC-profile selection, separate source calibration and target scale, typed field adoption, target inventory/equipment/control construction, conditional questions and later editing. Preserve exact raw invalid input and independent property overrides/evidence.
- **Evidence:** the independently testable draft, input, recomputation and provenance slices of W03/W04/W06–W08/W15–W17/W19; independent scale/units/frame and inventory/CG/inertia expectations; absent/zero/invalid distinctions; draft reimport and undo/reset round trips. Every player-meaningful generated value has a typed editor, coherent governing-input route or validated override supported by its law. Qualified coupled-domain/readiness assertions depend on M6; restart, immutable-version and full reimport journeys depend on M7. This milestone does not claim those whole journeys pass early.
- **Exit:** fully resolvable original fixtures produce an editable compiled draft with no unresolved questions, and changing supported inputs recomputes consistent outputs without overwriting manual work. Estimates remain estimates. The executable readiness predicate is specified for the candidate domain.
- **Stop/reopen:** unsupported topology, invalid raw state, infeasible locked inventory or out-of-domain equipment remains blocked/editable. Never delete an engine or reshape a wing merely to fit. Input/profile/producer changes invalidate dependent proposals and checks; a compiler-accepted draft alone cannot fly under this milestone's acceptance.

## M6: Qualified frozen trial

**Work:** AC-FS-08/09 and AC-09/11, physics/SF/FL/energy/start owners. **Entry:** M4/M5 plus a preregistered candidate law/profile domain.

- **Deliver:** a passing owning numerical campaign, an executable qualified-envelope predicate covering permitted inventory-derived CG/inertia, equipment and actuators, and exact check-to-launch context. Close start/reset/return/crash/recorder/replay behavior for the stated modes.
- **Evidence:** the applicable 240/480/960 Hz campaign or a separately preregistered and reviewed alternative; held-out cases and boundary counterexamples; the trial/readiness slices of W11/W17/W19; C26's check/actual-launch mutation case. Saved-version/restart assertions remain M7 gates. Retain failures and distinguish numerical stability, source-simulator agreement and real RC calibration.
- **Exit:** exact candidates inside the qualified domain may take the checked unsaved trial path. The receipt binds source/visual/definition/physical/profile identities to actual launch context; a change cannot reuse a stale start result. Existing AC-12 failed evidence is not reclassified by this plan.
- **Stop/reopen:** missing/failed owning gate, changed check context, unavailable physical law or inputs outside the envelope blocks readiness while preserving the editable result and previous flight. Runtime membership checks do not rerun a research campaign for each edit; laws or envelope expansion require new qualification.

## M7: Saved, portable and packaged automatic journey

**Work:** AC-FS-10/11, with AC-13/14/18/19 and required repository/platform gates. **Entry:** M1–M6 and a complete authorized real W01 source in the actual advertised profile.

- **Deliver:** bounded immutable original/normalized/authoring/physical closure, exact semantic recompile verification, truthful publication/CAS recovery, Home resolution, clean restart and new-revision editing. Keep source-content export rights separate from local conversion capability.
- **Evidence:** the **complete applicable W01–W19 suite** on the integrated candidate, including W10's physical-byte preservation and readiness invalidation, W15–W17's history/reimport/qualification boundaries and W19's override behavior. Run **W01 and W13 on the exact real source and original independent fixtures** in clean advertised desktop exports, alongside W02/W09/W12/W14/W18 failure/recovery cases. The player selects the source and OpenRC performs all required conversion with shipped dependencies; source/profile-resolved cases ask zero follow-up questions. Verify save → Home → restart with original source unavailable → edit/new version → checked flight, alongside the unsaved-trial path. Every journey has an explicit outcome; a justified capability-specific omission cannot remove behavior required by the advertised profile.
- **Evidence:** frozen 1080p-first budgets on named Windows/Linux/macOS targets intended for release; peak memory/live-worker/main-thread-stall/cancel/drain observations; all applicable required CI; closed corrupted/missing dependencies, draft failures and uncertain commit outcomes. Record actual OS/filesystem behavior instead of assuming portability.
- **Exit:** all advertised capabilities and platforms have complete evidence on the integrated release candidate. Publish the precise source/profile/target matrix and known unavailable forms. No silent dropping of a failed target or substitution of a manual preparation path.
- **Stop/reopen:** any required gate, exact real source, shipped runtime, saved closure or advertised target remains incomplete. A consciously revised release scope needs a new published manifest and corresponding evidence. Changes invalidate the affected receipts according to the [invalidation table](#requalification-and-change-control).

## M8: Later source families and calibration

**Work:** AC-FS-12/13/14/15. **Entry:** M7's shared baseline for advertised expansion; bounded research may proceed earlier.

Legacy FSX/FS9/P3D decoding, native MSFS 2024 composition, additional physical families and RC calibration are separate increments. Each needs exact dialect/source rights, positive fixtures, refusal cases, profile/limits, qualification predicate, lifecycle and packaged evidence for its claimed scope. A legacy manual preparation route remains a partial capability. Native 2024 attachment substitutions or a custom flight law cannot inherit 2020 compatibility by sharing a file extension. Low-Re fitting needs identifiable parameters, uncertainty and independent held-out RC evidence. Reopen only the applicable capabilities when their laws, sources or composition rules change, while preserving M7's immutable supported revisions.

### Resource and responsiveness contract

Every advertised profile needs finite numeric limits, units, measurement boundaries and a named owning stage. Freeze them after the M3 capacity spike and **before** the production qualification corpus; use separate engineering trials while choosing them. Do not invent measured capacity in this document. Blank, unbounded, unknown or retrospectively relaxed values do not pass M3/M7.

| Budget | Required definition and proof |
| --- | --- |
| Source and expansion | Aggregate/per-file captured bytes, entries, dependency edges, path lengths/depth, nesting, compressed/expanded bytes, tokens and decoder workspace; bound actual work, not only declared sizes |
| Normalized output | Keep all current Creator ceilings unless a separately measured owner revision changes them, including 32 MiB model, 200,000 triangles, 512 nodes, 32 materials, 16 images and 16,777,216 aggregate pixels; count all retained/engine-built resources |
| Concurrency | Initial policy: one active import job and one coalesced latest pending selection. Freeze internal worker/process count and peak owned bytes; A→B→C cannot start unlimited A/B/C pipelines. Superseded work drains before its budget is reused |
| Memory and lifetime | Whole-process peak plus import-attributable peak, decoder workspace, decoded images/GPU residency and retained old/new preview/staging bytes on named hardware; include the previous accepted aircraft/flight rather than measuring only an empty app |
| Time and interaction | Stage deadlines, longest main-thread stall, conversion time, cancellation acknowledgement and complete drain/release latency; define sampling/instrumentation, warm/cold runs and frozen repeat count. Serialization, image decoding, engine scene creation and fallback rebuilds are included |
| Failure accounting | Observe live workers, owned handles/scenes/staging objects and publication state after failure/cancel/retry/close. A timeout or unsupported indivisible call is a failed/blocked stage, never a success with a hidden background tail |

Source ceilings and output ceilings are different policies. Qualified in-app reduction may fit a large bounded source into the output limits, but cannot delete required surfaces or shift physics with visual quality. For an external worker, specify the owner, deadline enforcement, termination and join/reaping mechanism, including child work, output quarantine and cleanup. An elapsed timer alone does not stop a hung worker. For a noninterruptible in-process/engine call, demonstrate an input-bound completion strategy within the frozen UI/resource limits or change the integration through isolation/redesign. A sampled successful run alone is insufficient. A timeout must remain undrained while owned work is alive; a token cannot interrupt an API that does not accept it.

## Independent oracle requirements

Before coding each fixture's converter assertion, write its expected source selection, values/units/axes, selected part inventory, material sample values, node/pivot identity and allowed omissions. Use hand-derived analytic geometry, original uncompressed references, primary format rules and the existing trusted boundary as applicable. An expected result computed by the candidate converter or the same suspect third-party function is not independent.

Use exact equality for specified indices, identities, defaults and zero/missing classification. For float geometry/material comparisons, declare reference precision, absolute/relative tolerances and why they reflect the representation; freeze them before the campaign. Include positive and intentionally wrong counterparts so an assertion that always refuses or always accepts cannot pass. Report unsupported rather than fabricate an oracle when source semantics remain unknown.

Two small reference checks illustrate the required precision: a right-handed +90° Z rotation followed by translation `(10,0,0)` maps `(1,2,3)` to `(8,1,3)` before any OpenRC frame conversion; a triangle-list index slice of one primitive starting at index 3 in `[2,1,0,5,4,3,8,7,6]` selects `[5,4,3]`, with byte offset 6 for unsigned 16-bit storage relative to the accessor start. These are fixture definitions, not universal MSFS encoding guesses. C03's expression targets and C18's half-float values are similarly bounded known answers; none proves runtime fidelity by itself.

## Requalification and change control

| Changed input | Required invalidation / retained evidence |
| --- | --- |
| Display name or pure paint | Invalidate affected presentation/publication identities and visual checks. Reuse unchanged physical/numerical evidence only when exact physical inputs/laws remain unchanged |
| Source, variant, LOD, material, node graph or correspondence | Re-resolve affected closure and visual/binding checks; invalidate physical proposals only where those inputs feed them. A new byte identity never inherits an old source receipt |
