# Multiplayer: zero-spend implementation plan

**Owner:** multiplayer implementation lead, coordinating the existing SF/physics, UI, AFC, FL, DR and DT owners. **Prefix:** `MP-00…08`. **Status:** research and planning only; no multiplayer runtime delivered by this change. **Reviewed:** 2026-11-16 (America/Bogota), against `main` at [`cfb5acd5cfbcbf83f7f9220116c67fa082e8f27b`](https://github.com/bultodepapas/OpenRCsimulator/commit/cfb5acd5cfbcbf83f7f9220116c67fa082e8f27b).

This is the authoritative implementation plan. The [MP-01/02 protocol and delivery contract](multiplayer-protocol.md) owns exact bytes, adapter ownership and first implementation slices. The [research](../research/multiplayer-2026-11-15/README.md) owns alternatives, dated prices/quotas and calculations; the [repository audit](../research/multiplayer-2026-11-15/repository-audit.md) owns source evidence. [Twenty practical investigations](../research/multiplayer-2026-11-15/round-3-20-investigations.md) add reusable tools/examples and record a source-drift check against newer `main` at `6dfe1b9179af408f6b765b91ca164e626570db9f`; repin selected assets before implementation. [STACK](../STACK.md#boundaries-and-data-flow) remains the simulation contract.

## 1. Decision and first product

Build **two-player LAN free flight with built-in ENet**, qualify direct internet joining, then **four-player private rooms hosted by a player**. Every pilot runs their own aircraft's existing physics. Other aircraft are visual replicas. Keep this local/direct path usable without a service account.

After private rooms work, timebox an **Epic Online Services (EOS/EOSG) connectivity trial**. It is the preferred candidate for easier joins through NAT and optional service-backed lobbies. Adoption requires exact-engine/platform tests and confirmed no-fee eligibility. [Source review of EOSG 2.3.1](../research/multiplayer-2026-11-15/eos-trial.md) found sender-attribution and guest-identity concerns; its high-level peer is blocked until reviewed fixes and adversarial tests close those findings. If the trial fails, ship the qualified LAN/direct/private-network scope; do not replace it with an unverified promise. A **Cloudflare Workers Free directory** is an independent fallback for discovery of reachable ENet hosts. Select one online room service; do not build EOS, Firebase, Supabase and a custom relay simultaneously.

The first useful release supports one approved stock field, one stock fixed-wing aircraft, two pilots, host/join/leave, names, connection diagnostics and clean failure. Expand the bundled aircraft allowlist after replica checks. Free flight includes formation practice without shared collisions. A room is a roster plus rules and lifecycle; it can exist on the host before any cloud directory exists.

**Zero spending means no new project invoice.** It assumes existing computers, internet and development tools. It does not promise free electricity, unlimited capacity, permanent availability or successful connections through every network. No paid plan, new domain, expiring credit or automatic paid fallback is a required dependency.

## 2. Boundaries and ownership

| Proposed component / path | Owns | Must preserve |
| --- | --- | --- |
| `app/networking/` — session, codec, transport adapters, room state | Admission, routing, clocks, sequence/epoch handling, bounded queues and shutdown | No network writes into the local solver or controller; transport continues during local menu holds |
| `app/render/multiplayer/` — remote aircraft presentation | Interpolated transform, approved model, simple animation, label and stale status | No `FlightSession`, input device, camera/audio listener, local statistics or collision participant per remote aircraft |
| `app/ui/multiplayer/` | Host/join, roster, ready state, mismatch/failure messages | Existing screen stack, loading cancellation, controller arming, recorder prompts and explicit resume |
| `app/tests/test_mp_*.gd` | Codec, clocks, admission, impairment and lifecycle fixtures | Existing checked-runner and test-queue rules; real multi-machine evidence remains separate |
| Optional `services/multiplayer-directory/` | Small directory and quota enforcement if that route is selected | Metadata only; no physics, aircraft assets or flight telemetry storage |

These paths are **proposed**, not present networking modules. Shared edits in `app/app_root.gd`, `app/main.gd`, existing presentation builders, sessions and exports stay coordinated with their owners. Reuse companion visual construction and [frame/model-offset conversion](../../app/render/frames.gd), with position at the fixed body datum O, not the changing live CG; do not reuse its AI session/manager as a remote plane.

The host controls membership, room settings, readiness and entity ownership. Each connection controls only its assigned aircraft's pose. This is suitable for friendly flying; it does not establish fair competitive scores. One `VehicleModel` per `Simulation` remains intact. Multiple independent sessions already exist for AI, but remote visual presence does not require another solver.

A wrapper fork, new native adapter, optional mapping/discovery spike or unresolved public-room hardening needs a separate estimate; it is not absorbed into the service timebox. The twenty research topics are a selection of reusable work and alternatives, not twenty additional required projects.

## 4. Session and room contract

Admission progresses through `connecting → compatibility → loading → ready → flying`. Connected is not ready. A bounded cancel/failure route exists at each stage. Reliable configuration and a current baseline must arrive before a replica is visible. The initial compatibility gate requires the same source/build family, protocol major, approved field bytes/scene identity, aircraft definition/model revision and shared environment profile. Platform-specific package hashes may differ; record them without requiring Windows and macOS binaries to be identical.

Use one stock world/profile first. Pin shared conditions and a fixed lighting selection before launch; lock changes during flight. Animated scenery/cloud details may differ locally: a shared starting time does not synchronize visuals driven by independent simulation clocks. Start with calm/no evolving turbulence. Shared gusts or animated world time later need a separate room-clock sampling design; copying a seed does not synchronize clients that pause or run slowly. Aircraft can differ only after each admitted stock model's visual/data identities are qualified. Custom Workshop models, downloaded skins and automatic content transfer are deferred.

| Event | Required behavior |
| --- | --- |
| Pilot menu or focus loss | Preserve existing safe local pause. Publish `PAUSED`, freeze that replica and stop its extrapolation. Network receive/host forwarding/heartbeats continue; no global pause and no remote command resumes local controls |
| Resume, reset, crash/restart, teleport | Reliable new flight epoch + accepted baseline; clear old interpolation; never sweep through the field from an obsolete pose |
| Client connection loss | Remove/fade stale replicas; apply existing safe local hold and offer explicit offline continuation or rejoin; local input never waits synchronously for network |
| Host leaves, sleeps or crashes | End the room within the timeout; other pilots enter the same safe local fallback. **No seamless host migration** in this plan, including when a service can promote its lobby owner |
| Rejoin | Fresh connection identity and roster/baseline; no old backlog. A stale packet or reused peer number cannot regain ownership |
| Loading, cancel, Home, quit | One connection owner; deterministic teardown; no ghost entities, sockets or signals retained after cancellation/exit |
| Workshop, checkpoint restore, time scaling | Leave the room through existing recorder/save flow before entering. No online restoration of a player-only checkpoint or unilateral room-time rewrite |
| Recording/statistics | Existing local logs contain only the local flight; remote presentation is not recorded/replayed and earns no local credit. Label this clearly; whole-room replay is later work |

Disable AI companions in the first online mode to keep the qualified workload and lifecycle bounded. Preserve the offline setting. If menu holds cannot be isolated safely in MP-02, explicitly leave the room on that transition; MP-04 must qualify continuous routing during local pause before shipping host rooms.

## 5. Snapshot, adapter and timing contract

The [MP-01/02 contract](multiplayer-protocol.md) owns the revised 128-byte layout, 64-bit room incarnation, precise surface semantics, control framing, status/epoch ordering, clock mapping and fixture list. It supersedes the earlier proposed layout; no shipped network protocol exists. Keep 240 Hz local physics and publish detached accepted samples at 20 Hz wall time, outside solver transactions. Quantization never writes back into simulation state.

Use a standalone, manually polled `SceneMultiplayer` owned outside the flight subtree; disable automatic server relay and object decoding. Guests address host 1, the host validates then forwards explicitly, and clients use the authoritative application roster. Logical channel 1 carries reliable controls; channel 2 carries unordered sequenced poses/probes/heartbeats. Two channels must be configured on both ENet peers. Reserve one bounded temporary admission slot beyond the admitted pilot cap for best-effort refusals; exhausted transport capacity can still produce a timeout.

Start with **200 ms interpolation delay**, linear position plus shortest-path quaternion slerp, **extrapolation disabled**, 500 ms active-pose stale marking and a 5 s liveness timeout. A later measured extrapolation option must remain within 100 ms and handle simulation/wall-time mismatch, including stalls before DEGRADED detection. A live paused aircraft remains visibly frozen with its original pose timestamp. Host, individual guest and pose liveness are separate. The previous 100 ms delay did not leave bracketing margin for the stated two-hop Internet profile; [the analytical bound](../research/multiplayer-2026-11-15/round-2.md#reproducible-analysis-and-evidence-ladder) motivates the new starting point, not a measured pass.

Validate identities, message phase, complete bounded data, render conversion, sequences, epochs and clock plausibility before mutating replicas. Reliable controls and poses may cross in transit. A new flight becomes visible only after its reliable baseline, and delayed old status cannot override it. Local reset/restore signals require their actual transition receipt; they are not interchangeable.

Application queue/size limits do not bound engine reassembly or drain-all polling under hostile traffic. Friendly LAN is the first qualified scope. Public stranger rooms require transport-level hardening and adversarial evidence. A future non-Godot backend speaks the explicit application schema, not Godot's private RPC protocol; WebSocket transport would still need a separate latency trial.

## 6. Online route and hard-zero budget

**EOS first investigation:** follow the [bounded trial](../research/multiplayer-2026-11-15/eos-trial.md). Pin source, release asset, exact SDK and notices; a 4.7 loading fix does not prove 4.8-beta2 compatibility. Do not adopt the inspected peer until actual EOS sender is bound to packet attribution and malformed input is safely rejected. Avoid the destructive anonymous-login helper; prove first-user initialization and returning-guest persistence. Qualify fresh direct/forced-relay sessions and required OS exports. A configured developer product is needed; mandatory Epic player login is not assumed. Ship only a least-privilege user-required game-client policy; never trusted-server/admin credentials. No account or deployment is created by this plan.

**If selecting the independent directory:** use the provider's free subdomain and Workers Free with SQLite Durable Objects; HTTPS JSON, max **five advertised rooms initially**, host heartbeat every 30 s, TTL 90 s, list at most every 30 s and only while visible. An invite code locates a room; a separate random capability admits a private join, with expiry and owner revocation. Keep owner tokens out of listings. Here “private” means unlisted, possession-based friendly access; a capability sent over plain ENet does not establish confidentiality or an authenticated identity against an on-path observer. Stronger claims require a qualified protected channel. Publish reachable endpoints only for opted-in hosts and resolve them for intended joins; an HTTPS heartbeat does not prove UDP reachability.

Reserve 30% of provider request/write/duration allowances. The [revised model](../research/multiplayer-2026-11-15/round-2.md#directory-costs-and-failure-contract) includes durable counter writes: ten hosts plus ten continuously open browsers at 30 s cost at least 86,400 writes/day under that model; five hosts plus ten browsers reduce this to 57,600 before other work. Meter actual completed SQL cursors and keep request/DO/write buckets separate. An approximate per-location edge rate limiter is not a global quota; a paid spending alert/limit is not equivalent to the Free plan. Use short operations and lazy expiry, not continuous per-room timers. Stop admission/listing when the application allowance is consumed, return a useful unavailable state and retain direct join. Count other account traffic, cleanup, retries, index writes and hostile requests. Application counters improve availability planning; the actual provider **Free plan's refusal beyond limits** is the spending boundary. Confirm it in the selected account before deployment. Require fail-closed or a proven safe/no bypass origin for routed endpoints; quota failure must not bypass admission. These guarantees do not cover unrelated paid account products. No auto-upgrade or paid relay failover. Recheck dated terms before implementation and public release. [Quota model](../research/multiplayer-2026-11-15/README.md#capacity-and-cost-models)

UPnP automation is off and held until collision-safe mapping creation, ownership, cancellation and cleanup are proved. The pinned API can overwrite a mapping and does not expose a conditional delete/ownership query; a local success flag is insufficient. Keep manual forwarding as a fallback rather than deleting an ambiguous mapping. Router work must be bounded and off the main thread. A local mapping alone does not establish a reachable path through ISP CGNAT; provider-supported interworking is optional and unverified. Optional LAN discovery also needs its own engine-work limits; a script loop cap does not bound the pinned UDP drain loop. [Connectivity investigations](../research/multiplayer-2026-11-15/round-3-20-investigations.md) own these findings and optional test routes. Eligible Tailscale/ZeroTier personal networks are private test tools with installation/account limits, not required public infrastructure. Plain direct ENet is not automatically an encrypted/authenticated service; make no such claim. Public stranger rooms wait for reviewed transport-level admission, fragmentation, rate and work limits plus actual abuse tests. No credentials for paid/provider administration go in exports.

## 7. Acceptance gates

All numbers below are **proposed pass criteria**, not achieved measurements. Record exact build, OS/hardware, resolution, transport/route, payload size, peers, reference trace, wall-time length, p50/p95/p99 and failure counts. Follow [existing verification scope](../tools/shared.md#verification-scope), checked runners and shared-host admission. Full required CI remains its own gate.

| Gate | Required evidence |
| --- | --- |
| **A — local correctness** | Same fixed input tape produces identical accepted local state with networking off/on for each qualified backend; malformed/oversized/duplicate/out-of-order/old-epoch packets cannot mutate local state. Healthy LAN admission ≤5 s excluding asset load. Cancel works at every stage; 50 cycles leave no residual replicas/sockets/signals |
| **B — four-pilot network and lifecycle** | 60-minute one-host/three-client session; controlled 100 ms RTT per client↔host leg (50 ms one-way base), up to ±20 ms one-way jitter and 2% random loss on each traversed directional link. Record the actual impairment distribution, seed and placement; two traversed loss links compound. Target p95 rendered remote sample age ≤300 ms and stale display <1% over active periods, excluding intentional PAUSED time and explicitly marked injected outages; the ordinary jitter/loss profile remains included. Report total/included seconds and each exclusion; separately prove paused peers remain live/frozen without restamping. Also exercise 200 ms loss bursts, duplication, reordering, 1 s stalls, asymmetric links, host sleep/kill, pause/focus/Workshop/quit, resets and late joins. Separate source timestamp age from clock-estimation uncertainty; report failures, not just averages |
| **B2 — motion/performance** | Compare rendered replicas to recorded truth at their intended delayed timestamp for taxi, level flight and fast roll/reset traces; initial residual targets p95 ≤0.5 m and ≤2° outside marked discontinuities. Network-only p95 main-thread CPU ≤1 ms on the declared reference host; no unbounded queues or monotonic memory growth after warm-up. Qualify additional visual cost separately at **1080p first** against the existing physics/frame gates; reduce room cap/visuals if unmet |
| **C — service and cost** | Shared: actual account/plan/terms, outage/backoff/offline fallback, no charges or automatic paid route, full/mismatch and possession-based invite admission/expiry/revocation. **EOS route:** fixed/qualified sender attribution, first-user/returning-user identity, verified direct and forced-relay cases, and lobby teardown. **Directory + ENet route:** reachable joins, honest unreachable-host failure, expired listings filtered within TTL, quota refusal fixture plus provider evidence and actual request/write/duration accounting; no relay is required or claimed. Simulated quota exhaustion must be labeled simulated |
| **D — release matrix** | Real Windows x86_64, Linux x86_64, macOS ARM64 and Intel/Rosetta paths that will be claimed; each used as host and client, with distinct-machine/OS pairs. Exporting a ZIP is not target-OS execution. Required CI results, controller safety, local statistics/recorder behavior and offline launch pass. Untested target combinations remain unsupported beta claims |

Keep network impairment injection above the transport for reproducible codec/state tests; add real OS/network tests for transport effects it cannot emulate. A clean LAN run cannot close Internet/relay gates. Eight participants and spectators must repeat the capacity/performance gates; spectators still consume bandwidth and room slots.

## 8. Deferred scope and stop rules

Ghost files and pass-the-controller sessions can be zero-service side features; they do not verify live networking. Split screen needs separate input/camera/session work and is not assumed cheaper. Native WebRTC, GD-Sync and an application WSS relay remain researched alternatives, not parallel mandatory implementations.

Defer aircraft-to-aircraft collisions, shared control/instructor handover, aerotow, cross-platform input lockstep, rollback of the full solver, persistent worlds, global ranked results, integrated voice, asset upload/download and automatic host migration. Later informal drone races may share **client-reported** results, but sparse presentation snapshots must not adjudicate gate crossings; the DR track owns its 240 Hz race model.

Stop expansion if any phase changes offline flight results, cannot preserve pause/arming/recording, relies on unverified native binaries, has unbounded traffic/memory, requires a chargeable service or lacks real evidence for its advertised network/platform scope. Deliver the last qualified smaller scope. A free lobby's maximum members and a synthetic throughput estimate never justify increasing the product cap.
