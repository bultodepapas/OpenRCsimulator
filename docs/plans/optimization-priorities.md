### Frame stalls and sustained FPS

The November 2026 Windows, ANGEL and PRIMIS tours showed that a delayed frame can cause extra 240 Hz catch-up ticks in the following frame. An expensive tick can amplify a hitch that began in rendering, presentation or OS work. Keep the two intervals separate. The [frame attribution](../research/god-test/2026-11-24-frame-attribution.md) and [direct phase timings](../research/god-test/2026-11-24-flight-tick-cost.md) identify the builds, routes, windows and hosts.

## Hardware and admission

Qualify the actual release route and backend on the named host. Normally test 1920×1080 first, then higher resolutions and finally 1280×720. On Apple Silicon with Retina (2×), qualify full-screen native display pixels and the native-pixel reconstructed 3D result where MetalFX is used. Record output, drawable and internal pixels. Use the [Apple campaign](apple-silicon-performance.md#campaign-protocol-and-acceptance-budgets), [native admission guide](../../research/native-kernel/README.md#normal-flight-backend-selection) and [graphics capability policy](automatic-graphics.md) for the platform under test.

Engine forks, shader prewarming, speculation/prefetch, SIMD, scheduler hints or GPU compute each require a named residual cost and an independently testable mechanism. Preserve the current transaction and actual backend refusal/fallback. Numerical changes follow the [flight logging workflow](../FLIGHT-LOGGING.md) and applicable numerical checks. Prior source audits and completed experiments are available in the [October scan](../research/godot-optimization-scan-2026-10-27.md), [November source audit](../research/performance-audit-2026-11-19/README.md), and [original dated per-step register](https://github.com/bultodepapas/OpenRCsimulator/blob/8d4169f8febfd7d78a028eaa817414217a54f24b/docs/plans/optimization-priorities.md#frame-stalls-and-sustained-fps).

## 6. Acceptance and stop rules

Freeze identities, workload, display, power, observer and cache state before changing one mechanism. Calculate paired differences per run under the [baseline protocol and gates](global-performance-visual-quality.md#baseline-protocol). Keep cold, warm, paused and active periods distinct and compare the full affected route. Report observer-on/off variance. Component timings, headless speedups and a single hardware tour select experiments. Product claims require the named release workload and target hardware. Physical scanout, input-to-photon latency and pilot readability each need their own observations.

Record the result in the owning evidence home. Retain the baseline for inconclusive or harmful changes. A confirmed repeatable hitch or leak can justify a repair even where steady-state FPS barely changes. Stop once the named budget is met, or identify the remaining bottleneck before expanding scope.
