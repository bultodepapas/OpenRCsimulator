# In-game scenery import for Phoenix RC flying sites

**In progress, 2026-11-20.** Landscape owns **L-PX**. The target experience is to choose a Phoenix site in Home, preview it, install it locally, fly a circuit from the photographed pilot position, land, and return to the same field after restarting. Home offers local panorama previews and experimental runway starts for five exact revisions. The starts use estimated ground and visually aligned pilot viewpoints. Source-matched flight still needs independent geometry and contact measurements. [Runway and Windows evidence](../research/phoenix-flying-sites-2026-11-20.md#calibrated-runway-in-the-production-importer)

The [source inventory](../research/phoenix-flying-sites-2026-11-20.md) covers 29 stock descriptors, 286 descriptor entries in the local map pack and one additional club site. The pack and ISO share 23 descriptor hashes. Some files named DDS are JPEGs, multiple sites can share a directory, and the current aircraft package probe rejects all four embedded PKGs in this pack. These findings determine the implementation order. **No site has yet been qualified in OpenRC.**

**Airfield is the first stock target.** Its installed descriptor locates six medium panels, a cubemap, eleven position records and 21 object records. Medium face 4 independently matches the photographed hangars and pavement. The corrected DDS decoder restores a displaced 1,000-byte pixel span, and the medium panels now join in the same order across all 29 stock sites. Use the native viewpoint to verify absolute orientation. Use the Builder box exports to begin verifying obstacle flags. [Corrected texture layout](../research/phoenix-flying-sites-2026-11-20.md#corrected-panel-decode-during-l-px-implementation) · [Controlled exports](../research/phoenix-flying-sites-2026-11-20.md#controlled-builder-experiment)

**What changes after inspecting the installation.** A file reader walked 350 positions and 805 objects across all 29 stock panoramas. This gives the importer an exact regression target for discovery and record boundaries. Start with fixed-eye panoramas and the 572 primitive records. Then qualify the 90 areas, 104 skylines, 16 grids and 23 marker objects against authored examples. Keep a site's preview usable while individual starts, surfaces or effects await verification. [File layouts and per-site counts](../research/phoenix-flying-sites-2026-11-20.md#installed-stock-files)

## What the player can do

1. Open **Home → Landscape → Import scenery**. Pick a site folder, an installed Phoenix environments directory, a Builder test/export folder, or a supported archive. Offer the common Phoenix locations as shortcuts. Scan only the selected source. Keep Club and Green available while the scan runs.
2. Show a searchable list with one row per candidate, thumbnail, author when present, source, installed version, and estimated install size. A 9.57 GB map pack must be browsable before expanding any site. Let the player select one or several entries and cancel individual jobs. Explain a missing face, ambiguous reference or unsupported feature on that site's row.
3. Offer a draggable 360° preview from the pilot eye. Show which cameras, aircraft starts, ground types, obstacles and effects the conversion can reproduce. Provide **Locate missing assets** and, for a complete photo set, **Align panorama** with horizon, heading, pilot eye and a known runway measurement. Store manual calibration as an editable local override with its own identity. Keep source fidelity and user estimates visible.
4. Install on confirmation. **Fly** becomes available only for a validated start, ground and supported playable area. A visual-only site can stay in the library for later repair. Select, rename locally, reimport, roll back or remove from Home. A failed import or a cancelled preview keeps the current field and aircraft selection. A fresh session applies a field switch.

## Runtime design and ownership

| Boundary | Implementation decision |
| --- | --- |
| Source capture and decoding | Add a proposed `app/landscapes/import/phoenix/` adapter. Expose discovery, dependency resolution and conversion as independent operations. Read folder, ZIP and PKG members through one bounded, read-only interface. Normalize case and separators for lookup while retaining raw names. Reject path escapes, links/reparse points, aliases, ambiguous matches and inconsistent sizes before following references. Keep limits for nesting, entries, inflated bytes **per selection**, decoded pixels and time. Skip incidental executables. Parse any supported script-like source as data only. [Existing research reader](../../research/aircraft-creator/phoenix/README.md) |
| Converted data | Define a versioned site manifest with display metadata, provider/profile, raw member hashes, converter version, asset roles and dependencies, units/frame transform, pilot stations, typed spawns and headings, available modes and feature diagnostics. Store visual/depth geometry separately from ground support, material regions and obstacle proxies. Record each as decoded, user-adjusted, estimated, missing or unsupported. Prove structure with bounded record readers and paired authoring changes. Printable strings alone cannot establish record boundaries. |
| Local installation | Put only generated, validated data under a proposed `user://landscapes/` library. Use a stable library ID and immutable content revisions. Stage to a sibling directory, verify hashes and space, then atomically publish the revision and catalog pointer. Deduplicate exact closures, keep different variants with the same name, serialize competing updates per ID, pin active revisions and recover stale staging on startup. Generate outputs from trusted application code. Keep the source path optional after installation. |
| Catalog, Home and flight | Extend the [landscape catalog](../../app/landscapes/catalog.gd) with one application-owned adapter for installed data. Load its lightweight index before [preferences](../../app/app_state/preferences.gd) resolve the saved ID. Use the same revision for Home, flight and restart. Existing Home cycles IDs, caches by field JSON and uses the Club field ID for runway eligibility. Replace those assumptions with a library selection and explicit per-site capabilities. Separate runway/hover eligibility from Club-only Natural Random. Keep truck courses independent. [Landscape integration](../LANDSCAPES.md) · [Home selection](../../app/app_root.gd) |
| Physics and replay | Compile representable pilot, runway and surface data through [FieldLoader](../../app/data/field_loader.gd). Field v1 requires a logical runway and axis-aligned rectangles. Never invent a runway or flatten a slope to pass validation. For unsupported shapes, add a versioned optional ground/support contract with GP, or keep the affected start/site in preview. Install scalar float64 NED ground and obstacle data at the session boundary. Bind their identity to checkpoints/replay and the visual revision to preview/capture reuse. An image-only update invalidates the preview cache. A changed contact world requires a new session. [Flight session](../../app/sim/flight_session.gd) · [Collision world](../../app/scenery/collision_world.gd) · [Frame conversion](../../app/render/frames.gd) |
| Images and frame time | Prefer the existing engine decoder where verified, with an independent DDS decoder as an offline reference. Validate dimensions, blocks, mip lengths and full cube-face sets before GPU allocation. Choose one complete tier or derive six consistent faces within device limits. The Holdfast high set alone would occupy about 627 MiB as six uncompressed RGBA8 faces before mipmaps or staging. Decode incrementally, show thumbnails first, release temporary buffers, and stage bounded uploads on the render thread. Keep import I/O and conversion outside flight ticks. [DDS specification](https://learn.microsoft.com/en-us/windows/win32/direct3ddds/dx-graphics-dds-pguide) · [DirectXTex reference](https://github.com/microsoft/DirectXTex) |

The Landscape owner owns the manifest, catalog, library, source adapter and proposed `test_landscape_import_*.gd` checks. UI owns the browser, focus, localization and saved selection. CAM/FW/TOD/VQ own camera, sky, lighting and graphics integration. GP/LU/SC/CR and flight-session owners own support, collisions and damage. AC-PX can share verified container or image primitives. The aircraft converter's model scale and GLB material rules have aircraft-specific assumptions. [Aircraft format research](../research/aircraft-creator/phoenix-stock-format-2026-11-20.md)

**First engineering decision.** Implement a panoramic stock reader and a separate recognizer for the sparse Builder export. The measured stock layout starts its position count at byte 2481. The entire controlled box export is only 856 bytes and shares header word 4 with two stock panoramas. Select a profile using its verified sections and bounds. Read fixed-width strings only up to the first in-slot NUL. Key a position by descriptor revision and source ordinal. Store its raw label, class and six source floats. All 29 sites have repeated labels and three repeat a class/label pair. Offer a vehicle start only after its class, pose and supporting surface are verified. [Position counterexamples](../research/phoenix-flying-sites-2026-11-20.md#panoramas-and-position-records)

Advance through the counted object table before reading its length-prefixed images. Validate every count and size against the remaining bytes and the job's budget. Preserve the four source channels, including the fourth byte of embedded 32-bit BMP data. Decode large embedded images lazily. A tag or variant with unknown length ends the object's verified prefix and blocks any gameplay relying on the unresolved section. Keep already verified panorama assets available for preview. Check the original 805 boundaries on the installed corpus, then freeze the decoder and predict the results of fresh, independently described exports. [Object layouts and regression corpus](../research/phoenix-flying-sites-2026-11-20.md#object-records-and-embedded-images)

## What must line up in flight

- **Camera and panorama.** Establish the source-to-NED frame, metric scale, eye, horizon and yaw using an asymmetric cube with labelled corners and a measured baseline. Derive numeric face order, flips and rotations per verified profile. Render from the authored eye with rotation, tracking and zoom. Home's ordinary model-framing camera, close-up, chase, fly-by, orbit and FPV can translate the eye. For single-station photography, use a fixed-eye Home preview and offer only compatible flight views. Allow another station only with its matched panorama. [Pilot camera](../../app/render/pilot_camera.gd) · [Camera rig](../../app/render/camera/camera_rig.gd)
- **Ground, depth and contact.** Qualify planes, cubes, spheres and cylinders first, then material areas, skyline silhouettes and 50×50 grids. Check front/behind and hit/miss independently. The tested Builder word-4 Collidable byte occupies part of the repeated tag in stock words 1–2. Verify flags per layout before constructing physics proxies. Preserve source transforms and test a rotated obstacle, a grid-cell boundary and a material transition. An unresolved obstacle in the advertised circuit or an unknown landing surface keeps that circuit in preview. [Stock object types](../research/phoenix-flying-sites-2026-11-20.md#object-records-and-embedded-images)
- **Lighting, masks and water.** Preserve the photo's sky and baked time of day. Align aircraft lighting and shadows to it. Preserve the named cubemap's alpha for the mask pass. Eighteen stock cubes contain values on both sides of the shipped shader's cutoff. Calibrate mask registration and colour orientation separately. Verify the connection from a specific embedded image to an effect by changing one authored feature, then test reflections, water level and physical water response independently. Include Lagos Rocks and Lakeside with opposite constant-valued 2048² images. [Installed shaders and images](../research/phoenix-flying-sites-2026-11-20.md#masking-water-and-3d-presets)
- **Local environment.** Keep visual windsocks, deterministic wind zones, thermals and ambient sound as separate capabilities. Bind a shared asset only through a verified reference or producer rule. Report uncertain extras with the site. Preserve independent quality controls for visual detail and keep identical physical behavior across presets. [Field world](../FIELD-WORLD-PLAN.md) · [Environment contract](../../app/sim/environment.gd)

## Release scorecard

1. **Coverage.** For each source and header profile publish unique candidate **closures** (descriptor plus resolved asset hashes), then numbers discovered, previewed, playable with limitations, fully playable and refused, with reasons. Report unresolved candidates even when closure hashing is impossible. Show both collection entries and deduplicated totals. Publish separate counts for camera/spawn, texture, support/materials, occlusion/contact, water and environment fidelity. Never extrapolate a release percentage from the map pack's advertised count.
2. **Registration and physics.** With an asymmetric, known-metric synthetic scene, check all six faces, twelve seams, pole orientation and the four occlusion/contact flag combinations. Proposed starting tolerances are ≤2 pixels on labelled landmarks at 1080p with fixed pose/FOV and ≤2 cm on independently specified ground/spawn landmarks. Compare real sites against reference views at matched FOV and independent ground/contact observations with their measurement uncertainty recorded. Exercise front/behind, hit/miss, taxi across materials, takeoff, landing, crash and reset. Compare a fixed input tape across texture tiers and check checkpoint refusal after a physics revision. Reference flights assess field behavior, not Phoenix aircraft dynamics. [Flight logging](../FLIGHT-LOGGING.md)
3. **Product and recovery.** Test keyboard/controller navigation, localized diagnostics and filenames, install/update/remove, two same-name sites, repeated/concurrent imports, restart and failed source resolution. Switch Club → imported → Green → imported. Test airplane and helicopter routes only for capabilities being advertised. Extend [landscape tests](../../app/tests/test_landscapes.gd), [field integration](../../app/tests/test_field_integration.gd), [checkpoint tests](../../app/tests/test_landscape_checkpoint.gd) and [pack checks](../../app/tests/check_field_pack.gd). Test bundled resources in an empty profile and player-installed data in a populated one.
4. **Resource and distribution gates.** On clean Windows, Linux and macOS exports, import without an editor, Python, 7-Zip or Phoenix installed. Measure cold/warm indexing and first preview, selected-site install time, peak RAM/VRAM/disk, flight frame-time p95/p99 and resource recovery after repeated switches. Compare against the same aircraft/renderer/preset on a bundled field and the owning frame budget. Use 1920×1080 first, then higher resolutions, then 720p fallback. Apple Silicon Retina uses native panel resolution with output, drawable and internal pixels reported separately. Qualify on modest and high-end hardware with a pilot readability review. Distribute importer code and owned fixtures. Keep third-party field content local unless redistribution rights are documented.
