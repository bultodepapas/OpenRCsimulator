# Phoenix package research probe

This read-only Python probe accompanies the [dated investigation](../../../docs/research/aircraft-creator/phoenix-2026-11-17.md) and proposed [AC-PX plan](../../../docs/plans/phoenix-aircraft-import.md). It demonstrates a narrow container/file-tree profile on seven pinned PKGs. It is not a Phoenix importer, complete format specification, geometry decoder, image validator or production security qualification.

The code uses Python's standard library. It does not download anything, execute simulator/source code, extract members, follow stored source paths or bypass opaque member encodings. No aircraft binaries are committed here. Obtain a permitted local sample using its original creator/community link and the exact ZIP member listed in the [inventory](../../../docs/research/aircraft-creator/phoenix-source-inventory-2026-11-17.json).

## Inspect one exact package

For the author's Freewing SU-35 v23, select `SU-35 v23.pkg` from the ZIP linked in the inventory, then run from the repository root:

```bash
python3 research/aircraft-creator/phoenix/inspect_pkg.py '/path/to/SU-35 v23.pkg' \
  --sha256 2111d5c87704eb7670e5888c6a2303933c45f203b6a02a986c500e22373d785e
```

The expected hash is required so the output is tied to the recorded bytes. It is not an authenticity, license or physical-validation claim. The program prints JSON on success and a rejection on stderr with exit code 1 on a format/I/O failure. Body offsets identify the concatenated inflated stream, not positions in the compressed source. Member names remain untrusted data; do not turn them directly into filesystem paths.

The report identifies package numeric labels, chunk sizes, member bytes/hashes and heuristic content signatures. Names retain raw bytes as hex alongside display text and its chosen decoding; identical display names need not identify identical source bytes. PNG/BMP dimensions come from unchecked image headers, not full image decoding. Printable-ASCII classification is a heuristic. The script never interprets `7.000000` as Phoenix 7 or a proven format version.

## Research profile limits

| Limit | Value |
| --- | ---: |
| Actual captured input | 64 MiB |
| Aggregate inflated body | 128 MiB |
| One inflated zlib block | 1,024,000 bytes |
| One file member | 32 MiB |
| Total directories and files | 2,048 |
| Tree depth | 32 |
| One stored string | 4,096 bytes |
| Trailing zero padding | 512 bytes |
| Cumulative raw name bytes repeated in reported member paths | 256 KiB |
| Serialized JSON report | 8 MiB |

These are conservative probe limits, not product promises or universal Phoenix limits. The numeric header must use the observed decimal form with six fractional digits; its meaning is still unresolved. File records must have zero children in this observed profile. Compressed streams must finish cleanly, match declared sizes and have no unused bytes. The body prefix must match the observed profile; nonzero trailing data is rejected. A rejected file may be another legitimate but unimplemented dialect.

The script retains chunks and their joined body during inspection, so the inflated-byte ceiling is not a peak-memory claim. It has no asynchronous cancellation or platform resource campaign. It reports paths without enforcing a production extraction policy because it has no extraction operation. Product adoption requires the additional capture, path/alias, dependency, cancellation, native-decoder and lifecycle gates in AC-PX.

## Reproduce checks

Synthetic checks use original generated bytes and need no aircraft assets:

```bash
python3 research/aircraft-creator/phoenix/check_probe.py
```

They cover a known file offset/hash, source-path omission, distinct name encodings, uninterpreted numeric labels, invalid headers, truncation, checksum/length errors, unused compressed data, tree records/leaves, excessive padding, cumulative entries, deep-name output amplification, resource limits and the CLI hash gate. Path-like names deliberately remain JSON data. These checks test meaningful boundaries but are not a fuzzer, proof of safety or runtime qualification.

To repeat the exact real-sample comparison, prepare an external directory containing the seven selected PKGs named by inventory ID: `freewing-su35.pkg`, `extra300.pkg`, `wasp18.pkg`, `wasp20.pkg`, `su37.pkg`, `yak54.pkg` and `aw109.pkg`. The inventory records each original ZIP and member name. Then run:

```bash
python3 research/aircraft-creator/phoenix/check_probe.py \
  --inventory docs/research/aircraft-creator/phoenix-source-inventory-2026-11-17.json \
  --samples-dir /path/to/local-pkgs \
  --report /path/to/phoenix-checks.json
```

The checker requires each input hash and full probe result to match the inventory. Its output records Python/zlib versions and probe/checker/inventory identities. [The dated receipt](../../../docs/research/aircraft-creator/phoenix-probe-verification-2026-11-17.json) was generated with this command by the lead review. Regenerate it after changing the probe, checker or inventory. Outer-ZIP CRC and separate PHX/VAR/document observations are recorded research; this checker does not decode their grammars.

Do not add third-party samples to this directory merely because they are downloadable. New public regression fixtures should be original or explicitly licensed, with independently known geometry/semantic answers. Keep corpus growth separate from compatibility claims.
