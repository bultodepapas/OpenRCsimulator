# Handling probe

`run_handling.py` runs bounded braking and steering tests through `VehicleDynamics.step`. Every case calls `VehicleDynamics.initialize` on a level, uniform road at the same north/east coordinates, then seeds forward and lateral body velocity plus four pure-rolling wheel speeds once. The probe does not edit state after initialization; it records four-wheel support before the first simulation step and advances state only through the dynamics solver. The runner requires the native backend and writes a CSV trace, JSON receipt, and engine log to fresh paths.

`--solver baseline` launches the sparse frozen project in `baseline_sources/app`; its project, GDScript dependencies, vehicle descriptor, native extension, receipt, and DLL are isolated from the active app. `--solver current` launches `app` with current dynamics and descriptor validation, while reusing the frozen course parser and practice-course material fixture. Neither mode swaps the active app DLL. `--vehicle PATH` selects a descriptor explicitly. `--scenario all` runs full/0.6 braking and a fixed countersteer tape at 10 m/s on asphalt, grass, and gravel; `brake` omits steering, while `swerve` omits braking. `--speed` accepts 1–20 m/s.

The CSV includes every state component, inputs, speed, energy, contact counts, tilt, and validity-gated heading/slip telemetry. Heading is omitted above 60 degrees body tilt; body slip is omitted below 0.5 m/s planar speed. Receipts include per-case stopping, yaw, lateral-slip, recovery, energy, tilt, contact, support, and finite-state metrics, plus before/after source hashes. Baseline and candidate use the same coordinates, speed, lateral seed, wheel-spin recipe, material and control tapes; static support height and state hashes naturally differ with their vehicle descriptors.

The flat fixture uses the estimated practice-course materials uniformly: asphalt μ=0.85 / rolling multiplier=0.025, gravel μ=0.65 / 0.055, and grass μ=0.50 / 0.08. The vehicle model multiplies these surface values by its rolling-resistance coefficient (0.035), so the resulting effective Crr values are 0.000875, 0.001925, and 0.0028. These synthetic values support solver-to-solver comparisons and do not represent measured real-surface drag. Use the airfield route receipts for the actual runway and circuit materials.

Retained CSVs are compressed after capture to keep evidence compact. `compress_evidence.py` verifies the original receipt hash and row count, writes a deterministic `.csv.gz`, verifies the decoded payload, then adds storage path/hash metadata while preserving the original CSV path and content hash. Run it only once on a newly captured, uncompressed receipt; it removes the raw CSV after verification. `plot_handling.py` reads and hash-checks either raw CSV or compressed storage traces.

See the [supported-start handling report](../../../docs/research/rc-monster-truck/RCV-handling/drive-handling.md) for the final paired results. The older v2 traces began above the ground and are retained as exploratory drop-start evidence, not the supported braking baseline.
