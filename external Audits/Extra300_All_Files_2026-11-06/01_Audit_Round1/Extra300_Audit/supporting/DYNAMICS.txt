## New candidate: reuse a mass-property result within the same Extra stage

**Status:** guarded one-file experimental patch with bounded exact software evidence, no measured performance improvement. Not production-ready. This opportunity concerns finite-glow mass inventory and is separate from consolidated M09/M10 wing/propeller reuse, A3 stage validation, and A6 O1–O6.

`app/physics/glow/flight.gd:452–454` unconditionally runs `_stage_mass_context(owner,values)` and computes `feed_mass` through `properties()`. Stock Extra has no `fuel_feed`. In this branch `point()` does not put the calculated mass in its return value because `airframe` is empty (`:574–578`). Its caller, `evaluate()`, receives no mass, and recomputes it with `properties()` (`:666–672`). `MassInventory.evaluate_reference()` rebuilds mass, CG, six inertia components, and tensor inverse (`app/physics/mass_inventory.gd:231–276`). Thus each normal Extra stage performs the same mass calculation twice. Four stages × 240 Hz = **960 duplicated evaluations per simulated second** under this exact ordinary route. Event-location trials and endpoint/observer calls are excluded; this is a source-level operation count, not latency or a speedup measurement.

With soft hull contacts active near the ground, `_airframe()` (`flight.gd:649–661`) enters `FlightSession._ground_evaluation()`, which calculates `GlowFlight.properties()` yet again before `HullContact.loads_at_properties()` (`app/sim/flight_session.gd:4385–4393`). There can therefore be a third mass evaluation in that near-ground route. The tested candidate removes **one** duplicate, giving 2→1 airborne and 3→2 near ground. Passing the same validated stage-local properties into the existing optional `_ground_evaluation(..., properties)` argument may remove the remaining duplicate, but that separate change has **not** been implemented or tested here. It requires keeping supported alternate-owner signatures and dispatch intact.

**Why the guard is exact for the local calculation:** no feed line; `line=0`; `0 < fuel <= capacity`. Then `_stage_mass_context` obtains `main = clamp(fuel - 0,0,capacity) = fuel`, line = 0, and total = `fuel + 0`; both paths call `properties()` for the same finite float and reference. Out-of-range, zero/signed-zero, nonfinite, optional feed/line, or other paths retain the old recomputation. This is a statement about this guard and ordinary immutable owner state; it does not prove equivalence under arbitrary callback mutation of aircraft/model/reference data between evaluations.

**Experimental patch:** `stage-mass-reuse.patch`. It retains the normal `point(..., include_stage_coupling=false)` output, while its internal stage-enabled route carries a private `_stage_mass_reuse` payload. Guarded candidate source SHA-256 `204d47c85183e1f5340d4926f71fe71635d6177bb0502668f6ccf5bafa257ef8`; baseline/source `a70a73e8409b42dfdcee33c6ea72e09492a66de59d180ced730817c2c64e6e55`. This private payload still changes the observable output if a caller explicitly requests `point(..., true)`. The final design must decide/document the internal-interface boundary and preserve existing supported dispatch/trust/refusal semantics; it must not assume a field is immutable just because the current ordinary session is stable.

## Known-planned limitation, excluded from new serious findings: coasting propeller strike

Existing guard `app/sim/flight_session.gd:3045–3057` requires `engine_running` as well as `aux RPM >= 300`, while the session models a physically coasting shaft after public `glow_cut()`. This was checked, but GP-17 in `docs/plans/advanced-ground-flight-physics.md:919` already calls for stopped/coasting blade coverage, so it is **not counted as a new finding**. A controlled Extra pose with `pitch=-0.07 rad`, 15 m/s body-forward velocity, 1 mm prop-disc penetration, and no terminal hull/gear condition produces a strike at 7473.19 RPM if enabled, yet after public `glow_cut()` and 10 accepted ticks the 7222.02 RPM rotor produces no strike and restart is accepted; an artificially stopped 0-RPM control also yields no strike. This is a staged contact case, not a flown landing or physical failure-rate measurement. `probe_coasting_strike.gd` and checked receipt `checks/coasting-strike-evprv1x5/report.json`. A second staged pose with smaller 19.35 mm main-wheel compression is in `checks/coasting-strike-clear-82t4h80i/report.json`.
