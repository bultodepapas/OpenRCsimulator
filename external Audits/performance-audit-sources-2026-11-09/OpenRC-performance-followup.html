1. Outcome and priorities

Two changes earned inclusion in the local patch. The companion pilot reduces tested held-conflict command time by approximately 11–13%, and integer keys reduce complete Timber cache-cold paint repair by 15.9% on this host. Both preserve the tested outputs without reducing the 240 Hz simulation rate. A separate whole-mesh fingerprint experiment did not show a convincing complete-repair benefit and remains unpromoted.

The local patch changes two runtime algorithms: companion scoring and Timber paint-grid keys. It includes their source-identity admission updates, two permanent regression tests and Godot UID sidecars. It also supplies the two missing UID sidecars responsible for current release-preflight failure. The patch has 11 files, 223 insertions and nine deletions; most additions are tests. No physics rate, force model, solver state, native admission policy or graphics quality was changed.

The spatial-wind experiments produced useful discrimination. Stage-local temporal caching removed substantial source work but did not establish a complete-session benefit. Simpler wall-taper specialization and batched trigonometry wrappers produced encouraging complete-step screens, but control variability and source-admission work prevent a production recommendation. The shadow decoder saved about 2 MiB of logical temporary index materialization per collection without a convincing complete-collection improvement; it was not promoted.

No new displayed FPS, GPU-frame, frame-percentile or physical input-latency improvement is claimed. This environment has a headless Linux CPU, without a target display, exposed GPU or usable Mac session. It can execute reference physics, controller logic, imported-mesh operations and correctness checks, but cannot qualify the complete rendered experience.

3. Actual execution paths and measurement scope

Production runs from app/. Home selects and prepares an aircraft, scenery, environment, render hierarchy and shadow representation. The active session supplies a vehicle model to the shared Simulation kernel; its state uses float64 arrays, with rendering conversions at the boundary. Aircraft loads, ground/contact handling, propulsion and wind sampling feed the stage evaluator. Companions have their own sessions and plan at 60 Hz while integration remains 240 Hz. UI, statistics, recording, audio, transforms and rendering add work outside the core step timer.

The main application requests the native stage backend where it is admitted: the pinned aircraft evaluator admits Linux x86-64 only. Apple Silicon uses the reference evaluator, and companion sessions also retain their reference default. Exact source/configuration checks can instead select the reference backend. Tools and replay have their own defaults. Changing physics/ or sim/ without rebuilding and qualifying the native mirror can therefore disable a faster backend: a locally faster reference function could make the actual application slower. The review keeps this admission effect separate from arithmetic timing.

The pinned engine is 4.8.beta2.official.cafc17a19, full source cafc17a192acf67903910a68aeb3c076c0907a4b. Project settings specify Compatibility by default, Mobile for ARM64, 4× MSAA, 240 physics ticks/s and at most 12 catch-up steps per rendered frame. The 1280×720 configuration default is not the qualification target: repository guidance makes actual 1920×1080 primary, then larger resolutions. Graphics changes must preserve physics.

Executed measurements used the official Linux x86-64 editor binary, headless/Dummy drivers, an AMD EPYC 9V74 shared host, an eight-core container quota and 8 GiB memory limit. They are not release-template, GPU, Apple Silicon or physical-controller measurements. Timing campaigns were serialized; an early shadow timing run overlapped a source download and was discarded, then repeated. All quoted timings identify the exact measured candidate and workload.

The existing checked runner verifies logs, completion markers and exit state. A zero process exit alone is insufficient. 4. Companion prediction: exact reduction of repeated roots and turn rates

Location: app/ai/companions/pilot.gd, _score_bank; callers in _avoidance_velocity, companion agent/manager scheduling and source admission in profile_loader.gd. This develops A33’s companion predictor proposal; it is not a newly discovered instability.

Distance mathematics

An eight-second horizon with a 0.25-second step evaluates 33 positions. For each threat, the original computes a three-dimensional Euclidean distance at every position, then retains its minimum. With qj = ΔNj² + ΔEj² + ΔDj², the proposed untraced path uses:

before: minimum = min_j(sqrt(q_j))
after:  minimum = sqrt(min_j(q_j))

For finite nonnegative q, square root is monotone, so the minimum distance is preserved. The candidate retains the original product/addition order for q, the same ordered minf updates, and the final distance in meters before separation margins and ranking. It does not compare a squared distance with a meter threshold. Equal rounded roots need no argmin tie-breaking because this accumulator retains only the distance value. The trace path still computes every original root and stores every distance.

This changes 33 square-root wrapper calls per threat and bank to one when tracing is off: a 96.97% reduction in that sub-operation, not in command time. The complexity remains O(BNT), where B is evaluated banks, N threats and T=33 samples; sine/cosine, propagation, minimum comparisons and traffic preparation remain. No new heap buffer is added.

Turn-rate reuse

ramp = clamp((midpoint - reaction_margin) / response_time, 0, 1)
bank = lerp(current_bank, candidate_bank, ramp)
rate = g * tan(bank) / max(speed, 3)

Once ramp == 1, all inputs to the last two expressions are unchanged for the remainder of that prediction. The candidate computes the first saturated result normally and reuses that exact floating-point result. It deliberately does not replace lerp(a,b,1) with b, which can change rounding. At the current constants, 32 tangent/division evaluations become eight, saving 24 per bank. The initial zero-ramp interval was left unchanged. Ownership is local to one score call, with no cross-call invalidation problem.

Source scheduling matters. A clear prediction normally evaluates one bank; active selection evaluates the nominal plus eleven candidates, with another score in the held-maneuver case. Diagnostic trace generation adds work separately. Three companions each considering three threats at 60 planning updates/s would reduce the clear-path distance-root count from 17,820 to 540/s. Avoidance increases that count conditionally; twelve banks must not be assumed for every command.

5. Timber paint repair: use the cell coordinates directly

Implemented location: app/aircraft/timber_visual_details.gd, _build_paint_face_index and _covering_paint_at. This refines the existing TT-21 paint-repair grid; the grid and bounded repair cache themselves were already implemented. It is a new measured representation improvement, not a claim that spatial indexing was absent.

Follow the attributed cost

The initial mesh-hash experiment barely changed complete cold repair. A separate instrumented run attributed substantial script time to grid construction, splitting and coverage. Its frame-percentage output is meaningless because the test performs synchronous work during SceneTree initialization; only function call counts and total/self-time attribution were used. The clean timing runs do not enable that profiler.

# Both versions already calculate the same signed integer cell coordinates.
# Insert:
before: key = "%d:%d:%d" % [x, y, z]
after:  key = Vector3i(x, y, z)

# Lookup; cell is already a Vector3i in the original code:
before: candidates = index.get("%d:%d:%d" % [cell.x, cell.y, cell.z], [])
after:  candidates = index.get(cell, [])

The old decimal triple and the new integer triple identify the same cells. Both builder bounds and query cells already narrow through Vector3i, so this patch introduces no new quantization, division, floor operation or tolerance. The pinned engine stores three int32 coordinates, hashes those coordinates and compares all three for equality. A hash collision does not merge distinct cells. The GDScript runtime cannot discard the original formatting while the resulting string is used as the dictionary key.

The algorithm’s complexity is unchanged. Let K be the total number of face-to-cell insertions and Q the number of indexed coverage queries. The change removes K+Q decimal-format operations, each supplied with a temporary three-element Array, while retaining bucket growth and candidate-face tests. A separate counter-only repair of the actual five imported meshes measured K=115,669 and Q=15,152: 130,821 formatting operations and argument arrays removed per cache-cold repair. Per-mesh insertion counts were 5,062, 3,209, 50,627, 28,628 and 28,143. The counters were absent from timing.

Index ownership stays local to one synchronous repair. No cross-frame or persistent cache needs invalidation. Faces enter each bucket in the same order, preserving material insertion order and strict-less-than tie decisions. An empty index still means full scan; a missing bucket in a nonempty index still means no candidates. Memory should avoid the retained string payloads and temporary formatting arguments, but native allocation/peak-RAM savings were not measured. Integer coordinates contain 12 logical bytes; this is not a complete Dictionary-entry size.

Separate LOD-fingerprint experiment: retained as unpromoted evidence

_mesh_content_sha256 loops S surfaces, and its helper asks for mesh.get("_surfaces") each time. A hash-local native-only snapshot changes that portion from S² to S surface retrievals. 6. Spatial wind: compare removed work with complete-step cost

Locations: app/physics/wind_spatial_field.gd:315–355, wind_aircraft_flow.gd, wind_field.gd, app/sim/environment.gd and app/physics/math3d.gd. The original prepared frequencies, mode layout and gust search are already implemented. No frequency, time step, aerodynamic law, station location or RK reduction order was reduced.

Temporal phase cache: not promoted

Each mode computes a temporal remainder fposmod(omega * (simulation_time_s + epoch_offset_s), TAU), then combines it with the separately reduced spatial phase. A stage-local cache can reuse only that temporal result among equal-time point queries. With 24 modes, ten points and four groups, the conditional saving is 24×9×4 = 864 products and remainders per tick, or 207,360/s at 240 Hz. A separately owned pre-step group can add 216 more per eligible tick. This ceiling requires a stable exact built-in provider/time, active nonzero RMS, finite nonzero epoch and eligible omega, and ten successful airborne queries per group. Zero epoch/RMS, below-ground returns, refusals and generic/thermal fallbacks reduce it.

The guarded prototype checked exact provider classes, callback ownership, live omega, epoch and layout, and kept custom callbacks, retained point samplers and thermal fallback on their old paths. It passed 163 focused comparisons and the existing affected suites. A separate untimed real-session instrumented copy recorded 648 cached-mode hits on the first tick and 1,080 on the next, proving that the optimization executed. This required fresh scratch and validation overhead: two 24-element float64 arrays contain 384 bytes plus runtime containers.

Wall specialization and wrapper batching: promising screen

The C2 wall weight is h(x)=x³(10+x(−15+6x)), with x already clamped to [0,1]. When x compares equal to one, the existing small integer intermediates evaluate exactly to one. Selecting 1.0 only for that saturated case removes the polynomial, redundant clamp and script call. Zero, interior, NaN and other cases retain the original expression; the derivative path is unchanged. This assumes the built-in polynomial implementation; an overridden helper needs its original dispatch. No general algebraic reassociation or approximate trigonometry is involved.

The second change batches the original cosine, sine, vertical-phase product, sine and cosine into one script helper, preserving their order. It replaces four Math3D wrapper calls per mode with one call and five float64 writes/reads. All four transcendental operations remain. At 50 queries per measured Stik tick and 24 modes, that is 3,600 fewer script calls per tick, with 50 short-lived 40-byte logical arrays: 480,000 payload bytes allocated per simulated second, plus container overhead. The pinned GDScript compiler’s ordinary-call path does not perform the interprocedural C++-style inlining assumed by some micro-optimization advice.

The component sweep passed 7,575 checks and retained 540 timing rows across 8/24/64 modes and three heights. Above the wall transition, the combined screen often improved more; near the ground, the extra branch can lose. Large drifting component results were not promoted as stable speedups.

Decoder experiment: memory arithmetic did not become a complete win

The original decoder validates and materializes every serialized LOD index array before selecting a level. The experiment first chooses from metadata, validates every index as before, and materializes only the winner. The imported Corsair fixture has 55 eligible surfaces and 255 LOD records. All 913,938 indices remain validated; 390,930 winning indices are materialized, avoiding 523,008 int32 entries, 216 arrays and 2,092,032 logical temporary bytes per sweep.

It passed 3,023 synthetic comparisons, including malformed nonwinners, duplicate thresholds, absent winners and 16/32-bit cases. Seven complete imported-model pairs had identical position bytes, bounds and metadata. Decoder-only medians were 63.367→56.539 ms, but complete collection was 126.608→126.382 ms and the candidate was slower in five of seven pairs. The candidate was not promoted. These headless results do not measure GPU memory or launch responsiveness.

Next concrete improvements

First, collect full/proxy information in a single traversal and reuse each mesh’s face stream while it is already live. Godot caches its TriangleMesh/BVH, but get_faces() still expands a fresh ordered position array. The full Corsair fixture’s second expansion represents 963,573 Vector3 records, about 11.56 MB of logical position payload. This is data volume, not measured peak memory or time. Reuse per mesh, without retaining every stream simultaneously. Preserve visibility, propeller exclusion, full fallback, face order, transforms, snapping, raw LOD vertices and bounds.

The successor already implements the resource-deferral half of the disabled-cue proposal. Current Shadow.create/bind_model avoids the generic texture and projected node, mask viewport, receiver and shader materials until first activation. It still collects and retains the authoritative bind-time shape before checking the cue. The live Home test retained 178,551 triangles, about 6.13 MiB of logical float32 position payload; this is not measured allocation or VRAM. Existing warm projectors remain allocated for reuse. Deferring geometry itself requires a design that preserves mutable suspension/articulation and avoids a large first-enable stall.

Do not substitute a finite aggregate AABB for the final all-point finite-and-bounds guard: the pinned bounds reduction can ignore a later NaN, padding and floating arithmetic affect edges, and resource creation before validation changes behavior. The existing final 535,365-point guard is expensive source work, but a replacement needs a direct equivalence argument and adversarial tests.

GPU math opportunities requiring actual render evidence

The afterimage work is a refinement of A26’s existing screen/mip dependency investigation. The shader’s quartic profile is alpha × exp(−x⁴/2), where x is distance divided by radius. With at most eight contributions and each alpha bounded by one, discarding only beyond three radii would bound omitted alpha by 8e−40.5≈2.06×10−17. That is an analytical error budget, not bit identity, a floating-point shader bound or proof that the screen copy disappears. Offscreen light sources can still affect visible pixels. Test positive witnesses, FOV/resolution changes, HDR ranges, moving occlusion and actual Compatibility/Metal pass dependencies.

app/render/countryside_surface.gdshader:92–118 computes filtered stubble/windrow expressions even where ordinary wheat/maize have zero harvested contribution. The source layout has thirteen wheat and nine maize parcels among 54; those counts do not measure visible pixels. A coherent crop specialization might save the periodic-band integrals and color work, but shader compilers may already eliminate some work. Preserve derivative behavior and filtering at crop/headland boundaries; compile and capture both supported backends before assigning a GPU gain.

Do not trade simulation behavior for cheaper arithmetic

RK stages depend on their own intermediate states and times. Wind, mass, station air, force, moment and rotor caches cannot be shared across them merely because neighboring states are close. Preserve serial reductions, NaNs, refusal ordering, rollback and source/configuration ownership. Known same-evaluation airflow and invariant preparation candidates remain relevant, but they need actual attributed cost before deeper rewrites. The native candidate that computes legacy wind before overwriting it also requires optimized-object inspection: compiler elimination, libm errno and floating-exception behavior can change the apparent saving.

Input accumulation is already disabled in main.gd; recommending that as a fresh latency optimization would duplicate implemented behavior. Likewise, lowering physics Hz or allowing a low active-background frame cap can change simulation pace and control response. At 240 Hz with twelve catch-up ticks per frame, a sustained 15 FPS active cap permits at most 180 ticks per wall-second. Rendering and scheduling policies must measure simulation-to-wall-time ratio rather than report FPS alone.
